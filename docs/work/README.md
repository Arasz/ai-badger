# work — dated records of work done, not documentation of how things are

A work record describes a moment: what was proposed, what was decided, what was reviewed, what
broke. It is true of its date and is never updated to stay current — that is what makes it a
record. Documentation of how the framework works today lives in the quadrants
(`../reference/`, `../explanation/`, `../how-to/`, `../tutorials/`); decisions that bind live in
`../adr/`.

Filenames are `YYYY-MM-DD-slug`. A file here without a date is a placement error.

This directory is deliberately *not* grouped into `plans/`, `research/`, `designs/`, `reviews/`
or `incidents/`. Kind is not a subject, and those five were tried and removed — see
`../adr/` and PR #111.

| `2026-08-01-post-backlog-review.html` | Owner review gate over the seven refinement decisions raised while clearing the backlog (P1, P2, W1, F1, F2, B1, B2). Generated by the `owner-gate-review` skill; the form carries each decision's claim and detail verbatim. |
| `2026-08-01-session-decisions-review.html` | Owner review gate over the six decisions raised during the 0.61–0.66 release run (D1–D6). D6 is the one that produced this directory. |
| `2026-08-01-gherkin-spec-elicitation-research.html` | Research validating a `create-task-spec` skill that elicits a Gherkin specification by questioning rather than proposing. Records six claim verdicts, the grammar-as-question-generator argument, and the architecture chosen on 2026-08-01. |
| `2026-08-01-work-quality-rules.md` | Where each of sixteen proposed working rules belongs — five become `common` invariants, the rest are task lifecycle, delegation policy, or the `--risk` switch. Written while four packages were running against it; leaves once they merge. |
| `2026-08-02-hermes-task-tracking.md` | Evidence-first research on how the `/task` skill's tracking is (and is not) hooked into Hermes Agent: the four task hooks are Claude-only by design, the scaffolded scripts never fire under Hermes, every tracked task's checkpoints are all-zero — and Hermes's `state.db` demonstrably stores the per-model and per-subagent token data the tracker never reads. 14 findings (10 measured, 4 read). |

The first three are generated HTML forms rather than prose. They are kept because the form *is* the
record: each carries its decisions verbatim, and the reviewer's verdicts were ingested from them.
The third is a research record — true of its date, superseded rather than updated. The fourth is
the first plain-markdown record here.
