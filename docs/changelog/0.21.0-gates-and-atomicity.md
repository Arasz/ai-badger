# 0.21.0 — A gate that cannot fail is not a gate

**Review:** `docs/reviews/2026-07-26-full-project-review.md`
**Plan:** `docs/plans/2026-07-26-remediation-plan.md` (Wave 3)
**Incident:** `docs/incidents/2026-07-27-untagged-releases.md`

Wave 3 fixes the mechanisms that were supposed to catch the earlier waves' defects and
could not: a release guard with a stale baseline, schemas validating nothing, hooks that
failed without a trace, and writes with no way back. Findings are referenced by their
review IDs (F-09…F-13, F-16, F-23, F-24, F-25) plus two found during the work.

## Fixed

- **F-11 — no release tag existed past `ai-badger--v0.2.0`.** `VERSION` had reached
  `0.20.0`, so `release_guard.py` compared every commit against an 18-minor-old baseline,
  always found changes, always found a bumped `VERSION`, and always passed. It was
  structurally incapable of failing for 32 consecutive releases. `ai-badger--v0.20.0` is
  now cut at the Wave 2 merge; the 32 skipped versions stay untagged rather than being
  retro-tagged into a verification they never had. A batching policy was considered and
  **rejected** — it would have described the drift and removed the only baseline. New
  `UNTAGGED RELEASES` output names any changelog version between the last tag and
  `VERSION`, so the next skipped tag is visible on the first occurrence.

- **F-10 — a failed git command read as "nothing changed".** `_git` returned `""` on any
  non-zero exit, so a broken `git diff` printed `no shipped-surface changes — PASS`. It now
  raises `GitCommandFailed`; the guard prints `GIT COMMAND FAILED` and exits 1.

- **F-09 — `find_root()` downloaded and then executed unpinned `main`.** With no local
  framework it cloned the GitHub repo into `$HOME` and returned it, and
  `scaffold`/`refresh`/`drift` `exec_module` from there — reachable by running
  `validate.py --all` from the wrong directory, out of a function named "find", in a module
  documented as "deterministic and offline". `find_root()` is now a pure lookup that raises
  `FrameworkRootNotFound`; `ensure_root(allow_network=True)` is the only network path and
  clones `--branch ai-badger--v{version}`, never a branch. An unusable cache is reported,
  never `git pull`ed in place.

- **F-23 — non-atomic writes to shared state.** `tracker_lib.save_json` already did this
  correctly; `dump_json` (manifest, config, plugin.json, marketplace.json, index.json),
  `save_manifest`, and `mcp_index._write_index` did not, so an interrupted write truncated
  the file it replaced. `badger_lib.atomic_write_text` is now the shared implementation.
  `learned_skills_sync.load_manifest` returned an *empty* manifest when `learned.json`
  existed but would not parse — and both callers write the result straight back, so one
  truncated file discarded every learned-skill record. It now raises `ManifestUnreadable`
  and the sync refuses.

- **F-13 — hooks failed soft and totally silently.** Four hooks ended in
  `except Exception: pass` with nothing recorded anywhere, and `ai_badger_hooks` logged real
  failures at DEBUG. Each hook now writes one line to stderr and to
  `~/.ai-badger/hook-errors.log` before swallowing: exception **type and location only**,
  never the message, which can quote a scanned command or path.

- **F-16 — `adjust_skills.py` deleted directories it never owned.** A hand-authored
  `.github/skills/task/` — Copilot's own convention — was `rmtree`d with no ownership check
  and no note, and a plain file there raised `FileExistsError`. Ownership now mirrors
  `scaffold._owns_link`: our symlink, or a manifest-recorded target, and nothing else. The
  whole file previously had no test; it now has seven.

- **F-24 — `validate.py --all` covered 6 of 17 schemas.** `mcp-servers.json`,
  `external-tools.json`, `stack.json`, `dependencies.json` and `scaffolding.json` had
  schemas and were validated by nothing, while `mcp_tools.py` swallowed their parse errors
  with a bare `continue`. `--all` is now driven by `SCHEMA_INSTANCES`, and every schema not
  in it must appear in `SCHEMAS_WITHOUT_LOCAL_INSTANCES` with a reason — a new schema that
  validates nothing fails the build. Coverage went from 6 files to 38. The two silent
  `continue`s now append a note naming the file and the error type.

- **F-49 — the agent capability matrix was validated by nothing.**
  `features/common/support.json` pointed at a `support.schema.json` that did not exist.
  Written here against the real data (`supported` is boolean-or-`"partial"`, `format` is
  prose-or-shape, and `aiBadgerSupport` may not be true where the agent lacks the
  capability), and covered by `--all`.

- **F-50 — found by F-24's own fix.** The first run of the new coverage failed:
  `features/claude/stack.json` and `features/hermes/stack.json` were both missing the
  required `name`. Neither had ever been validated. Fixed in the same commit.

- **F-25 — a scaffold that died partway left no way back.** `run()` wrote
  `manifest.json` last, so any raise left framework files on disk with no manifest —
  reported by den-refresh as "never fully scaffolded" and rejected by feed-badger.
  `manifest.json.partial` is now written before the first step and after each one, and
  deleted only when the real manifest lands. den-refresh backs up `.ai-badger/` before
  **every** re-scaffold, not only breaking ones.

## Behaviour changes worth knowing

- **The release guard can now fail.** It failed on this branch, correctly, before the
  version bump. Expect the first post-tag PR touching `skills/`, `features/`, `scripts/`,
  `schemas/` or `index.json` to require a `VERSION` bump — that is the restored behaviour.
- **`find_root()` raises where it used to clone.** Any workflow relying on the implicit
  download breaks by design; the error names `--root` and `ensure_root(allow_network=True)`.
  Note that `ensure_root` can only fetch a *tagged* release, so versions before 0.20.0 are
  not fetchable — see the incident report.
- **Learned-skill sync refuses on an unreadable `learned.json`** instead of silently
  starting a new empty one. Fix or remove the file to resume syncing.
- **`.github/skills/<name>` that ai-badger did not place is now left alone**, and named in
  the notes with the manual step. Copilot will not discover the scaffolded skill until it
  is removed by hand — that is the trade for not deleting the user's work.
- **`den-refresh` always writes `.ai-badger.bckp/`.** Add it to `.gitignore` (done here).
- **Hooks now write to `~/.ai-badger/hook-errors.log`**, capped at 1 MB and rotated by
  truncation.
