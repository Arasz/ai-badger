# 0.218.0 — ai-raccoon decision records replace Semantica

**Minor** (a shipped integration is withdrawn; pre-1.0, the minor slot is the breaking slot) ·
**Date:** 2026-11-11

ai-badger no longer ships Semantica. ai-raccoon now keeps the decision records: it stores
versioned decisions for each task, next to the project memory that agents already search.
ADR-0048 records why (`docs/adr/0048-ai-raccoon-decisions-replace-semantica.md`). The research
is in `docs/work/2026-11-11-replace-semantica-with-raccoon-decisions-research.md`.

## Removed

- **The `semantica` MCP server.** Its catalog entry (`features/common/mcp/semantica/`: `meta.json`,
  `server.md`, `tools.json`, the `check.py` and `install.py` prerequisite scripts, and the
  `semantica_mcp_wrapper.py` export fix) and its `features/common/stack-mcp.json` entry. The
  scaffold does not declare the server any more, for any harness.
- **The `semantica-knowledge-graph` skill** and its two scripts, `export_semantica_graph.py` and
  `semantica_export_autosave_hook.py`. The plugin copy under `skills/` is removed too.
- **The `semantica-export-autosave` hook.** It saved the `export_graph` result to
  `.semantica/<session>.json`. It is removed from `hooks.json` and `hooks-manifest.json`, and from
  the Hermes plugin (`ai_badger_hooks.py`).
- **The Semantica nudge.** The context-enrichment hook no longer tells the agent to call
  `record_decision` on Semantica. The `semantica_nudge` session-store family is removed from
  `badger_store.py` (every vendored copy).
- **The `semantica-graph.json.tmpl` template** and the optional `semantica>=0.6.8` line in
  `engine/requirements.txt`.
- **The Semantica test suites** (`test_mcp_semantica_catalog`, `test_semantica_export_hook`,
  `test_semantica_export_autosave_hook`, `test_semantica_knowledge_graph_skill`,
  `test_semantica_mcp_scripts`, `test_semantica_session_export`). `tests/test_semantica_removed.py`
  replaces them. It asserts that no catalog entry, hook, script, generated tree or live document
  names Semantica.

## Added

- **Decisions in the `ai-raccoon-memory` skill.** A new section 9, "Decisions", gives the four ids
  each write takes (`projectId`, `taskId`, `sessionId`, `requestId`), the write order
  (`register_decision_task` once, then `record_decision`), the tools that change a decision
  (`amend_decision`, `transition_decision`, `supersede_decision`, `link_decisions`) and the read
  tools (`query_decisions`, `find_decision_precedents`, `get_decision_graph`,
  `preview_decisions`, `export_decisions`). The verification checklist has a decision item.
- **An optional ai-raccoon step in `decision-record`.** After the project's own record is written,
  the skill also calls `record_decision` in ai-raccoon when the server or the
  `ai-raccoon decisions` CLI is available. The project's own record stays the primary record
  (ADR-0047). When ai-raccoon is not available, the agent skips the step.
- **A new `reflect` step in `/task`.** The step runs `query_decisions` with the task id to confirm
  that the decision exists, and does not record it again. Then it calls `transition_decision`
  (the outcome held) or `supersede_decision` (it did not).
- **The ai-raccoon catalog describes the decision tools.** `meta.json` and `tools.json` name the
  decision records.

## Upgrade notes

Use ai-raccoon 2.6.1 or later. Arasz/ai-raccoon#932 fixes the output schema of the decision
tools. In ai-raccoon 2.6.0 and earlier, the write lands, but Claude Code rejects the reply because
the schema marks null fields as required. If a reply is rejected, do not retry. Check the write
with `ai-raccoon decisions query --project-id <id>`. If a retry is necessary, send the same
`sessionId` and `requestId`, so the server replays the first result.

A re-scaffold merges agent configuration additively. Thus it does not remove the Semantica
entries that an earlier version wrote. Remove them by hand:

- **Claude Code** — remove the `semantica` server from `.mcp.json`. In `.claude/settings.json`,
  remove `semantica` from `enabledMcpjsonServers`, the `mcp__semantica__*` rule from
  `permissions.allow`, and the `PostToolUse` entry whose matcher is
  `^(mcp__.+__|.+-)?export_graph$` (its script is gone, so the hook does nothing).
- **Copilot** — remove the `semantica` server from `.github/mcp.json` and from `.mcp.json`. The
  scaffold rebuilds `.github/hooks/ai-badger-hooks.json`, so the old hook goes away by itself.
- **pi** — remove the `semantica` server from `.pi/mcp.json`.
- **Hermes** — remove the `semantica` entry under `mcp_servers` in `~/.hermes/config.yaml`. The
  next refresh deletes the stale `export_semantica_graph.py` copy from the Hermes plugin.
- **Codex** — no action. The scaffold rebuilds its managed block in `.codex/config.toml`, so the
  `semantica` server goes away on the next refresh.
- **mcp-index** — remove the `semantica` source from `.ai-badger/mcp-tools.json`.
- **Old exports** — delete the `.semantica/` directories and remove their ai-raccoon watch with
  `remove_watch`. ai-badger does not migrate them. Newer ai-raccoon releases can import Semantica
  export files.
- **The Semantica tool** — uninstall `semantica-mcp` if nothing else uses it.

ai-badger does not drop the `semantica_nudge` table in the user database or delete
`~/.ai-badger/semantica-nudge/`. They are left on purpose: they hold no data that anything reads.

This version is not in `BREAKING_VERSIONS`. The removed hook commands are guarded by a file
check, so a stale entry does nothing. A full re-scaffold does not remove the MCP entries either,
so to require one would not help. A scaffold step that prunes them is a follow-up.
