# 0.151.0 — the config's prose surfaces for staleness review

`project.summary` and `project.domain` are the only free-form prose the framework renders
into managed agent files — via the `{{PROJECT_SUMMARY}}` / `{{PROJECT_DOMAIN}}` slots of
`template_rendering.compute_doc_slots`, re-rendered on every scaffold. Nothing else in the
scaffold is prose: every other slot is structured, and every file it lands in is
fingerprinted. Which meant the prose was the one thing that could go silently stale — a
project evolves, the summary keeps describing the project as it was at scaffold time, and
every refresh and drift report stayed green while the scaffold faithfully re-rendered the
outdated sentence into every managed copy.

## What changed

- **drift.py gained `proseReview`.** `compare()` now returns a `proseReview` list (and the
  CLI prints a matching section): one entry per non-empty prose slot, carrying the
  `configKey`, the template `slot` it fills, the `value` as written, and the note
  "human-written — review for staleness". The list is read from the target's own
  config.json, the same way `_config_drift` reads it.
- **den-refresh reports it.** The refresh report carries `drift.proseReview`, alongside the
  other drift keys the operator already reviews.
- **One list, two readers.** The slot list now lives once, as `PROSE_SLOTS` in
  `template_rendering.py` (which `compute_doc_slots` renders from). `drift.py` duplicates
  the two-entry mapping — it runs standalone, the same reason `_bootstrap_lib` is duplicated
  into every entry point — and `test_prose_staleness_review.py` pins the two lists to each
  other and to what `compute_doc_slots` actually renders, so they cannot drift apart
  silently.

## What deliberately did not change

- **Prose is never a drift signal.** It gates neither drift.py's exit code nor refresh's
  re-scaffold decision: a re-scaffold cannot freshen stale prose — it would faithfully
  re-render the same words — so gating on it would re-scaffold on every run, forever. The
  fix is a human re-reading the summary, which is exactly what the surfaced listing asks
  for.
- **Nothing rewrites the prose.** config.json is project-owned (#172); drift and refresh
  report, they do not edit.
- **No name-matching heuristic.** A "warn when the summary mentions a name that matches no
  path in the tree" check was considered and rejected: telling domain nouns from path names
  needs project knowledge, so the generic version warns on ordinary words — a
  false-positive machine, not a review aid. The honest signal is the listing itself.

## Upgrade notes

- Consumer-repo action: none required. Run `den-refresh` to pick up the reporting scripts;
  the report gains `drift.proseReview` on the next refresh, and drift's CLI prints the
  section when the config carries prose.
- Report readers: `drift.proseReview` is always present in the refresh report (an empty
  list when the config carries no prose), and every entry is advisory — it never appears in
  `changed`/`removed` and never triggers a re-scaffold.
