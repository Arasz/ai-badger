# 0.211.1 — The memory gate's footer status counts every search

**Classification:** Patch
**Date:** 2026-10-21

## Fixes

- **The pi adapter's memory-gate footer segment appears for every search the gate answered.**
  The segment counted only the raw outputs the gate captured, and it was published only when
  that count was above zero. The gate captures a raw output for a single standalone shell
  grep, so pi's native search tool, `cd dir && grep …`, `grep … | head` and every other shape
  answered the search with no capture: the counter stayed at zero and the footer said nothing,
  even though the gate had run and delivered its memory result.

  The adapter now counts the patterns the gate searched as well as the raw handles it captured
  for them, and publishes the segment whenever the gate searched. The segment is
  `[mem <searched> <fetched>/<captured>]` — the searches the gate answered, and the fetched
  share of the captures. A session with no capture reads `0/0` rather than pretending a capture
  the agent never got a chance to fetch.

  The vendored adapter is a copy; the canonical source is
  [Arasz/pi-badger-integration](https://github.com/Arasz/pi-badger-integration) (pull request
  #90), vendored with `bun publish.ts --ai-badger`.

## Upgrade notes

None: the segment's format changed from `[mem <captured> <fetched>%]`, and it now appears in
sessions where it used to stay empty. Nothing else reads it.
