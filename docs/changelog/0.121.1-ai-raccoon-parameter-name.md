# 0.121.1 — The ai-raccoon Guidance Named a Parameter the Server Does Not Have

**Type:** PATCH
**Date:** 2026-08-15

## What Changed

`project_id` → `projectId` everywhere the ai-raccoon guidance names the parameter:
`features/common/mcp/ai-raccoon/server.md` (the block inlined into every scaffolded agent
file), `features/common/skills/ai-raccoon-memory/SKILL.md`, and the deny message in
`memory_first_gate.py`.

## The instruction could not be followed

The server declares `projectId`. An agent that read the instruction literally sent an argument
no tool accepts, and the call failed schema validation on a missing required field — it was not
coerced, because there is no `project_id` property to coerce into.

Three independent sources agree, and they were checked before the rename rather than after:

| Source | What it says |
|---|---|
| The live `memory_search` schema | `required: ["projectId", "query"]`; no `project_id` property |
| The server's reference documentation | "Every tool requires `projectId` (camelCase — all parameters are camelCase), except `memory_promotion_list` where it is optional" |
| The server's tool signatures | `projectId` throughout |

The second source is why the fix is uniform rather than per-tool: the contract is stated for the
whole surface, so every occurrence was wrong for the same reason.

## Proven to fail

`tests/test_memory_first_gate_worktree.py:60` pinned the old string. It was run **before** the
assertion was updated and failed on exactly the substring under change:

```
AssertionError: assert 'project_id=main-repo' in
  'Memory-first gate: run memory_search (projectId=main-repo) before repo text search; ...'
```

Assertion updated, both halves green. That check is what stops the label drifting again in
silence; a rename nothing objects to is a rename nothing is guarding.

## Python Naming Was Left Alone

In `memory_first_gate.py` only the **displayed label** changed. The function `project_id()`, the
`.format()` keyword and the `AI_RACCOON_PROJECT_ID` environment variable keep their snake_case
spelling, which is correct for Python. The defect was never the Python convention — it was that
convention leaking into a sentence describing a wire contract.

## Scope

Text, one test assertion, and the generated files that carry the block — this repository's own
agent files, its hooks copy, and the plugin-skills copy, all regenerated rather than hand-edited.
No behaviour change: the memory-first gate fires on the same condition and returns the same
decision. Only the sentence it prints is correct now.

Found by running `den-refresh` on a consumer project, where the regenerated `CLAUDE.md` carried
the wrong parameter name into the project.
