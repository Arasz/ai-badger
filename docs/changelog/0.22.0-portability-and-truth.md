# 0.22.0 — portability, and documentation that matches the code

**Review:** `docs/reviews/2026-07-26-full-project-review.md`
**Plan:** `docs/plans/2026-07-26-remediation-plan.md` (Wave 4)

Wave 4: the correctness details that survive a code read but not a careful one, and the
pass where every document was checked against the behaviour it describes. Findings are
referenced by their review IDs (F-14…F-22, F-26…F-39, F-48).

## Fixed

- **F-21 — prompt markers fired on Windows paths.** `H:\Projects\foo.py, can you check
  this?` lowercases to `h:\projects…`, which matched the bare `h:` hint prefix and silently
  injected *"HINT: … you MUST perform a research pass"* into the model's context. The
  injection is silent `additionalContext` by design, so the user got a distorted answer with
  no signal at all. A single-letter prefix now requires whitespace or end-of-prompt after
  it; `hint:` / `feedback:` / `extension:` are unchanged.

- **F-22 — `.mcp.json` inherited the wrong agent's overrides.** A `for agent in agents: …
  break` loop meant that with `agents: ["copilot", "claude"]`, the **copilot** overrides
  landed in a file only Claude Code reads — a silent misconfiguration decided by list order.
  Each generated MCP file now takes the overrides of the one agent that reads it:
  `.mcp.json` and `~/.claude/settings.json` → claude, `.github/copilot/mcp-config.json` →
  copilot, `~/.hermes/config.yaml` → hermes. The last three applied no overrides at all
  before. When the owning agent is not configured, the file is written without overrides and
  a note names the servers that lost them.

- **F-20 — the maintainer's home directory shipped as a default.**
  `_DEFAULT_USER_STATUSLINE = "/Users/arasz/.claude/statusline.sh"` leaked a username into
  every scaffolded project and, because rendering gates on `.exists()`, made the feature
  silently dead for every user who is not the author. There is no sensible default for a
  per-machine path, so there is none: set `CLAUDE_USER_STATUSLINE`, now documented.

- **F-14 — unguarded third-party imports in directly-invoked scripts.** `mcp_index.py` and
  `adjust_agents.py` imported `yaml` at module scope while `mcp_tools.py` guarded the
  identical import. Both now degrade the way `mcp_tools` already did — exit 1 with an
  install hint, or a note on the scaffold — and `mcp-index/SKILL.md` gained the
  Prerequisites section it never had.

- **F-15 — the `task` skill is POSIX-only and did not say so.** `tracker_lib` imports
  `fcntl` at module scope and `task_tracker` shells out to `crontab`, so the skill cannot
  import on Windows. It now declares `platforms: [linux, macos]`.

- **F-26 — `install_plugins.py --dry-run` could not be turned off.** It was
  `action="store_true", default=True`. The CLI is now honestly print-only: execution lives
  in one place, `scaffold.py --execute`, which runs the same commands with a timeout and
  records each outcome.

- **F-31 / F-32 — claims that did not match the code.** `scaffold.py`'s Usage synopsis
  omitted `--overwrite-agent-files`, `--reset-seed-files` and `--execute` — the last decides
  whether the scaffold runs shell commands. "Pure-stdlib Python 3.8+" was wrong on both
  halves: `jsonschema` and `pyyaml` are real dependencies, and `badger_lib` claimed 3.9+
  while CI's floor is 3.8. `pyproject.toml` now pins `py-version = "3.8"` so pylint enforces
  the floor — deliberately not a `[project] requires-python`, which would add a fourth
  version literal that ADR-0001 exists to prevent.

- **F-18, F-19, F-27–F-30, F-33–F-35 — the documentation pass.** `RELEASING.md` described a
  Hermes discovery mechanism that shipped in 0.7.1 and was **reverted**; two `config.json`
  examples used `pluginScope`, a key the schema rejects outright; the pre-0.7.0 design doc
  was linked with no qualifier; three planning docs still said "Proposed" for work shipped
  in 0.7.0/0.13.0/0.18.0; `docs/scripts.md` listed 3 of 7 scripts, omitting four of the five
  CI gates; the index omitted ADR-0003 — the authoritative record for the *current* Hermes
  mechanism; `dictionary.md`, the anti-drift document, had drifted on the skill-extension
  path; `manifest.schema.json`'s "during transition" note had outlived 11 minor versions;
  and two ADRs shared number 0002 in a repo where code cites ADRs by number (the MCP tool
  index ADR is now 0004).

- **F-36 — the instruction-size budget checked one file out of five.** `HERMES.md` and
  `.hermes.md` were already 24–26 lines over the same budget with no mechanism looking at
  them. Every agent discovery file that exists is now checked, and all offenders are named
  at once.

- **F-37 — a hint repeated every single turn.** Hermes' `pre_llm_call` appended the same
  three-command usage line unconditionally. This project's own `0.18.0` changelog names an
  unconditional line as the reason a broken hook went unnoticed for weeks. Now once per
  session.

- **F-38 — `_Default routing._` was a placeholder that read like a policy.** With
  `personaRouting: []`, the rendered agent file now says nothing is configured and names the
  key that would configure it.

- **F-39 — instructions that contradicted the project.** `python.instructions.md`
  prescribed pyright and ruff to a project that deliberately uses pylint only, with the
  rationale written in its own `pyproject.toml`. It now defers to `commands.lint`.

- **F-48 — a test that asserted nothing matching its name.**
  `test_pre_llm_inject_with_index_no_double_injection` checked only `result is not None`,
  with two comments describing a check that was never written. It is now named for what it
  tests and asserts it.

## Behaviour changes worth knowing

- **`h:foo` (no space) is no longer a hint marker.** `h: foo` and `hint:foo` still are.
- **Generated MCP config content changes** for any project whose servers declare
  `agentOverrides` and whose `config.agents` does not start with the file's owning agent.
- **The statusline chain is off until you set `CLAUDE_USER_STATUSLINE`.** It was already off
  for everyone but the author; now it says so instead of pretending.
- **The end-of-task budget nag can now fire for `HERMES.md` or
  `.github/copilot-instructions.md`**, not only `CLAUDE.md`.
- **`docs/adr/ADR-0002-mcp-tool-index.md` is now `docs/adr/0004-mcp-tool-index.md`.**
- This repo's own `.ai-badger/` scaffold was regenerated at 0.21.0 → the managed agent files
  changed accordingly.
