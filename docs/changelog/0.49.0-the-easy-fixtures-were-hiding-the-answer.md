# 0.49.0 — the easy fixtures were hiding the answer

[`docs/retrieval.md`](../retrieval.md) is updated for what the hard fixture set found. Its
previous conclusion — that the matcher is saturated and there is no meaningful headroom — was
true of the instrument, not of the matcher.

Documentation only. No behavior changed.

## What changed in the document

- **The headline numbers are now two columns, not one.** Easy set: recall@1 0.930, recall@3
  1.000, false fire 0.267. Hard set: recall@1 **0.442**, recall@3 **0.481**, false fire 0.333.
- **The per-class breakdown is the finding**, and it is not a uniform collapse:

  | Class | recall@1 | recall@3 | mean overlap |
  |---|---|---|---|
  | near-dup | 1.000 | 1.000 | 0.783 |
  | user-voice | 0.200 | 0.333 | 0.229 |
  | paraphrase | 0.000 | 0.000 | 0.000 |

  BM25 is perfect on the class built to be hard — disambiguating genuinely near-duplicate tools —
  and scores zero on seventeen paraphrases that share no vocabulary with their target. The
  failure is lexical coverage, not ranking, and no weight or threshold change can reach it.
- **recall@1 moved 0.907 → 0.930** with no matcher change, because a fixture naming only one of
  two functionally identical tools (`rider:search_regex` / `rider:search_in_files_by_regex`) was
  scoring a correct answer as wrong.
- **The two "margins" are disambiguated.** *Threshold headroom* (0.0089) and the runner's
  *class separation* `coverage_margin` (−0.201) measure different things and disagree in sign.
  Both are true: the threshold is finely balanced, and no threshold anywhere cleanly separates
  positives from false fires.
- The regression gate and the instrument are described as the different things they are — the
  hard set asserts no recall bar, deliberately, because a gate you can always pass tells you only
  that you have not regressed.

## What was deliberately not changed

The 0.48.0 changelog entry still reports recall@1 of 0.907. That was the number 0.48.0 shipped
with; a changelog entry is a record of a tree at a point in time, and editing it to match a later
measurement would falsify the record rather than correct it.
