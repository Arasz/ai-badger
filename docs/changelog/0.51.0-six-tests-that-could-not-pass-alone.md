# 0.51.0 — six tests that could not pass alone

`pytest tests/test_version_sync.py` failed all six of its tests. The same six passed in the
full suite. Nothing was wrong with them.

## What was happening

`tooling/version_sync.py` put `engine/` on `sys.path` for `badger_lib` and **nothing** for its
own sibling `index_build`. A bare `import index_build` therefore resolved only when something
else had already placed `tooling/` on the path — which `tests/test_index_build.py` does, and
which sorts alphabetically before `test_version_sync.py`.

So the file passed inside the suite by accident of collation order, and failed the moment anyone
ran it on its own. That is the normal first move when debugging a failure, and it produced six
red tests and no defect.

Running the script was always fine: executing `python tooling/version_sync.py` puts its own
directory on `sys.path[0]` implicitly. Importing it did not.

## The fix

One line, matching what every feature script in this repository already does
(`sys.path.insert(0, _SIBLING_DIR)`) — the script now reaches its own siblings rather than
depending on a caller having done it.

## Proof

| | before | after |
|---|---|---|
| `pytest tests/test_version_sync.py` | 6 failed | 7 passed |
| full suite, reverse file order | 6 failed | 1932 passed, 0 failed |

The reverse-order run is how this was found: 113 test files fed to pytest in reverse collation
order. It is worth repeating occasionally — a suite that only passes in one order is one
rename away from a mystery.

An isolation test now pins it: the file loads with `tooling/` removed from `sys.path` and
`index_build` cleared from `sys.modules`, so a regression fails on its own terms rather than
waiting for someone to run the file by itself.
