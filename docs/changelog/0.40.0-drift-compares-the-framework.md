# 0.40.0 — drift compares the framework, and every check must prove it can fail

Two entries' worth of work at one version: the defect, and a guard against the class it belongs
to.

## `den-refresh` could not see a changed skill

[#110](https://github.com/Arasz/ai-badger/issues/110). Found by running `den-refresh`
end-to-end after the 0.35.3 → 0.39.0 arc.

With the framework five files and 87 lines ahead of the scaffold, it reported:

```json
{"reScaffolded": false, "drift": {"changed": 0, "removed": 0, "skipped": 0, "newItems": 0}}
```

A direct scaffold run immediately afterwards changed those five files. **The entire 0.39.0
feature would not have been delivered to a project refreshing from 0.38.0.**

For a directory-valued entry — which is every skill — `compare` hashed the **scaffolded copy**
and checked it against the hash recorded *when that copy was written*. Both sides are the
project's own state, so they match unless the user edited the files locally.

> It answered *"has this project modified its copy?"* while `den-refresh` needed *"has the
> framework moved ahead?"*

Non-directory entries were always correct — they hash the framework source.

### Why the fix is not "hash the source instead"

The scaffolded copy genuinely cannot answer the framework question: it is **rendered output**.
Tests are stripped, extensions pruned and then merged into `SKILL.md`, `project-local.md`
appended. Comparing the source against the recorded *target* hash would flag every skill,
forever.

So `scaffold.record()` now writes **`sourceHash` + `sourceMeta`** covering the framework source
directory, and `compare` measures framework drift source-to-source. Both fields are optional; a
manifest that predates them reports `skipped` **with a note**, never a silent clean — the
question has no recorded answer, and saying "no drift" would be the same defect again.

### What was kept

*"Did the project edit its copy?"* is a different and still useful question. It survives as its
own **`locallyModified`** category — never conflated with framework drift, and never triggering a
re-scaffold. A re-scaffold overwrites those edits, so the operator should hear about them first.

The `_within` traversal check (a crafted manifest `target` must not steer the hasher out of the
project) is intact, and now sits on the only path that reads a manifest target — feeding the
local-modification question alone.

### Two smaller defects in the same run

**A `frameworkVersion` difference is now drift in its own right.** The version is embedded in
rendered output — `manifest.json` and the `> Scaffolded by ai-badger X` stamp in every generated
agent file — so a version-only change genuinely makes those files stale.

**`refresh.py` no longer advances `config.json`'s stamp unconditionally.** That write is what let
its own next report read the number it had just written and call itself current, while
`manifest.json` and every agent file were still a version behind — and `drift_notice_hook`, which
reads the manifest, kept firing after a "successful" refresh.

## Every check must prove it can fail

The repository named this class in [0.21.0](0.21.0-gates-and-atomicity.md) — F-11 was
*"structurally incapable of failing for 32 consecutive releases"* — and it kept recurring:

| | The degeneracy |
|---|---|
| **F-11** (0.21.0) | An 18-minor-stale baseline: always found changes *and* a bump. |
| **[0.35.3](0.35.3-an-untagged-release-fails-the-guard.md)** | Detected untagged releases, printed them, returned **0**. |
| **[0.34.0](0.34.0-skills-that-arrive-and-a-root-that-agrees.md)** | `is_instrumented()` read a string containing `${CLAUDE_PROJECT_DIR}`, so **every** hook reported not-instrumented. |
| **#110** | Compared the project against its own recorded hash. |

One shape: **a comparison that can only produce one answer, and that answer looks like success.**
Every instance was caught by a human noticing something downstream. Never by a test.

`tests/test_every_check_can_fail.py` is a registry of **provocations, executed rather than
asserted about**. Each check declares a callable that builds the same fixture with and without a
defect, and the meta-test runs **both arms** — provoked must fail, clean must pass. The second arm
is load-bearing: without it, a fixture broken for setup reasons proves exactly as much as the
degenerate checks this hunts.

Coverage is discovered mechanically — `gates/*.py`, scripts declaring `--check`, module-level
`compare(`, and every finding kind parsed out of the behaviorist's `_finding(...)` calls. **A new
check with no provocation fails the build.** Exemptions are permitted but must name a reason and
are meant to shrink; there is one.

18 provocations, 41 tests, roughly 15 seconds.

A static "does a failure-asserting test exist?" scan was rejected: it is fuzzy and gameable, and
**three of the four instances above already had passing tests**. The tests were not missing — they
all mutated the wrong side.

### The relapse surface, closed

`release_guard`'s `NO RELEASE TAG FOUND` path is a deliberate always-pass, so under
`actions/checkout`'s default `fetch-depth: 1` — which fetches no tags — the whole gate becomes a
silent no-op. That is F-11's exact shape. A test now asserts every workflow running
`release_guard.py` checks out with `fetch-depth: 0`.

Its first version could not fail, which is worth recording: it searched the workflow for
`fetch-depth: 0`, and **the comment above that setting explains the hazard by naming it** — so a
substring search read the warning as the answer. It now compares comment-stripped key lines, and
both arms are proven.

## Upgrading

Re-scaffold. Your manifest predates `sourceHash`, so the first `drift` run reports your skills as
`skipped` with a note; the version rule then forces the re-scaffold that populates it, and the
run after that is comparable.
