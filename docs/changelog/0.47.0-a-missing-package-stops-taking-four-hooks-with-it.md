# 0.47.0 — a missing pyyaml no longer takes four hooks down with it

## The defect

`features/common/hooks/ai_badger_hooks.py:29` was:

```python
import yaml  # pylint: disable=import-error
```

module-level and unguarded — the only such import in the tree. Every other yaml import is
guarded or function-local (`mcp_index.py`'s `try`/`except ImportError` with `YAML_MISSING_HINT`,
`adjust_agents.py` and `mcp_tools.py`'s function-local imports), matching the rule
`CONTRIBUTING.md` already states: pyyaml is optional, "imported behind a guard and degrades to a
printed note." Three lines below the bad import, `debug_log` shows the intended shape:

```python
try:
    import debug_log  # pylint: disable=import-error
except ImportError:  # pragma: no cover - a missing logger must never break a hook
    debug_log = None
```

`ai_badger_hooks.py` is the Hermes plugin module. If pyyaml is absent from that environment, the
bare `import yaml` raises at import time, `register()` never runs, and the drift notice, the
commit reminder, the session/context hints, and the MCP tool recommendation all vanish together
— silently, before any of ai-badger's own error handling exists.

## The fix

`import yaml` is now guarded exactly like `debug_log`, falling back to `yaml = None`. The only
other yaml use in the module, `_load_mcp_index`'s `yaml.safe_load(...)`, now returns `None`
before touching `yaml` at all when the import failed — the same "index absent" outcome the
function already produces for a missing `.ai-badger/mcp-tools.yaml`, so every existing caller's
None-handling covers it for free.

## Why `deps_guard` didn't catch it

`gates/deps_guard.py` checks that a third-party import is *declared* in
`engine/requirements.txt`. pyyaml is declared there, as optional — the guard has no notion of
"declared optional, therefore must be guarded," so an undeclared-but-unguarded import was
invisible to it.

## Why `DEGRADING_HOOKS` didn't catch it

`tests/test_deployment_shapes.py::test_a_stale_vendored_shim_degrades_rather_than_raising_in_a_hook`
already parametrizes over `ai_badger_hooks` and asserts it degrades rather than raising — but it
simulates a *stale vendored `_bootstrap_lib` shim* (ADR-0011's breaking predicate change), not a
missing pyyaml. Every test process in this suite has pyyaml installed as a dev dependency, so
`import yaml` always succeeded regardless of which bootstrap scenario the test constructed; the
module-load failure this issue describes never occurred in that harness. The gap is a missing
scenario, not a weak assertion, so a new test —
`tests/test_ai_badger_hooks_missing_yaml.py` — patches `builtins.__import__` to fail for `yaml`
specifically (mirroring `test_mcp_index.py::test_missing_yaml_degrades_with_a_message`) and
asserts the module still imports, `register()` still wires all three hooks, and each non-yaml
hook still runs.

## Not covered

Migrating `.ai-badger/mcp-tools.yaml` to JSON — which would remove this import's reason to exist
at all — is a larger, separate change with a consumer-project migration path to design; it is
being tracked in ADR-0012 on another branch, not decided here.

## Migration

None. The guarded import is behaviorally identical whenever pyyaml is present, which is every
shipped deployment shape that has been tested until now.
