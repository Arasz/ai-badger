# v0.142.0 — git-dir guard review fixes: false positives, bypasses, and an honest fail-open story

A code review of the git-internals guard and the config-health hook found nine confirmed
defects, each reproduced before fixing. Every fix landed with a test that was witnessed RED
against the pre-fix behaviour and GREEN after.

## Fixes

- **F1** — The health hook warned on every unpushed branch (`git switch -c` leaves
  `branch.<name>.merge` unset by design) and prescribed a repair that exits 128 there. It now
  warns only when `refs/remotes/origin/<branch>` exists — a genuinely lost tracking section.
- **F3b** — The Hermes arm scanned `execute_code`/`patch` payloads with no size bound while
  the Bash path caps at `MAX_COMMAND`; a payload-sized `execute_code` reached the 30 s hook
  timeout, which Hermes fails CLOSED on. The same cap now applies, and the module docstring
  states the Claude/Hermes fail-open asymmetry accurately (the earlier "fails open everywhere"
  claim was wrong for Hermes).
- **F4** — The guard refused backups and reads: `cp .git/config /tmp/backup` was denied with
  the source called a write target, `chmod -R 700 .git` denied, `python3 -c "read"` denied.
  `cp`/`mv`/`ln`/`install` now check only their last non-flag argument, `chmod`/`chown`/`touch`
  are not mutators at all, and interpreter one-liners deny only when the code string also
  carries a write-indicator token.
- **F5** — `sudo -n rm .git/config` was allowed: the first wrapper flag was returned as the
  program name. Flags inside a skippable prefix are now consumed (`env -u NAME` and `env
  NAME=v` included).
- **F6** — `MAX_ANCESTORS = 8` let a deep ref inside a bare repo (`refs/remotes/origin/a/b/c/d/e/ref`)
  escape the structural probe; raised to 12 and pinned by a test so the bound cannot silently
  regress below the counted ref layout.
- **F7** — `sed --in-place` was allowed while `sed -i` denied (prefix flag matching), and a
  subshell's `cd` leaked past its `)` to arm the gate on an ordinary `rm config` afterwards.
- **F2** — A missing guard sibling module made the registered Hermes hook silently inert. It
  still fails open (an inert guard must not brick tooling) but logs a `missing` warning once
  per process.
- **F8** — The invariant and repair playbook named `git config --edit` as the same raw-file
  trap while the guard allowed it unconditionally; the guard now special-cases it, and the
  docs state that it is enforced.

## Test honesty

- The installer test that claimed to verify guard delivery only asserted tuple membership;
  it now runs the installer and asserts the file lands beside the hook it arms (F9b).
- The vacuous `test_b20_lefthook_install_is_allowed` row was deleted and replaced with rows
  that discriminate the pre-fix behaviour.
- New allow rows pin the whole backup/read class the guard previously refused.
