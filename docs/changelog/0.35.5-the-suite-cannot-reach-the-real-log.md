# 0.35.5 — the test suite cannot reach the real audit log

A full-suite run wrote a record into the developer's own
`~/.ai-badger/debug/audit.jsonl`:

```json
{"t":"2026-07-28T05:34:12+00:00","c":"some/hook","e":"start","v":"0.35.3"}
```

`some/hook` is a name that appears nowhere but `tests/test_debug_log.py`. The suite was
writing into the very log `call-behaviorist` reads, which means fabricated components in a
health report — the same class of problem [0.35.4](0.35.4-behaviorist-stops-inventing-failures.md)
had just finished removing from the analyzer.

## Why a point fix was the wrong shape

Running `tests/test_debug_log.py` alone never leaks, and **every** `log_event` call site in
that file already redirects the sink. The escape is order-dependent, and the reason is
structural rather than local:

`DEBUG_DIR` is `Path.home() / ".ai-badger" / "debug"`, resolved **at import time**. Scripts
are loaded by path, so each `load_script` call produces a *fresh module object with its own
globals* — and `monkeypatch.setattr` reaches exactly one of them. Any copy loaded by some
other route keeps the real path. Hunting the specific ordering would fix one route into a
defect with many.

## What changed

A session-scoped autouse fixture points `$HOME` (and `USERPROFILE`) at a scratch directory
before anything is imported. Every copy of `debug_log`, however and whenever it is loaded,
now resolves its sink under that directory. Per-test redirection still works and is
unchanged; this is a floor beneath it, not a replacement.

Two tests hold the guard in place: one asserts a freshly loaded copy of each `debug_log` —
canonical and vendored — points away from the real home, and one forces logging on with
nothing patched and asserts the write lands in the scratch home. The second is the honest
form of the property: the write still happens, it simply cannot arrive anywhere that matters.

Capturing `REAL_HOME` at conftest import time is what lets a test still name the directory it
must avoid, after the fixture has moved it.
