# 0.210.2 — The memory gate's footer status

**Classification:** Minor
**Date:** 2026-10-20

## Features

- **The pi adapter counts the memory-first gate's work and shows it in the footer.** The gate
  answers a repo text search with the memory result and keeps the raw `grep`/`rg` output alive
  for about two minutes; the `get-raw-text-search` skill fetches that output back. Nothing said
  whether a capture was worth its cost. The adapter sees both halves — the gate's answer arrives
  as `additionalContext`, the fetch arrives as a bash call — so it counts them and writes one
  bracketed segment into pi's footer: `[mem <captured> <fetched>/<captured>%]`. A session that
  captured nothing shows no segment at all.

  The vendored adapter is a copy; the canonical source is
  [Arasz/pi-badger-integration](https://github.com/Arasz/pi-badger-integration) (pull request
  #83), vendored with `bun publish.ts --ai-badger`.

## Changes

- The pi adapter ships `mem-status.ts` beside `index.ts`, `hook-bridge.ts`, `bus-prefilter.ts`
  and `bus-store.ts`; `adjust_hooks.py` copies every file of the adapter directory, so the
  scaffold ships it without a change.
- The framework's own scaffold was refreshed for 0.210.2. Its MCP declarations follow the
  current catalog: `ai-raccoon` is `scope:user` (the operator registers it once in the
  user-global config), and `hermes` is declared only where the `hermes` binary is on PATH.

## Upgrade notes

None: the footer segment is new, and nothing else changes.
