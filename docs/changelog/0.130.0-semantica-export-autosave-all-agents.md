# 0.130.0 — Semantica: export autosave reaches Claude & Copilot; upstream export bug probed

**Type:** MINOR
**Date:** 2026-08-20

MINOR because the autosave hook gains a surface: `semantica-export-autosave` now wires
Claude Code (PostToolUse) and Copilot (postToolUse), not just Hermes (#418). The upstream
Semantica export bug this work found is documented, probed, and worked around — not fixed
here (it lives in the semantica package; see below).

## The upstream bug this task's live test caught

`export_graph` — the only window into Semantica's in-memory graph — is broken in semantica
0.6.5 and 0.6.6 (and on GitHub main at the time of writing):

1. **The `json` branch calls `JSONExporter().export(graph)`** but that method requires a
   `file_path` argument, so every `export_graph(format="json")` returns
   `{"error": "JSONExporter.export() missing 1 required positional argument: 'file_path'"}`.
2. **Every RDF branch (`json-ld`, `turtle`, `nt`, `xml`) prints a rich progress bar to
   stdout**, which over stdio MCP corrupts the JSON-RPC framing — the client times out
   (observed: 300s timeout on an empty graph; the same call returns in <1s directly).

Consequence: no agent could export the graph, so `.semantica/` dumps never happened and the
AiRaccoon persistence bridge was dead regardless of watches. The fix ships in a semantica
release after 0.6.6 (PR opened upstream); ai-badger's side of it:

## What shipped

1. **Error payloads are never saved as graph dumps** (`export_semantica_graph.py`). The
   Hermes transport wraps the MCP result as `{"result": "<json>"}`; an inner
   `{"error": ...}` dict passed `extract_graph_json`'s outer-only error check and was saved
   to `.semantica/<session>.json` (observed live). RED → GREEN.
2. **Claude Code and Copilot get the autosave hook (#418).** New
   `semantica_export_autosave_hook.py` — a stdin-JSON PostToolUse transport that delegates
   to the same `autosave_export` the Hermes plugin runs — wired via hooks-manifest.json
   (claude PostToolUse, copilot postToolUse), with the source hooks.json command the
   scaffold's hook wiring resolves by script name. The stale "deferred — #418" exemptions
   in `tooling/validate.py` are deleted.
3. **`check.py` probes the installed server's export branch** instead of a fail-closed
   version floor. `semantica>=0.6.7` would fail everyone until an external PR lands; a
   functional probe (`export_graph_works()`) warns and exits 0 when export is broken, since
   the graph tools (`record_decision`, `query_decisions`, ...) still work. Verified against
   real 0.6.5: probe returns False.
4. **Semantica stays declared by default**: `test_semantica_is_declared_by_default_in_the_
   common_stack` pins it in `features/common/stack-mcp.json` so a regression is deliberate.
5. **SKILL.md gotchas** document the upstream export bug and the all-agent autosave wiring.

## Deferred

- **Once-per-session export nudge for claude/copilot** (the Hermes plugin has one via
  `pre_llm_inject_context`; claude/copilot run the hook as a fresh process per invocation,
  so a session-once nudge needs marker-file state — deliberately deferred to its own PR
  rather than rushed into this one). The SKILL.md workflow step ("Call `export_graph`
  before finishing") and the autosave hook itself carry the demand side meanwhile.
