# 0.36.2 — the four repo gates move to `gates/`

First step of [ADR-0011](../adr/0011-engine-and-tooling-directories.md). `scripts/` held three
unrelated concerns behind one file-type name — the library every bootstrap shim imports,
maintainer catalog tooling, and gates that only CI and the pre-push hook ever run. The
screaming-architecture invariant names exactly that shape.

`deps_guard.py`, `docs_guard.py`, `release_guard.py` and `tdd_guard.py` now live in `gates/`.

They are the cleanest cut in the directory: nothing imports them, no bootstrap shim references
them, and `is_framework_root` never looks at them — so this move carries none of the risk the
`engine/` + `tooling/` split does. `badger_lib.py` has not moved; each gate reaches `../scripts`
for it.

## `gates/` is deliberately not shipped surface

It is **not** in `release_guard.SHIPPED_PATHS`. A consumer never runs a gate, so a gate-only
change no longer demands a `VERSION` bump. That is a real change to release discipline and is
recorded in `gates/release_guard.py`'s docstring, `CONTRIBUTING.md` and `docs/scripts.md`.

This release itself still needs a bump, because the *deletions* land inside `scripts/`, which
remains shipped surface — it still holds the engine and the catalog tooling.

## Three guards had to learn about their own new home

`deps_guard.CODE_ROOTS`, `tdd_guard.CODE_ROOTS` and `docs_guard.CHECKED_ROOTS` all gained
`gates/`. Without that, each would have silently stopped guarding the directory it now lives in —
a gate that no longer inspects itself.

## The check whose absence would have let this go unlinted

The *executable* pylint invocations in `verify.sh` and the CI workflow were already
directory-agnostic (`git ls-files '*.py'`), so they picked up `gates/` with no edit at all. Only
the **declared** command in `.ai-badger/config.json` named directories literally, and it would
have gone on saying `pylint scripts features tests` — correct-looking, and missing a directory.

A new test, `test_every_gate_is_a_pylint_target`, now fails if any top-level directory holding
our `*.py` is absent from that declaration. It generalises past this move: the next directory
cannot be silently unlinted either.

Verified rather than assumed — a deliberate `E0602` planted in `gates/tdd_guard.py` failed both
the pylint lane and `pylint scripts features gates`, then was removed.

## Upgrading

Nothing required. No consumer-visible path moved; `scripts/badger_lib.py` is exactly where it
was. If you invoke a guard directly in your own tooling, the four paths changed —
`scripts/<name>_guard.py` → `gates/<name>_guard.py`.

## Not done

Phase 2 of ADR-0011 — `engine/` and `tooling/` — is a separate breaking release. Historical
records under `docs/adr/`, `docs/plans/` and past changelog entries still say
`scripts/<guard>.py`; they describe the state at the time and are left alone by design.
