# 0.26.0 — the default skill set has one home

**Wave 13 of the remediation plan** (`docs/plans/2026-07-27-deferred-work-plan.md`),
addressing architecture findings I8 / R7.

## `code-review-checklist` now ships

It has been in the catalog since it was written — indexed, tested, six stack extensions —
and it appeared in neither the scaffold's default list nor the plugin's ship list. It reached
**nobody**, by either route, for its whole life, and no check noticed.

It is now scoped `default`: scaffolded into every project and exposed by the plugin.

## Omission is now an error

The two lists that decided what a user gets (`scaffold.DEFAULT_SKILLS` and
`sync_plugin_skills.COMMON_SKILLS`/`CLAUDE_SKILLS`) were hand-maintained copies of the same
product decision. Both now derive from `badger_lib.SKILL_SCOPES`, the single declaration of
which skills ship:

- `default` — installed without being asked for
- `optIn` — catalogued, installed only when named

`skill_scope()` raises `UnknownSkillScope` instead of assuming, and
`test_every_catalog_skill_is_reachable_by_a_declared_route` fails on any catalogued skill with
no declaration — in both directions, so a stale entry naming a deleted skill fails too. A new
skill cannot repeat this bug silently.

The scope is stamped onto each skill entry in `index.json` (`schemas/index.schema.json` gained
an optional `scope`), so the decision is visible in the generated catalog.

Rationale, and why the declaration is a constant rather than SKILL.md frontmatter:
`docs/adr/0005-default-skill-set.md`.

## Upgrading

Re-scaffold (`welcome-ai-badger`, or `den-refresh` on an existing project) to pick up
`code-review-checklist`. Nothing is removed and no existing skill changes; projects that never
re-scaffold are unaffected.
