# 0.159.0 — the pi bus pushes: idle sessions wake for their mail

**Minor** (additive) · 2026-09-01

## What changed

pi sessions now receive message-bus mail the moment it is sent, instead of only
when the session happens to act. The pi adapter arms a poll timer at
`session_start` (tui/rpc modes only, default every 2 s); each tick runs a
sub-millisecond read-only watermark check against the user DB, and only when the
fingerprint changed does it spawn the existing Python delivery script. Idle
sessions wake (`pi.sendMessage` with `triggerTurn`) on 1:1 and project mail;
machine broadcasts are injected without waking (visible immediately, entering LLM
context at the next turn). Mid-run mail queues as steer, never interrupting a
turn. The turn-boundary seams (`before_agent_start`, per-LLM-call `context`)
stay, now gated by the same prefilter — ending the per-LLM-call spawn cost.

The store transaction stays the single exactly-once owner (ADR-0024): the TS
side never writes, never reads rows, and never classifies mail. The txn now
returns a delivered-batch summary (`{addressed, broadcast}`) that the adapter
uses only to choose the wake mode, and its failure path is wire-distinguishable
(`aiBadgerBus.error`) so a fail-open `{}` can never silence the poller.

Also: `send_message.py` refuses `--project-id` targets that no project on the
machine resolves (msg-10's undeliverable-by-construction class), and the
hook-error log carries the sanitized exception message — the 44 content-free
`OperationalError` lines a day are diagnosable now — with a leak guard keeping
mail content out of logs.

Measured root causes and the full decision record: **ADR-0026**. Research
records: `docs/work/2026-09-01-pi-push-api-surface.md`,
`docs/work/2026-09-01-pi-bus-delivery-root-cause.md`.

## New features

- Push delivery to pi sessions (in-adapter poll + wake), tui and rpc modes.
- `AI_BADGER_PI_BUS_WAKE` (`off|addressed|all`, default `addressed`) and
  `AI_BADGER_PI_BUS_POLL_SECS` (default 2, floor 0.5) environment knobs.
- Store txn batch summary; additive `hookSpecificOutput.aiBadgerBus` response
  field (`{addressed, broadcast}` on mail, `{error: true}` on the fail-open
  path, absent on clean-empty `{}`).
- Send-side target validation with candidate-listing refusals.
- pi-badger-integration canonical adapter healed back into byte-equality
  (reverse-sync; `publish.ts --check` passes with the two new adapter files in
  the exact set).

## Changes

- The delivery hook's failure log line now includes the exception message
  (sanitized); log rotation and fail-open behavior unchanged.
- `deliver_for_session` returns `(messages, summary)`; vendored store copies
  re-synced byte-equal everywhere.
- Cursor-wrap guard: a cursor above `MAX(id)` reads as cursor-less for that
  read (gate + cap re-apply) instead of silently skipping rebuilt tables.

## Fixes

- Idle pi sessions no longer miss mail (the dominant loss: pull-only delivery
  burning the 30-minute first-read gate while the session waited).
- Unresolvable project targets are refused at send time with the ids that DO
  resolve, instead of landing rows nothing can ever match.
- The 5 s seam-spawn timeout no longer applies to off-critical-path timer
  spawns (30 s), removing the 5 s/5 s store-busy-timeout race for polls.

## Upgrade notes

- Other harnesses (claude, hermes, copilot) keep their pull-seam delivery;
  push is pi-only in this release (the other hosts have no in-process timer
  surface — cross-harness push is a recorded future decision).
- Scaffolded projects receive the new hook/store copies on their next
  den-refresh; the wake feature's summary falls back safely (treated as
  addressed) against older hook copies.
- Run the one-shot den-refresh project-id backfill before relying on send-side
  validation in repos scaffolded before 0.157.0.
