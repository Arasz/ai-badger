# 0.115.1 — disjoint files are not isolation

The `task` skill told the orchestrator to split work by naming which sections **share a file** —
"those serialise, the rest do not." That sentence does not merely omit the isolation rule; it
teaches the failure it is supposed to prevent.

## What it licensed

Three implementation agents were dispatched into one worktree, on genuinely disjoint files, by an
orchestrator applying that criterion correctly. Their files never overlapped. Their **build** did.

One agent finished its work and then sat blocked, polling, because another had left the tree
non-compiling mid-edit — an interface changed, its caller not yet updated. A third's test numbers
were measured against a tree a fourth was mutating, so its gate result could not be cited for
anything.

Nothing was lost and no defect shipped, which is exactly why it is worth a release. The failure is
quiet: it costs throughput and silently invalidates per-agent verification, and the guidance as
written gave no reason to expect either. The orchestrator had also satisfied the existing rule —
it *was* in a worktree rather than the primary checkout. "Am I in a worktree?" is the wrong
question when fanning out.

## What changed

`features/common/skills/task/SKILL.md`, in the dispatch guidance and the gotchas list. The
criterion is rewritten rather than caveated, and "isolated" is now stated exactly, because the
vague version is what failed:

- **Two axes.** A worktree of its own, *and* a workspace id of its own in every shared store that
  supports one — the memory bank, the scratch/notes tier — consolidated or discarded when the agent
  finishes. A shared workspace id has the same shape as a shared tree: one agent's partial findings
  are read as another's context.
- **At every depth.** The skill already permits two levels of dispatch, so an agent that dispatches
  its own agents owes each of them the same two things. A sub-agent sharing its parent's tree is the
  same collision one level down, and harder to see.
- **Use the agent tool's own isolation** rather than creating worktrees by hand. A manual step before
  each dispatch is the one that gets skipped when the work feels urgent — which is how this happened.
- **Two things travel with the worktree and get forgotten:** any per-directory permission or
  auto-approval mode has to be armed for the new path too, or the agent stalls waiting for an answer
  nobody is there to give; and the gate is still re-run on the merged result, because each per-agent
  run measured a different tree.

## The over-correction, named

The instinct after the collision is to serialise the dispatches. That removes the collision by
removing the parallelism, and it is worse than it looks — the sequential round that followed cost
most of an afternoon's throughput for a problem isolation already solves. The skill now says to
prefer isolation and fall back to sequential only when the work genuinely cannot be split.
