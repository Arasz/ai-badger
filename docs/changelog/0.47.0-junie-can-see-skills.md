# 0.47.0 — Junie can finally see the skills ai-badger claimed to give it

Reported in [#137](https://github.com/Arasz/ai-badger/issues/137): Junie has a skills
mechanism, and two authoritative files claimed ai-badger supported it, while nothing ai-badger
ran ever wrote a skill anywhere Junie reads.

## What was false

- `features/common/support.json`, `agents.junie.capabilities.skills` asserted
  `"aiBadgerSupport": true` with `"mechanism": "SKILL.md format"` — a path-free claim, and the
  only row in the whole capability matrix asserting support with no path and no
  `scaffoldedBy`. `features/junie/` had no `adjustments/` directory at all.
- `docs/dictionary.md`, the **Skill** row's Junie column read `N/A (inline instructions)` —
  false in the opposite direction, claiming Junie has no skill concept.

## The fix

`features/junie/adjustments/adjust_skills.py` symlinks each scaffolded skill into
`.junie/skills/<name>/`, matching JetBrains' documented project-scope discovery path
(`<projectRoot>/.junie/skills/<name>/SKILL.md`, required, project wins over user scope on a
name collision). It is the same shape as the Copilot and Claude adjustments, including the
ownership discipline: only entries resolving into `<target>/.ai-badger/skills/` are ever
replaced or pruned, a foreign directory or symlink survives untouched with a note explaining
why, and an empty skill list prunes nothing owned (#129) — the same guard the Copilot/Claude
adjustments carry, not reintroduced as a bug on a fourth surface.

`support.json` now names the real path and both scopes, and `aiBadgerSupport: true` is earned:
the symlinker landed in this same PR. `docs/dictionary.md`'s Skill row is corrected, and so is
the adjacent **Skill scope** row, which was also wrong — Junie does have project (`.junie/skills/`)
and user (`~/.junie/skills/`) scope. The other three adjacent `N/A` cells (external skill,
skill source, skill installation) stay `N/A`: no such mechanism is established for Junie, and
none is invented here to fill a cell.

## Deliberately out of scope

User-scope `~/.junie/skills/` is not scaffolded. ai-badger materializes project state; it does
not own a user's home directory for Junie the way it does for Hermes
(docs/adr/0003-hermes-skill-discovery-via-namespaced-symlinks.md) — there was no reported
staleness or discovery gap here to justify reaching into `~/.junie/`, and project scope alone
closes the bug this issue reported.
