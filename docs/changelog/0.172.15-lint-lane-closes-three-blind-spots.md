# 0.172.15 — lint lane closes three blind spots

**Patch** · 2026-09-24

## What changed

- `gates/shipped_paths_guard.py`: `ABS_PATH_RE` now also catches `/root/`, `/var/folders/` and
  `/private/var/folders/` (macOS's per-user temp dir), alongside the existing `/Users/`,
  `/home/` and `C:\Users\` patterns. Widening the regex alone turned the real tree red: three
  tracked copies of `artifact-verification/references/verification-tracker.md:76`
  (`features/common/`, `skills/`, `.ai-badger/`) carried a real `mktemp` output path from one
  maintainer's Mac. The literal is now `mktemp -t hermes-verify-<purpose>-XXXXXX.sh`, already
  the portable pattern the same doc recommends a few lines above it.
- `gates/workflow_lint.py`: `permissions: write-all` — the widest scope there is — now fails
  the lint at both the top level and inside a job. Declaring *some* `permissions:` block was
  previously enough, so the least-privilege half of `pin-actions-to-sha.md` let the broadest
  possible grant straight through.
- `gates/skills_lint.py`: a `features/*/skills/*/SKILL.md` glob matching zero files now fails
  the lint instead of printing `ok ... 0 SKILL.md checked`, the same reasoning
  `tooling/validate.py`'s `hooks_manifest_agent_gaps` already applies to its own glob —
  checking nothing and finding nothing are not the same answer.
