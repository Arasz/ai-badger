# 0.29.0 — documentation that still points at the tree

## The problem

The documentation refactor earlier on 2026-07-27 moved files around `docs/`. Every link that
broke in the process was found by hand, one grep at a time, because nothing in this repo checked
that a document still describes the tree it sits in. The same absence had already produced:

- `docs/hermes-claude-compatibility.md` quoting a hook command path that stopped being true when
  the catalog moved under `features/common/` — wrong for several releases, noticed by a reader;
- a changelog index three releases stale. `docs/changelog/README.md` is the *only* way to
  reconstruct the release timeline in a repo that deliberately has no root `CHANGELOG.md`, and
  0.27.1, 0.28.0 and 0.28.1 had entries that nothing linked to. This release adds those rows.

Every other non-negotiable invariant in `CLAUDE.md` has a script behind it. "The docs are true"
had nothing.

## `scripts/docs_guard.py`

A gate in the same shape as `release_guard.py` and `tdd_guard.py`: stdlib only, offline, one
`check()`, a verdict line, exit 0 or 1. It runs in CI and as a pre-commit hook, and it checks
three things.

**Relative links resolve.** Every `[text](target)` and `[label]: target` in a root `*.md` or
anything under `docs/` must name a path that exists. `http(s)://`, `mailto:` and bare `#anchor`
targets are skipped; a `#fragment` is stripped before resolving. This is the check that pays for
the whole script — it is exactly the breakage a file move causes, and it is the one a human
reviewer never catches, because a moved file leaves the *text* of the link looking correct.

**Backticked repo paths exist.** A span like `` `scripts/foo.py` `` names a file, and if that file
is gone the sentence around it is wrong. This check is deliberately timid, because a noisy gate
gets switched off: a span must have no whitespace, no glob or placeholder character, a known
extension, and a first segment naming this framework's own surface (`scripts/`, `features/`,
`schemas/`, `hooks/`, `tests/`, `docs/`, `.github/`, `.claude-plugin/`). Anything else is
ignored, misses included. `.ai-badger/…` is outside that surface on purpose: in a document it
means "in a scaffolded consumer repo", not "in this checkout".

**The changelog set is self-consistent.** Every `docs/changelog/*.md` is named
`{version}-{slug}.md` and has a row in `docs/changelog/README.md`, and the version in `VERSION`
has an entry. The index is checked in both directions — a row pointing at a deleted entry is a
broken relative link, and an entry with no row is reported by name.

## What is exempt, and why

A gate that fires on documents nobody may edit is a gate that gets disabled.

- **`docs/archive/` is not scanned at all.** Preserving references to paths that no longer exist
  is what an archive is *for*.
- **Records keep the link check but not the path check.** `docs/adr/`, `docs/changelog/`,
  `docs/design/`, `docs/incidents/`, `docs/plans/`, `docs/research/`, `docs/reviews/` and
  `docs/specs/` describe a tree as it was at a moment or as it is proposed to be. A plan naming
  `tests/test_deployment_shapes.py` before that file exists is the plan working. An ADR may not
  be edited after acceptance at all, so a dead path in one could never be fixed. Links are still
  checked there: a link that no longer opens is broken for a reader whatever the document is.
- **`.docs-guard-ignore`** at the repo root takes one repo-relative prefix per line, matching
  both a document (then not scanned) and a referenced path (then never reported). It currently
  holds one entry: the frozen pre-0.7.0 `docs/ai-badger-framework-design.md`, which names the
  `plugins.json`/`marketplaces.json` mechanism 0.7.0 deleted.

**Line numbers are not checked.** A citation like `scaffold.py:772` in a 715-line file is
*usefully* wrong — it tells you the file moved — and any check strict enough to catch it is noisy
enough to be turned off.

## What was deliberately not built

The [docs-structure research](../research/2026-07-27-docs-structure-and-contribution.md) lists
Vale, markdownlint and lychee together as the standard docs-sync stack, and rates the bundle
"Do it". Only the link-checking half of that recommendation is implemented here, by a hand-written
script, and the rest is declined:

- **lychee** and any other external link checker reaches the network. A per-PR gate that fails
  because someone else's site is down is a tax on the contributor, not a signal about the change.
- **markdownlint** needs a Node toolchain for what would be style, not truth.
- **Vale** lints prose. At one or two maintainers its signal-to-noise ratio is the worst of the
  three, and the research says as much.

Nothing in this release makes a network call, needs a package installed, or takes long enough to
notice in a pre-commit hook.

## Upgrading

No project-side change and no re-scaffold: `docs_guard.py` is a framework gate, not scaffolded
surface. If you work in this repo, `pre-commit install` picks up the new `docs-guard` hook.
