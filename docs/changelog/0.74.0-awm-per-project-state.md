# 0.74.0 — AWM state is per project

`~/.claude/awm/state.json` held one project. Enabling AWM in a second checkout silently
disarmed the first, so two concurrent sessions could never both be covered. It now holds one
entry per project, each with its own mode and its own clock; a pre-0.74 file is read as a
single entry and rewritten in the new shape on the next change.

The banner was the more misleading half. `awm_context.py` decided whether to print from
`enabled` and `expires_at` alone and never read the project, so it announced away mode in every
project on the machine — including the ones where `awm_gate.py` denied every call. An agent was
told "no user is available: never ask questions" while each of its tool calls went to a
permission prompt. Measured on one evening: 186 consecutive `out_of_scope` denials under a live
away banner. Both hooks now read the same per-project entry.

`disable` and `status` are scoped the same way: `disable` ends this project's window and names
any other still open, and `status` reports this project, not whichever one was enabled last.
