# 0.172.13 — release tooling agrees on what ships

**Patch** — `tdd_guard`, `release_guard` and `version_sync` fixes from the phase-5 audit
(L8-2, L8-3, L8-6/D6, L8-8, N-1). 2026-09-24.

## What was wrong

- **`tdd_guard` diffed against the tip of `--base`, not the branch point.** Once
  `origin/main` moved on, its own later commits — including its own test changes — showed
  up as differences from the branch's working tree. An unfiltered path check then counted
  main's test file as "tests changed", so a branch that changed code with no test of its
  own could pass.
- **A deleted test counted as a test change.** `tdd_guard` never looked at a path's git
  status, so removing a test alongside a code change satisfied the gate exactly as adding
  one would.
- **The pi adapter's TypeScript had no gate coverage.** `tdd_guard`'s documented scope was
  `.py` and `.mjs`; the 4 shipped `features/pi/adjustments/*.ts` files could change with no
  test and nothing noticed.
- **`release_guard`'s shipped-root list missed `hooks/` and `.claude-plugin/`.** Both load
  from the plugin root at runtime, so a hook or plugin-manifest change could ship with no
  version bump — the exact "same version string, different code" failure ADR-0001 exists to
  prevent.
- **`version_sync` had no notion of `features/common/data/model-groups.json`.** Its stamp
  targets were a hand list (plugin.json, marketplace.json, index.json, the scaffold stamps).
  The registry's `frameworkVersion` field went unstamped through four releases (013d793,
  PR #482, PR #494, 71971d6, 43a634d) and needed a manual follow-up commit each time.
- **`version_sync --check` passed on an empty or non-matching marketplace.** Like the
  `skills_lint` glob that passes when it matches nothing, a `marketplace.json` with no
  `plugins[]` entry named like `plugin.json` read as "nothing to disagree with".

## What changed

- `tdd_guard` diffs against `git merge-base <base> HEAD`, not `<base>` directly, and only
  `--diff-filter=AMR` (with `-M` for rename detection) counts as a test change: an add, a
  modify or a rename-and-edit satisfies the gate; a plain delete does not.
- Shipped pi TypeScript under `features/pi/adjustments/` is now code; files matching
  `features/pi/tests/*.test.ts` are tests (D6).
- The shipped-root list moves into shipped code as `tooling/release_paths.py`, imported by
  `release_guard` (`gates/` may depend on `tooling/`, never the other way — `version_sync`
  still imports nothing from `gates/`). The list gains `hooks`, `.claude-plugin` and
  `BREAKING_VERSIONS`.
- `version_sync.stamp_targets()` **derives** its stamp list: every tracked-or-present
  `*.json` under the shipped roots whose top level has a string `frameworkVersion`, except
  `index.json` (index_build's own target). `sync()` writes them; `check()` reports them.
  This is what stamps `features/common/data/model-groups.json` from here on — including in
  this release, where the tool did it rather than a hand edit.
- `.ai-badger/*.json` files of the same shape (`manifest.json`, `model-groups.json`,
  `config.json`) are reported by `check()` and never rewritten by `sync()` — they are
  scaffold output, and writing them here would assert a re-scaffold that never ran.
- `version_sync --check` now fails when no `marketplace.json` entry names `plugin.json`'s
  plugin.

## Upgrade notes

- Re-scaffold to pick up the tooling. No shipped file format changed.
