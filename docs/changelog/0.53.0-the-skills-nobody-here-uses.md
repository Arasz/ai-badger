# 0.53.0 — the skills nobody here uses

Issue #172, and the maintainer's own observation about this repository: *"we could recommend
skills to prune on the den refresh — this repo is not using this ai-badger skills"*.

`den-refresh` now reports it. Its JSON gains a `skillUsage` section naming, for every skill the
project holds, whether anything was ever observed using it:

```jsonc
"skillUsage": {
  "channels": { "invocation": "claude-transcripts", "hooks": "audit-log" },
  "window": { "from": "…", "to": "…", "days": 3.4, "transcripts": 108, "auditRecords": 842 },
  "used":   [ { "skill": "task", "evidence": "invocation", "count": 7, "last": "…" } ],
  "unused": [ { "skill": "feed-badger", "reason": "delivered, and not invoked once in the observed window" } ],
  "cannotTell": [ { "skill": "welcome-ai-badger", "reason": "runs once per project lifetime, by design…" } ],
  "limits": [ "…" ]
}
```

The payoff is the listing budget, not disk: a host allots a fixed slice of context to skill
descriptions and drops the least-invoked first, so a skill nobody here invokes crowds out one
somebody does.

**It reports; it does not prune.** `config.json` is project-owned — the same posture as 0.46.0's
"a config edit is drift" and as `newStacks`. The candidate list is for a human to accept via
`exclude.skills`, and that edit is self-executing on the next refresh.

## Two channels, and only one of them can prove absence

The trap the issue names is real: the audit log records **hooks**, and six of this repo's eleven
skills ship one. Built on hook records alone, the report would have recommended deleting
`welcome-ai-badger` — the skill that installs the framework — because a skill with no hook cannot
appear in that log however heavily it is used.

So the two channels are not symmetric, deliberately:

| Channel | Sees | Can say "used" | Can say "unused" |
|---|---|---|---|
| `claude-transcripts` — `~/.claude/projects/<mangled cwd>/*.jsonl`, this project and its worktrees | `Skill` tool calls and slash commands, for any skill | yes | yes |
| `audit-log` — call-behaviorist's records, via the new `behaviorist.hook_activity(project)` | hook activity, for hook-shipping skills only | yes | **never** |

A hook that fired means the skill is doing work here every session even when nobody typed its
name (`evidence: "hook"`, and this repo's `commit-reminder` at 611 records is the case) — that is
grounds to leave it alone, never grounds to prune. Silence in that log is not absence, and the
report says so where a reader will see it.

Three things therefore land in `cannotTell` rather than in the recommendation:

- **`welcome-ai-badger`, unconditionally.** It runs once per project lifetime by design, and
  pruning it removes the ability to scaffold. Issue #172 asked whether lifecycle skills get
  exempted; they do, and it is the only exemption.
- **A skill wiring a hook that calls no debug logger.** It may be firing every session and can
  never say so — call-behaviorist's own `not_instrumented` distinction, applied to skills.
- **Everything, when there is no transcript store.** No invocation channel, no prune candidate:
  the report degrades to a `hint` naming the fix (`behaviorist.py on 4h`, then work normally)
  and recommends nothing at all.

## The window travels with the claim

"Never used" from three days of records about a quarterly skill is a confident wrong answer, so
the window is part of the finding — `window.days`, the transcript count, and a `limits` entry
that fires below 14 days. `limits` also states the two things neither channel can see: work done
through another agent (Hermes, Copilot and Junie need their own answer, and get an explicit "not
observable here" rather than a silently Claude-only recommendation), and hookless silence.

Only skill names and timestamps are read out of a transcript; no message content is parsed,
stored or reported.

## Fired in anger against this repository

Eleven skills delivered, 108 retained transcripts, 842 audit records, a 3.4-day window:

- **used** — `auto-wm`, `call-behaviorist`, `den-refresh`, `task` (invocation);
  `commit-reminder`, `mcp-index`, `prompt-markers` (hook)
- **unused** — `code-review-checklist`, `feed-badger`, `maintain-agent-instructions`
- **cannot tell** — `welcome-ai-badger`

Which is exactly the observation that opened the issue, now arriving on its own.
