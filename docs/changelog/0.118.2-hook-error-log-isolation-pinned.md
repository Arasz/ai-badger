# 0.118.2 — Hook-Error-Log Isolation Is Now Pinned

**Type:** PATCH
**Date:** 2026-08-14

## What Changed

`tests/test_suite_isolation.py::TestNoHookCanWriteTheRealErrorLog` — two cases asserting no
hook under test can append to the operator's real `~/.ai-badger/hook-errors.log`.

## The leak was already closed; nothing asserted it

Every hook wraps its body in a bare `except Exception` that appends to
`Path.home() / ".ai-badger" / "hook-errors.log"` and exits 0, and several tests raise inside a
hook deliberately — `test_registration_failure_does_not_block_the_prompt` accounts for 227 of
the 241 historical entries on its own.

What keeps those writes out of the real log is the `_home_off_limits` session fixture, which
redirects `$HOME` before any hook module is loaded. Measured before changing anything:

| | |
|---|---|
| Real log mtime | **2026-07-28 08:20** |
| Real log size | 241 lines |
| Full-suite runs on 2026-08-14 | 3 (3888, 3897, 3910 tests) — added **0** entries |
| `HOOK_ERRORS_FILE` under test | resolves to the pytest scratch home, not `REAL_HOME` |

So the 241 entries are a historical backlog from before the fixture existed, not a live leak.
The gap was that **nothing asserted the redirect held**: `TestTheRealHookErrorLogIsSurfaced`
covers the reporting half (a leak that happens is caught at teardown), and the prevention half
was unguarded. A change to fixture ordering, or a hook resolving the path some other way, would
have gone unnoticed until the real log grew again.

## Proven to fail

The redirect in `conftest._home_off_limits` was temporarily neutered and the new class run
against it: both cases failed. Restored, both pass. A guard that has only ever been green is
indistinguishable from one whose comparison cannot discriminate.

That run also showed the blast radius the guard exists to prevent — with `$HOME` unredirected
the FS observer immediately reported writes into the real checkout's
`.ai-badger/task-tracking/` (`.write.lock`, `current-session.json`, `poll_limit.log`). The real
hook-error log itself did not grow, because those two cases only read module attributes.

The hook list is **derived** — every file under `features/` defining `HOOK_ERRORS_FILE`, six
today — so a new hook spelling the path itself is covered the day it lands, rather than added
to a list someone has to remember. `_hooks_that_write_the_log` asserts the discovery is
non-empty, so an emptied glob fails loudly instead of passing vacuously.

## Not Changed

The 241-entry backlog in the operator's real log is left alone: it is the operator's state, not
this suite's to delete. The teardown note keeps reporting it.
