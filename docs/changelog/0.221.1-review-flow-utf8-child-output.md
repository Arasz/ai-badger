# 0.221.1 — review-flow reads and writes UTF-8 on any locale

**Patch** · **Date:** 2026-11-19

- On Windows, the review-flow publish step failed. Python decoded `gh` output with the locale
  code page (cp1252), so non-ASCII text in a PR body or comment became mojibake or raised. A
  manual retry with `PYTHONUTF8=1` worked.
- Every child process the review-flow scripts start (`gh` in `review_publish.py`, `git` in
  `review_flow_cli.py`, `review_rules.py` and `review_flow_store.py`) now decodes its output as
  UTF-8 with replacement, and encodes stdin as UTF-8. `PYTHONUTF8=1` is no longer needed.
- `review_flow_cli.py` writes its JSON result as UTF-8 bytes. Before, a cp1252 console raised
  `UnicodeEncodeError` on a character such as `→`, the same defect 0.189.3 fixed in the
  task-graph server.
- `tests/test_review_flow_utf8.py` simulates a cp1252 locale and console, and fails when a
  text-mode child process in the review-flow scripts does not name `encoding="utf-8"`.

## Upgrade notes

Nothing required. A `den-refresh` replaces the scaffolded copies.
