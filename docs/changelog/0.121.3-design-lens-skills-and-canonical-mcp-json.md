## The `.github/mcp.json` Correction

An earlier commit on this branch pruned that file to one server and argued the four-server version
was stale. That was wrong, and `scaffold_freshness_guard` caught it:

```
.github/mcp.json  (content differs, regenerates differently)
```

`.github/mcp.json` is a committed generated artifact, so it must be machine-independent. Under
`AI_BADGER_MCP_AVAILABILITY=all` — what the guard and CI both use — the scaffold emits all four
servers with bare commands.

The pruning was real but local. On the developer's machine `hermes`, `ai-raccoon` and `semantica`
resolve under `~/.local/bin` and `~/.dotnet/tools`, so 0.28.0 rewrites them `${HOME}`-relative, and
0.53.0 then declares a divergent rendering only in `.mcp.json`. That is correct for the untracked
local `.mcp.json` and wrong for the tracked artifact.

**The lesson worth keeping:** regenerate a committed generated file the way the *gate* does, not
the way your shell does. The env var in the guard's own suggested command is part of the contract,
not decoration.
