# 0.46.0 — an invariant must be true

[#130](https://github.com/Arasz/ai-badger/issues/130).
`features/common/invariants/version-changelog-required.md` was always-on, so it rendered
into every scaffolded project's agent files, unconditionally:

> ### Always bump VERSION and add changelog entry
>
> Every release — no matter how small — must:
> 1. Bump `VERSION` (semver patch for fixes, minor for features, major for breaking changes)
> 2. Add a `docs/changelog/{version}-{slug}.md` entry describing what changed
> 3. Update `docs/changelog/README.md` if adding a new changelog format convention

`VERSION`, `docs/changelog/{version}-{slug}.md`, and `docs/changelog/README.md` are ai-badger's
own file layout, named literally. In a project with none of them, an agent following the
invariant fabricates a changelog tree nobody asked for. This was not a mis-scoped preference —
it asserted a fact about the target repo's file layout that was false for most of them. Every
other `common` invariant (guard clauses, minimal comments, TDD, small commits) is stack- and
layout-agnostic; this was the only one asserting a concrete path exists.

In one downstream project it landed in 8 of 9 agent files and had to be deleted by hand
([jsaa#382](https://github.com/Arasz/job-search-ai-assistant/pull/382)), came back on the next
refresh, and is now permanently declined via `exclude.invariants`
([jsaa#390](https://github.com/Arasz/job-search-ai-assistant/pull/390)). `exclude` makes it
survivable, but it puts the burden on every project to notice a false invariant and opt out,
rather than on the framework to only ship invariants it can know are true.

## The split

- **`features/common/invariants/traceable-releases.md`** — a new, always-on invariant naming no
  path: releases must be traceable, "using whatever version marker and release notes this
  project already keeps," with an explicit anti-fabrication clause for projects that keep none.
  Ships from `common`, same as before, to every project.
- **`features/changelog/invariants/version-changelog-required.md`** — the old, concrete file
  moved unchanged (byte-identical) into a new `changelog` stack, gated on evidence: a
  `docs/changelog/*.md` tree. Only a project that already keeps one gets the concrete convention.
  `detect.py` proposes the stack automatically; anyone else can opt in by hand
  (`config.json.stacks`).

**Rejected alternatives:** dropping the concrete form entirely throws away a genuinely true
convention for the projects it does describe (this framework's own repo included). Keeping it in
`common` and only rewording it removes the reported harm but demotes ai-badger's own enforced
release convention — `release_guard.py` and `docs_guard.py` check exactly this path — to a vague
principle in the one place it is a checked fact. Per-item `requires` metadata on invariants would
reach a gate the stack mechanism already implements end-to-end, for a new sidecar convention and
schema change.

## The `_superseded_reason` gap this closes

Moving a catalog file out of `common` exposed a real gap: `Scaffolder._superseded_reason` (the
prune step run on every re-scaffold) only knew two reasons to stop delivering a previously
scaffolded file — declined via `config.exclude`, or the delivering stack left `config.stacks`.
There was no case for "the framework itself dropped the item from the catalog." Reproduced by
scaffolding against the old catalog, then re-scaffolding against this one: every agent file
de-rendered the invariant correctly, but `.ai-badger/invariants/version-changelog-required.md`
stayed on disk with its manifest entry silently dropped — the same "beyond the reach of every
later check" failure #116 fixed for whole stacks.

`_superseded_reason` gets a third case: when a manifest entry's `feature` is one of the types
recorded with the *source's* hash (`skills`, `personas`, `invariants`, `instructions`) and its
recorded `source` path no longer exists anywhere in the framework, the file is pruned (with a
note) if untouched, or left in place (with a note) if the project edited it. The case is scoped
to those feature types deliberately: `templates` and `adjustments` record the source's hash too,
but compare it against the *target*, so an unscoped version would call every rendered
`CLAUDE.md`/adjustment "edited here" the moment any upstream template moved — nobody edited them.

This makes the file move **non-breaking**: `den-refresh` converges on its own, in one refresh,
whether a project never declined the old invariant (drift reports the removal and the new one,
the copy is pruned with a note, the generic one renders), had edited its copy (left in place,
reported), or had already declined it via `exclude` (the exclusion goes inert with an actionable
note, not an error).

## This repo's own scaffold

This repo keeps `docs/changelog/*.md`, so it now declares the `changelog` stack in
`.ai-badger/config.json.stacks` — exactly what `detect.py` would propose — and its own agent
files keep the concrete convention verbatim alongside the new generic one.

Measuring that surfaced two more things, fixed here:

- **`agentDocs.maxLines` needed raising to 160.** `HERMES.md`/`.hermes.md` land at 148 lines
  after this change, and were *already* 144 lines against a default budget of 110 with no
  override in place at all — nothing enforced it. A new test,
  `tests/test_agent_doc_budget.py`, gives this repo its first mechanical check of the budget it
  ships to every other project.
- **`claude_md_compact.py`'s `--max-chars`/`--max-lines` flags were dead** in any project that
  sets `agentDocs`: `main()` mutated the module's `CLAUDE_MD_MAX_CHARS`/`CLAUDE_MD_MAX_LINES`
  globals, but `doc_budget()` reads `agentDocs` from `config.json` and returns it unconditionally
  whenever present, ignoring the mutated constants entirely. Found while adding `agentDocs` to
  this repo's own config broke `test_custom_max_lines_override_raises_the_budget`. Fixed by
  threading `max_chars`/`max_lines` as optional arguments through `tracker_lib.doc_stats` /
  `claude_md_stats` (`None` means "use `doc_budget()`"; an explicit value wins) and deleting the
  global mutations from `claude_md_compact.main()`.

Stacked on [#133](https://github.com/Arasz/ai-badger/pull/133) (issue #128): this is the only
one of three PRs landing at 0.46.0 that re-scaffolds `.ai-badger/`, so its diff also carries
#133's `configHash` addition to `.ai-badger/manifest.json` — not authored here.

## Migration

- **Never declined the old invariant:** the next refresh reports the removal and the new generic
  invariant as drift, prunes the stale copy with a note, and renders the replacement. No action
  needed; opt into the concrete form by adding `changelog` to `config.json.stacks` if wanted.
- **Edited the copy:** left in place, reported, same as any other edited file.
- **Already declined it via `exclude.invariants`:** the exclusion now matches nothing and
  produces a non-fatal "safe to remove from config.json" note; nothing errors.
