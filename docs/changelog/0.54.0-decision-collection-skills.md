# 0.54.0 — two skills for getting a decision out of a human

Two catalog skills, fed back from a downstream project that used them for a real design review
and a real refactor. They are a pair: the second one calls the first.

## `create-refinement-document`

Generates a **review form** — one card per decision, a verdict control and a notes box — that
emits structured markdown. The reviewer clicks and types; the agent gets back a file where every
answer is bound to its decision by construction.

The failure it removes is specific and was measured, not imagined. Prose feedback loses the
mapping from answer to question. Answer slots hand-edited into markdown are better but still lose
content: a line-shaped slot hid multi-line answers, and a reader parsing only the marker line
reported six points unanswered when every one had a written answer beneath it. A form cannot lose
the mapping, because the DOM enforces it.

It ships with what a `file://` page can and cannot do, measured on Chrome 150, Playwright Firefox
153 and WebKit 605 rather than assumed — `showSaveFilePicker` exists only in Chromium, needs a
user gesture, and cannot be pointed at a folder programmatically; every `file://` page shares one
`localStorage` origin, so the storage key must be unique per review or one document's answers load
into another's form. The claims it could *not* settle in headless are listed as unverified, with
the check that would settle each.

## `differential-feature-refactor`

For a feature that has drifted from its intended design: produce a side-by-side of *what we have*
versus *what we will have*, get it annotated, and turn that into a refactor spec and a plan.

Its one rule is **never infer design intent from code shape.** Requirements, ADRs and recorded
rulings are the only authority on intent; code is evidence of what was built, never of what was
meant. The rationalization table is the useful part — "no callers, so it's dead code" is evidence
about wiring, not about intent, and that exact reading nearly deleted a ratified extension point
five days after it landed.

Undefined points use a fixed, greppable block shape with exactly three lettered propositions, and
they live in the section they belong to rather than collecting into an "Open Questions" heading
where they get skimmed and lost.

## Scope

Both are declared `SKILL_SCOPE_DEFAULT`. That is a judgement call, not a requirement of the
change — either one can be moved to `optIn` with a one-line edit to `badger_lib.SKILL_SCOPES`.

## Generalisation

Both were written in a project and are contributed without it: the war stories keep their shape
and lose their nouns, the code-graph steps are conditional on the project having such a server,
and the spec-skill cross-reference names a capability rather than a specific plugin.
