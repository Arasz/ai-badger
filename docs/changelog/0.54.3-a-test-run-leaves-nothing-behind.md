# 0.54.3 — a test run leaves nothing behind

Closes [#222](https://github.com/Arasz/ai-badger/issues/222).

Running the suite wrote into the developer's live task-tracking state, and left a
daemon running afterwards. Both were measured on this repo, not inferred.

## What was wrong

### The suite wrote into real tracking state

`.ai-badger/task-tracking/current-session.json` collected sessions that never
existed — one keyed `s1`, a literal test fixture id, another whose
`transcriptPath` was a pytest temp HOME while its `cwd` was the real checkout:

```json
"s1": {
  "cwd": ".../pytest-of-arasz/pytest-31/test_each_hook_records_the_pro0/proj",
  "recordedAt": "2026-07-31T14:24:42"
}
```

`tests/conftest.py` redirected `$HOME`, but `tracker_lib.resolve_project_root`
does not consult `$HOME`. It reads `$CLAUDE_PROJECT_DIR`, then walks up from the
cwd looking for `.ai-badger/config.json` — which the suite's own checkout has. So
the walk landed in the real repo, past the redirect.

The timing made a fixture insufficient anyway: `tracker_lib` freezes
`DATA_DIR` and friends into module constants at **import**, which happens during
collection, before any fixture runs. This is the same hazard the file already
documents for `AI_BADGER_DEBUG_DIR`, where a session fixture alone was measured
still leaking 76 records.

### A test run left a daemon running

Worse than a stale file. `session_start_hook.py` launches `poll_limit.py` with
`start_new_session=True`, and `tests/test_debug_log.py` exercises every hook
without mocking the spawn. The result outlived pytest by 22 minutes at `PPID 1`,
writing into the real tracking directory and acting on fixture data as though it
were real sessions:

```
Resuming session sid-1 (task-tracking task T01)...
```

It was trying to resume sessions that had never existed.

## What changed

**One seam for detaching.** `tracker_lib.spawn_detached(argv, cwd, log_path)` is
now the only place ai-badger starts a process that outlives its parent.
`session_start_hook` and `poll_limit`'s `resume_session` both route through it,
so how detaching works is decided once — and a test patches one function instead
of `subprocess.Popen` at each call site. `start_new_session=True` is asserted
against that seam rather than re-asserted at every caller.

**The project root is redirected, at import time.** `conftest.py` points
`$CLAUDE_PROJECT_DIR` at a scratch directory, assigned rather than
`setdefault` — a suite run from a Claude Code session inherits that variable
already pointing at the real project.

**A floor under both.** `conftest.py` wraps `subprocess.Popen` to record every
`start_new_session` child and kills any survivor at session teardown. The wrap
is on `subprocess.Popen` itself rather than on `spawn_detached`, because
`load_script` hands out fresh module objects that a module-level patch would not
reach, while `subprocess` is a genuine singleton.

The reaper kills the process **group**, not the leader. `start_new_session`
makes each child a group leader, and `poll_limit` shells out to `claude` — so
signalling only the leader leaves that grandchild to reparent to PID 1 and
survive, which is the leak being closed rather than a smaller version of it.
`test_reaping_kills_a_grandchild_too` fails with *"the grandchild outlived the
reaper"* if the group kill is reduced back to `child.kill()`.

## Two leaks a sentinel could not see

The first version of this fix was verified with a sentinel file in
`.ai-badger/task-tracking/` and a full-suite run. Both survived — and both were
the wrong instrument. Review found two leaks that passed underneath it.

**A single-file run still wrote a phantom session.**
`tests/test_debug_log.py` sets `CLAUDE_PROJECT_DIR` to a directory it never
creates. `resolve_project_root` rejects a path that is not a directory and falls
through to the cwd walk, which finds the real checkout. Running the whole suite
hid it — by then `tracker_lib` was already imported and cached under the good
value — so the property held for exactly one collection order:

```console
$ python3 -m pytest tests/test_debug_log.py      # before the fix
$ cat .ai-badger/task-tracking/current-session.json
{"sentinel": "do-not-touch", "sessions": {"s1": {...pytest tmpdir...}}}
```

The directory is now created before it is named as the project.

**Every full-suite run created `features/.ai-badger/task-tracking/`.** The
scratch project had a `.ai-badger/` but no `config.json`, so a *spawned* child —
which re-resolves in its own interpreter, where none of this isolation exists —
found no marker and fell back to `script_dir.parents[3]`, landing inside the
tracked source tree. `.gitignore`'s unanchored `task-tracking/` hid it from
`git status`, which is the same blind spot #222 was reported through. The
scratch project now carries the marker.

The lesson is in the instrument, not the bugs: **a sentinel in one directory
tests one directory.** So the check is now the one #222 actually asked for — a
session fixture snapshots every `task-tracking` file in the checkout and asserts
none was added or changed, and the reaper's return is asserted empty rather than
discarded.

## Verification

```console
$ python3 -m pytest tests/test_debug_log.py       # the single-file case
45 passed — sentinel intact, features/.ai-badger absent

$ python3 -m pytest -q
2414 passed, 18 skipped — tree-wide guard green, reaper returned nothing
```

Each guard was confirmed able to fail: reverting the scratch marker and the
spawn patch trips *"1 detached process(es) outlived the suite"*, and reducing
the group kill to `child.kill()` trips *"the grandchild outlived the reaper"*.

## Known residual

A hook reached from a **child interpreter** can still spawn a daemon the
in-process `Popen` wrapper cannot see, since the wrapper only exists in the
pytest process. Observed as orphans whose `cwd` is the checkout. Tracked
separately — it needs a different mechanism than wrapping a class in one
process.

## Behaviour changes worth knowing

None for a scaffolded project at runtime. `spawn_detached` is a refactor of two
existing call sites with the same arguments; the tracking and reaping live in
`tests/conftest.py` and ship with no consumer-visible effect.

If you have a phantom session in your own `.ai-badger/task-tracking/`, it is
gitignored local state and can simply be deleted.
