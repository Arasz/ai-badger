# 0.111.0 — the default doc budget fits the floor

The shipped `agentDocs` default was `110` lines / `12000` chars. A one-stack, one-agent project —
the floor of what ai-badger can render, with no override — comes out at **158–221 lines**
depending on the stack.

So the default was unreachable by the generator's own minimum output. Every freshly scaffolded
project was over budget on day one, and the stop hook told its owner to compact generated files
that cannot go below the floor. A reminder that fires every session with nothing to act on is
worth what one that never fires is.

Default is now `260` lines / `17000` chars. `maxChars` moves with `maxLines` for the same reason
0.110.0 moved this repo's own: at the observed ~65 chars per line, 260 lines needs ~16.9k, so
leaving chars at 12000 would make the stated line budget unreachable.

## How it was found

By dogfooding, not by a test. Refreshing a real 12-stack consumer to 0.110.0 put all four of its
agent files over its own `225/13000` override — and it had already been over at 0.108.0. Measuring
the floor to see whether that was the consumer's size or the framework's default answered it: a
one-stack scaffold breaches the default on its own.

## The floor is the worst stack, not a representative one

| stack | lines | chars |
|---|---|---|
| dotnet | 221 | 14284 |
| aspire | 173 | 11542 |
| azure / cosmos / react / github | 167 | ~11.3k |
| common / claude | 158 | 10639 |

The first cut of this measured `python` alone (159 lines) and set the default to 200. The test then
failed on the suite's default config, which is `dotnet` — 221 lines. A default picked from one
representative stack would have left every dotnet consumer over budget, which is the same defect
one size smaller.

## The check

`test_the_shipped_default_budget_fits_a_single_stack_project_on_every_stack` scaffolds each stack in
`index.json` on its own, with no `agentDocs` override, and asserts no agent file is over budget.
Nineteen scaffolds in ~1.2s.

Both lists are derived rather than pinned: the stacks come from `index.json` (guarded against
disagreeing with `features/`, so the loop cannot silently stop covering the catalog) and the sizes
from what the scaffolder actually renders. A new stack or a new common invariant is measured, not
assumed.

Seen failing at `110`, and again at `200/14000` where it named `dotnet` — the assertion carries the
offending stack, not just a size.

## Five tests rewritten

Each because a literal that used to sit above the old default now sits at or below the new one:

- `test_claude_md_over_line_budget_exits_one` — input derived from `CLAUDE_MD_MAX_LINES`; the char
  sibling likewise from `CLAUDE_MD_MAX_CHARS`
- `test_custom_max_lines_override_raises_the_budget` — its 200-line input would have passed without
  its own `--max-lines` flag
- `test_doc_budget_reads_an_override_from_config` and `test_a_partial_override_keeps_the_other_default`
  — their override literal was `200`, so at a 200-line default the assertion is satisfied by the
  constants alone, whether or not the override is read
- `test_an_override_lifts_a_file_that_was_over_budget` — override derived so it always clears the
  fixture

Proven, not assumed: mutating `doc_stats`'s `overBudget` to a constant `False` turns the two size
tests red; mutating `doc_budget` to ignore the override entirely turns all three override tests red.
Every mutation restored byte-for-byte (sha256 verified).

## What this changes for consumers

A project with its own `agentDocs` override is unaffected — the override always wins. A project
without one gets a looser budget, so nothing that passed starts failing. Consumers relying on the
old default to keep their agent files tight will want an explicit override now.

`.ai-badger/config.json` in this repo keeps its own `256/17500`.
