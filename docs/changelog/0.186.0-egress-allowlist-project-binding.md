# 0.186.0 — a locked project can allow named hosts; plaintext and mismatched project ids are refused

**Minor** · 2026-10-03

Follow-up T1a of the data-access plan (`docs/work/2026-10-02-data-access-follow-ups-plan.md`),
recorded in [ADR-0035](../adr/0035-host-allowlist-and-project-binding.md). See the updated
[data access reference](../reference/data-access.md).

## What changed

- **`allowHosts`.** `dataPolicy` also accepts `{"mode": "local-only", "allowHosts": [...]}`. A
  locked project can now reach a named company endpoint, such as a decider in the company cloud.
  - The allowlist **relaxes the lock but never replaces the opt-in.** Sending still needs
    `AI_BADGER_ALLOW_THIRD_PARTY=1`, so a committed config, including one in an untrusted clone,
    cannot switch egress on.
  - Hosts match exactly, on the host that is actually dialled.
  - With several locking ancestors, only hosts every one of them lists are allowed (the
    intersection).
  - One bad entry voids the whole list; the project stays locked.
- **Plaintext refused.** Every non-loopback `http://` destination is refused, opted in or not.
  URLs whose dialled host differs from the parsed host are refused as well (whitespace, control
  characters, `\`).
- **Project id binding.** When `AI_BADGER_PROJECT_ID` is set and differs from the project id found
  from the working directory, the memory pipeline does not run, and the single local search
  remains.
- **Jev.** The advisory resolves its endpoint through the same rule. A refusal now reports
  `not-opted-in`, `locked` (naming the config and the missing `allowHosts` entry) or `plaintext`.
- **Re-runs keep the allowlist.** Re-running `welcome-ai-badger` keeps a valid `allowHosts`
  object verbatim. An invalid one becomes `"local-only"`, with a note that the list was dropped.

## Upgrade notes

- **Old scaffolders reject the object form.** Scaffolders older than 0.186.0 refuse
  `{"mode": ..., "allowHosts": ...}`. The 0.185.0 runtime reads it as a full lock, which fails
  closed.
- **Exported project ids.** If you export `AI_BADGER_PROJECT_ID` globally, the OpenRouter
  pipeline now runs only in the project that id names.
- **Proxy.** `HTTPS_PROXY` is still not honoured; that is the next change.
