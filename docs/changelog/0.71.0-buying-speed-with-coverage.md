# 0.71.0 — buying speed with coverage

One machine, several sessions, and every one of them running the whole suite on every automated
gate. The slow half of that suite — end-to-end and integration — is the half that competes with
itself: two full runs at once tell you about the machine, not about the code. The sessions that
did not want to pay for it had no way to say so, so they paid anyway.

`start --risk` says it. Automated gates then run formatting, fast tests and the lint/rule check;
no e2e, no integration suite.

## What it does not do

It does not delete the full run. It moves it to a place the agent chooses: once, before
integrating, as the only session working at that moment. The switch buys speed with coverage and
the coverage is still owed — the skill body says so in the same words, because a switch documented
as free is a switch used as free.

## Why `status` prints it

A reduced gate mode nobody can see is the dangerous kind: the next reader takes a green run for a
full one. So the flag is recorded on the task entry and
`task_tracker.py status` prints `risk=on` for that task and nothing at all for the others. Naming
only the reduced mode is deliberate — a `risk=off` on every ordinary line is a column readers stop
seeing.

It is sticky across a resume, too. A resumed task re-runs `start` without repeating its flags, and
gates quietly returning to full is the exact surprise the switch exists to avoid. A later `start`
can raise it; nothing lowers it but a new task.

Default is off, and a task that never passes `--risk` behaves exactly as it did in 0.70.1.

## Tests

`tests/test_task_tracker.py::TestTheRiskSwitchRunsGatesInLimitedMode` — 5 cases: the flag lands on
the entry without disturbing the branch; an unasked task records `risk: false` rather than a
missing field; the switch survives a reattach plus a second `start`; a later `start` can raise it;
and `status` names the risky task while leaving a second, ordinary task's line clean.

Both halves were checked by mutation: dropping the sticky fallback fails the resume case, and
silencing the `status` suffix fails the status case.
