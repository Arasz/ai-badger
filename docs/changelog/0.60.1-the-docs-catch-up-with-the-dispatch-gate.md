# 0.60.1 — the docs catch up with the dispatch gate

A documentation pass over the 0.60.0 release ([ADR-0015](../adr/0015-delegation-needs-a-mechanism-not-more-prose.md)).
No behaviour changes.

The `task` skill still told readers that a dispatch naming no model "silently inherits
the session's, which is the expensive one". Since 0.60.0 neither half is true: a
dispatch that names no model takes the `model:` lane in its persona's frontmatter, and
the `PreToolUse` dispatch gate denies one whose persona has no lane. That sentence now
says what the mechanism does.

The rest is drift the release left behind:

- `README.md` — the token-spend section stopped at measurement; it now names the lanes
  and the gate that closed the leak. The catalog tree lists the `delegator` persona and
  `delegation.md.tmpl`.
- `docs/framework-architecture.md`, `docs/getting-started.md` — the scaffolded
  `.ai-badger/` layouts list the generated `delegation.md`.
- `docs/index.md` — the inline ADR list stopped at `0014`.
- `docs/dictionary.md` — the plan phase dispatches Opus, not Fable/Sonnet; a new row maps
  the persona `model:` lane across agents, including Copilot deliberately dropping it.
- `docs/hermes-claude-compatibility.md` — `/task` routes Opus/Sonnet/Haiku; Fable has not
  been a routine lane since 0.17.4.
