# 0.62.0 — A declared MCP server names what must already be installed

`stack-mcp.json` can mark a server `declare: true`, and ai-badger then writes its launch
config into `.mcp.json` and `.github/mcp.json`. Nothing recorded what has to be on the machine
for that config to work.

So when it is not there, the failure is the agent's own connection error — which names neither
ai-badger, nor the server, nor the thing to install. The Aspire MCP server is `aspire agent
mcp`, a subcommand of the Aspire CLI. `code-review-graph` is a Python distribution that the
launch interpreter has to be able to import. Both facts existed only in someone's head.

## What changed

`meta.json` gains a `prerequisite` block: `summary` (required), `check`, and `install`.

It lives in `meta.json` rather than a stack's `stack-mcp.json` for the reason the schema
already gives for `package` — it is a property of the server, not of one stack's opinion of it.
Bounded by `additionalProperties: false` like every other object in that schema, so a
mistyped key fails validation rather than being ignored.

```json
"prerequisite": {
  "summary": "the Aspire CLI — the server is `aspire agent mcp`, a subcommand of it",
  "check": "aspire --version",
  "install": "https://aspire.dev/get-started/install-cli/"
}
```

The scaffold reports it, for declared servers only and after decline filtering — telling
someone to install a prerequisite for a server they declined is noise. Real output from a run
against this repo:

```
note: prerequisite — code-review-graph needs the code-review-graph Python distribution,
importable by the interpreter that runs the launch command; check: python3 -c 'import
code_review_graph'; install: python3 -m pip install code-review-graph. ai-badger declares the
server, it does not install it.
```

That last sentence is the point. ai-badger declares servers; it has never installed one, and
this does not change that.

## The gate

A catalog test asserts every server declared anywhere in `features/*/stack-mcp.json` records a
prerequisite. A server that genuinely needs nothing still has to say so — otherwise a reader
cannot tell "nothing required" from "nobody wrote it down", which is the same ambiguity
ADR-0005 exists to remove for skills.

11 tests added, none changed.
