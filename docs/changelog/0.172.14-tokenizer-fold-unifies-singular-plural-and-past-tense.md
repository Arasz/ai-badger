# 0.172.14 — the tokenizer's suffix fold unifies singular/plural and base/past tense

**Patch** — the MCP retrieval tokenizer's suffix fold treated singular/plural and
base/past-tense forms of the same word inconsistently, splitting them into different tokens
half the time. 2026-09-24.

## What was wrong

- `_fold` stripped `es`/`s` when the remainder left at least 3 characters, but never handled
  a trailing `e`-final base or a `-ss` word. That meant `class` folded to `clas` while
  `classes` folded to `class`; `issue` stayed `issue` while `issues` folded to `issu`;
  `update` folded to `updat` while `updated` also folded to `updat` by coincidence but
  `use`/`uses`, `process`/`processes`/`processing`, `pass`/`passes`, `create`/`creating` and
  `merge`/`merged` all split the same way. Of the 12 pairs measured, only `box`/`boxes` and
  `test`/`tests` already unified.
- The mismatch could push a query below the coverage gate: `class` in a query for "search
  for that symbol" no longer overlapped the `search_symbol` tool's `classes` in its
  description, and the long-fixture-set recall dropped a point to it (0.969 recall@1/@3).

## What changed

- The fold rule is now: `ies` -> `y` (unchanged); a token ending in `ss` is left alone;
  otherwise strip the first of `ing`, `ed`, `es`, `s` that leaves at least 3 characters, then
  strip one trailing `e` from that base when at least 3 characters remain.
- Verified against all 12 measured pairs (issue/issues, file/files, class/classes,
  update/updated, process/processes, process/processing, use/uses, box/boxes, pass/passes,
  test/tests, create/creating, merge/merged) and every existing pin
  (tests/testing, companies->company, gas, ladies->lady, cats->cat).
- `bm25.Bm25Corpus.idf`'s docstring said an absent term scores 0; the formula gives that
  term the *maximum* idf instead (see the 0.50.0 entry below). Docstring only, no behavior
  change.

## Measured effect (`tooling/retrieval_eval.py`)

| Set | Before | After |
|---|---|---|
| quality (`mcp_queries.jsonl`) | r@1 .930 / r@3 .977 / false-fire .133 | unchanged |
| long (`mcp_queries_long.jsonl`) | r@1 .969 / r@3 .969 / false-fire .0625 | r@1 1.000 / r@3 1.000 / false-fire .0625 |
| hard (`mcp_queries_hard.jsonl`, instrument, not a gate) | false-fire .333 | false-fire .389 — `generate unit tests for this class` (adjacent-negative) now clears the coverage gate against `rider:search_symbol`, whose intent names "classes" |
| observed (`mcp_queries_observed.jsonl`) | false-fire .222 | unchanged |

No gated bar moved against its bar, so the 0.20 coverage threshold (`mcp_matcher.py`) was not
re-swept.
