# 0.172.13 — SessionEnd stops deleting the bus cursor, plugin-server tags stop showing empty

**Patch**: fixes in the message-bus session hooks and the MCP tool hint. 2026-09-24.

## Fixes

- **SessionEnd no longer deletes the message-bus cursor.** `message_delivery_hook.py`'s
  `_close` and `ai_badger_hooks.py`'s `on_session_end_message_delivery` both called
  `Store.delete_cursor(session_id)` on close. A host that reuses the same session id on
  resume (Claude Code's `--resume` default) then looked like a brand-new session to the
  store, and its first-delivery 30-minute gate replayed mail the session had already
  received. SessionEnd is now a no-op for the bus in both copies (the canonical hook and
  the byte-identical `features/common/skills/send-message/scripts/` copy); Rule 6's
  cursor death is the 4-day prune alone (`Store.open_user()`'s own retention sweep).
  `Store.delete_cursor` itself is untouched here — a later package removes the
  now-dead method.
- **`tags_for_display` misreads a plugin-decorated MCP server name.** Both copies of the
  helper — `context_enrichment.py`'s factored version and `ai_badger_hooks.py`'s Hermes
  duplicate — split a `server:tool` reference on the FIRST colon. `claude mcp list`
  decorates a plugin-provided server as `plugin:<plugin>:<server>`, so the split resolved
  to a server literally named `plugin`, the tag lookup found nothing, and the `[ai-badger]
  Relevant MCP tools:` hint printed empty parentheses for every plugin-hosted tool. Both
  copies now split on the LAST colon (`rpartition`), the same fix `mcp_index.py`'s
  `_split_tool_ref` already applied. The duplication between the two copies stays: R38 —
  `context_enrichment.py` is not delivered to `.ai-badger/hooks`. A parity test pins both.

## Changes

None outside the fixes above and the tests that pin them.
