# 0.162.2 — status-report: fix tracker_lib import off-by-one

**Patch** (content fix, no shape change) · 2026-09-05

## What changed

`status_report.py` bootstrapped `tracker_lib` via `parents[1] / "task" / "scripts"`.
`parents[1]` of `skills/status-report/scripts/status_report.py` is
`skills/status-report`, so it built `skills/status-report/task/scripts`
(nonexistent). The import failed, was swallowed to `lib=None`, `_tracking_ready`
went False, and the report fell back to `executed-tasks.json` — printing
`(no task in progress) + (no plan file)` despite live `IN_PROGRESS` rows in the
store. Fixed to `parents[2]` (`skills/`), where `skills/task/scripts/tracker_lib.py`
lives. Same fix applies to scaffolded consumers (`.ai-badger/skills/...` mirrors
`features/common/skills/...`).

## Fix

One-word: `parents[1]` -> `parents[2]` in
`features/common/skills/status-report/scripts/status_report.py` (+ regenerated
mirrors `skills/...` and `.ai-badger/...`). Regression test
`TestTrackerLibImportPath` asserts `parents[2]/task/scripts/tracker_lib.py`
exists and the bootstrap uses `parents[2]`.

## Provenance

Feed from job-search-ai-assistant, where the scaffolded copy was hand-patched
(`AI_BADGER_ALLOW_GENERATED_EDITS=1`) after the report showed empty despite a
live task; verified the one-word fix restores current-task + checklist +
subagents.
