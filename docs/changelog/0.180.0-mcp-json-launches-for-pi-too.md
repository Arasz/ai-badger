# 0.180.0 — `.mcp.json` carries the launch every configured reader can start

**Minor** (scaffold-affecting) · 2026-09-29

`.mcp.json` is read by three hosts: Claude Code, the Copilot CLI (by cwd-upward lookup, #189)
and — since 0.148.0 / ADR-0023 — the pi-mcp-tools fork, which loads `<ctx.cwd>/.mcp.json` at
`session_start`. The generator knew about the first two only. Its `agentOverrides` resolved for
Claude whenever Claude was configured, so the shared file carried Claude's
`${CLAUDE_PROJECT_DIR}/…` launch — and the fork's claude conversion expands `${HOME}` and
nothing else, dropping any entry with another unexpanded `${VAR}` **whole** (`claudeMcpConfig.ts`,
recorded as `skipped:unexpanded-var` in the merge ledger). A pi session in a project that also
configures Claude silently lost every server whose Claude override anchors its arguments —
`task-graph` among them.

## What changed

- `mcp_tools.py` names pi as a reader of `.mcp.json` (`McpDestination.readers`), and
  `_override_reader` gains the anchor-free floor: when a configured reader's conversion expands
  `${HOME}` and nothing else (`EXPANDS_HOME_ONLY`), the shared file resolves its agent overrides
  **for that reader** and carries the anchor-free launch, with a note naming what the
  anchor-preferring reader lost. One entry, one launch every reader of its file can start: pi
  resolves the project-relative form against its own working directory (pi started at the
  project root — the only case where `<ctx.cwd>/.mcp.json` is found at all without a `/resume`
  move — has the file and the launch path in the same directory), and the Copilot CLI's own
  `.github/mcp.json` has carried the same anchor-free form all along (#193 calls the two
  renderings "the same launch").
- Four tests in `tests/test_stack_mcp_servers.py` pin it: the project-relative launch when pi is
  configured, the dropped-launch note, Claude's anchor unchanged without pi, and a pi-only
  project resolving for pi without the "names none of them" note.

## Behaviour changes worth knowing

- **A project configuring Claude *and* pi now gets the project-relative launch in `.mcp.json`**,
  not Claude's `${CLAUDE_PROJECT_DIR}` anchor. Claude Code resolves it when launched at the
  project root — the assumption the `task-graph` base command was designed around
  (`docs/work/plan-sections/p2-api-contract.md` B3). The anchor remains Claude's whenever pi is
  not configured. If one deployment ever needs both guarantees at once, the contract's recorded
  flip — a `~/.local/bin` shim behind `availability.command` (p2 B3) — is the path.
- Claude-only and Copilot-only projects see no change; the pi-only project's "written without
  agent overrides" note no longer fires (pi is a named reader now).
