# 0.56.0 — a task records which model did the work

`token-usage.json` reported `cacheEfficiency` as its quality signal. Measured
across 1250 real Claude sessions, that number is **0.975–0.986 on every single
one**, including the most expensive session on the machine. It cannot separate a
cheap task from a costly one, so it was answering a question nobody needed asked.

## What the measurement actually said

Same 1250 sessions, via `ccusage`:

| | |
|---|---|
| all-time cache efficiency | **0.982** (17.6B reads vs 330M writes) |
| top 1% of sessions (12) | **55.9%** of all cost |
| top 5% of sessions (62) | 92.5% of all cost |

Two things follow. Long context is not the problem — it is being served from
cache at roughly a tenth of write price. And per-session hygiene is not the
lever, because 1188 of 1250 sessions together account for ~7% of spend.

The lever is the model mix:

| Model | Output tokens | Cost | Cost per 1M output |
|---|---|---|---|
| opus-tier | 23.7M | $5,045 | $213 |
| mid-tier | 20.6M | $1,611 | **$78** |

Comparable output volume, **3.1× the cost**. Which model produced a task's output
is the largest lever available — and it is exactly what this skill's delegation
policy already claims to steer, with nothing recording whether it did.

## What changed

`parse_transcript_usage` now returns `byModel`, keyed on each assistant
message's `model`, summing input/output/cache tokens and message count. It is a
**partition** of the existing `cumulative` totals, not a second opinion —
sidechains included, because a subagent's tokens are billed work and its model is
the choice under scrutiny, and `<synthetic>` or absent both key as `unknown` so
nothing is silently dropped. There is a test asserting the totals reconcile.

`compute_usage` turns two checkpoints into `outputByModel` (this task's delta,
so a previous task's work is never attributed to it) and `modelMix` (each model's
share of the output).

`task_tracker.py status` gains a `mix=` column showing the dominant model and its
share:

```
issues-drain IN_PROGRESS  tokens=8214553  cacheEff=0.978  mix=opus-5:82%  grade=-
```

Run against this repository's own largest transcript, the split reads:

```
claude-opus-5      1,936,278   81.6%   msgs=2014
claude-fable-5       437,923   18.4%   msgs=632
<synthetic>                0    0.0%   msgs=56
```

An ai-badger session doing 81.6% of its output on the most expensive tier, with
nothing on the mid or cheap tiers. That is the number the delegation policy
exists to move, and it was invisible until now.

## No prices are recorded

Deliberately. Rates change, and a stale hardcoded price would be a confidently
wrong number in a file people trust. Output tokens per model is the durable half
of the answer; a reader applies today's rates to it.

## Behaviour changes worth knowing

None at runtime. `cacheEfficiency` is still recorded and still shown — it is now
documented as a *collapse* detector rather than a quality score.

A checkpoint written by an earlier version has no `byModel`, so a task already in
flight when this lands finishes with an empty `outputByModel` rather than
failing. There is a test for exactly that.

## Rewritten test worth naming

`tests/test_tracker_lib.py::test_parse_transcript_usage_missing_file_returns_zeroed_result`
asserts the whole returned dict by equality, so it had to learn the new
`"byModel": {}` key. The assertion is unchanged in what it claims — a missing
transcript still returns a fully zeroed result — it just now covers one more
field of it.
