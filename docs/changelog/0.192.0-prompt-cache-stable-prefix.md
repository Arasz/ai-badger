# 0.192.0 — the prompt prefix stays byte-stable

**Minor** (additive) · **Date:** 2026-10-17

The harness places prompt-cache breakpoints, not skill files. Claude Code caches
automatically, and pi sets Anthropic `cache_control` breakpoints on the system prompt, the
last tool and the last message. What ai-badger controls is whether the text it scaffolds stays
identical between requests, since one changed byte reprices everything after it.

- New `claude` stack instruction file, `claude.instructions.md` (applies to `**/CLAUDE.md` and
  `.claude/**`): always-loaded files stay a pure function of the catalog and the config, and
  per-turn context goes into the latest message instead of CLAUDE.md. It is a scoped
  instruction rather than a common invariant, so it costs nothing on turns that do not edit
  those files and stays within the 35-invariant budget.
- `tests/test_prompt_cache_stability.py` scaffolds the same config for every agent at two
  different times and fails if any agent-facing file differs, or if a discovery file carries a
  timestamp. The manifest and project id are exempt because tooling reads them and prompts
  do not.
- `pi.instructions.md` documents pi's built-in breakpoints and `PI_CACHE_RETENTION`
  (`long` for a 1-hour TTL, `none` to disable). No pi extension is needed.

Run `den-refresh` to pick up the new instruction file.
