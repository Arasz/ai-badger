# 0.60.0 — delegation becomes a mechanism

A delegation policy already existed in two prose places, and 205 measured
dispatches ignored both: 101 named no model, 82 silently inherited the expensive
session model, none reached a scaffolded persona. This release ships the three
mechanisms [ADR-0015](../adr/0015-delegation-needs-a-mechanism-not-more-prose.md)
records, cheapest and most binding first:

1. **Every catalog persona names its model lane.** `model:` in persona frontmatter
   now survives into `.claude/agents/` (`architect`/`code-reviewer`/`delegator` →
   opus, the implementers → sonnet). The Copilot adjuster deliberately drops the
   key — one host's model names are not another's. A catch-all test refuses a
   catalog persona without a lane.
2. **A dispatch that names no model is refused.** A `PreToolUse` hook (matcher
   `Agent`) denies any dispatch whose subagent type has no frontmatter lane and
   whose call passes no `model`, with a reason that names the fix. **Upgrade
   note:** this means model-less dispatches to the built-in agent types
   (`general-purpose`, `Explore`, `Plan`) and to plugin personas start being
   refused the first session after a re-scaffold — pass `model` on the call, or
   use a persona with a lane. It fails open on anything malformed, and never
   auto-approves. It denies rather than injecting a default, because a
   per-invocation `model` outranks the frontmatter lane — injection would
   override mechanism 1 on every call.
3. **The `delegator` persona plus a generated map.** A work-routing lead for long
   multi-package sessions — contract, six-step dispatch procedure, lanes by
   required derivation, a ~2k-token dispatch floor, no dispatch without a named
   verifier, a per-dispatch ledger. Its first read is `.ai-badger/delegation.md`,
   described below.

Also in this release: every wired hook command survives its script going missing
at runtime. In a git worktree session `${CLAUDE_PROJECT_DIR}` resolves to the
main checkout, which may not carry the script — and a missing file *blocks* the
call a `PreToolUse` hook gates. Found minutes after wiring the dispatch gate,
when it blocked this repo's own next dispatch. The wired command now tries the
project copy, falls back to the session cwd's copy, and reports the skip with a
`systemMessage` instead of going silently inert.

## The delegation map

Every scaffolded project now gets `.ai-badger/delegation.md`: one page naming the
personas it can hand work to, the lane each one runs in, the routing rows that
dispatch work to them, the verifiers that prove the work, and the MCP servers
reachable from the config the project already gets.

The facts were all scaffolded already — spread across `.ai-badger/agents/*.md`,
`config.json` and `.mcp.json`. A session that wanted to delegate had to read three
places to find out who was even available. The agent docs (`CLAUDE.md`/`HERMES.md`)
gained one line under "Agent delegation": every dispatch names its `model`, and
the map is where to look.

## What it looks like

```markdown
# Delegation map — ai-badger

> Scaffolded by ai-badger 0.60.0. Regenerated on every scaffold; do not edit.

## Personas available here

- `architect` — Design and decomposition specialist — ... Lane: opus.

## Routing (config.json personaRouting)

- Design, decomposition and ADRs — before any non-trivial multi-file change → `architect`

## Verifiers

- `test`: `python3 -m pytest -q`

## MCP servers reachable here

- `code-review-graph` — This project has a knowledge graph
```

## How it is built

`features/common/templates/delegation.md.tmpl` and the same `{{SLOT}}` renderer
every agent file uses — no new machinery. `STACKS`, `PERSONA_ROUTING` and
`COMMANDS` are the slots `compute_doc_slots` already computed for CLAUDE.md, so
the map and the instruction files cannot disagree about them. Two slots are new:

- `PERSONAS` — read from `.ai-badger/agents/*.md` rather than from the catalog, so
  a persona a project added by hand is on the map too. The lane comes from the
  persona's own `model:` frontmatter, and a persona that names none is reported as
  running on the **session default** rather than being given one.
- `MCP_SERVERS` — the declared, project-scoped servers, blurbed with the first
  sentence of the `server.md` their catalog entry ships.

Every input degrades on its own: no routing, no commands, no servers, or no
personas each render a `_None ..._` line instead of an empty section.

The map is written by `TemplateRendering.write_delegation_map` and recorded in the
manifest like any other template, so drift and the freshness guard see it.

## Also

- `McpTools.project_server_names()` — the declared, project-scoped server names,
  sorted. One expression, one owner; `run_adjustments` was already spelling it out.
- `tests/test_mcp_catalog_instructions.py`'s "every template carries the MCP slot"
  check now scopes itself to the templates that carry `{{INVARIANTS}}` — an agent's
  instruction file. The delegation map names servers instead of carrying their
  instructions, so it is not one.
