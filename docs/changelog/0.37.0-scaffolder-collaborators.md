# 0.37.0 — `Scaffolder` stops being six mixins pretending to be one object

Wave 6. Internal; no consumer-visible behaviour changes.

`Scaffolder` inherited from six mixins — `McpToolsMixin`, `HookWiringMixin`,
`StatusLineWiringMixin`, `TemplateRenderingMixin`, `AgentFilesMixin`, `ExtensionsMixin`. None
could be constructed alone. They communicated through `self`, so any of them could reach any
attribute or method of any other, and none could be tested or reasoned about in isolation. At 555
lines it was the largest class in the codebase, in a 922-line file.

It is now `class Scaffolder:` — a plain class holding a `ScaffoldContext` and six collaborators.
**Zero `*Mixin` classes remain.**

## The measurement that made this safe

103 direct `Scaffolder(...)` constructions across 23 test files depend on this object's shape, and
they are the highest-degree nodes in the whole knowledge graph (see
[the architecture baseline](../reviews/2026-07-28-architecture-baseline.md)). So the first work
package had one hard constraint: **`ScaffoldContext` had to be introduced with zero lines changed
under `tests/`**, via read/write property delegation. It was, and that is the checkpoint proving
the extraction behaviour-preserving.

`run()`'s step order is load-bearing — it is recorded into `manifest.json.partial`. The literal
was captured from a real run *before* any edit and asserted after every one of the nine work
packages:

```python
['start', 'personas-and-instructions', 'skills', 'agent-files', 'hooks', 'config-and-mcp']
```

It never changed.

## What the plan got wrong, and the code corrected

- **`carried_body` is a method, not a data attribute.** Making it a `ScaffoldContext` field would
  have shadowed the method. It is resolved by the collaborator argument instead.
- **`statusline_wiring` imports `hook_wiring`** for two command-parsing helpers. Pre-existing and
  not state-carrying; documented as the second permitted edge rather than removed.
- **`Scaffolder._merge_external_tools` is called unbound on the class** by a test, and one test
  patches `_scaffold_claude_mcp_user` **on the instance** to simulate an unwritable home. Both
  needed seams a naive delegation would have closed. The suite found these, not a reading.

## Extraction order

Leaves first — `Extensions`, `StatusLineWiring`, `HookWiring`, `McpTools` — then
`TemplateRendering` (which reads the external-tools cache `McpTools` fills, now on the context),
then `AgentFiles` (the only collaborator taking another collaborator as a constructor argument).
One commit per work package.

## Rewritten tests

- **`tests/test_mcp_tools_notes.py`** — three tests grafted the mixin on with
  `collector.__class__ = type("Bound", (_Collector, McpToolsMixin), {})`, impossible once it is a
  collaborator. They now build a real context. **All three assertions are unchanged in meaning**;
  only the receiver moved.
- **Five files, 53 call sites, receiver rename only** — `scaf._generate_mcp_json()` →
  `scaf.mcp.generate_mcp_json()` and equivalents, across `test_stack_mcp_servers.py`,
  `test_settings_preservation.py`, `test_mcp_user_tool_paths.py`,
  `test_scaffold_external_tools.py` and `test_scaffold_manifest.py`. No fixture, input, expected
  value or assertion altered.

Nothing was deleted. 17 tests added.

## Note

`Scaffolder` keeps five public delegations (`wire_hooks`, `wire_statusline_capture`,
`unwire_statusline_capture`, `assemble_instructions_doc`, `assemble_hermes_doc`). Only
`wire_hooks` has a caller; the other four exist for API stability and are candidates for deletion
in a later pass.
