# 0.15.1 — error recovery and GH issue creation for scaffold skills

Added an **Error Recovery** section to the three scaffold skills (`den-refresh`,
`welcome-ai-badger`, `feed-badger`). When a script fails, the agent now:

1. **Parses the structured error** from the script's JSON output.
2. **Attempts automatic recovery** using a skill-specific fix table (fix config
   validation errors, rebuild index, install missing deps, update version, etc.).
3. **Offers to create a GitHub issue** in `Arasz/ai-badger` if recovery fails —
   gated on `gh` availability and **explicit user permission**.

## What changed

| Skill | Recovery table covers |
|---|---|
| `den-refresh` | config invalid, manifest missing, index stale, version mismatch, scaffold exception, missing deps |
| `welcome-ai-badger` | jsonschema missing, index stale, config validation errors, scaffold exception, no stacks detected, agent file conflicts |
| `feed-badger` | manifest missing, no candidates, gh auth failure, branch conflicts, push rejected, index/validate errors |

## Issue creation

- Requires `gh` CLI authenticated and user approval.
- Issue title: `bug: <skill-name> failed — <error summary>`
- Issue body includes: error JSON, recovery attempts, environment info,
  sanitized project config.
- Labels: `bug, triage`.

## Why

Previously, script failures surfaced raw errors with no recovery guidance.
Agents had to ask the user what to do. Now the agent tries known fixes first
and can file a structured bug report when it can't recover — closing the loop
between "something broke" and "upstream knows about it".
