# 0.193.0 — limited mode for machines where hooks are disabled

**Minor** (additive) · **Date:** 2026-10-17

When an organisation's managed Claude Code settings set `disableAllHooks: true`, every hook stops,
plugin and managed ones included, and nothing reports that ai-badger's hooks are gone. Limited
mode is a per-machine switch that replaces what it can with commands run by hand.

- New `task/scripts/limited_mode.py`. `checkin` reads the project's `.ai-badger/hooks/hooks.json`,
  runs each `SessionStart` command with the payload Claude Code would have sent, and prints what it
  would have injected. `checkin --end` does the same for `Stop`, including a Stop hook's
  `decision: block` reason. It refuses inside a subagent, which would otherwise read the parent's
  mail.
- `limited_mode.py on` / `off` write and remove a marked block in `CLAUDE.local.md` at the main
  checkout's root. The block tells the agent to check in and to follow by hand the rules the
  dispatch gate, the memory-first gate and the other guards used to enforce.
- The managed `.gitignore` block now ignores `CLAUDE.local.md`, so the switch never reaches a
  commit. Committed files, including `.claude/settings.json`, are unchanged: teammates outside the
  policy keep every hook.
- New how-to: `docs/how-to/run-without-hooks.md`, including what limited mode cannot replace
  (per-turn delivery, state-dependent guards, memory follow-through telemetry, checkpoints for
  interrupted turns).

Run `den-refresh` to pick up the script and the `.gitignore` entry.
