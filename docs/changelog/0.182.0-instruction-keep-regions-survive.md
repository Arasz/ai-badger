# 0.182.0 — a project's keep region survives in instruction, invariant and persona files

**Minor** (scaffold-affecting) · 2026-09-30

The framework promises projects one survival path: content between `<!-- ai-badger:keep-start -->`
and `<!-- ai-badger:keep-end -->` rides across a re-scaffold. That promise held for the managed
agent files (`CLAUDE.md`, `AGENTS.md`, the Copilot and Hermes files) and for templates, and nowhere
else. `copy_file` — the path that writes every instruction, invariant and persona file — was a bare
`shutil.copyfile`, so a `den-refresh` replaced the project's edited copy with the framework's fresh
one and dropped the region with it. One consumer lost its Cosmos registry guard line to exactly
this, and the test pinning that line caught it only after the fact.

## What changed

- `Scaffolder.copy_file` carries preserved regions the same way the managed agent files do:
  `TemplateRendering.copy_carrying_regions` writes the fresh framework body and re-seats every keep
  region the file already had, in order. Nothing carried means a byte-for-byte copy, so the common
  case is unchanged. Malformed markers leave the file untouched with a note, rather than costing the
  project its content.
- `personas`, `invariants` and `instructions` are now `hashes_source` feature types (ADR-0006),
  because their written output is no longer a copy of the framework source. Their manifest entries
  gain `outputHash` (the written file's hash, D11) and `hash` stays the source's. Without this, a
  carried region would read as framework drift on every later refresh.
- Tests: `tests/test_scaffold_instruction_keep_regions.py` covers the region surviving, the body
  still refreshing around it, malformed markers leaving the file alone, and a carried file not
  reading as drift. The prune suite's dropped-item coverage now models the new entry shape.

## Behaviour changes worth knowing

- **An instruction file with malformed keep markers is no longer overwritten.** The re-scaffold
  leaves it untouched and says so in the notes; fix the markers and re-run.
- **Manifests written before this version carry no `outputHash` for the three types**, so a copy
  whose catalog source disappeared is left in place with a "cannot tell whether it was edited" note
  instead of being pruned. The next re-scaffold that records the entry clears it.
- **No re-scaffold is required** to pick this up: the next one carries whatever regions are already
  on disk.
