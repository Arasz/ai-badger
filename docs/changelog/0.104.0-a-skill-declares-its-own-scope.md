# 0.104.0 — a skill declares its own scope

Two mechanisms answered two questions about a skill, in two places. Its directory under
`features/<stack>/skills/` said which stack owns it; a 36-entry hand-kept dict in
`engine/badger_lib.py` said whether it ships unasked. [ADR-0018](../adr/0018-where-the-skill-routing-declaration-lives.md)
collapses that to one: the directory still answers the first, and a `scope:` key in the skill's
own `SKILL.md` frontmatter answers the second.

`SKILL_SCOPES`, `skill_scope()`, `UnknownSkillScope` and `default_skill_names()` are deleted.

## The point of the change is what a missing declaration now costs

ADR-0005 exists because `code-review-checklist` was complete, correct, catalogued and reached
nobody for its entire life. Its fix was "omission is an error". That was thinner than it read:

- `default_skills_in` and `opt_in_skills_in` both did `SKILL_SCOPES.get(...)` and **skipped an
  undeclared directory silently**.
- The hard failure came from one test that diffed `index.json` against the dict, covering the
  common stack only.
- `skill_scope()`'s `UnknownSkillScope` — the raise ADR-0005 credits — had **zero production
  callers**. Verified before deleting it.

A missing or invalid `scope:` is now `gates/skills_lint.py` **rule 12**: a hard failure at
authorship, in the linter that already parses all 51 catalog `SKILL.md` files on every gate run.
The declaration and the thing declared are the same file, so a `git mv` or a forgotten second
edit cannot separate them.

Rule 12 applies to `features/common/skills/` alone. `stack_local_skills` returns a stack
directory's whole catalog whatever the scope, so requiring the key on the other 15 skills would
be a value nothing reads.

## What the readers do now

| Reader | Before | After |
| --- | --- | --- |
| `default_skills_in` / `opt_in_skills_in` | `SKILL_SCOPES.get(dir.name)` | `skill_scope_in(dir)` reads the frontmatter |
| `inclusion_notes` | consulted the module constant | takes the default set as an argument |
| `index_build._skill_items` | copied the dict value | reads the frontmatter |
| `stack_local_skills` | every skill *not* in the dict | every skill in the directory |
| `SkillDelivery.discover_stack_local` | walked every configured stack | skips `DEFAULT_COMMON_STACKS` |
| `sync_plugin_skills`, `scaffold.DEFAULT_SKILLS` | unchanged — both already derived from `skills_for_stack` | |

`index.json` still carries `scope`, now derived from frontmatter, so `drift.py`'s
`item.get("scope")` consumer is untouched.

## The correction ADR-0018 needed

The ADR recommended deleting `stack_local_skills`' `not in SKILL_SCOPES` clause outright, on a
measurement that it "already excludes nothing". It excluded 36 things, at a call site nobody
traced: `resolve_stacks` always puts `common` first in the stack list, and
`SkillDelivery.discover_stack_local` walks *every* stack in that list. The clause was the only
thing keeping the common catalog's 22 `optIn` skills out of every scaffold.

Measured with the clause deleted and no caller guard, against three configs:

| Config | Correct | Clause deleted, unguarded |
| --- | --- | --- |
| bare defaults | 14 skills | **36** |
| an `optIn` skill named explicitly | 19 skills | **36** |
| `stacks: ["dotnet"]`, nothing named | 25 skills | **47** |

The clause is gone as recommended; the caller skips the common stacks instead, and
`test_stack_local_discovery_never_reaches_into_the_common_catalog` fails without that guard.

## Evidence

- The `.ai-badger/skills/` tree delivered for all three configs above is **identical** before and
  after — diffed as trees, not as code paths.
- Every `scope` value in `index.json` is unchanged for all 51 skills: 14 `default`, 22 `optIn`,
  15 stack-local with no scope.
- Deleting `scope:` from a real `SKILL.md` fails `skills_lint` rule 12 and two tests.
- No skill name appears in two stack directories (51 directories); planting one fails the new
  test. This replaces the hazard the exclusion clause used to hide.
- `engine/badger_lib.py` drops from 1036 to 985 lines, so the `# pylint: disable=too-many-lines`
  on line 1 — which cited ADR-0005 for a reason that was never its own — is gone with it.
