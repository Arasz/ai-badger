# 0.172.5 — the consumer journey deletes only its own scratch

**Patch** — a safety fix to `gates/consumer_journey.py`; no change to what the journey checks. 2026-09-24.

## What was wrong

The journey's cleanup ran `shutil.rmtree(scratch)` whenever `--keep` was not given, and
it ran on every exit path:

- **A refusal deleted what it refused.** `--scratch $HOME` printed
  `REFUSING TO RUN ... is the real home`, returned 1, and then removed the home directory.
- **A parent of `$HOME` passed the check.** `check_scratch_home` refused the home and
  anything inside it, but not an ancestor, which was later removed with the home in it.
- **An existing `--scratch` was removed wholesale**, whatever it held before the run.

## What changed

- `check_scratch_home` refuses a scratch that is `$HOME`, inside it, or an ancestor of it.
- The journey removes only a directory it created: the `mkdtemp` default, or a
  `--scratch` path that did not exist and was created by this run. An existing
  `--scratch` is left as found, and a refusal over a `--scratch` deletes nothing.

## Upgrade notes

- No action required. The pre-push hook and `consumer-journey.yml` use the `mkdtemp`
  default, which is still created and removed as before.
- If you pass an existing directory as `--scratch`, the run's files now stay in it;
  remove them yourself.
