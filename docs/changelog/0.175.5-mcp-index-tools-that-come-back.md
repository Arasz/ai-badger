# 0.175.5 — mcp-index: reappeared tools, honest folding, honest counts, honest errors

**Patch** (behavior fix, no shape change) · 2026-09-24

## What changed

Five confirmed defects in `mcp-index`, none of which needed a schema or a cross-package
dependency to fix (plan-v2 §P13 states the file-mode rule inline rather than waiting on P04).

- **A tool that reappears stays `removed` forever.** `_sync_tools` only ever added names
  present in the current listing but absent from the index, and marked names absent from the
  current listing but present in the index. A name in both directions — a server restart or a
  version bump that restores a tool it used to drop — never ran the un-remove path, so
  `mcp_matcher._iter_tools` kept skipping it indefinitely. `update` now flips a reappeared
  tool's `status` back to `active`, keeping its curated tags and intent.

- **The legacy YAML subset parser silently folded a real newline into a space.** pyyaml
  encodes an embedded newline in a single- or double-quoted scalar as a blank physical line
  between two folded lines (YAML's own rule: one blank line between fold-lines is a real line
  break, not a space-fold). `_logical_lines` dropped blank lines outright and space-joined the
  continuation regardless, so `intent: 'note: use with care\nsecond line'` became `'note: use
  with care second line'` — wrong, but silently so, because the round-trip guard rebuilds both
  sides of its comparison from the same already-folded lines and cannot see a value that
  happens to still need the same quoting after the fold. The parser now refuses (returns
  `None`) whenever a continuation extends an already-quoted value, matching its own contract
  ("refuses rather than silently returning a wrong parse").

- **`parse_hermes_test_tools` stopped at the first tool with no description**, and returned
  the truncated list as authoritative (`tools_known = True`), silently dropping every tool
  after it. It now accepts a bare tool name as a valid entry, and — using the header's own
  `Tools discovered: N` count as the one honest completeness signal — returns `None` (not
  answered) whenever the parsed block's length does not match `N`, the same as a server it
  could not test at all.

- **`--from-json` was documented as reading a saved file**, but always took the JSON text
  itself; a bad document (a file path, a non-object JSON value) raised an uncaught
  `JSONDecodeError` or `AttributeError`. The docs (`mcp_index.py`, `SKILL.md`) now say it
  takes the JSON text directly, and both failure shapes exit 2 with a message instead of a
  traceback.

- **`mcp_index`'s own local `atomic_write_text` had drifted from the canonical one**: it
  dropped the mode-preservation step, so every write reset `.ai-badger/mcp-tools.json` to
  `mkstemp`'s always-0600, even when the file was 0644 and shared via git. It now preserves an
  existing file's mode, and gives a brand-new file `0o666 & ~umask` — `mkstemp` deliberately
  ignores the process umask for its own temp file, which is wrong for the file that temp file
  is about to become.

## Wiring

- `features/common/skills/mcp-index/scripts/mcp_index.py`: `_sync_tools` un-removes a
  reappeared tool; `_fetch_mcp_tools` catches `JSONDecodeError`/`AttributeError` from
  `--from-json` and exits 2 with a message; `_write_index`'s local atomic write preserves an
  existing file's mode and computes `0o666 & ~umask` for a new one.
- `features/common/skills/mcp-index/scripts/legacy_yaml_subset.py`: `_logical_lines` refuses a
  continuation of an already single- or double-quoted value.
- `features/common/skills/mcp-index/scripts/host_listings.py`: `parse_hermes_test_tools`
  accepts a description-less tool line and checks the parsed count against the header's `N`.
- `features/common/skills/mcp-index/SKILL.md`: corrects the `--from-json` description.
- Mirrored into `skills/mcp-index/` and `.ai-badger/skills/mcp-index/` via
  `tooling/sync_plugin_skills.py` and the self-scaffold.
- `tests/test_mcp_index.py`, `tests/test_legacy_yaml_subset.py`,
  `tests/test_mcp_index_hermes_test_discovery.py`: new gates for all five, each confirmed red
  against the unfixed code and confirmed red again under a targeted defect re-injection.
