# 0.61.3 — Naming the test that spawned a daemon, instead of guessing

#222 wrapped `subprocess.Popen` in `tests/conftest.py` so every `start_new_session` child is
tracked and reaped at teardown, with the reaper's return asserted empty. That works for anything
the **pytest process** spawns.

It cannot work for a hook reached from a **child interpreter**. The wrapper is a class replaced
in one process's `subprocess` module; a subprocess gets a clean `subprocess`, so the grandchild
it detaches is invisible to the parent's list and never reaped. #232 recorded the residual
rather than leaving it to be rediscovered.

It was rediscovered anyway. On 2026-08-01, ten orphaned `poll_limit.py` daemons were alive at
once on one machine, aged 17 to 21 hours, all at PPID 1 — six of them owned by `/private/tmp`
worktrees that had already been deleted, one with its own script deleted out from under it. They
write into `.ai-badger/task-tracking/`, which failed an unrelated pre-push `pytest` lane twice
that morning: the session fixture that watches that directory blamed the suite for a concurrent
daemon's writes.

## What changed

Policing the outcome does not work — there is no reach into another interpreter, a `ps` scan is
racy and would match a developer's own daemon, and an env kill-switch is production code that
exists only for tests. So this names the **call site**.

`tracker_lib.spawn_detached` — the single seam every detached spawn already goes through —
appends a record when `AI_BADGER_SPAWN_LOG` is set: `argv`, `cwd`, `pid`, `$PYTEST_CURRENT_TEST`,
and `by` (the spawning process's pid). `conftest` points it at a scratch file and fails the
session on anything left in it.

`by` is what makes the assertion precise. A spawn whose `by` is the pytest process was already
tracked and reaped by #222's wrapper. A spawn from any other pid came from a child interpreter —
the case the wrapper structurally cannot reach, and the only one worth failing a run over.

The variable is unset outside the suite, so the code is inert in production. It never raises: an
unwritable path, a directory where the file should be, or a stubbed `Popen` returning something
without a `.pid` are all swallowed. A diagnostic that can fail the thing it observes is worse
than no diagnostic — and the `.pid` case was not hypothetical, `tests/test_tracker_lib.py` caught
the first draft doing exactly that.

## Acceptance

A full-suite run leaves no `poll_limit.py` process whose `cwd` is inside the checkout, asserted
rather than eyeballed. Verified: 2591 passed, and `ps` after the run shows none.

The mechanism is proved able to fail by `test_a_spawn_from_a_child_interpreter_records_a_different_pid`,
which runs `tracker_lib` in a real subprocess and asserts the breadcrumb crosses the process
boundary carrying a foreign `by`. Without that, an empty log would be indistinguishable from a
broken probe.
