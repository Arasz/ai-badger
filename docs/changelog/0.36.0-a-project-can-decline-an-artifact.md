# 0.36.0 — a project can decline a framework artifact

Until this release there was **no supported way for a project to say "I do not want this."**
Deleting `.ai-badger/skills/foo` got it restored on the next refresh and left
`.claude/skills/foo` as a dangling symlink. Worse, `docs/getting-started.md` told users, of
invariants: *"Delete the ones you do not want before committing."* A refresh restored them. The
documentation promised a mechanism that did not exist.

[0.34.0](0.34.0-skills-that-arrive-and-a-root-that-agrees.md) said this would ship separately.
It ships here.

## `config.exclude`

```json
"exclude": {
  "skills":     ["mcp-index"],
  "invariants": ["tdd-mandatory"]
}
```

Declines catalog items **by index name**, for the four name-addressable feature types:
`skills`, `personas`, `invariants`, `instructions`. Keys are optional; an absent key declines
nothing. A typo is a schema validation error, not a silent no-op — the inner object is
`additionalProperties: false` too.

The set is derived from the feature registry as `[ft.name for ft in FEATURE_TYPES if
ft.drift_reports_new]`, not written out a second time where it could drift from it.
`templates`, `hooks` and `adjustments` are deliberately excluded: they materialise outputs
under names of their own rather than their index name, so an index name would have nothing to
bind to.

## Enforced once

Filtering happens in **`Scaffolder.__init__`**, because every consumer — `scaffold_skills`,
`symlink_hermes_skills`, the adjustments context, the dependency check — reads `self.skills`.
Putting it in either entry point instead is precisely what produced
[#104](https://github.com/Arasz/ai-badger/issues/104), where `welcome-ai-badger` and
`den-refresh` disagreed about what a project should receive. `refresh.py` needed no change, and
that is the point.

`symlink_hermes_skills` filters separately and says why in a comment: its input is the names
**on disk**, not `self.skills`, and an excluded skill's copy is deliberately left behind.

## Hook wiring skips rather than refuses

`hook_wiring.py` rewrites hook commands into `.ai-badger/` **without checking the target
exists**, so declining the `task` skill would have wired three `settings.json` entries pointing
at nothing.

Refusing to exclude a hook-bearing skill was the alternative, and it was rejected: it would make
`task` — the largest skill — permanently undeclinable, and would need a second, hook-aware
validation rule. Script absence also arises with no exclusion at all (a partial scaffold, an
upstream rename), and an entry pointing at nothing is broken in every one of those cases. The
sibling branch already degraded this way.

A related defect surfaced only by running it: because an excluded skill's directory is left on
disk, an existence check alone still wired the hook, and a hook an *earlier* run had already
written survived — `settings.json` is merged into, never rewritten. A previously-wired hook for
a declined skill is now removed, with a note.

## What a declined item does to what is already there

`adjust_skills.py` now **prunes links it placed and no longer delivers**, which also fixes the
dangling-symlink defect that plain deletion leaves today. Only ever links ai-badger
demonstrably placed — our own symlink resolving inside `.ai-badger/skills/`, or a path recorded
in `manifest.json`. A hand-committed file is never touched.

Manifest-recorded `*.md` copies are pruned too, deliberately: an orphaned invariant would
otherwise be offered back to the framework as a project contribution by `feed-badger`.

**An excluded skill's `.ai-badger/skills/<name>/` directory is left in place.** The asymmetry is
intentional — removing a directory is not ours to do on the strength of a config line. The
consequence worth knowing: `feed-badger`'s `detect_additions` still walks it and its manifest
entry is gone, so a leftover skill directory can read as a project addition.

## Also

**The last residue of #104.** `DEFAULT_SKILLS` was `default_skill_names()`, which includes
`auto-wm` — a `features/claude` skill — and printed a permanent `not in index common.skills —
skipped` note on every single scaffold. It is now `default_skills_in(common)` and the note is
gone.

`docs/getting-started.md` no longer tells you to delete files; it points at `exclude`, and gains
a **Declining an artifact** section.

## Not included

**No ADR.** The research proposed one, but the number it suggested is taken, and the reasoning
here is a decision the maintainer may want to word directly. Recorded in
[`docs/research/2026-07-27-skill-removal-semantics.md`](../research/2026-07-27-skill-removal-semantics.md)
meanwhile.

## Upgrading

Nothing required — with no `exclude` key, behaviour is unchanged. Adding one takes effect on the
next `welcome-ai-badger` or `den-refresh`, and prunes what an earlier run installed. Review that
first diff: anything ai-badger did not place is left alone and named in a note.
