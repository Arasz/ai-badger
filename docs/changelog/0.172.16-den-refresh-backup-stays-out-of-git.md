# 0.172.16 — den-refresh's backup stays out of git

**Patch**: fix in `den-refresh` and the managed `.gitignore` block. 2026-09-24.

## Fix

`refresh.py` rmtree's and recopies `.ai-badger.bckp/` on every refresh, including a run with
no drift (the backup is unconditional by design). It copied `tracking.db` and its `-wal`/`-shm`
sidecars straight into the backup, and the managed `.gitignore` block only ever covered the
live database under `.ai-badger/task-tracking/` — never the backup directory itself. Every
refresh therefore left the copied SQLite files untracked.

- `check_breaking_and_backup`'s `shutil.copytree` now skips any `*.db*` name in addition to
  nested git checkouts, so the live task-tracking database never enters the backup.
- The managed `.gitignore` block now also ignores `.ai-badger.bckp/` wholesale, so any other
  file a future backup picks up stays untracked too.

## Upgrade notes

Run `den-refresh` (or `welcome-ai-badger`) to pick up the wider managed `.gitignore` block.
