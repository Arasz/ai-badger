# 0.189.3 — task-graph MCP server survives a non-UTF-8 console

**Patch** (content fix, no scaffold-shape change) · 2026-10-08

## What changed

`task_graph_server.py` wrote its NDJSON responses as **text** to `sys.stdout` with
`json.dumps(..., ensure_ascii=False)`. On Windows `sys.stdout` encodes with cp1252, which
cannot represent `→` (U+2192) — and ten tool descriptions carry it. The `initialize`
handshake succeeded (no arrow in it), so `/mcp` reported a successful reconnect; the next
request, `tools/list`, raised inside the write and killed the process:

```
File "…/encodings/cp1252.py", line 19, in encode
UnicodeEncodeError: 'charmap' codec can't encode character '\u2192' in position 8519
```

The input side was already byte-safe — `serve()` reads `sys.stdin.buffer` and decodes UTF-8
with replacement. The output side had no matching handling.

`serve()` now writes through a small `_write_line()` helper: UTF-8 bytes to `sink.buffer`
where the sink has one, a plain text write for an in-memory sink such as `io.StringIO` in
the tests. This mirrors the input side and sidesteps the console codec.

The defect predates this release: `serve()` is unchanged since the initial task-graph commit
(`ecca060e`, 2026-09-29). The existing test harness set `encoding="utf-8"` on the child
pipes, which hid it on every OS. The new regression test forces `PYTHONIOENCODING=cp1252`,
so the crash reproduces on any platform.

## Upgrade notes

Nothing required for a consumer. A `den-refresh` replaces the scaffolded copy.

## Provenance

Reported from a Windows consumer running Claude Code: `/mcp` showed task-graph as
"Reconnected", but every `tools/list` call killed the server. A local
`PYTHONIOENCODING=utf-8` workaround held it; this fixes the server so the workaround is no
longer needed.
