# 0.157.1 — Leg-scoped cursor, defer seams, armed test hold

## What changed

- **A gated first read no longer sweeps other legs' mail (L1).** When a session's first
  delivery runs 1:1-only (unresolved project, the D7 fail-open), the cursor now lands
  over what that leg delivered within the gate window instead of global MAX(id) —
  in-window project/broadcast mail survives for a later session whose project resolves.
  First reads with a resolved project keep the global landing, so the dropped overflow
  is still never revisited (R5, pinned by R1c).
- **pi delivers on the first turn (P4/D4).** The session-start delivery spawn is gone:
  mail is read and injected through `before_agent_start` (result message) and the
  per-turn `context` event (appended to the message array) — consumption and injection
  coincide, and a session that never turns consumes nothing.
- **Hermes delivers on the first turn (P5/D4).** The session-start stash
  (`_bus_pending`) is dropped: the FIRST `pre_llm_call` reads mail, advances the cursor
  and injects through the return channel in one transaction; turn 2+ are live-read
  only. `on_session_end` keeps cursor deletion; the drift notice keeps
  `on_session_start`.
- **The send CLI derives the harness session id (P9/R9).** The env leg now reads one
  var per registered session source (`CLAUDE_CODE_SESSION_ID`, `PI_SESSION_ID`,
  `HERMES_SESSION_ID`, first-set-wins) instead of claude's alone — an agent under pi
  or Hermes no longer records the task-tracked id as its sender, so its own broadcast
  cannot re-deliver to it across the id-drift shape (the live 0.157.0 incident).
- **The test hold needs arming (P3/D3).** `AI_BADGER_TEST_HOLD` parks a delivery only
  when `AI_BADGER_TEST_HOLD_ARMED` is also set; a hold value leaked into an
  unconfigured environment is inert instead of a deadlock. The in-process hold registry
  is unchanged, and the exactly-once race test arms the hold explicitly.

## Consumer impact

- Sessions that received a gated 1:1-only first delivery may now also receive
  project/broadcast mail sent before that first delivery but after the gate window
  opened — previously silently dropped.
- pi and Hermes sessions see mail from their first turn; there is no separate
  session-start delivery injection anymore. A session that never reaches a turn
  consumes nothing, so its mail survives for a later session.
- Agents running under pi or Hermes with explicit `--sender-session` are unaffected;
  derived sends now record the harness id the consumer will carry.
