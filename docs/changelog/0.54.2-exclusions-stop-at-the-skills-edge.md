# 0.54.2 — a skill's exclusions stop at the skill's edge

Follow-up to [0.53.2](0.53.2-dir-entry-hashes-what-it-owns.md) / [#224](https://github.com/Arasz/ai-badger/issues/224),
which taught `detect_additions.py` to skip OS droppings when scanning managed
directories. It reached for the exclusion list that was already there —
`SKILL_EXCLUDE_PATTERNS` — and that list is wider than the job.

## What was wrong

`SKILL_EXCLUDE_PATTERNS` mixes two kinds of name:

```python
["tests", "test_*.py", "*_test.py", "evals", "__pycache__", "*.pyc", ".DS_Store"]
```

`__pycache__`, `*.pyc` and `.DS_Store` are artefacts — nobody wrote them and
nobody wants them contributed, wherever they turn up. `tests` and `evals` are
*skill-authoring conventions*: they mean "not shipped" only because that is how a
skill directory is laid out. Anywhere else they are ordinary words.

`excluded_by_patterns` matches any **path segment**, so applying the whole list
to every managed directory meant a project file under a directory that happened
to be named `evals` was dropped without a word:

```console
$ ls .ai-badger/instructions/evals/
custom.md            # a project's own instruction file

$ feed-badger        # ...offers nothing to contribute
```

The file was not reported as a candidate and not reported as skipped. It was
simply absent, and the only clue was a name collision with a convention that
belongs to a different tree.

A second, narrower case: `dir_content_hash(exclude_rel=...)` skipped the excluded
*files* but still counted the directories that exist only to hold them. When an
adjustment writes into a directory chain the source skill does not have,
`dir_count` differed by construction — the same shape of false "locally
modified" verdict #224 was about, arriving by a different route.

## What changed

The two kinds of name are now separate constants, and the wide one is defined in
terms of the narrow one so they cannot drift apart:

```python
ARTEFACT_EXCLUDE_PATTERNS = ["__pycache__", "*.pyc", ".DS_Store"]
SKILL_EXCLUDE_PATTERNS = ["tests", "test_*.py", "*_test.py",
                          "evals"] + ARTEFACT_EXCLUDE_PATTERNS
```

- `detect_additions.py` scans managed directories with
  `ARTEFACT_EXCLUDE_PATTERNS`, except `.ai-badger/skills/` — that *is* a skill
  tree, so it keeps the full list. Nothing else applies the authoring
  conventions.
- A degenerate `exclude_rel` naming the directory itself (`""` or `"."`) is
  ignored rather than honoured. Every path descends from it, so honouring it
  reduced the whole fingerprint to the hash of nothing.
- `dir_content_hash` no longer counts a directory that is an ancestor of an
  excluded path and holds no file this entry owns. A directory containing both
  an excluded file *and* an owned one still counts, so a real new directory in a
  skill is still structural drift.

## Behaviour changes worth knowing

`feed-badger` will now offer project files under a `tests/` or `evals/`
directory **outside** a skill tree as contribution candidates. They were being
hidden; if your project keeps such a directory under `.ai-badger/instructions/`,
expect it to appear in the next scan. Files inside skill directories are
unchanged.

## No re-scaffold required

No manifest format change. Already-scaffolded projects get the corrected verdict
from the new code against their existing manifests.
