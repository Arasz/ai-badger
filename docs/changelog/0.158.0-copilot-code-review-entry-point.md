# 0.158.0 — code-review: the Copilot review entry point

## What changed

- **The github stack ships a `code-review` skill** — the review entry point GitHub Copilot
  code review loads from `.github/skills/`. GitHub's docs say Copilot is more likely to use
  skills whose directory name and description target review, and that it reads skills from the
  head branch; this skill is that entry point, with both facts encoded (review-focused name and
  description; gotchas about head-branch semantics and comment-only verdicts).
- **It routes; it does not review.** The body is an ordered route — rank by blast radius
  (`review-changes`), run the pass/fail gates (`code-review-checklist`), judge changed tests
  (`review-tests`), name the missing coverage (`design-tests`), stretch to a whole-project review
  only when asked (`complete-project-scope-code-review`) — with an inline baseline when an
  opt-in sibling was not delivered. Tests pin that every routed name resolves to a catalog skill,
  so an upstream rename breaks loudly instead of stranding the route.
- **Per-stack adjustments use the one extension mechanism** (ADR-0006): dotnet, react, ts,
  python and azure sections merge into the shipped body at scaffold time, each gated on its
  stack, each pointing at the stack-specific reference files the sibling skills carry. A
  project without a stack ships without its section, and the merged body is measured against
  the always-loaded budget at worst case (all five stacks).
- **Delivery is stack-local discovery** (ADR-0010): a project with the github stack configured
  gets the skill unasked, and the copilot adjustment symlinks it into `.github/skills/`. A repo
  hosted on GitHub without Actions workflows adds `"github"` to `config.stacks` to opt in.
- **The dotnet-workload observability reference is retagged** `code-review` → `review`: the old
  topical tag now names a shipped skill owned by the github stack, which made the cross-stack
  reference check correctly refuse a dotnet file "pointing" at it.

## Why a router and not more review content

The catalog already carries the review depth; a second checklist would drift from the first.
The entry point exists because Copilot needs one review-focused file to load and the project
needs a place where its stack adjustments decide which depth applies — both are routing jobs.

## Tests

`tests/test_code_review_router_skill.py` (9): routed names resolve to catalog skills; routed
siblings declare a readable scope so the fallback promise is decidable; extension `requires`
name stacks the catalog knows (a typo'd requires ships nothing and says nothing); github-stack
delivery without an explicit include; the `.github/skills/` discovery symlink; sentinel/marker
hygiene after the merge; stack sections arrive with their stack and never without it; the merged
body stays inside the lint budgets.
