# 0.169.0 — the whole catalog ships by default

**Minor** (scaffold-affecting) · 2026-09-11

Every common-stack skill is now `scope: default`
([ADR-0028](../adr/0028-all-catalog-skills-ship-by-default.md)). The 20 formerly-optIn skills —
the `documentation` gateway, the navigation trio (`review-changes`, `debug-issue`,
`refactor-safely`) and the 15 fed-back workflow skills, including the sqlite pair — arrive with
every scaffold, ship in the plugin copy, and are delivered by `den-refresh`. Projects no longer
maintain a `config.include.skills` list to receive the framework's current best practice.

## Changes

- `scope: optIn` → `scope: default` in 23 `SKILL.md` files: the 20 catalog skills and the three
  `documentation` gateway members (never catalog items of their own, ADR-0021).
- `docs/skills.md`: the at-a-glance `Ships` column and the opening counts now read
  **46 `default` / 0 `optIn`**.
- The opt-in mechanism is unchanged and stays ready for a future skill: `config.include.skills`,
  the `availableOptIn` section in every report, and the inclusion notes all still work. Today the
  tier is empty.

## Upgrade notes

- **A refresh delivers the whole catalog.** To decline a skill, add its name to
  `config.exclude.skills`; an excluded skill is not delivered and the discovery links ai-badger
  placed for it are removed. The `.ai-badger/skills/<name>/` copy already on disk is left alone.
- A project already running `code-review-graph` receives ai-badger's `review-changes`,
  `debug-issue` and `refactor-safely` copies on the next refresh — the contention their `optIn`
  was meant to avoid. Exclude any that would conflict.
- Re-scaffold is recommended, not required: nothing existing breaks, and the new skills arrive on
  the next `den-refresh` or `welcome-ai-badger` run.
