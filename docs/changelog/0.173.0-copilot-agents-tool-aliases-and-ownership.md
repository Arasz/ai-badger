# 0.173.0 — Copilot agents: documented tool aliases and ownership

**Minor** — `features/copilot/adjustments/adjust_agents.py` (P09). 2026-09-24.

## What was wrong

- `PERSONA_MAP` wrote Copilot custom-agent `tools` values (`list_files`, `get_diff`,
  `run_command`) that are not Copilot's documented aliases. Copilot ignores unrecognised
  names, so the generated `test-engineer.agent.md` ended up with neither `edit` nor
  `execute` (L7-8).
- The adjuster overwrote `.github/agents/<name>.agent.md` with no ownership check,
  unlike the Claude and pi arms, which both refuse to touch a file ai-badger did not
  place (L7-6).

## What changed

- `PERSONA_MAP` now uses Copilot's documented aliases (`read`, `edit`, `search`,
  `execute`, `agent`, `web`, `todo`). `architect` and `code-reviewer` stay read-only
  (`read`, `search`); `test-engineer` gets `edit` and `execute` (owner ruling D7).
- The adjuster now mirrors the `_ours` ownership check the Claude and pi arms use: a
  target is ours to (re)write only when the prior manifest recorded it, or the file on
  disk still carries ai-badger's managed-file header. A collision with a hand-authored
  `.agent.md` is left untouched and reported in `notes`, never overwritten.
- Delivered agent files now carry the same managed-file header the Claude and pi arms
  write, so the header check has something to find on a fresh delivery.
