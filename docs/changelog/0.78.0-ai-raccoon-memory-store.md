# 0.78.0 — AiRaccoon becomes an optional common memory server

ai-badger now recognizes AiRaccoon (`arasz.ai-raccoon`) as a common MCP server and emits its
zero-arg `ai-raccoon` stdio configuration when the tool is on PATH. Projects without it keep
their existing MCP configuration unchanged, and stale entries are removed on a later scaffold
without touching other or user-authored servers.

- `features/common/mcp/ai-raccoon/` catalogs the server: meta, instructions, and the 19
  memory tools (`memory_search`, `memory_write`, `memory_share`, workspace and watch tools)
  with curated intents and closed-vocabulary tags.
- `features/common/stack-mcp.json` declares it with conditional availability — the same
  mechanism Hermes already used.
- `features/common/skills/ai-raccoon-memory/` ships a memory skill: watch-on-docs ritual
  first, search-first workflow, escalation by result, write discipline, and verified
  pitfalls (no `path` param, never pass `context`, `memory_embed_pending` without `limit`,
  `memory_delete_context` needs full access mode).

**What a consumer must know:** install the server with
`dotnet tool install -g arasz.ai-raccoon` to get the declared MCP entry. The skill watches
your docs directory on session start; old tool builds without watch tools need
`dotnet tool update -g arasz.ai-raccoon`.
