# 0.137.0 — consolidate-stack-skills: two gateway skills replace fourteen registrations

Date: 2026-08-24. Task: consolidate-stack-skills (plan.md Revision 2). ADR: [ADR-0021](../adr/0021-gateway-skills.md).

## What changed

### Gateway skills ([ADR-0021](../adr/0021-gateway-skills.md))

A **gateway** is a level-1 skill directory carrying `manifest.json` (`kind: "gateway"`). Its
members live under `<gateway>/references/<member>/` — one nesting level below registration,
where no agent looks — and the manifest is the only declaration they exist. Fourteen
specialized skills consolidated into two gateways:

- **`dotnet-workload`** absorbs the eleven dotnet stack skills (bdd-testing, domain-modeling,
  flaky-test-diagnosis, hosted-service-review, hosted-service-testing, logger-message-design,
  mcp-server, sqlcipher-encryption, system-commandline, tool-publishing,
  observability-contract-review).
- **`documentation`** keeps its name and absorbs scaffold-/update-/migrate-documentation; their
  ledger extension fragments travel inside their member dirs and stay config-gated.

The win is on registration/discovery surfaces, not body loading — bodies were already lazy.
A dotnet-stack scaffold advertises one skill description where it advertised eleven (~1.2–2k
tokens off every consuming agent's discovery context, an estimate), and member bodies now load
only after the gateway routes to one.

### skills_lint rule 13

Gateway manifests are validated from disk: parseable JSON with `kind`, non-empty members whose
`paths.skill` exists and matches its directory name, unique names, orphan detection for any
directory under `references/` no member claims — and a member's `purpose` must equal that
member's own frontmatter `description:` byte for byte. The gateway's own SKILL.md stays under
rules 1–12; there is no gateway exemption.

### Derived aliasing replaces SKILL_GROUPS["documentation"]

`badger_lib.gateway_aliases(root)` walks `features/*/skills/*/manifest.json`; a config naming a
skill a gateway absorbed resolves to the gateway on both include and exclude, and the scaffold
report says so (`included 'update-documentation' — resolved to gateway 'documentation'`). An
ambiguous member name claimed by two gateways raises rather than resolving silently.
`SKILL_GROUPS` now holds only `testing`. This repo's own `.ai-badger/config.json` still names
the three old documentation skill names and delivers the gateway through exactly this path.

### Numbers

Catalog page scope 43 → 41; common level-1 42 → 40; default 20 unchanged; optIn 22 → 20;
total catalog SKILL.md files 58 → 46. index.json: common lists 40, dotnet lists 1.

## What a consumer project sees on next `den-refresh`

Configs naming any absorbed member keep working — the alias map resolves them to the gateway.
The refresh reports the moved skills as drift and offers the new config; accepting it is
optional. Nothing breaks silently.

## Tests

New `tests/test_skills_lint_gateways.py`: manifest validity, ghost paths, orphan members,
name/directory agreement, purpose byte-equality, gateway fully linted (T5),
`gateway_aliases` unit tests including the loud-ambiguity case (T12), alias-aware inclusion
notes (R4), alias-aware exclusions (R5), member extension merge/prune end-to-end (R3).
Rewritten: `test_skill_groups.py` (gateway semantics + ported sibling-citation scan over the
documentation member tree), `test_skill_scope_declarations.py`, `test_config_include.py`
(canonical optIn skill → `documentation`), `test_stack_skill_discovery.py` (canonical
stack-local skill → `dotnet-workload`), `test_catalog_has_no_harvest_artifacts.py` (harvest
sample paths + gateway-aware orphan scan). `validate.py` exempts gateway manifests from schema
coverage because rule 13 is their validator; member extension descriptors validate through the
existing skill-extension schema at their new depth.

Accepted prose drift: historical changelog entries and `docs/work/` records keep the old flat
paths; they describe those releases as shipped.
