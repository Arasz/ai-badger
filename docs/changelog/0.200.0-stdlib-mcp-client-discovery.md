# 0.200.0 — `mcp-index --discover` asks servers for their tools without hermes

**Minor** (feature) · **Date:** 2026-10-18

- **`--discover` no longer needs hermes.** `mcp_index.py init|update --discover` now asks each
  server the listing left unenumerated for its own tools with a stdlib-only MCP client
  (`features/common/skills/mcp-index/scripts/mcp_client.py`): stdio and unauthenticated streamable
  HTTP, initialize → `notifications/initialized` → every `tools/list` page, under one deadline per
  server. Servers are asked in parallel (up to 8); `--discover-timeout N` sets the per-server
  deadline (default 20s). Before this, with hermes absent, every server `claude mcp list` named
  stayed `tools: {}`.
- **Server configs come from Claude Code's own files** (`scripts/server_configs.py`): local scope
  and user scope in `~/.claude.json`, the project `.mcp.json` (only servers approved through
  `enabledMcpjsonServers` or `enableAllProjectMcpServers` and not in `disabledMcpjsonServers`,
  read from `~/.claude.json` and the `.claude/settings*.json` files), and installed plugins' `.mcp.json` or
  `plugin.json` for `plugin:<p>:<s>` names, with `${CLAUDE_PLUGIN_ROOT}` expanded.
- **`--discover` runs each configured server command**, as `claude mcp list` does. One stderr line
  per server names the outcome: `enumerated N tool(s)`, `no config`, `needs authorization`,
  `timed out`, `failed: <reason>`, `not run: pending approval in Claude Code`.
- **Still unenumerated, and named:** `claude.ai <Name>` OAuth connectors, OAuth-only servers, legacy
  `sse` servers, managed enterprise config. They keep the catalog seed. A server with no config
  still falls back to `hermes mcp test` when hermes is installed.
- **An enumerated server is the whole truth.** Its tools replace the catalog seed, so a seeded tool
  it does not list is marked `status: removed` on `update` (curation kept), and a failing
  `claude mcp list` phrase for it is dropped so its status reads `ok`. A server that fails on any
  page is left exactly as the listing had it.
- **A server's own tool description now always fits `intent`.** Heuristic intents are collapsed to
  one line and cut at a word to the schema's 200 characters; one under 10 becomes the usual TODO.
  Real servers describe tools in 300-700 characters, and the first live `--discover` run had its
  whole write refused by schema validation.
- **Host CLIs run in `--target`.** `claude mcp list`, `hermes mcp list` and `hermes mcp test` ran
  in the caller's directory and listed that project's servers; once `--discover` made a listing
  carry tool detail, `update` run from elsewhere marked the target's real servers `absent`.
- **Enumeration never makes an unnamed source `absent`.** Whether a source the listing omits is
  gone is decided from the listing's own tool detail, before `--discover` runs: only
  `hermes mcp list --json` / `--from-json` listings carry it. `claude mcp list` plus `--discover`
  updates the servers it names and leaves every other source untouched.
- **Hardening.** A stdio server runs in its own process group and the group is killed after the
  call, so `npx`/`uvx` grandchildren do not survive; the exit wait never runs past the deadline.
  Streamable HTTP answers server requests sent on the SSE stream (`ping` → `{}`, others -32601),
  skips non-JSON events and reads a final event with no trailing blank line. One message over
  16 MiB is `failed: response too large`, and any unexpected client exception fails that server
  only instead of aborting `--discover`.
