# 0.199.0 — the /task skill no longer probes for usage limits

**Minor** (feature removal) · **Date:** 2026-10-18

- **`poll_limit.py` is gone.** SessionStart no longer launches a background poller. Each of its
  probes ran `claude -p "Reply with exactly: ok" --model claude-haiku-4-5-20251001` as a full
  session in the project directory, so every probe paid for CLAUDE.md, hooks and MCP context:
  measured from the owner's Claude Code transcripts on 2026-10-18, 494 probes cost about 14.0M
  cache-write and 38.5M cache-read tokens.
- **`resume_cron.py` no longer probes before resuming.** Stalled tasks (not finished, session
  process gone, transcript quiet) are resumed directly. If the limit is still in force the resume
  fails and `RETRY_COOLDOWN_MINUTES` bounds the next attempt. `install-cron`, `uninstall-cron`
  and `start --cron` are unchanged.
- **`tracker_lib.spawn_detached` and the test-suite detached-child reaper are removed.** The
  poller was their only production caller.
- **Upgrading.** Re-scaffold to drop `poll_limit.py` from `.ai-badger/`. Pollers already running
  keep going until they exit (at most 12 hours); stop them with `pkill -f poll_limit.py`. Leftover `poll_limit.pid` and `poll_limit.log`
  in `.ai-badger/task-tracking/` can be deleted.
