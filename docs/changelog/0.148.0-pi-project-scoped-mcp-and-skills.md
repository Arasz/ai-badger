# 0.148.0 — pi discovery is project-scoped: the fork reads `.mcp.json`, the adapter serves project skills, the scaffold stops writing global state

pi sessions now discover exactly the MCP servers and skills the project scaffold declares —
the same server set Claude Code gets, project-scoped, with no cross-project accumulation in
`~/.pi/agent/settings.json`. The pi-mcp-tools fork reads the project's scaffold-managed
`.mcp.json` directly at `session_start` (project-over-global merge, gated by pi project
trust), the vendored adapter contributes `<cwd>/.ai-badger/skills` via `resources_discover`
(ungated — ADR-0023's recorded asymmetry), and the scaffold's pi adjustments become
migration-only removers that clean up their own previously-written global entries.
ADR-0023 records the decision; the owner gate approved all five design decisions.

## What changed

- **Fork (`Arasz/pi-mcp-tools`):** new claude-format converter (`claudeMcpConfig.ts`) —
  `type:"stdio"`/absent → local, `${HOME}` prefixes expanded (the scaffold emits them),
  other `${VAR}` skip with a warning, `tools:["*"]`/empty/absent → no filtering (the
  pass-through to `filterPatterns` would have thrown `RegExp("*")` per tool and killed
  every tool of every scaffolded server), glob-ish patterns anchored to regex, every
  `RegExp` try/caught fail-open per-pattern, `http`/`sse` → `remote` (transports already
  shipped), unparseable file ⇒ global-only fallback. Config load moved from
  extension-init to `session_start` (where `ctx.isProjectTrusted()` exists), wrapped
  defensively — a converter error degrades to global-only, never a headless `exit(1)`.
  A merge ledger records per-server source (`project:.mcp.json` / `global settings` /
  `skipped:…` / `untrusted-project`) and is reported by `mcp_list_servers` (a tool — the
  headless-visible channel; extension commands throw when queued) and `/mcp-status`.
  `saveDisabledTools` is now atomic (unique temp + rename).
- **Adapter:** ungated `resources_discover` handler contributes the project's skills path
  (source-verified honored in all modes including headless; live-probed both directions).
- **Scaffold adjustments (`adjust_mcp.py`/`adjust_skills.py`):** migration-only. Removal is
  shape-aware (regenerate-from-declaration + deep-equal, command shlex-split-or-literal —
  name-keyed removal would destroy user edits: all scaffolded projects share the same five
  server names) and gated on capability marker files in the installed extensions
  (`.ai-badger-capability-project-scope-mcp`, `.ai-badger-capability-resources-discover`) —
  never version numbers, per-extension so a pre-adapter machine never loses its only skills
  route. Marker absent ⇒ skip-with-warning. `--no-install` prints the removal proposal.
  `pi_settings.py` gains `remove_mcp_servers`/`remove_skills_path` under the existing
  atomic/idempotent/unknown-key-preserving contract.
- **support.json pi rows:** `mcpServers` now states the fork-reads-`.mcp.json` mechanism
  with the measured trust sentence (scaffolded projects without pi-trust-requiring
  resources arm **in all modes** — pi's short-circuit, verified in dist source), local
  stdio **and** remote `http`/`sse`; `skills` names `resources_discover`, ungated.
  A new honesty test pins the rows by JSON path; the old "the scaffold merges into
  settings.json" claim is a must-not-contain phrase.
- **New precondition pin:** the scaffold writes no pi-trust-requiring resource into a
  project's `.pi/` (personas only) — the guard that keeps "minimal project arms headless"
  true by construction goes red the day the fragile case becomes the common case.

## Discovered en route (operational)

- **The plan's original trust premise was false.** Rev 1 said "headless arms nothing until
  `/trust`"; pi actually short-circuits trust to `true` for projects without
  trust-requiring resources — scaffolded projects arm headless day one. Two lanes caught it
  independently in dist source; tests now pin **both** directions (minimal project arms; a
  project with `.pi/settings.json` and no saved decision stays global-only headless).
- **The "latent `/new` bug" was also false** — pi re-invokes the extension factory per
  session replacement, so per-session Maps made the planned duplicate-registration guard
  unnecessary. The restructure is still required: config load needs `ctx`, and a factory
  throw exits headless pi, so init is defensive.
- **The claimed existing byte-identity gate did not exist** (`test_framework_copies.py` is
  the #109 cleanup module) — repo A gained a real fork↔canonical parity test (loud-skip
  when the fork checkout is absent).
- **`.mcp.json` is gitignored** — every repo-side test builds its own fixture project; no
  test may read a checkout's live file.
- Extension capability markers are dotfiles shipped through the publish flow's recursive
  walk (readdirSync is dotfile-safe; the walk's node_modules exemption is the only filter).
