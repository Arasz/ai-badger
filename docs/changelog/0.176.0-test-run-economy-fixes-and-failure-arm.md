# 0.176.0 — test-run economy: real persistence, real classification, counted failures

**Minor** — `test-economy/scripts/suite_economy.py`, `suite_economy_hook.py`, and a new
`test-run-economy-failure` manifest entry (D13 = A). 2026-09-24.

## What was wrong

- `open_store()` built its own inline family with `legacy_path=lambda: None` — a callable
  *returning* None, not an absent one. `_check_resurrections` calls `family.legacy_path()`
  unconditionally when `legacy_path` is not None, so every store open crashed on
  `None.exists()`. The test-economy state was never saved and the budget nudge never fired
  (L2-1, caller half).
- `is_test_run` compared `argv[0]` exactly against bare launcher names, so this repo's own
  mandated `.venv/bin/python3 -m pytest` (the venv-python invariant) was never recognised as
  a test run at all. `_pytest_kind` treated any non-dash token as a selector, so an option's
  own value (`--tb short`, `-n 4`, `-p no:cacheprovider`) or trailing shell syntax
  (`| tail -5`, `; echo done`) silently downgraded a full-suite run to "filtered" — the
  opposite of the module's own "err toward full" policy (L4-7).
- The hook's per-session counter went through two separate store round trips — `get_entry`,
  then `advance_session`, then `set_entry` — so two concurrent invocations on the same
  project raced the read-write gap and one increment was lost. Eviction at the session cap
  used dict insertion order, dropping whichever session had been running longest instead of
  whichever had gone quiet (L4-8, test-economy half).
- Claude's `PostToolUse` "Runs immediately after a tool completes successfully" (hooks.md):
  it never fires for a failing Bash call, so a failing full-suite run — the run most worth
  nudging on — was never counted on Claude at all.

## What changed

- `open_store()` now calls `badger_store.open_user()` with no override: `test_economy` is
  already registered in `USER_FAMILIES`, born in SQLite with `legacy_path=None`.
- `is_test_run` matches the launcher's basename (`PurePosixPath(argv[0]).name`), not its raw
  `argv[0]`, so a path-qualified launcher counts the same as a bare one. `_pytest_kind` now
  skips a known flag's separate value token and stops scanning at a shell metacharacter
  (`|`, `;`, `&&`, `>`), even one glued onto the previous token with no space (`-q;`).
- The hook's read-modify-write now goes through a new `suite_economy.update_entry`, built on
  the store's existing `kv_update`: the read, the advance, and the write run inside one
  transaction, so a concurrent call blocks on the write lock and sees this call's result
  first. `new_session_entry` gains a `last_seen` timestamp, stamped on every advance;
  eviction at the session cap now drops the session with the oldest `last_seen`, never
  whichever joined the dict first.
- The hook echoes back whatever `hook_event_name` it was actually called with (defaulting to
  `PostToolUse` when absent, matching every existing caller) instead of hard-coding
  `"PostToolUse"`.
- A new manifest entry, `test-run-economy-failure` (claude arm only, `PostToolUseFailure`),
  sits beside the existing `test-run-economy` entry, whose `PostToolUse` arm (and its
  hermes/copilot arms) are untouched. pi reads the generated `.ai-badger/hooks/hooks.json`,
  whose `PostToolUse` group still lists `suite_economy_hook.py`, unmoved.
- `tooling/validate.py`'s `HOOKS_MANIFEST_AGENT_EXEMPTIONS` records why
  `test-run-economy-failure` names no `hermes`/`copilot` arm: both already count every
  observed run, pass or fail, through the sibling `test-run-economy` entry's single
  post-tool hook.
