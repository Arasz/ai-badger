# 0.194.0: rtk ships as the first `tools` feature

**Minor** (additive) · **Date:** 2026-10-17

[rtk](https://github.com/rtk-ai/rtk) compresses shell command output before it reaches the model.
ai-badger now ships it as a catalog tool, the first member of a new `tools` feature type for
command-line tools that are not MCP servers. ADR 0039 records the design.

- New feature type `tools` (registry, index, manifest, `schemas/tool.schema.json`) and the catalog
  entry `features/common/tools/rtk/`: `meta.json`, a `tool.md` usage note, `check.py` (rtk 1.0.1 or
  later, and rejects the unrelated crates.io `rtk`) and `install.py` (prints the BUSL-1.1 licence
  note and the Apache-2.0 `rtk-oss` alternative first; never pipes a download into `sh`).
- A project opts in with `"tools": {"rtk": {"hooks": [...]}}` in `.ai-badger/config.json`. Without
  that key nothing changes. The scaffold prints the check and install commands, and runs them only
  under `--execute`, before the per-agent adjustments.
- Hook commands are guarded: a missing rtk, a failing rtk, or output that is not JSON leaves the
  command untouched, and every entry carries an `AI_BADGER_TOOL=rtk` marker so removal is exact.
- The safety guards now see through rtk. `shell_parser` treats `rtk` and its run-anything
  subcommands (`err`, `test`, `summary`, `run`, `bypass`, `proxy`) as wrappers, so
  `rtk err git push --force` gets the same verdict as `git push --force`, and away mode no longer
  auto-approves `rtk run -c '...'`. The memory-first gate and test economy recognise `rtk grep` and
  `rtk pytest`.

Per-agent hook wiring (Claude, Codex, Copilot, pi, Hermes) lands in later commits of this release.
