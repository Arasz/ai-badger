# 0.135.2 — Prompt rules phase 2: hooks and validation scripts

**Patch** — automation for remaining prompt-engineering rules from the research-based framework.

## What changed

- **Consolidated restart detection** (Rule 2B/2C): the `user_prompt_hook.py` now counts consecutive `f:` feedback markers in marker-state.json and injects a restart advisory after 2+ consecutive feedback turns.
- **Grounded feedback hook** (Rule 3C): new PostToolUse hook (`grounded_feedback_hook.py`) captures Bash/terminal failure output and injects it as evidence for the next correction turn. Wired for Claude, Copilot, and Hermes.
- **Reasoning scaffolding linter** (Rule 6B): standalone script (`reasoning_scaffold_lint.py`) scans instruction files for CoT anti-patterns like "think step by step" and "analyze this carefully".
- **Constraint count validator** (Rule 8B): standalone script (`constraint_count_lint.py`) counts invariants under the "Non-negotiable invariants" section and warns when the count exceeds a threshold (default 35).
- Trimmed task SKILL.md preflight/operator sections to fit the 5000-char body limit.
- Fixed model.json `mustAppearIn` paths for copilot-instructions.md.

## Why

The first phase (0.135.1) added the invariant rules as documentation. This phase adds the automation layer: hooks that enforce the rules at runtime and validation scripts that catch drift at CI time.

## Upgrade notes

No configuration changes required. The new hooks are auto-wired by the scaffold. The validation scripts can be run manually or added to CI:
- `python3 .ai-badger/skills/maintain-agent-instructions/scripts/reasoning_scaffold_lint.py <file-or-dir>`
- `python3 .ai-badger/skills/maintain-agent-instructions/scripts/constraint_count_lint.py <file> [--threshold N]`
