# 0.35.4 — the behaviorist stops inventing failures

Running `call-behaviorist analyze` against this repository returned **`degraded`** with 13
findings, 6 of them `high`. Checking each one against the actual files, **none described a
broken hook**. Seven were manufactured by the analyzer itself.

A health tool that cries wolf is worse than no health tool: `never_observed` is the finding
the skill exists to produce, so a false one spends the credibility of every true one.

## What was wrong

### A hook was named by its filename, not by what it logs

`_matches` derived the expected component name from the script's filename stem —
`user_prompt_hook` for `prompt-markers/scripts/user_prompt_hook.py`. But that script logs
under `COMPONENT = "prompt_markers_hook"`. The two never compared equal, so a hook that had
run **66 times in 20 hours, firing 12 times**, was reported as `never_observed` — "it may
never load or never fire" — *and*, from the same run, as an `unexpected_component`. The pair
is self-contradicting: one run cannot be both absent and unrecognised.

`analyze` now reads each wired script's `COMPONENT = "…"` declaration and matches on that,
falling back to the filename stem when a script declares nothing. Expected components are
still *named* by their project-relative path, so two skills shipping a `user_prompt_hook.py`
stay distinct — that property was the reason for path-naming and it is unchanged.

### `unknown` was counted as a version

`framework_version()` returns the string `unknown` when it finds no VERSION file above the
code that ran. `_observed` collected it like any other version, so `len(versions) > 1` fired
and produced `version_skew` — *"copies disagree (plugin cache vs .ai-badger/ scaffold)"* —
on five components at once. Every copy involved was in fact `0.35.2`.

The sentinel is now excluded from the skew comparison. It still appears in `observed`, because
suppressing the finding must not amount to hiding the evidence.

### A scaffold could not name its own version

The sentinel was reachable at all because a scaffold ships no `VERSION` file. `.ai-badger/`
does record `frameworkVersion` in `manifest.json`, so `framework_version()` now consults it,
nearest-ancestor-first.

Ordering matters: the manifest sits *below* a host repository's own root, so a scaffolded
project that versions itself can never have its number mistaken for ai-badger's. A source
checkout, which has no manifest above it, still reads its `VERSION` exactly as before.

### Records did not say where they came from

`log_event` only records a project when the caller passes one, and `session_start_hook` and
`user_prompt_hook` never did. **364 of 626 records in the observed window were unattributed**,
and `_read_records` admits an unattributed record into *every* project's analysis. That is how
`unknown`-version records belonging to another repository ended up producing skew findings
against this one.

All three scaffolded hooks now attribute every record, via a shared
`debug_log.resolve_project_root(payload)` — `$CLAUDE_PROJECT_DIR` first, then the payload's
own `cwd`, then `None`, never a guess. `commit_reminder_hook` keeps its own copy of that
resolution: its core behaviour depends on it, and it must not stop working because an
optional debug import failed.

This also repairs `behaviorist on --project`, which could not scope to hooks that never said
which project they were running in.

## Verifying

`analyze` against this repository now reports the three wired hooks as observed and healthy.
The findings that remain are the honest ones: plugin-side components this project does not
wire, correctly classified `low`.

Tests: 1383 passing. New coverage names the defects directly —
`TestAHookIsNamedByWhatItLogs`, `TestAnUnknownVersionIsNotADisagreement`,
`TestAScaffoldedProjectKnowsItsVersion`, `TestARecordSaysWhichProjectItCameFrom`,
`TestEveryScaffoldedHookAttributesItsRecords` — each with a guard that the fix does not
overshoot: a genuinely silent hook is still `never_observed`, two real versions are still
skew, and a host repo's `VERSION` still cannot masquerade as the framework's.
