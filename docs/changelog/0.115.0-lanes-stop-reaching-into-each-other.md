# 0.115.0 — lanes stop reaching into each other

Two `PreToolUse` hooks, contributed from a project that runs several agent sessions across
several worktrees of one repo, plus the probe gate that proves them.

The incident behind them is small and expensive. An agent was told "kill any build you have
running" and ran `pkill -f "dotnet build"` — an unscoped pattern match that killed **another
session's** in-flight compile. The lost build was the cheap part: the other agent saw a failure
it had not caused and nearly "fixed" correct code to chase it.

## blast-radius-kill-guard

`PreToolUse` on `Bash`. Denies an unscoped process kill — `pkill`, `killall*`, or a `kill`
whose targets are not numeric PIDs or job specs — and shared-resource reaps, **while more than
one agent lane is plausibly live**. One lane live, or a count it cannot determine: allowed. It
is a guard against blast radius, not against killing things.

Re-issuing the *same* command opens an escape valve for it alone after three denials, counted
per (session, exact command) under `~/.ai-badger/blast-radius-guard/` with a one-day TTL. A
denial that cannot be argued with is a denial agents learn to route around.

Command parsing is a `shlex` lexer, not a substring match: segments split on shell operators,
the command word is found past env assignments, `sudo`, `env` and any absolute path, and
`sh|bash|zsh -c <string>` recurses — including the combined spellings `-lc`, `-cx`, `-ec` that
an exact `"-c"` test lets through.

### The stack-specific half is a table

The kill logic is stack-agnostic. The parts that are not — reaping a shared build server,
deleting a shared package cache — live in one `STACK_HAZARDS` table at the top of the file:
per stack, the `(program, words)` shapes that reap a shared service and the path fragments
whose recursive delete every lane feels. Seeded with dotnet, node, python and rust. Adding a
stack is adding a row; the lexer never learns a program name.

The table is a deliberate allowlist and says so — completeness is an explicit non-goal, because
an unlisted command is allowed through.

## cross-worktree-dirty-warning

`PreToolUse` on `Edit|Write|MultiEdit|NotebookEdit`. Warns, never blocks, when the file being
edited is also dirty in another worktree of the same repo — the quiet half of the same problem,
where two lanes edit one file and the second one's patch lands on content it never read.

The sweep (`git worktree list --porcelain`, then `git status --porcelain` per tree) is cached
**unfiltered** under `~/.ai-badger/dirty-sweep/` with a short TTL, so every lane on the machine
shares one sweep and each excludes itself at read time. It carries a global time budget (a
partial sweep beats blowing the hook timeout), writes the cache atomically, and validates the
cached shape on read — the text goes into a model's context, so a cache file is untrusted input.

Both hooks fail open on every error: a bad payload, a missing `git`, an unreadable cache, a
command that does not lex. Exit 0, say nothing, never block the call.

## The gate is the point

`verify_hooks.py` ships beside them: 84 probes, one command, non-zero exit on a defect. It
stubs lane liveness and worktree enumeration, so it is deterministic and touches no real
process.

It was put in front of the defect it exists to catch before it was believed. Narrowing the
shell recursion back to an exact `"-c" in args` match turns the three combined-flag probes
(`bash -lc`, `sh -ec`, `bash -cx`) red and the gate exits 1; restoring the lexer turns them
green again. `tests/test_cross_session_hooks.py` runs that mutation on a copy every suite run,
so the gate cannot quietly become a check that only ever passes.

The per-stack probes derive from `STACK_HAZARDS` itself — one DENY per row, and one *allow* per
row (`dotnet build`, `npm cache verify`, `pip install …`, `cargo build …`) so a row cannot
swallow the ordinary command it sits next to.

## Where they live

Under `features/common/skills/worktree-agent-isolation/scripts/`, the skill whose discipline
they enforce, following `generated_file_guard.py`, `memory_first_gate_hook.py` and
`dispatch_gate_hook.py`. That skill is `optIn`, so a project that never asked for parallel-lane
discipline gets neither hook, and declining it unwires both.

Registered in `features/common/hooks/hooks-manifest.json`, with their commands in
`hooks.json`. Both are Claude-only for now: `HOOKS_MANIFEST_AGENT_EXEMPTIONS` records why — a
wall for the kill guard (it counts live lanes from a Claude-specific per-process socket
directory, and Copilot's hook protocol has no block-with-reason channel), an honest
acknowledged gap for the warning, whose git sweep needs nothing Claude-specific.
