# 0.79.1 — catalog intents reworded for the retrieval instrument

A `mcp-index update` after an MCP server reload propagated the code-review-graph catalog into
the project index for the first time, and the retrieval instrument measured what that
propagation did: two false fires caused by incidental words in the curated intents. The
catalog entries were reworded so the curation survives and the instrument stays clean.

- **Two intents reworded in `features/common/mcp/code-review-graph/tools.json`:**
  - `get_impact_radius_tool`: "everything downstream that a change to it can reach" →
    "how far a change to it reaches". The word `everything` made the conversational turn
    "fix #165, its blocking everything else" fire a tool that must stay silent on it.
  - `query_graph_tool`: "imports or covering tests" → "imports and what covers it". The word
    `tests` made "generate unit tests for this class" fire — an adjacent-negative the hard
    fixture set pins as silence.
- **Measured, not guessed** (`tooling/retrieval_eval.py`, hard + observed fixture sets):
  hard recall@1 0.442 → 0.462 and recall@3 0.481 → 0.500, false-fire unchanged from baseline
  on all four fixture sets. This is the first wording of these intents validated against the
  instrument; the pre-catalog heuristic wording never was, and the raw catalog wording
  degraded it.
- **What a consumer must know:** a scaffold or den-refresh picks up the new intent wording for
  code-review-graph tools. The change is wording only — tool names, tags, and the tools
  schema are untouched.
