# 0.174.0 — pi adapter: bounded hook spawns, hook advice that persists, Claude's matcher rules

**Minor** (behavior change in the pi adapter) · 2026-09-24

## What changed

Six fixes to the pi hooks adapter, its installer and the pi trust probe.

**Hook spawns are bounded.** The 5 s gate and post-hook budget did not bound anything.
`spawn(..., {timeout})` killed only `/bin/sh`. The shipped `hooks.json` commands are
compound (`if [ -f ... ]; then python3 ...; fi`), so sh forks python, and python kept the
stdout and stderr pipes open until it finished on its own. Every hook now runs detached, in
its own process group. On timeout or abort the whole group gets `SIGKILL`. The spawn settles
on `close`, once every stream has drained, or on a 1 s grace timer after the group kill if
something outside the group still holds the pipes. It never settles on `exit`, because
output can still be in flight then. pi runs under Node, where the docs say exactly that.
`runGate(command, payload, {cwd, signal, timeoutMs})` is exported as the test seam. Post
hooks and the bus delivery script share the same spawn.

**Post hooks get a dict.** pi's `tool_result` carries `content` as an array of text and
image blocks. The adapter used to JSON-encode that array, so `tool_response` reached the
hooks as the string of a list. `memory_grade_hook` then parsed a list and gave up, and
`grounded_feedback_hook` refused anything that was not a dict. `tool_response` and
`response` are now the joined text blocks, parsed when they form a JSON object, and
`{"output": text}` otherwise.

**Hook advice reaches the model and the user.** The adapter used to drain post-hook stdout
unread, and it read only `permissionDecision` from gates. Commit-reminder, test-economy and
grounded-feedback `additionalContext` never reached the model, while the hooks' debounce and
escalation state still advanced. Post-hook `additionalContext` is now appended to the tool
result as one text block. pi persists that message, so the context stays on every later
LLM call. A `context`-event rewrite would have reached one request and vanished. A
`systemMessage` from a gate or a post hook, such as the cross-worktree dirty warning, is
now shown as a UI notice.

**Matchers follow Claude's documented rules.** `*`, `""` or a missing matcher match every
tool. A matcher made only of letters, digits, `_`, `-`, `,`, `|` and spaces is a list of
exact names. Anything else is an unanchored JavaScript regex. Before this, every matcher was
compiled as `^(?:...)$`, so `*` threw "Nothing to repeat" and its gate never ran on pi, and
`Edit, Write` matched nothing. The MCP-tail candidates stay, so pi's
`mcp_ai-raccoon_memory_search` still fires `memory_search` hooks. One version floor:
Claude Code before v2.1.195 treats a hyphenated matcher as a regex, not an exact name.

**The capability marker is installed.** The installer copied only `.ts` and `.json` files.
`.ai-badger-capability-resources-discover` has no suffix, so it never reached
`~/.pi/agent/extensions/ai-badger/`, and `adjust_skills` gates its settings migration on
exactly that file. The installer now copies every file in the adapter directory.

**The trust probe checks Run A's exit code.** `tooling/test_pi_hook_fires.py` printed Run A's
exit code and ignored it, so a pi that failed to start read as "project-local extension
blocked". pi 0.84.3 has no refusal exit code: in a headless run, `resolveProjectTrusted`
returns false and pi carries on without project resources (`dist/core/project-trust.js`).
Any non-zero Run A exit now fails the probe.

## Wiring

- `features/pi/adjustments/adapter/index.ts`: one `runHook` spawn for gates, post hooks and
  delivery; the exported `runGate`; `tool_result` returns the amended `content`.
- `features/pi/adjustments/adapter/hook-bridge.ts`: `toolResponse`, `parsePostStdout`,
  `withPostContext`, `systemMessage` on gate decisions and `resolvePost`'s `context`, and the
  new matcher rules in `commandsForTool`.
- `features/pi/adjustments/adjust_hooks.py`: installs every adapter file.
- `tooling/test_pi_hook_fires.py`: Run A fails on a non-zero exit.
- `features/pi/tests/hook-bridge.test.ts`: the matcher table takes its verdicts from
  `tests/hook_matcher_rules.py` (`claude_matches`), for the matchers the shipped hooks use,
  `*`, `""` and hyphenated names, in Claude and pi spellings. The payload, advice and
  context tests are new too.
- `features/pi/tests/adapter-entry.test.ts`: the timeout and abort seam tests (settle under
  2 s, grandchild gone), a 256 KiB decision, a writer that outlives the shell, and a real
  `AgentSession` run that finds the post-hook context in the persisted tool result.
- `tests/test_pi_adjustments.py`: the marker install, and the probe against a fake `pi`.

## Upgrade notes

- Refresh to pick up the adapter (`~/.pi/agent/extensions/ai-badger/`). No config change.
- Post-hook context now lands in pi transcripts, as it already did on Claude.
