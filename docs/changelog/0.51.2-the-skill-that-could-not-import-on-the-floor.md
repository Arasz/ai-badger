# 0.51.2 — the skill that could not import on the floor

`tool_descriptions.py` (new in 0.51.0, step 5 of the ADR-0014 rebuild) aliased its catalog type
as `Catalog = dict[str, dict[str, dict[str, Any]]]` — an *executed* expression, which
`from __future__ import annotations` does not defer. On Python 3.8, the version
`engine/requirements.txt` sets as the floor, subscripting builtin `dict` raises `TypeError`, so
the mcp-index skill could not be imported at all. Both 0.51.0 and 0.51.1 shipped this.

Local development runs Python 3.14 and never sees it; CI's 3.8 lane does, and had been red for
five consecutive pushes to main — while the pull-request checks stayed green, which is how five
merges sailed past it. The alias is now `typing.Dict`, and a new AST tripwire
(`tests/test_python_floor.py`) fails locally for any builtin-generic subscript in an executed
position in shipped code, so the floor breaks in a terminal before it breaks in CI.
