# 0.29.1 — the PR rule has a named exception

## What changed

The `pr-per-task` invariant said, without qualification:

> never push directly to the main/trunk branch

In practice a maintainer sometimes wants a change merged locally — the quality gates are the
real safety net, and a PR round-trip buys nothing when a rebase has already forced the branch
to be rebuilt twice. That happened repeatedly during the 0.27–0.29 series.

Doing it anyway would have left the invariant describing something nobody follows, which is the
exact drift this project spent 0.28.x eliminating. So the rule now states its exception instead
of being quietly broken.

## The exception, precisely

**Only an explicit instruction from the person you are working with lifts the PR requirement.**
An agent never grants itself the exception — not to save a step, not because the change looks
trivial, not because a rebase turned awkward. Absent that instruction the rule is absolute.

And it lifts the PR requirement *only*:

> The exception lifts the PR requirement and nothing else. Every gate still runs before the
> push: the PR was the record, not the safety net.

`CONTRIBUTING.md` carries the same amendment, aimed at contributors rather than agents.

## Why this is a patch, not a minor

Per `RELEASING.md`: minor is for anything that changes what scaffolding *does* to a consumer
repo. This changes the wording of an existing invariant file and nothing about scaffold output
shape, which is the definition of a patch.

## Upgrading

Re-scaffold to pick up the amended invariant in `CLAUDE.md`, `HERMES.md`, and
`copilot-instructions.md`. Nothing is removed and no behaviour changes; projects that never
re-scaffold keep the stricter wording, which remains correct — it is the default either way.
