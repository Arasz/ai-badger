# 0.51.0 — MCP rebuild step 7 of 8: the file Copilot actually reads, and the two hosts that only get a proposal

Step 7 of the [ADR-0014](../adr/0014-mcp-support-is-configuration-not-retrieval.md) rebuild.
Step 6 gave Claude an adjuster that approves and denies. This step finishes the other two hosts,
and it starts by admitting that one of the files ai-badger has been writing since 0.13.0 was
never read by anything.

## What shipped

### 1. `.github/copilot/mcp-config.json` was read by no Copilot surface

[#189](https://github.com/Arasz/ai-badger/issues/189). Copilot CLI reads a repo-committed
`.github/mcp.json` (and `.mcp.json`, looked up from the cwd upward); VS Code Copilot Chat reads
`.vscode/mcp.json`, a different schema; the coding agent reads the repository settings UI.
`.github/copilot/mcp-config.json` is on none of those lists. Every Copilot MCP declaration
ai-badger has made for eight releases went into a file nothing opens.

The writer now targets **`.github/mcp.json`**, and uses the one field that file has and
`.mcp.json` does not: a per-server **`tools` allowlist**, written `["*"]`. Registration-time
pruning, on the same shape Hermes uses.

`.vscode/mcp.json` is deliberately not written. It is a different schema (top-level `servers`
plus `inputs`, per-server `cwd`/`envFile`/`oauth`, and no `tools` field at all — tool picking is
UI-only), so writing both from one declaration set would mean asserting a shape nobody verified.

**The stale file is cleaned up on the next scaffold**, not left to rot: backed up to
`mcp-config.json.bak-<ts>` and removed when it is the shape ai-badger's own writer produces —
a top level of `mcpServers` alone, entries carrying only `command`/`args`/`cwd`/`env`/`tools`. A
file with a `type`, `url` or `inputs` key is valid Copilot configuration ai-badger has never
written, so it is **reported and left exactly as found**. So is one that will not parse.

### 2. Hermes: the last user-global write becomes a proposal

`McpTools.scaffold_hermes_mcp_user` merged a `scope: user` server into `~/.hermes/config.yaml`,
which ADR-0014 decision 6 forbids — and step 6's changelog said so, and left it for this step.
It is gone. `features/hermes/adjustments/adjust_mcp.py` prints a paste-ready block instead:

```yaml
mcp_servers:
  code-review-graph:
    command: "python3"
    args: ["-m", "code_review_graph", "serve"]
    enabled: true
```

**The retired writer was also writing the wrong key.** It merged into `mcp.servers`; Hermes
reads top-level **`mcp_servers`**. Nothing in this repository ever read the file back, so
nothing caught it. Every entry ai-badger has written to `~/.hermes/config.yaml` since 0.13.0 was
inert — the same defect as #189, on the other host, found the same way: by reading the host's
own documentation instead of the code that writes for it.

The snippet is built as **text, not `yaml.dump`**: pyyaml is an optional dependency here
(`engine/requirements.txt`), and a proposal that disappears when it is missing is not a
proposal. JSON is a YAML subset, so `json.dumps` does the quoting.

### 3. Copilot's coding agent: propose-only, with the secret prefix it needs

`features/copilot/adjustments/adjust_mcp.py` prints the `mcpServers` JSON for the repository
settings UI, with the `tools` array the coding agent requires and every `${VAR}` env reference
renamed to the `COPILOT_MCP_`-prefixed form it can resolve — the only secret shape documented
for that surface. A literal env value is left alone; only a reference needs a secret to exist.

Both new adjustments are `{"feature": "mcp", "script": "adjust_mcp.py"}` rows, one per agent, so
all three hosts now reach their MCP surface through the same mechanism.

### 4. `config.mcp.decline` stops the declaration itself

The rest of [#186](https://github.com/Arasz/ai-badger/issues/186). Step 6 denied a declined
server's tools in `.claude/settings.json` while still writing its launch config into
`.mcp.json`. That is contradictory on Claude and useless on Copilot, whose only committable
block *is* not declaring the server. So:

- a declined name is dropped from `declared_servers()` — it is not declared anywhere;
- it is **removed** from `.mcp.json` and `.github/mcp.json` if an earlier run wrote it, because
  merge-only would have left it launching;
- the Claude adjuster's `disabledMcpjsonServers` + `permissions.deny` stay, and are now purely
  about servers arriving by a route ai-badger does not own — plugin, user-global, CLI.

Where "decline" now lands, per host:

| host | what declining does | route |
|---|---|---|
| Claude Code | tools blocked project-wide, and the server not declared | `permissions.deny` + `disabledMcpjsonServers` (committed) |
| Copilot CLI | not declared, and removed from `.github/mcp.json` | absence; a server from elsewhere needs runtime `--deny-tool` |
| Copilot coding agent | left out of the proposed snippet | absence |
| Hermes | a proposed `tools: {exclude: ["*"]}` block | proposal only — no project route exists |

Only Claude has a committable rule that reaches a server ai-badger never declared. That is not a
gap in this step; it is the arrival-route asymmetry ADR-0014 §0 measured.

  become `test_copilot_mcp_json_*`, on `.github/mcp.json`; `test_copilot_env_propagated` keeps

## Behaviour changes worth knowing

- **A re-scaffolded Copilot project loses `.github/copilot/mcp-config.json` and gains
  `.github/mcp.json`.** Both are tracked files in a consumer repo, so the change shows up as a
  rename in the next commit. If the old file was hand-edited it is kept and reported instead.
- A `scope: user` server no longer reaches `~/.hermes/config.yaml`. Anyone who relied on that
  must apply the printed snippet by hand once — and should check whether the entry ai-badger
  wrote under `mcp.servers` was ever doing anything (it was not).
- `config.mcp.decline` now changes `.mcp.json`. A project that declines a server it previously
  declared will see the entry deleted, with the usual `.bak-*` copy beside the file.
- `config_guard` gained `remove_with_backup`; nothing here re-implements the backup naming
  (#173). `.github/**/*.bak-*` is gitignored, as `.claude/*.bak-*` already was.
- Adjustments now receive `mcp_declarations` (each declared server resolved for that agent's
  `agentOverrides`) and `mcp_declined`. An adjustment is loaded by path and cannot resolve
  `stack-mcp.json` itself, and the two propose-only hosts need the launch config, not just names.
