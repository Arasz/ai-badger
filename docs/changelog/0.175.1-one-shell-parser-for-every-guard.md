# 0.175.1 — one shell parser for every guard

**Patch** — security fix to the three `PreToolUse` guards that read Bash commands. 2026-09-24.

## Fixes

The git-internals guard, the blast-radius kill guard and the auto-wm gate each had their own
lexer. Piping hook JSON into the guards showed each of these coming back `allow`:

- git guard: `perl -pi -e … .git/config`, `sed -Ei … .git/config`, `sed -ni … .git/config`,
  `sudo -u root rm .git/config`, `cp -t .git/ x`, `mv --target-directory=.git x`,
  `rm .git/config; echo "a<newline>b"`, and `ln -s .git/config cfg` followed by an edit of
  `cfg`
- kill guard: `sudo -n pkill -f node`, `sudo -u root pkill node`, `env -u X pkill node`,
  `pkill node; echo "a<newline>b"`, `` echo `pkill node` ``

A commit message heredoc with a line that starts with `rm .git/config` was refused, because
the git guard read the body as a command.

All three guards now read commands through one module, `shell_parser.py`:

- **The whole command is lexed at once.** A quote that spans a newline stays one word, and a
  heredoc body is treated as data. Commands split on `;`, `&&`, `||`, `|`, `&` and newlines
  outside quotes.
- **Nested commands are found.** The parser looks inside `$(…)`, backticks, `<(…)`, `>(…)`,
  the substitutions in an unquoted heredoc, and the script given to `sh -c` or `eval`.
- **Wrappers are removed along with their options and option values.** This covers `sudo`,
  `env`, `nice`, `timeout`, `command`, `exec`, `nohup` and `time`, plus `doas`, `builtin`,
  `stdbuf` and `xargs`, which auto-wm already removed. `command -v` only looks a program up,
  so nothing is treated as running.
- **Each command reports** its program, arguments, combined short flags and redirection
  targets. `2>&1` duplicates a file descriptor and is not treated as a file.

Each guard keeps its existing policy:

- **git guard.** An in-place flag is found anywhere in a short-flag cluster, up to the first
  letter that takes a value, so `perl -Mstrict` is not read as `-i`. `cp`/`mv`/`ln`/`install
  -t DIR` write into `DIR`. A path is also checked after its symlinks resolve. A command not
  in the list is still allowed, but removing a wrapper can reveal a listed one, so
  `timeout 5 rm .git/config` is now refused. Hermes installs `shell_parser.py` next to the
  guard. Without that file, only the Bash check stops working.
- **kill guard.** Kills behind a wrapper, inside backticks or on a later line are found.
  Removing `xargs` reveals the program, so `pgrep … | xargs kill` counts as a pattern kill.
- **auto-wm gate.** The rules are unchanged and every #497 test passes. A wrapper option that
  takes a value no longer hides the program, so `env -u HOME curl …` and `xargs -I {} curl
  {}` now prompt. Input that cannot be lexed is still split without regard to quotes.

## Layout

Each guard ships a byte-identical copy of `shell_parser.py` next to itself and loads it by
path. A shim could not work here: auto-wm installs on its own into
`~/.claude/skills/auto-wm/`, and the git guard installs flat into the Hermes plugin
directory. Neither location has a canonical copy to load. `tests/test_shell_parser.py` finds
the copies with `git ls-files`, so no hand-kept list is involved. It checks that the copies
are identical and that every module loading the parser has a copy next to it.

## Verification

- The new gate tests fail on main and pass after the fix. Each defect below was put back one
  at a time, and the tests failed each time: per-line lexing, heredoc bodies read as commands,
  wrapper option values not removed, no symlink resolution, `startswith` flag matching, `-t`
  ignored, no value letters, backticks not parsed, file-descriptor duplication read as a
  file, `command -v` running its operand, and one copy changed.
- `tooling/validate.py --all`, `version_sync.py --check`, `changelog_index.py --check`,
  `index_build.py --check`, `gates/release_guard.py`, `scaffold_freshness_guard.py` and
  `sync_plugin_skills.py --check` all pass.
