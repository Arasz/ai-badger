# 0.206.0 — the memory-first gate reaches pi's read tool

**Minor** (new capability) · **Date:** 2026-10-19

The pi adapter (vendored at `features/pi/adjustments/adapter/`) now asks the memory-first
gate about a file before pi reads it, the same way the gate already redirects a text search.
A read therefore shares the grep gate's searched-pattern store, its project id and its JSONL
log (`~/.ai-badger/memory-first-search/searches.jsonl`): a path a grep already searched is not
searched again, and a read of a file the bank knows stops once, with the memory result in
front of the model.

- The adapter calls the framework's own `memory_first_gate_hook.py` with the read's path as
  the search pattern, so no framework hook changed: the gate's decision, its store and its log
  are the same ones a grep uses.
- A bank answer stops the read. The model gets the memory result and re-issues the read when
  it wants the raw file — the read is the fallback, the bank answers first.
- Nothing to offer lets the read through: no hits, a bank that could not search, a project
  without the ai-raccoon-memory skill, a gate that failed, a gate that timed out. The gate
  never stands between the model and a file.
- `PI_BADGER_READ_GATE=0` turns the read gate off. The grep gate keeps the framework's own
  switches.

The vendored copy is the canonical one in `pi-badger-integration`; this release carries it.
