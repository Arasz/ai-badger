# 0.109.0 — dogfood the consumer journey

Six defects reached `main` in one week. All six escaped a suite of ~3,740 tests, and they escaped
it the same way: the suite is thorough *in-process*, and none of it is a consumer.

| Defect | Why the suite could not see it |
| --- | --- |
| `--no-install` wrote 14 symlinks into `~/.hermes` | the test asserted the `plugins/` path a prior fix had patched, not the invariant |
| tracker state written into `features/.ai-badger/` | only happens when cwd is a real catalog directory |
| 3 tags shipped a stale `manifest.json` | the freshness guard exempts exactly those fields by design |
| `GIT_DIR` breaking three call sites | only exported by a real git hook in a linked worktree |
| the edit guard denying `project-local.md` | nothing scaffolds and *then edits as a user would* |
| 31 dangling `~/.hermes/skills/<project>/` links | nothing prunes a namespace whose project moved |

Measured on this branch: 38 `monkeypatch` calls in `tests/` redirect `HOME` or `Path.home`, and
71 call sites pass `--root <source checkout>` to a scaffold. Both are the right call for a unit
test, and both are exactly the difference between the fixture and an installation.

## What the journey does

`gates/consumer_journey.py` is one script that installs ai-badger the way somebody who has never
seen this repository installs it, then works in the result:

1. **Stage a plugin cache.** The framework's tracked tree is copied to
   `$HOME/.claude/plugins/cache/ai-badger` — a plain copy with **no `.git`**, which is the shape
   `git_provenance` and `_bootstrap_lib` resolve for every consumer and which no other test
   exercises. Every framework script the journey runs afterwards is run out of that copy.
2. **A real `git init`,** because provenance branches on `.git` existing.
3. **`detect.py` → author → `validate.py` → `scaffold.py --no-install`.** The config is the one a
   human would write: the detection proposal with `summary`, `domain` and `personaRouting` filled
   in. `validate.py` is run against it, not skipped.
4. **`--no-install` must add nothing to `$HOME`.** Not less than before — nothing.
5. **Then install for real,** and every entry `$HOME` gains must sit inside a namespace a consumer
   can point at: the framework's own `~/.hermes/plugins/ai-badger`, or `~/.hermes/skills/<project>/`.
6. **Check the scaffold is complete** — config, manifest, `state.json`, every delivered skill's
   `SKILL.md`, `CLAUDE.md`, `.claude/agents/`, and a `PreToolUse` hook actually registered on `Edit`.
7. **Work in it.** Three edits are attempted *through the command `.claude/settings.json`
   registers* — read from the file, never reconstructed, because a hook wired to a path that does
   not exist is this project's signature defect and only running what is registered can see it.
   A generated `SKILL.md` must be denied; `project-local.md` and the project's own `app.py` must
   be allowed. Then each edit is actually made, and `drift.py` — the reporter a consumer runs, a
   project having no `scaffold_freshness_guard` of its own — is asked after each: silent about
   `project-local.md`, loud about the hand-edited `SKILL.md`. A guard and a drift report that
   disagree are telling a project two different things about the same file.
8. **Re-scaffold over both edits.** This is what makes either verdict checkable: `project-local.md`
   survives byte for byte, which is *why* the guard allows it, and the hand edit to the generated
   file is reverted, which is *why* the guard refuses it.
9. **Re-scaffold again, with nothing changed in between.** Nothing but stamps may move, with no
   exemption list — the previous step is separate precisely so this one needs none.
10. **Tear the project down** and sweep `$HOME` for dangling links.

## Snapshotting `$HOME`

The `~/.hermes` leak was declared fixed by an acceptance check that hashed regular files. The leak
was 14 symlinks and two directories, so the check reported it clean while it was still happening.

`snapshot()` therefore records **directories and symlinks as entries in their own right**, and
records a symlink by its target without ever following it — a link retargeted in place is a
change, and a link into the project does not drag the project's tree into the diff. A file is
its digest, not its size: `~/.claude/settings.json` is edited in place. `__pycache__` is the one
exclusion, for the same reason `scaffold_freshness_guard` excludes it — running the scaffolder
out of a cache writes bytecode into that cache, and that is the interpreter, not the framework.

## `HOME` is a scratch directory, and the journey refuses otherwise

`check_scratch_home` runs before anything else and raises when the scratch directory *is* the
real home or sits inside it. `child_env` redirects `HOME`, `HERMES_HOME` and the three XDG
variables — `HOME` alone is not enough, since each of the others reroutes a write past it — and
drops `badger_lib.GIT_LOCATION_ENV`, because a journey invoked from a pre-push hook inherits a
`GIT_DIR` pointing at the operator's repository.

## The mutations

The journey is a check, so it was watched failing. Each mutation was applied to a private copy of
the framework, run, and reverted:

| Mutation | Journey's verdict |
| --- | --- |
| delete `if self.install:` in `scaffold.py`, so `--no-install` rebuilds the Hermes namespace | `--no-install: $HOME gained 16 entries` (2 directories, 14 links) |
| delete the `projectOwned` exemption in `generated_file_guard.py` | `guard: editing project-local.md was deny` |
| stop `drift.py` printing its `locallyModified` block | `drift: the drift report is silent about a hand-edited generated file` |

The first two are now REGISTRY provocations in `tests/test_every_check_can_fail.py`, so they are
re-run on every push rather than remembered. Each provocation runs the same fixture twice, with
the defect and without, and the mutation anchors assert their own presence — an anchor that has
moved fails loudly rather than producing an unmutated tree and a clean run that proves nothing.
The harness was itself watched failing: with the mutation stubbed to a no-op,
`test_check_fails_when_provoked` reports `expected exit 1, got 0`.

The allowlist of namespaces `$HOME` may gain cannot be derived from the scaffolder — the
scaffolder is what it checks — so `strays()` is unit-tested in both directions instead, including
the case that caught a real bug while it was being written: `~/.hermes/skills/<project>-old/`
was accepted, because `~/.hermes/skills` was on the list as a prefix rather than as a container.

## What it deliberately does not cover

- **A downloaded plugin.** The cache is staged from this checkout's tracked files, so it tests
  the cache *shape* (no `.git`, `frameworkRoot` resolved as a copy) but not the marketplace
  download itself. That would need network access in a gate.
- **Consumers who are not Hermes users.** The scratch home is given a `~/.hermes` directory so
  detection picks Hermes up, because the user-global writes this journey watches only happen for
  a Hermes agent. A Claude-only consumer's `$HOME` footprint is not separately walked.
- **`gates/scaffold_freshness_guard.py` run inside the project.** It re-scaffolds a repo *against
  itself* and needs `--root` to be both project and framework, which a consumer's repo is not.
  `drift.py` is what a consumer has, and the journey runs it; steps 8 and 9 then prove the two
  guard verdicts against what the scaffolder actually does, which is the ground truth both
  reporters approximate.
- **Pruning a namespace whose project is gone.** After teardown the journey requires every
  dangling link to lie inside `~/.hermes/skills/<project>/` — attributable to one directory a
  consumer can delete by name. It does not then clear them: 0.108.0 gave that job to
  `den-refresh --prune-namespaces`, which runs from a *live* project, and the journey has only
  the one it just deleted. Proving that command needs a second project and belongs with the
  command.

## Where it runs, and what it costs

- `verify.sh journey` — a new lane in `$LANES`, so it runs on every push and in `verify.sh all`.
- `.github/workflows/consumer-journey.yml` — its own job, `permissions: contents: read`, both
  actions pinned to full commit SHAs.
- Locally: `.venv/bin/python3 gates/consumer_journey.py`. `--keep` leaves the scratch directory
  for inspection; without it nothing survives outside `$TMPDIR`.

Measured 2026-08-08 on this change, five consecutive runs on an otherwise busy machine: **3.9,
4.6, 5.6, 6.9, 7.4s** wall clock. The four provocation runs it adds to `pytest` (two mutations ×
two directions) are **13.4s**. Against `verify.sh all` at 778s — measured 2026-08-07 at 43fbfb49,
of which pytest is 664s — that is under 3%, which is why it is a push lane and not CI-only. The
full pre-push run of this branch was 658s with the journey lane in it.
