# 0.51.0 — the legacy MCP registries are deleted

Step 4 of the MCP rebuild [ADR-0014](../adr/0014-mcp-support-is-configuration-not-retrieval.md)
describes, and the first one that is not additive. Steps 1–3 built the replacement and proved it
lands byte for byte where the old registries did; this step deletes them.

**Rendered output does not move.** A full scaffold run before this change and one after it were
diffed file by file: `CLAUDE.md`, `HERMES.md`, `.github/copilot-instructions.md`, `.hermes.md`,
every `.ai-badger/` file and `.mcp.json` are byte-identical. The only files that differ are the
two scripts edited here and the manifest hash that records them.

## Deleted

| removed | why it was safe |
|---|---|
| `features/common/mcp-servers.json` | it was `{"servers": []}` — byte-equivalent to absence, and no stack ships a sibling |
| `features/common/external-tools.json` | its one entry (`code-review-graph`) is re-expressed by `features/common/mcp/code-review-graph/` + `stack-mcp.json`, and the catalog already won on conflict |
| `schemas/external-tools.schema.json` | nothing left to validate |
| **`config.externalTools`** | absent from all four measured consumer configs |
| `targetAgents` in `schemas/mcp-servers.schema.json` | it validated and was read by no production code; `stack-mcp.json` never carried it |

## `config.externalTools` is a hard break, deliberately

`config.schema.json` sets `additionalProperties: false` and `scaffold.py` validates the config
*before* doing anything, so a project that still declares `externalTools` now gets

```
config.json is INVALID — aborting scaffold:
    - Additional properties are not allowed ('externalTools' was unexpected)
```

Delete the key. If it declared a server, declare that server in a `stack-mcp.json` entry with
`declare: true` instead; if it carried `instructions`, they belong in
`features/<stack>/mcp/<server>/server.md`.

Because the key can no longer reach a scaffold, the code that branched on it went with it: the
`config.externalTools` override — and its *silence*, which 0.51.0's step 3 honoured as a way to
decline a declaration — no longer exist. **A project has no way to decline a catalog-declared MCP
server.** `mcp` is not one of the four name-addressable feature types, so `config.exclude.mcp` is
not available either; that gap is filed rather than papered over.

This is **not** added to `BREAKING_VERSIONS`: that file means "a full re-scaffold is required",
and a re-scaffold is not what fixes a stale config key — editing `config.json` is.

## Still read, for one more release

`features/<stack>/mcp-servers.json` and `features/<stack>/external-tools.json` are no longer
shipped by this framework, but both readers stay: a stack that still has one keeps working, and a
reader whose input file is gone simply finds nothing rather than complaining. ADR-0014 step 8
removes the reader code and migrates its tests.

## Tests

`tests/test_mcp_legacy_files_removed.py` is new and pins every deletion above, including that no
script under `welcome-ai-badger/scripts/` mentions `externalTools` any more.
`tests/test_external_mcp_tools.py` is deleted — every one of its tests drove either the config key
or the deleted catalog file, and the four that would still have passed did so vacuously through
the catalog path that already has its own tests.
