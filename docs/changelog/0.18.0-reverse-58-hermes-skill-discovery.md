# 0.18.0 — reverse #58: restore Hermes skill discovery

**Issue:** #58 (reversed), #67
**ADR:** `docs/adr/0003-hermes-skill-discovery-via-namespaced-symlinks.md`

Third of three PRs. This one is a behavior reversal, not an addition.

## Why

`bafb952` made `Scaffolder.symlink_hermes_skills()` a no-op, justified by the claim that
"Hermes discovers project skills via the project-local skill directory". That claim is false:
Hermes resolves skills from `~/.hermes/skills/` plus `skills.external_dirs` and nothing else
(`agent/skill_utils.py`). The change did not fix the staleness #58 reported — it removed
discovery, making every scaffolded ai-badger skill invisible to Hermes.

#58 reported drift *between copies*. A relative symlink has no second copy to go stale, so
the symlink mechanism was never its cause. Its legitimate half — "a refresh should propagate"
— is addressed here by re-linking on every den-refresh.

## Changed

- `symlink_hermes_skills()` works again, gated on `hermes` in `config.agents`, writing
  relative symlinks into a per-project namespace at `~/.hermes/skills/<project>/`. The
  namespace is what avoids the cross-project name collisions that made `external_dirs`
  unusable.
- **It no longer `rmtree`s the namespace directory.** Ownership is decided per entry: only a
  symlink resolving into *this* project's `.ai-badger/skills/` is ai-badger's to remove.
  Real directories and foreign symlinks survive untouched, and a real directory colliding
  with a scaffolded skill name is skipped rather than clobbered. The original code would have
  destroyed a Hermes-authored skill living in that namespace — `agent-skill-discovery` is a
  real instance of exactly that.
- `den-refresh` re-links unconditionally, reading skill names from disk so additions link and
  removals drop. Deliberately not gated on the drift → re-scaffold path: with no drift there
  is no re-scaffold, and a hand-added or hand-removed skill would never propagate — which is
  #58's own scenario.
- One symlink per skill, plus a single link for the `learned/` tree. Per-skill links keep
  stale removal per-entry and leave the namespace directory writable by Hermes itself; a
  single namespace-level link would reintroduce the same data-loss failure mode as the
  `rmtree`.
- The false docstring is corrected, and `docs/audit-symlink-hermes-skills.md` is reconciled.

## Follow-up

This repo's own `.ai-badger/skills/` copies are still at 0.15.1 and now resolve through the
restored symlinks. Run `den-refresh` on this repo after merge — that staleness is exactly what
the restored relink exists to fix.
