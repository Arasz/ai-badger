# 0.66.0 — The plugin copy says it is the generic one

A project with the plugin installed *and* a scaffold registers every skill twice: bare from
`.claude/skills/`, and as `ai-badger:<name>` from the plugin.

Measured on 2026-08-01, the two copies of `code-review-checklist` had **byte-identical
frontmatter** — md5 `503cde95…` — and bodies differing by **28 lines**. The scaffolded one
carries six merged extensions; the plugin one carries none.

Name and description are the whole of what an agent sees before choosing. Identical name,
identical description, different body: a coin flip where one face silently lacks the project's
own checks, and nothing marks which.

## What changed

The plugin's `SKILL.md` keeps its frontmatter **verbatim** and carries a pointer instead of the
procedure. The procedure moves to `SKILL.full.md` beside it, unchanged.

Frontmatter is untouched deliberately: `description` is the only text an agent reads before
choosing, so rewriting it here would change what the skill *matches on* in order to fix a
question about which of two matches to take.

**Nothing is lost.** A user with the plugin and no scaffold still has the entire skill, one file
away, and the pointer names it.

## Three keep their body inline

`welcome-ai-badger` creates `.ai-badger/` — pointing at a scaffold it has not made yet would be
circular. `den-refresh` and `feed-badger` must run the *framework's* copy; ADR-0011 makes that
load-bearing across a breaking version boundary, where the project's copy is the stale one.

## One renderer, not two

`render_into` is the single place a shipped copy is produced, and `--check` renders into a
temporary directory and compares against that rather than reimplementing the rule. Two
implementations of "what should be there" is how a check starts disagreeing with the thing it
checks — and this one previously hashed the source directly, which the rendering would have
made permanently red.

## What this does not do

It does not reduce the number of registered skills. That was proposed and rejected: the
duplicate registration is a labelling problem, not a reason for a project to lose access to a
skill. Both entries remain; only one now claims to be the tailored one.
