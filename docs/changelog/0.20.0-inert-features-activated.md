# 0.20.0 — shipped features are actually shipped

**Review:** `docs/reviews/2026-07-26-full-project-review.md`
**Plan:** `docs/plans/2026-07-26-remediation-plan.md` (Wave 2)

Wave 2 of the remediation plan. Every fix here is a feature that was advertised in a manifest,
a SKILL.md, or a catalog and did nothing — plus the one hardening gate that had to land before
the riskiest of them. Findings are referenced by their review IDs (F-06…F-08, F-12, F-17).

## Fixed

- **F-17 — `.claude/skills/` could diverge from `features/` with no signal.** The shipped
  plugin copy was hand-synced, with no `--check`, no CI step, no pre-commit hook and no test.
  `sync_plugin_skills.py --check` now hashes both trees with `badger_lib.dir_content_hash` over
  the same exclude patterns the copy itself uses, and exits 1 on any divergence or missing copy.
  It is wired into `.pre-commit-config.yaml`, the CI workflow, and a parity test — so a
  `features/` change that forgets the copy now fails the build instead of shipping the old code.

- **F-12 — auto-wm auto-approved everything, machine-globally, without expiry.** Three guards
  now run before any allow decision, in both modes. **Expiry:** partner mode gets a window too
  (default 8h) and no window may exceed 12h; a state file recording no expiry is retired rather
  than honoured. **Project scope:** the state records the project AWM was enabled in, and a call
  whose `cwd` is outside that tree is never auto-approved — enabling it in one repo no longer
  arms every session on the machine. **Denylist:** destructive shell commands, network egress
  (`WebFetch`/`WebSearch`) and writes outside the project fall through to the normal permission
  prompt, logged from a closed reason vocabulary so no scanned byte reaches the audit log.
  `poll_limit.py` no longer runs `/auto-wm away 4h` on a limit reset unless started with the
  new `--auto-wm-on-reset` flag.

- **F-07 — the session hook was wired by nothing, and the one that was wired could not work.**
  `session_start_hook.py` — session recording, unfinished-task recovery, poller launch, all
  load-bearing for `task/SKILL.md`'s Recovery section — was scaffolded into every project and
  registered nowhere. Meanwhile `drift_notice_hook.py`, wired through the consumer's own
  `.claude/settings.json`, can never resolve `${CLAUDE_PLUGIN_ROOT}` there and exited silently
  in every consumer. A new plugin-provided `hooks/hooks.json` (declared in
  `.claude-plugin/plugin.json`) now registers drift notice where the placeholder is actually
  substituted, and `hooks-manifest.json` registers `session-start-tracking` for the scaffolded
  copy. Each manifest entry names its `script`, so a shared event hands each hook its own
  command instead of whichever came first.

- **F-06 — the skill installer emitted no install command for any skill.** With no `{name}`
  template declared by any agent, the per-skill install silently fell back to the *add-source*
  template: four identical `claude plugin marketplace add` lines, zero installs, empty warnings.
  Claude's marketplace instruction now declares `claude plugin install {name}@{sourceName}`; a
  missing `{name}` template produces a warning naming the skill instead of a silent duplicate;
  and the resolver reads the always-included catalog stack too, so `features/common/skills.json`
  (superpowers, pr-review-toolkit) stops being dead data. A test runs `install_skills` against
  the real `features/` tree — the fixture-only tests declared a template the catalog never had.

- **F-08 — managed headers pointed at files that do not exist.** `.hermes.md` claimed its source
  of truth was `.ai-badger/.hermes.md`, and `.github/copilot-instructions.md` pointed at
  `.ai-badger/CLAUDE.md` — a different document's identity. Both header call sites now pass the
  `aibCopy` path, and the in-body self-reference became a `{{SOURCE_OF_TRUTH}}` slot (claude,
  copilot and junie all render one shared template). A scaffold test parses every managed banner
  and asserts the path it names exists on disk.

## Changed

- **`config.json` gains `commonStacks`** (a string or list, default `"common"`). The
  always-included catalog stack's name is now config data rather than a literal repeated in
  `scaffold.py` and `install_plugins.py`; both resolve it through `badger_lib.resolve_stacks`.

## Behaviour changes worth knowing

- **auto-wm partner mode now expires.** Existing state files without an `expires_at` are
  refused by the gate and retired on the next event — re-run `/auto-wm partner` to get a fresh,
  project-scoped window. `awm.py partner` accepts an optional duration; `status` shows the scope.
- **auto-wm no longer auto-approves everything.** Denylisted calls reach the normal permission
  prompt. That is a fall-through, not a denial: with no user around (away mode) such a call
  simply waits.
- **`poll_limit.py` no longer enables auto-wm on its own.** Pass `--auto-wm-on-reset` to restore
  the old behaviour. This ordering is deliberate: wiring `session_start_hook.py` arms the only
  launcher of that chain, so the gate had to exist first.
- **`--execute` installs now run real per-skill commands.** Dry-run remains the default, but the
  emitted command list changed for every user.
- **Generated agent files change content.** The managed banner and the in-body source-of-truth
  line now name the correct `.ai-badger/` file; re-scaffold to pick them up.
- **Consumers' `.claude/settings.json` no longer receives `drift_notice_hook.py`.** Drift notice
  comes from the plugin now. An existing project keeps the stale entry until it is removed by
  hand — it was inert there anyway.
