# 0.160.0 — The Test-Run Economy

**Type:** MINOR
**Date:** 2026-09-02

## What Changed

Agents were running the same full test suite up to three times per change — once by hand, once
in the gate, once in CI — and re-running suites "to check stability" between edits. This
release makes the run budget explicit and enforced:

- **New invariant `test-run-economy`** — run each affected suite once (the modified surface
  plus the consumers of changed behavior — an API change pulls the frontend end-to-end that
  exercises it), and leave the full suite to CI on push. CI alive: skip the slow local gates
  by design and read CI's verdict. CI dead or absent: run the hooked-up local gates once
  before push; nothing hooked up, one manual full-suite run. Docs, comment discipline, and
  lint are on no skip side of this trade. Repetition is measurement, and measurement belongs
  to a named diagnosis — flake triage — never to verification.
- **New default skill `test-economy`** with a `PostToolUse` hook (claude + hermes + copilot)
  that classifies every shell command as a test run (full vs filtered), counts full-suite runs
  per project and session, and commands the economy on the run past the budget
  (`AI_BADGER_TEST_ECONOMY_MAX_FULL`, default 2 allowed — the nudge lands on the 3rd). From
  the escalation bar (`AI_BADGER_TEST_ECONOMY_ESCALATE_AT`, default 5) every further full run
  nags with the STOP form. The message names the local gate wiring it detected (lefthook,
  pre-commit, husky, a real git pre-push hook) so the CI-dead branch is actionable on the spot.
  Filtered runs never count; `go test ./...` counts full, `go test ./pkg/...` does not.

## What the skills now say

- **task** — the `gates` step and Phase 4 follow the CI variable: touched surface locally,
  once, when CI is alive; gates-once or one manual full suite when CI is dead. One run per
  suite per change; slow lanes only as the sole active session with CI dead or absent.
- **quick-task** — the fast gate gains the CI variable: CI alive means push and read CI's
  verdict; CI dead means the full local gates once before push. Lint and docs gates sit on no
  skip side. Re-running a touched suite that already passed is named as the theater it is.
- **git-work** — infra-shaped CI failures earn one rerun of the single failing job, then stop;
  flake attribution works from runs that already happened.
- **review-tests** — Pass 2 (determinism) names the one legitimate repetition: measuring a
  flake distribution deliberately, in isolation.

## Design notes

- The hook is advisory only — `additionalContext`, never `decision`/`permissionDecision`/
  `continue` (the 0.33.0 line holds). A store that cannot open fails open to silence.
- The hook script is `suite_economy_hook.py`, not `test_economy_hook.py`: the scaffold's skill
  delivery ignores `test_*.py` (test files must not ship), so a production hook must not wear
  a test's name.
- The nudge cannot read intent, so it also fires during deliberate flake diagnosis; the skill
  and the message say what takes a run out of the economy: naming the diagnosis.
- Counts are per session (a fresh session starts clean), keyed by resolved project root in the
  user store's `test_economy` family, last eight sessions kept per project.
