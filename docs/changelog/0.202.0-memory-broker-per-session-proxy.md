# 0.202.0 — one memory proxy per session, not one per search

**Minor** (feature) · **Date:** 2026-10-18

- **Per-session broker.** A new `SessionStart` hook (`memory_broker_hook.py`, Claude and Copilot)
  starts `memory_broker.py serve` detached. It holds one `ai-raccoon` proxy session and serves
  `memory_search` over a unix socket in `~/.ai-badger/memory-broker/` (directory 0700, socket 0600,
  named by the sanitized session id). `SessionEnd` stops it; it also exits after 30 idle minutes or
  on SIGTERM, and removes its socket. A dead proxy is reopened by the next request.
- **Parallel searches.** Concurrent requests are multiplexed onto the one proxy stream under
  distinct JSON-RPC ids and routed back by id; nothing sits behind a lock. A client that times out
  or hangs up leaves the session usable for everyone else.
- **Clients try the broker first.** `memory_context.search_block` (the memory-first gate) and
  `memory_context.build` (the per-prompt hook) search through the session's broker and fall back
  to today's per-call proxy spawn when there is no socket, the socket is stale (it is removed), or
  the broker does not answer. The hook contract is unchanged: fail open, exit 0.
- **Why.** The gate's 4 s budget was spent opening a proxy per call (0.8-3.7 s under load against
  0.3 s idle), so the hook cancelled searches the server was still running. Hermes and pi have no
  session hooks wired for this and keep the per-call path, as does Windows.
