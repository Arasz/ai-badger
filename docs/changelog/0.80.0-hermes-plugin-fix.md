# 0.80.0 — Hermes hooks ship as a real directory plugin

The Hermes-side hook surface was dead since the first hook shipped: ai-badger copied flat
`.py` files into `~/.hermes/plugins/`, but Hermes only loads **directory plugins**
(`~/.hermes/plugins/<name>/plugin.yaml` + `__init__.py` exposing `register(ctx)`), opt-in
via `plugins.enabled` — so none of the four hermes entries in `hooks-manifest.json`
(drift-notice, context-enrichment, commit-reminder, memory-grade) ever fired. Root-caused in
`docs/work/2026-08-06-hermes-integration-diagnosis.md`; this release ships the fix.

- **Real plugin directory**: the scaffold now installs `~/.hermes/plugins/ai-badger/` with
  `plugin.yaml` (declaring `on_session_start` / `pre_llm_call` / `post_tool_call`),
  `__init__.py` re-exporting `ai_badger_hooks.register`, and every sibling module the lazy
  imports resolve beside it. Legacy flat copies and the old manifest dir are removed so the
  user scope stays clean.
- **Opt-in enablement**: Hermes loads user plugins only when enabled — the scaffold's notes
  print the instruction (`hermes plugins enable ai-badger`, or `plugins.enabled:
  [ai-badger]` in `~/.hermes/config.yaml`). The plugin must be enabled once per machine.
- **Payload adapter**: Hermes' plugin emitter sends `function_name`/`function_args`/
  `session_id` (not the shell-hook `tool_name`/`args`/`cwd` spelling, and no `cwd` at all) —
  `post_tool_observer` now normalizes both spellings and falls back to the session process
  cwd, matching the `pre_llm_call` pop side.
- **Host attribution**: the memory-grade JSONL line gains `host` (hermes/claude/copilot) and
  `sessionId`, so "no usage" vs "no capture" is answerable from the log itself; manual lines
  keep both fields null. `memory_grade.py` lives at
  `~/.hermes/plugins/ai-badger/memory_grade.py` (helper path self-reports).
- **Staleness protection preserved**: the installer record
  (`.ai-badger/manifest.json` with `frameworkRoot` + version) moves INSIDE the plugin dir,
  where `badger_lib.copy_skew` reads it; a stale copy refuses to register exactly as before.
  A dead recorded root (e.g. a freshness-guard temp dir) degrades gracefully to "no version
  context", never to a broken session.
- The 0.79.0 changelog's "all three agents wired" claim was manifest-true but runtime-false
  for Hermes; the SKILL.md §8 host-coverage section now states the truth and the
  verification checklist includes the capture check that was missing.

**What a consumer must know:** after upgrading, re-run the scaffold (or `den-refresh`) once,
then `hermes plugins enable ai-badger` and restart the agent host — then verify with one
organic `memory_search` that a line lands in `~/.ai-badger/memory-grade/memory-quality.jsonl`
with `host` set.
