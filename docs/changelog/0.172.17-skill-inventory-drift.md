# 0.172.17 — no second skill inventory to drift

**Patch** — documentation fix; no code or scaffold behavior change. 2026-09-24.

## Fix

`docs/framework-architecture.md`'s "Skills location" section and README.md (the install
section, the tree diagram, and the `SKILLSDIR` mermaid node) each hand-wrote a skill total, a
`default`/`optIn` split, and a member list. c8da0f0 and f9c6f28 (ADR-0028/0029) changed the
catalog and updated only `docs/skills.md`, which derives its counts and is checked for it —
these two pages have no such check, so they went stale: "Thirty-six skills ... The fourteen
with `scope: default` ... The other twenty-two are `optIn`", contradicted by the current
frontmatter.

Deleted the counts and member lists rather than resynced them; both pages now point to
`docs/skills.md` as the one place that counts. `tests/test_docs_match_the_catalog.py` gained
`TestNoHandWrittenSkillCounts`, which fails on any `\d+ (skills|default|optIn)` or spelled-out
skill count in either file, so a new hand-written count can't creep back in unnoticed.

## Erratum: 0.168.0 shipped an undocumented behavior change

41d3d43 (2026-09-09), merged straight to `main` with no PR, added `OPEN_STATES` (a `STARTED`
task now counts as open), `untracked_lanes`, the `STALE` session marker, and
`tracker_lib.resolve_own_session`'s two-pass resolve to `status-report`. It shipped inside
0.168.0 (#483, 2026-09-11), whose changelog entry covers only the model-registry pin rotation
and never mentions it. No release recorded that these consumer-visible behaviors went out, in
violation of this project's own release-traceability rule.

This entry is the record 0.168.0 should have carried. No code changes with it — the behavior
has been live since 0.168.0; this is the paper trail.
