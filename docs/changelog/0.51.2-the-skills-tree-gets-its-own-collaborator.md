# 0.51.2 — the skills tree gets its own collaborator

Issue #194, part 1. `scaffold.py` was 997 lines. pylint's `C0302 too-many-lines` refuses at
1000, so the file had three lines of room, and the three releases before this one had each
spent some of it: 0.50.0's step 5 hit the same wall in `mcp_index.py` (1053 lines) and split out
`tool_descriptions.py`; step 6 tripped it at 1002 and paid it down by deleting a comment; step 7
landed at 999 by compressing one. Paying rent on a ceiling three times in a row is the signal
that the next feature to touch the file will be the one that has to split it, under deadline.
This splits it first.

Part 2 of the issue — recording "generated, not owned" authorship for the `.mcp.json` family in
`manifest.json` — is a behaviour change and is deliberately **not** in this release. #194 stays
open for it.

## Which seam

The issue nominated the MCP flow as "newest and most separable". That was true when it was
filed and is not true now: 0.51.0 already moved that flow into `mcp_tools.py`, and what remains
in `scaffold.py` is roughly twenty lines — four destination calls in `run()` and three keys in
the adjuster context. Splitting it would have produced a module too small to be worth naming.

The seam taken instead is the `.ai-badger/skills/` tree, the largest single subject left in the
file. Everything that writes to that directory or points anything at it now lives in
`skill_delivery.py`:

| Moved | From |
|---|---|
| `SkillDelivery.scaffold_skills` | `Scaffolder.scaffold_skills` |
| `SkillDelivery.discover_stack_local` | the stack-local loop inlined in `Scaffolder.run` |
| `SkillDelivery._stash_seed_once_files` / `_restore_seed_once_files` | `Scaffolder._stash_seed_once_skill_files` / `_restore_seed_once_skill_files` |
| `SkillDelivery.symlink_hermes_skills` | `Scaffolder.symlink_hermes_skills` (a one-line delegation stays, see below) |
| `relink_hermes_skills`, `_owns_link`, `LEARNED_SKILLS_DIR`, `SEED_ONCE_SKILL_FILES` | module scope of `scaffold.py` |
| `_within` | module scope of `scaffold.py` → `_shared.py` (two readers now: `prune_superseded` and the Hermes namespace containment check) |

One directory, one module: which skill directories land in it, what of the project's own edits
survive a re-copy (#15), and where the tree is republished for an agent that resolves skills
outside the repo (ADR-0003).

docstring, the imports, a class, and two context fields. That is the price of the boundary.

## What made it a pure move

Three small pieces of plumbing, no behaviour attached to any of them:

- **`ctx.record`** joins `ctx.record_template` on `ScaffoldContext`, with the same
  discard-by-default sink. `scaffold_skills` writes manifest entries, and a collaborator reaches
  manifest bookkeeping through the context — never through a sibling.
- **`ctx.reset_seed_files`** likewise: it was a `Scaffolder` attribute, and the seed-once stash
  reads it. `Scaffolder.reset_seed_files` is now the same `_ctx_property` the other run flags use.
- **`relink_hermes_skills` stays re-exported from `scaffold.py`.** `den-refresh`'s `refresh.py`
  loads that module by path and calls the function by name; so do three test modules. The import
  line that brings `SkillDelivery` in brings the function too, at no cost, and no caller had to
  move.

`Scaffolder.symlink_hermes_skills` also stays, as a one-line delegation, for the same reason
`wire_hooks` does: `run()` hands it to `_outside_project`, which is where a failed write outside
the project becomes a note instead of a lost scaffold.

## Proof

- **Behaviour:** full suite green — 2114 passed, 18 skipped (2106 + 18 on `62ac94d`, plus the
  eight new tests). No existing test was edited. The suite that pins the Scaffolder's structure
  (`tests/test_scaffold_context.py`), the Hermes namespace suite
  (`tests/test_scaffold_hermes_namespace.py`, which calls `scaffold.relink_hermes_skills`
  directly), and `tests/test_scaffold_manifest.py` (which monkeypatches
  `scaf.symlink_hermes_skills` to prove a failed home-directory write degrades to a note) all
  pass unmodified.
- **Re-scaffold:** this repo re-scaffolded against itself changes `.ai-badger/manifest.json` and
  nothing else — `generatedAt`, `frameworkCommit`, and the `welcome-ai-badger` skill's content
  hash and file count (15 → 16, the new module). Every rendered file — `CLAUDE.md`,
  `.github/copilot-instructions.md`, `HERMES.md`, the instructions and invariants — is
  byte-identical.
- **Double render:** `.mcp.json` and `.github/mcp.json` are byte-identical across two
  consecutive scaffold runs (SHA-256 compared).

`tests/test_scaffold_skill_delivery.py` is new and was written red: five tests drive
`SkillDelivery` from a hand-built context with no `Scaffolder` in scope, one asserts the
Scaffolder reaches its skills through the collaborator, one asserts the re-export the
`den-refresh` caller depends on, and one pins the line budget —
`test_scaffold_py_keeps_headroom_under_the_too_many_lines_ceiling` fails if `scaffold.py` grows
past 850 lines, so the next release cannot quietly pay rent on the ceiling again.
