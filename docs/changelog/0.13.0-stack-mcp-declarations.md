# 0.13.0 — stack MCP server declarations

## Added

- **`mcp-servers.json` per stack** — declare MCP servers recommended by a stack feature in
  `features/{stack}/mcp-servers.json`. The scaffold collects, merges, and scaffolds them into
  agent-specific config files automatically.
- **Schema** — `schemas/mcp-servers.schema.json` validates stack MCP declarations with fields:
  `name`, `command`, `description`, `env`, `scope` (project/user), `agentOverrides`, `targetAgents`.
- **Agent-specific scaffolding** for MCP servers:
  - Claude: `.mcp.json` (project-scoped) + `~/.claude/settings.json` (user-scoped)
  - Hermes: `.mcp.json` (project-scoped) + `~/.hermes/config.yaml` (user-scoped)
  - Copilot: `.github/copilot/mcp-config.json` (project-scoped)
  - Junie: `.mcp.json` (project-scoped, shared with Claude)
- **Merge semantics** — `externalTools` (user intent) takes precedence over stack declarations
  on name conflict. File-level merge is additive (never overwrites existing entries).
- **`features/common/mcp-servers.json`** — empty baseline for common stack servers.
- **`support.json` updated** — `aiBadgerSupport: true` for all agents' `mcpServers` capability.
- **48 new tests** — 16 schema validation tests + 32 scaffold integration tests.

## Changed

- `_generate_mcp_json()` now reads both stack `mcp-servers.json` files and `externalTools`,
  merging them before writing `.mcp.json`. Existing externalTools behavior preserved.
- `run()` orchestrates additional MCP scaffold steps: Hermes user config, Claude user config,
  and Copilot mcp-config.json generation.
