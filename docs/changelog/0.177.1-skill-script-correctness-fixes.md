# 0.177.1 — five skill-script correctness fixes, and MCP content-block shapes for two hooks

**Patch** — five independent one-function correctness bugs across skill scripts, plus MCP
`CallToolResult` content-block support for the semantica export hook and the memory-grade
hook. 2026-09-24.

## What was wrong

- `code-review-graph/scripts/install.py`'s `ensure_venv` printed the Python 3.10+ interpreter
  `find_suitable_python()` chose, then built the venv with `venv.EnvBuilder`, which always uses
  the *running* interpreter — the printed choice was decorative whenever the two differed.
- `review-tests/scripts/rules_index.py`'s `render_walk_review` sorted every rule in a pass by
  `(order, id)` alone, with no regard for parentage, so a child whose own `order:` value fell
  after a sibling L1 rule rendered under that sibling instead of under its real parent — wrong
  for 21 of 78 children in the committed `walk-review.md`.
- `semantica-knowledge-graph/scripts/export_semantica_graph.py`'s `extract_graph_json`
  recognised only the Hermes `result`/`structuredContent` envelopes and a bare `{"nodes": [...]}`
  dict. A successful export in the standard MCP `CallToolResult` envelope
  (`{"content": [{"type": "text", "text": <graph json>}]}`), or in a bare list of content
  blocks, matched neither and was silently never saved.
- `ai-raccoon-memory/scripts/memory_grade_hook.py`'s `_hook_result` had the same gap: once
  Claude's own MCP `PostToolUse` hooks are active, a `CallToolResult`-shaped or bare-block-list
  result would stash no search sources and lose follow-through tracking.
- `design-tests/scripts/scan_uncontrolled_resources.py` downgraded every `wall-clock-now` hit
  in a C# file to `mitigated` whenever a `FakeTimeProvider` field appeared anywhere in that
  file — including `DateTime.Now/UtcNow/Today`, `DateTimeOffset.Now/UtcNow` and
  `TimeProvider.System`, none of which a fake provider actually intercepts; all of them read the
  real system clock directly.
- `ai-raccoon-manual-checklist/scripts/derive-facts.py`'s `count_attribute_uses` matched the bare
  substring `[McpServerTool`, which also matches the C# SDK's class-level
  `[McpServerToolType]` (and likewise `[McpServerPrompt`/`[McpServerPromptType]`), inflating
  `mcp-tool-count`/`mcp-prompt-count` by one per tool/prompt class.

## What changed

- `install.py` builds the venv with `subprocess.run([py_exe, "-m", "venv", ...])`, matching the
  semantica installer.
- `rules_index.py` gained `_order_by_topology`: roots sort by `(order, id)` as before, and each
  root's children — sorted the same way — are inserted directly after it, recursing for
  grandchildren. `walk-review.md` (and its `skills/`/`.ai-badger/` mirrors) is regenerated.
- `export_semantica_graph.py` and `memory_grade_hook.py` both gained a shared content-block
  unwrapper covering the `CallToolResult` envelope and a bare block list. The real Claude Code
  MCP `tool_response` shape stays **UNVERIFIED** (hooks.md:2004 says only "depends on the
  tool"); starting a real `claude` to capture one is forbidden in this environment, so this
  release covers the two candidate shapes and structures the parser so a captured third shape
  is a new branch and a fixture, never a new caller. A follow-up capture with
  `call-behaviorist` debug logging on is still needed.
- `scan_uncontrolled_resources.py`'s `wall-clock-now` category is now never-mitigable for `.cs`
  files specifically (mirroring how `sleep-or-delay` is already TS-only mitigable); TS's
  `Date.now()`/`new Date()` stay mitigable via `useFakeTimers`, which really does intercept them.
- `derive-facts.py` matches `\[<attribute>\b` instead of the bare substring; the word boundary
  already excludes the `Type` suffix, so no `(?!Type)` lookahead is needed.
