# 0.207.2 — the shared parent scope, reviewed

**Minor** (new capability) · **Date:** 2026-10-19

The shared parent scope (0.207.0) went through a three-lane review after it shipped. The
implementation review and the test-quality lane passed it; the architecture lane found real
defects, and this release is what they turned into. Nothing here changes the design — the
shape of the feature is the one ADR-0041 records.

- **A refusal now writes nothing.** `collect` resolves every member's identity *before* it
  scaffolds the parent or the members, so a member whose identity the canonical lookup
  cannot resolve leaves the collection exactly as it was. Before, the parent was scaffolded
  and the members were listed first, and the refused member was already in the list.
- **The identity is decided once.** The lookup result is now the decision; the write path
  no longer re-runs a lookup that could come back ambiguous and mint an id on the way out.
- **The bank is not written to by default.** A name the bank does not know gets a local id;
  `--register` is the only way the shared scope registers anything with ai-raccoon. A
  collection must not silently register projects in the operator's memory bank.
- **`prune` refuses the last member** instead of failing halfway with an invalid
  configuration and leaving the collection claiming a member it had already detached.
- **A child cannot be enrolled twice.** A child that arrives carrying another collection's
  identity is refused with that collection named, instead of failing later with a link
  error that says the wrong thing.
- **The ownership ledger records paths, not this machine's layout.** A link's source is
  relative to the parent and the collection's own path is relative to the child; the child's
  manifest is a committed file and used to carry absolute paths.
- **The refusal names the command that restores the child**: `collect` for a child that
  carries the union, `sync` for one that carries its own stacks. `sync` used to be named
  for both, and it would have shrunk a union child to its local stacks.
- **The collection's default configuration is the framework's own proposal**, the same one
  `detect.py` prints, instead of a second hand-rolled copy.
- **The "only identical files may link" rule now has a test.** Removing the byte-equality
  precondition used to leave the whole suite green.

The 0.207.0 entry claimed the refusal happened "before anything is written"; in 0.207.0 it
did not. It does now.
