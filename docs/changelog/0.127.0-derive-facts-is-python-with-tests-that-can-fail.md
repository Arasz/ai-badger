# 0.127.0 — derive-facts Is Python, With Tests That Can Fail

**Type:** MINOR
**Date:** 2026-08-16

MINOR rather than PATCH because the shipped file changed name and extension:
`features/ai-raccoon/skills/ai-raccoon-manual-checklist/scripts/derive-facts.sh` is gone and
`derive-facts.py` takes its place. A consumer that scaffolded at 0.126.0 gets a different file on
disk, which is a scaffold-output change, not a content fix.

## The defect

`derive-facts.sh` — the `ai-raccoon-manual-checklist` skill's fact-derivation script — counted the
MCP tool surface with a loose `grep -rho "\[McpServerTool"`. Against AiRaccoon v1.20.0 that
returned 28; the real count, and what the live server reports, is 27.

The 28th match was not an attribute use. `src/AiRaccoon/Tools/McpToolInventory.cs:7` is a doc
comment naming the attribute in prose, because that file *is* the reflection-based tool inventory:

```
///     The MCP tool surface, derived by reflection over this assembly's own `[McpServerTool]`
```

A file documenting the attribute it reflects over is exactly the shape this script exists to
support, so the overcount was not a one-off — any future file doing the same would inflate the
count again. In the run that caught this, the bad count manufactured a phantom "two new tools
since 1.19.1" (only `memory_performance` was added), sending a checklist lane looking for a tool
that does not exist. A derived number that is wrong is worse than a hand-typed one, because it
carries the authority of having been measured.

## The fix, and why it is now Python

The counting rule: match whole lines, drop any line whose trimmed content opens with `///`, `//`
or `*`, and count the attribute occurrences on what remains. Filtering by *comment-line shape*
targets what made the match wrong — it is prose, not code — rather than the shape of the
attribute. Requiring `[McpServerTool(Name` instead (what all 27 happen to look like today) would
also pass now, but it repeats the same failure in reverse: a future tool written as a bare
`[McpServerTool]` would silently *under*count.

Expressed in bash, that rule is three chained greps, and its correctness is only observable by
building a fixture tree and running a subprocess. ai-badger is a Python codebase; the script is
now `derive-facts.py`, with the rule as `count_attribute_uses(source, attribute)` — a pure
function over text, no filesystem, no shell. The CLI contract is unchanged and byte-for-byte
identical: same three stdout lines in the same order, same two stderr lines on failure, same
`exit 1`, same first argument defaulting to the current directory. Verified by diffing both
streams of the old and new scripts against the real AiRaccoon tree (`version=1.20.0`,
`mcp-tool-count=27`, `mcp-prompt-count=2`) and against three failing trees.

The `.sh` is deleted rather than kept as a wrapper. Two copies of a fact-deriving script is
precisely the drift the skill exists to prevent, and a wrapper means a future fix can land in one
and not the other.

## Tests

`tests/test_derive_facts.py` — 30 tests, replacing the four subprocess tests that lived in
`tests/test_ai_raccoon_stack.py`:

- The counting rule, asserted on source text alone: a `///` doc comment in prose does not count, a
  `//` line comment and a `*` block-comment continuation do not count, an indented comment does
  not count, a bare `[McpServerTool]` does count, a named `[McpServerTool(Name = …)]` counts, two
  on one line count twice, and an attribute after code on the same line counts.
- Every failure path — missing csproj, missing `Tools/`, missing `Prompts/`, empty
  `<PackageVersion>`, an unresolved MSBuild property reference, zero tools, zero prompts — exits
  non-zero, prints both stderr lines, and prints nothing to stdout.
- The stdout contract as an exact string, because SKILL.md tells the runner to copy it verbatim.
- One end-to-end subprocess run, so the shebang, exit code and stream split are covered as a real
  invocation.

The doc-comment test was written first and confirmed red against a naive implementation that
counts every occurrence (`assert 3 == 2`).

## SKILL.md

Step 2 now names `python3 scripts/derive-facts.py <repo-root>`. The Gotchas entry that warned
about `grep -c` is rewritten rather than deleted: the underlying trap is a *count that cannot
fail*, and Python has its own silent zeros — `rglob` over a directory that no longer exists
yields nothing and summing an empty sequence is `0`. Neither raises, which is why the script
treats zero as a failure rather than a result.
