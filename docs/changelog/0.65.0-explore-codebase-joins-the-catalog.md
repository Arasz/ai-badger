# 0.65.0 — `explore-codebase` joins the catalog, and `MANAGED_EXTERNALLY` empties

0.63.0 rewrote three of the four skills `code-review-graph` auto-installs — `review-changes`,
`debug-issue`, `refactor-safely` — into the catalog as `optIn` skills this framework owns.
`explore-codebase` was left behind, and became the only member of
`sync_plugin_skills.MANAGED_EXTERNALLY` with no `features/` copy.

That asymmetry had no reason behind it except the order the work landed in, and it was
load-bearing in the wrong place: three tests used `explore-codebase` as their externally-managed
exemplar *because* it was the last one without a catalog copy.

## The skill

A rewrite, not a copy: 80 lines against the original's 28, sharing exactly one line with it
(the frontmatter fence). Same treatment as its three siblings — every step carries a baseline
that needs no graph server, and graph calls are named by shape with an instruction to discover
real tool names from the server's own listing, so the skill is worth its slot in a project with
no MCP servers at all.

Its subject is orientation rather than search: establish the shape, find the module boundaries
the imports actually show rather than the ones directory names suggest, read the entry points,
then follow **one real path end to end** before reading anything else. It ends by requiring the
regions left unread to be named — an exploration that reports only what it found reads as
complete when it is partial.

`optIn`, like its siblings, and for the same reason: a project with `code-review-graph`
installed already receives its version, and shipping ours `default` would put this framework's
symlinks in contention with another tool's files.

## `MANAGED_EXTERNALLY` is now empty, and stays

Every skill it held has been rewritten into the catalog, so nothing is externally managed today.
The constant remains: the next tool that writes its own skills into a project will need it, and
it gates deletion in `_orphans()` as well as writing.

The three tests that named a real skill now supply their own synthetic member instead. They
broke twice for the same reason — the exemplar kept being rewritten out from under them — and
what they test is the mechanism, not the membership. The prune test in particular now proves the
guard still works with an empty set, rather than retiring quietly along with its last entry.
