# 0.152.0 — the runtime stores move to SQLite (P0: store module + task family)

The JSON/JSONL runtime stores behind ai-badger's hooks and tracker CLI move to two SQLite
databases — a project-level `.ai-badger/task-tracking/tracking.db` and a user-level
`~/.ai-badger/ai-badger.db` — behind one stdlib store module, `engine/badger_store.py`,
vendored verbatim into every consumer skill per ADR-0009. ADR-0024 is the decision record;
the schema was ruled by the project's own `sqlite-schema-review` gate (P0.6a) and the built
surface passed an exit review (P0.6b). The committed knowledge log, `config.json`,
`mcp-tools.json`, and the other documented exclusions stay JSON on purpose.

## What changed

- **`engine/badger_store.py` (new).** WAL + `busy_timeout=5000` + `synchronous=NORMAL`;
  `meta(schema_version)` failing closed on newer versions with the upgrade path named;
  call-time env path resolution (`AI_BADGER_TRACKING_ROOT` / `AI_BADGER_USER_ROOT` /
  `AI_BADGER_DEBUG_DIR` — never import-time); lazy migration COMMIT-then-rename with
  idempotent per-family import and a legacy-flock hold; per-key last-write-wins dual-read
  with an open-time resurrection gate (a legacy file newer than the migration stamp fails
  closed — old-code/new-code interleaving is the steady state, not a transition window);
  0600/0700 re-asserted on every open/write including `-wal`/`-shm`; reads fail open; hooks
  never block on store errors; 60-day retention on log tables (hook audit, awm decisions,
  searches — the G0-approved scope).
- **Task family rewired.** `task_tracker.py` CLI (verbs/exit codes identical),
  `tracker_lib.py` (flock+atomic-replace replaced by store transactions; `resolve_own_session`
  order unchanged), the session/user-prompt/stop hooks, statusline capture/poll/wiring, and
  the session-source readers all read/write rows; first write imports the legacy JSON and
  renames it `*.migrated.json`. FINISHED-terminal and the attach-refusal (exit 2) keep their
  application-level checks plus a partial unique index (`tasks(session_id) WHERE state <>
  'FINISHED'`) as defense in depth.
- **marker-state** (prompt-markers hook) moved to the store with the no-creation contract
  preserved — the hook opens the DB only inside an existing `.ai-badger/` — and the
  100-entry audit cap is now test-pinned rather than conventional.
- **Scaffold delivers a managed `.gitignore` block** (`tracking.db`, `*.db-wal`, `*.db-shm`
  anchored to the task-tracking dir; marker-delimited, idempotent merge, refusal on
  unbalanced markers), guarded by the freshness guard as scaffold output.
- **Subagents stay a JSON column** (P0.6a ruling; the revisit trigger and the cheap seam are
  registered in ADR-0024).

## Consumer impact

- Scaffolds gain the gitignore block and the vendored store copies; den-refresh delivers both.
- Legacy JSON files migrate on first write and are renamed, never deleted — delete the DB and
  the runbook (`*.migrated.json` rename-back + lazy re-import) recovers.
- Direct `Read`/`Grep` of the migrated stores no longer works for agents; the tracker CLI,
  hooks, and helper verbs are the surfaces. The knowledge log and plans are untouched.
- `AI_BADGER_DEBUG_DIR` keeps its whole-sink contract (the audit DB derives from it when set).
