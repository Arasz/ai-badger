# 0.187.7 — task-graph launches on every OS

**Patch** (scaffold-affecting) · 2026-10-03

## What changed

- The task-graph launch is now `uv run --no-project python -c <code>`. The code is a stdlib
  walk-up from the session's working directory to the nearest
  `.ai-badger/skills/task-decomposition/scripts/task_graph_server.py`, which it then runs with
  `uv run --script`. It needs no `sh` and no `git`, so a session started in any subdirectory
  works on Linux, macOS and native Windows. It replaces the `sh -c 'cd "$(git rev-parse ...)"'`
  launch from 0.187.5.
- A new `windows-latest` CI job proves the launch on native Windows.
- Hermes now gets the same launch (it had the plain `uv run --script` command) and resolves the
  script from its own working directory.
- `schemas/stack-mcp.schema.json` accepts a server-level `args` array, passed unsplit; when it
  is present `command` is the executable alone. An agent override replaces `command` and
  `args` field by field.
- The task-graph prerequisite now says `uv on PATH`, with no mention of `git`.
- The launch code avoids `"`, `\`, `%`, `^`, `&`, `|`, `<`, `>` and `!`, so Windows command-line
  quoting cannot mangle it; a test pins that.

## Behaviour changes worth knowing

- **Hermes operators must re-merge the entry** in `~/.hermes/config.yaml`. That file is
  operator-owned and is never rewritten, so the old plain command keeps working only from the
  project root.
- **Delete the `task-graph` entry from `.pi/mcp.json` before den-refresh.** Existing entries are
  never rewritten (the `mcp_tools` union merge), so the old `sh -c` launch stays until you do.
- The launch costs about 20 ms and leaves one idle Python process of about 20 MB per session
  (measured on macOS).
- Where `uv` lives in `~/.local/bin`, `.mcp.json` records `${HOME}/.local/bin/uv`, and
  task-graph is then declared only there: one declaration per server (#193). Copilot's
  `.github/mcp.json` gets no entry in that case. Follow-up: #560.
