# 0.51.0 — the MCP catalog carries the instructions

Step 2 of the MCP rebuild [ADR-0014](../adr/0014-mcp-support-is-configuration-not-retrieval.md)
describes. `code-review-graph`'s instruction block moves out of an escaped JSON string inside
`features/common/external-tools.json` and into a real markdown file,
`features/common/mcp/code-review-graph/server.md`.

**Nothing a consumer reads changes.** Re-scaffolding this repository against itself after the
migration changed exactly one line in each of its seven agent files — the version stamp. The MCP
block did not move a byte.

## What shipped

- **`features/common/mcp/code-review-graph/`** — the first catalog entry. `server.md` (the prose
  that reaches every agent file), `meta.json` (the server's identity; `package` moves here from
  `external-tools.json`, because it is a property of the server rather than of one stack's use of
  it), and `tools.json` (curated intent + tags for the five entry-point tools).
- **`features/common/stack-mcp.json`** declares the server with `declare: true`.
- **`{{MCP_INSTRUCTIONS}}`** joins `{{EXTERNAL_MCP_INSTRUCTIONS}}` in the agent templates, and
  `McpTools.fill_mcp_described` fills it from the catalog, finding each server's directory
  through `index.json` — which is what the step-1 feature type was for.
- **Two schemas**, `mcp-server.schema.json` and `mcp-server-tools.schema.json`, so the new
  catalog files are validated by `validate.py --all` like every other catalog file.

## Precedence, stated once

One server, one block, one source. In order:

1. the project's own `config.externalTools` entry, if it names the server — the user's word is
   still the last one;
2. the mcp catalog's `server.md`;
3. the legacy `external-tools.json` `instructions` string.

A server the catalog describes stops rendering its legacy block, so the text cannot appear twice
during the migration. A `stack-mcp.json` entry naming no catalog directory is **reported** rather
than silently dropped: the name is the join between the two files, and a typo in it is otherwise
invisible.

## Why the two slots sit adjacent on one line

`{{MCP_INSTRUCTIONS}}{{EXTERNAL_MCP_INSTRUCTIONS}}`, with no separator. An empty slot on its own
line renders as a blank line, which would have shifted every byte below it. Adjacent, whichever
slot carries the block produces identical output — which is what made a byte-for-byte regression
test possible at all. Step 4 removes the second token and leaves the first.

## `tools.json` has no consumer yet

Said plainly: it is catalog data, and the `mcp-index` overlay that reads it is step 5 of the
build order. Its value rests on a measured fact — a host that defers tool definitions shows the
model tool *names* with no descriptions (ADR-0014 §1) — but nothing in this release reads it.

## Behaviour worth knowing

- Nothing. The launch declaration still comes from the legacy reader, so `.mcp.json` is
  unchanged too; that half migrates in step 3.
- `features/common/external-tools.json` and `features/common/mcp-servers.json` are untouched and
  still read. They are removed in step 4.
