# 0.87.3 — Duplicate `description:` keys fixed, and a lint rule to stop the next one

PR #320 (0.86.0) shipped 20 catalog skills with two `description:` keys in frontmatter: a long,
trigger-oriented first line and a short generic stub second. `badger_lib.skill_description()`
scans for the *first* `description:` line, so `tooling/validate.py`'s `skills_lint` (0.87.0)
validated the good text — but a real YAML parser resolves duplicate mapping keys to the *last*
occurrence, so every agent host reading the file with one saw the weak stub instead. The
skills-lint gate landed one PR after the duplicates and passed the already-defective corpus,
because nothing checked for the duplication itself.

## What changed

- **`skills_lint` rule 11** (`tooling/validate.py`) — rejects a SKILL.md whose frontmatter
  repeats a top-level key. Counts raw `key:` lines rather than parsing YAML (ADR-0005: pyyaml
  stays optional), so the check works without the optional dependency and catches the exact
  divergence that let the 20 files ship: a validator reading only the first occurrence, and a
  YAML-reading host reading the last.
- **20 SKILL.md files fixed** — the short stub `description:` deleted from each, leaving the
  long trigger-oriented description both the validator and every YAML-reading host now agree on:
  `artifact-verification`, `design-gate-audit`, `documentation-drift-audit`,
  `parallel-expert-review`, `research-record-audit`, `review-gate-diff-verification`,
  `sqlite-bank-space-diagnosis`, `sqlite-schema-review`, `dotnet-bdd-testing`,
  `dotnet-flaky-test-diagnosis`, `dotnet-hosted-service-review`, `dotnet-hosted-service-testing`,
  `dotnet-logger-message-design`, `dotnet-mcp-server`, `dotnet-system-commandline`,
  `dotnet-tool-publishing`, `observability-contract-review`, `cron-watchdog-authoring`,
  `hermes-plugin-development`, `mcp-tool-surface-testing`. Six of these had a YAML-resolved
  description that did not start with `Use when`, and so would have failed rule 5 under correct
  semantics: `artifact-verification`, `design-gate-audit`, `parallel-expert-review`,
  `sqlite-schema-review`, `dotnet-hosted-service-testing`, `dotnet-mcp-server`.
- **`badger_lib.skill_description()` left unchanged** — with rule 11 in place a duplicate key
  cannot exist in the catalog going forward, so first-vs-last no longer matters for this
  function; changing its scan order was considered and rejected as solving a problem the new
  rule already forecloses (see the PR discussion for the fuller argument).
- **Tests** — `tests/test_skills_lint.py`: a fixture test for rule 11, and a standalone corpus
  test (`test_real_corpus_has_no_duplicate_description_key`) that counts raw `description:`
  lines per shipped SKILL.md independent of rule 11's own implementation.

## Migration

None — the lint is a gate over the catalog; consumer projects re-scaffold to pick up the
corrected descriptions but nothing behavioural changed in the scaffolder itself.
