# 0.153.0 — the user-level runtime stores move to SQLite (P1: away mode, commit-reminder, feedback)

The user-scope runtime state migrates into `~/.ai-badger/ai-badger.db` (P1 of the 0.152.0
runtime-store migration; ADR-0024): away mode, commit-reminder, grounded-feedback stashes, and
memory-grade search telemetry. Every legacy file is imported on first write and renamed
`*.migrated.json`/`*.migrated.jsonl` — never deleted.

## What changed

- **User-DB schema live.** `awm_state` (per-project keyed), `awm_decisions` (append log,
  ts-indexed), `commit_reminder` + `commit_reminder_pending` (per-project keyed),
  `pending_feedback`, `searches` — all through the same store discipline as P0 (call-time env
  resolution, dual-read, fail-open reads, 0600 incl. sidecars, pre-created before connect).
- **Away mode** (`~/.claude/awm/`): state rows keyed by resolved project root (sibling
  checkouts isolate), decisions append as rows with the legacy line shape preserved verbatim,
  **60-day retention replaces `MAX_DECISION_LINES=5000`** — the prune runs on write, throttled
  to once per hour, and fails open.
- **Commit-reminder + grounded feedback**: `ensure_committed` state and pending stashes become
  per-project rows; the pending-feedback pop (`ai_badger_hooks.py` Hermes path) is a single
  atomic `kv_update` — a stashed message is delivered at most once, and a store failure leaves
  it stashed for next turn.
- **Migrated-file perms (D17):** a renamed legacy file inherits the DB's re-asserted mode —
  a foreign-written laxer-mode legacy file can no longer survive the rename.
- **Log-family import pattern** (new store capability): JSONL families import with `(ts,
  payload)` content dedup, crash-idempotent, torn lines quarantined with the rename.

## Consumer impact

- `~/.claude/awm/state.json` + `decisions.jsonl`, `~/.ai-badger/commit-reminder/*`,
  `~/.ai-badger/pending-feedback.json` migrate on first write and are retired (renamed).
- Old checkouts running against the same user DB keep working through the dual-read window;
  a legacy file rewritten after migration trips the fail-closed divergence guard with the
  upgrade path named.
- Decisions older than 60 days are deleted on the next write — export before upgrading if the
  audit history matters.
