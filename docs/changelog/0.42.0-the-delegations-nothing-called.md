# 0.42.0 — the delegations nothing called

[0.37.0](0.37.0-scaffolder-collaborators.md) moved `Scaffolder`'s work onto six collaborators and
kept five public delegations "for API stability". Its own changelog recorded that only one of them
had a caller and named the other four as candidates for deletion. This release deletes them.

Gone from `Scaffolder`:

- `wire_statusline_capture` → `StatusLineWiring.wire`
- `unwire_statusline_capture` → `StatusLineWiring.unwire`
- `assemble_instructions_doc` → `TemplateRendering.assemble_instructions_doc`
- `assemble_hermes_doc` → `TemplateRendering.assemble_hermes_doc`

`wire_hooks` stays: `run()` calls it, and three test modules reach it through the `Scaffolder`.

## Why they were dead rather than merely unused

Two of the four were bypassed by the class that declared them. `run()` already called
`self.rendering.assemble_instructions_doc(...)` directly, and the tests that exercise rendering
already reached `TemplateRendering` on its own. So the delegation was not an unexercised path — it
was a second name for a path exercised elsewhere, which is the shape that makes a class look larger
than the work it does.

The statusline pair had no caller at all, in the framework or in the suite. `StatusLineWiring` is
reached through `run()`.

## Scope

| | before | after |
|---|---|---|
| `Scaffolder` | 593 lines | **576** |
| public methods | 20 | **16** |

The line count is the smaller half of the point. `Scaffolder` was the knowledge graph's top hub
largely because its constructor was pinned 110 times across 24 test files; the shared test factory
that landed first is what made this deletion a one-file change rather than a survey of everything
that might name these methods.

## The check that keeps them gone

`tests/test_scaffold_context.py` already pinned the nine private MCP shims retired in 0.37.0. The
four public delegations join them under the same shape: a named set asserted absent from
`vars(Scaffolder)`, plus a positive assertion that `wire_hooks` is still there. A future refactor
that re-adds a pass-through gets a failing test naming it.

## Upgrading

Nothing required for consumers. Nothing in the framework, the plugin, or any scaffolded project
called these methods — they were reachable only by importing `scaffold.py` and calling them by
hand. Code doing that should call the collaborator instead: `scaf.statusline.wire()`,
`scaf.statusline.unwire()`, `scaf.rendering.assemble_instructions_doc(...)`,
`scaf.rendering.assemble_hermes_doc(...)`.

The minor bump reflects the removal of public names, not a behaviour change: no scaffolded output
differs, and no re-scaffold is needed.
