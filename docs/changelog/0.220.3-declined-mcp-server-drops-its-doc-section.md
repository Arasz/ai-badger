# 0.220.3 — a declined MCP server loses its instructions section; ai-badger drops its own Hermes stack

**Patch** · **Date:** 2026-11-13

- A server named in `config.mcp.decline` no longer gets a `## MCP Tools: <name>` section in the
  generated agent files. Before, the decline removed the launch config but every agent file still
  told the agent how to use the refused server.
- This repository no longer scaffolds itself with the `hermes` stack or the `hermes` agent, and
  declines the `hermes` MCP server. `HERMES.md`, `.hermes.md`, the `hermes-agent-author` persona,
  the `hermes-plugin-development` skill and the hook copies only the Hermes adjustment delivered
  are gone from the tree. The `features/hermes/` catalog is unchanged; consumers are not affected.
- Removing an agent or a stack now removes every copy of its discovery files. The manifest
  records the `.ai-badger/` source-of-truth copy (`aibCopy`), the alias (`alsoTarget`, such as
  `.hermes.md`) and each Copilot `.github/instructions/<name>` copy, so the stack prune reaches
  them. Before, only the primary file (`HERMES.md`) was recorded and the copies stayed. An edited
  copy is kept and reported, the same as any other pruned file. A project that dropped a stack
  before this release has no record of the old copies: delete them by hand.
- The `.ai-badger/` source-of-truth copy is recorded with `editable: true`, so the edit guard
  still allows edits to it. A pruned file that holds `ai-badger:keep` regions is left in place
  and reported, because a refresh carries those regions into the rewrite and its `outputHash`
  then matches.
