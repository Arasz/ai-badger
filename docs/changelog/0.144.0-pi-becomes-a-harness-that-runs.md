# v0.144.0 — pi becomes a harness that runs (2026-08-29)

0.141.0 shipped pi support that could not work: the hooks adapter extension
was never written, so the installer copied an empty directory and reported
success, and the cron extension registered a script that did not exist and
wrote a launchd plist with no scheduling key. Review found eighteen defects.
This release fixes them and closes the gaps that stood between pi and daily
use.

## The two blockers

- The hooks adapter extension now exists, at `features/pi/adjustments/adapter/`.
  It translates pi's `tool_call` into the payload ai-badger's real gates parse
  and runs each matching PreToolUse command: deny blocks with a reason, ask
  goes to `ctx.ui.confirm` behind `ctx.hasUI`, approve passes through.
- Cron can fire. `run-job.ts` ships and exports `default {scheduled()}`, the
  plist carries `StartCalendarInterval`, `launchctl bootout` runs before every
  load so an edited schedule stops firing the old definition, and the stale-job
  prune scans both label prefixes instead of one.

The plan named `ai_badger_hooks.py` as the adapter's shell-out target. That
module is a Hermes plugin with no `__main__` and no stdin read — it would have
exited 0 and gated nothing. The real seam is the gate list in
`.ai-badger/hooks/hooks.json`, which the adapter reads rather than keeping a
second copy to drift from it.

## Silent failure, everywhere it was found

- `adjust_hooks` and `adjust_cron` both returned `[]` and reported success when
  their source directory was missing. Both now fail loud, naming the path.
  Partial success stays honest: hook scripts that did land are still reported.
- A hook gate that times out, exits non-zero or prints non-JSON now notifies on
  every occurrence and allows. A gate that fails must not fail silently.
- Writing to a gate that exits before reading stdin raised an unhandled EPIPE
  inside pi's process. Found by running the adapter against this repo's real
  gates rather than mocks.

## Things that were claimed but not true

Measured against installed pi 0.84.3:

- The task tracker's resume command was `pi -p --resume <id>`. `--resume` takes
  no argument, so it could never have worked. It is now `pi -p --session <id>`.
- `support.json` claimed pi loads skills "79/79 unmodified from
  `.claude/skills/`". pi does not read `.claude/skills/` at all.
- It also claimed 34 hook events and a superset of Claude's. The count is
  unstable across counting conventions; both claims are gone.
- `customAgents` cited `*.agent.md`. That is copilot's convention; pi matches
  plain `*.md`.
- `pi.instructions.md` carried five more claims that did not survive checking.

## Gaps closed

- **Skills reach pi at all.** `adjust_skills.py` merges the project's skills
  path into pi's user-global settings through a new `pi_settings.py` whose
  writes are atomic, idempotent, and preserve keys it does not understand.
  User-global is deliberate: `trust.json` does not exist here and
  `defaultProjectTrust` is unset, so pi's headless modes ignore project
  resources entirely — a project-scope write would have done nothing.
- **MCP servers are applied**, not just proposed, when installing.
- **Away mode** (`AI_BADGER_PI_AWAY=1` or `/away`) auto-approves explicit "ask"
  decisions only — never an error, never a missing gate — and notifies on each
  one so the trail is auditable. Default off, session-scoped, nothing persisted.

## Two defects that only pi could expose

- **pi was never in this repo's own `config.agents`.** Every pi adjustment begins
  `if "pi" not in config.agents: return applied=False`, so all of it was inert
  here and no extension was ever installed. Registered with no agent — the same
  shape of defect as the rest of this release, one level up. pi is now listed.
- **Re-scaffolding grew `AGENTS.override.md` without bound.** `carry_keep_regions`
  appends the existing file's preserved blocks to the freshly rendered body, which
  is right until a template ships a keep region of its own — and pi's
  `AGENTS.override.md.tmpl` is the first that does. Run N produced N copies.
  Preserved regions now fill the template's own slots, and only regions the body
  has no slot for are appended. The scaffolder's "idempotent, safe to re-run"
  contract holds again, and the freshness guard stops failing for anyone with pi
  enabled.

## Personas that run

- `adjust_agents.py` writes each scaffolded persona to `<project>/.pi/agents/<name>.md` — a plain `.md`, which is what pi's agent discovery matches. Only `name` and `description` survive: a persona's `model` and `tools` are Claude's vocabulary and would be rejected by the delegated pi process. A missing `.ai-badger/agents/` is an `ERROR:` note naming the path.
- `features/pi/subagent/index.ts` is ai-badger's own subagent extension, installed user-scope by the same arm. It registers one `delegate` tool that spawns `pi -p` with the persona body appended to the system prompt, and reads `<cwd>/.pi/agents/*.md` itself through `node:fs` — project-local resources are trust-gated and pi ignores them under `-p` without a saved decision, so reading them directly is what makes the personas live headless.
- `support.json`'s pi `personas` and `customAgents` rows stop claiming support ai-badger did not ship and name the arm that now provides it.

## Also

- `adjust_mcp` splits commands with `shlex`; an unbalanced quote raises rather
  than silently mangling the command.
- A vendored `node_modules` under `features/` is no longer treated as catalog
  content. `features/pi` carries a bun/tsc gate, and running it used to turn
  the Python suite red — the two gates could not both be run in one tree.
- Dead helpers removed: `adjust_hooks._framework_version`,
  `adjust_mcp._yaml_block`.
