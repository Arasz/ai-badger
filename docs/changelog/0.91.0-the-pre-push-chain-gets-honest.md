# 0.91.0 — the pre-push chain gets honest, and the gates that existed start blocking

Four gates in this repo were written, tested, documented, and then wired to nothing. This
release connects them, and corrects the one number the gate chain told about itself.

## The gate chain was lying about its own cost

`.lefthook/pre-push/verify.sh` carried a comment reading "pytest is 49s of a 75s gate", and
`tests/test_verify_gate.py` restated it as "the twelve non-pytest lanes total 14s, pylint 12s,
pytest 49s". Measured end to end on 2026-08-07 against `43fbfb49`, with
`/usr/bin/time -p ./.lefthook/pre-push/verify.sh all`:

```
  ✓ version-sync   0s      ✓ paths          0s      ✓ js             3s
  ✓ index          0s      ✓ validate       0s      ✓ pylint       104s
  ✓ plugin-skills  1s      ✓ scaffold       3s      ✗ pytest       664s
  ✓ deps           0s      ✓ tdd            1s
  ✓ docs           1s      ✓ release        1s      real 778.54
```

**778 seconds, not 75.** pytest alone is 664s of it — 85% of the gate. The recorded
"pre-push gets SIGKILLed" pattern is wall clock, not memory; nothing here was tuned for memory.
Both comments now carry the measured figures and name the date and commit they came from.

`pylint` is now run with `-j 0`. Measured back to back on the same machine over the same 234
files: **232s serial against 62s parallel**, identical verdict. CI runs it the same way.

## `--risk` finally buys something

`task_tracker.py start --risk` has parsed, persisted and printed the flag since 0.71.0, and
nothing has ever read it back. `verify.sh pre-push` now asks
`.lefthook/pre-push/risk_mode.py` whether the branch being pushed belongs to an unfinished
`--risk` task, and drops the `pytest` lane when it does — the 664s one, and the only one whose
removal moves the number. The cheap lanes and the lint/rule check still run, which is what
`skills/task/SKILL.md` has always promised. A reduced run says so, names the task, and repeats
that the full suite is still owed before integrating.

Every failure mode of the query — no tracker, no branch, corrupt JSON, a finished task, no
python — resolves to the full gate.

## Both `.mjs` validators now run in a gate

`validate-agent-instructions.mjs` and `check-agent-drift.mjs` ran in no gate at all: only their
unit tests did, while the skill's own description advertised "when validation/drift checks fail
in CI". They now run in the `validate` lane and in `.github/workflows/pylint.yml`, so drift
between `.ai-badger/agent-instructions/model.json` and the files it describes fails a push and
a build.

### and they no longer hang on a seven-character pattern

`compilePattern` capped pattern *length* at 500 characters and handed anything shorter straight
to `new RegExp`. `^(a+)+$` is seven characters. Run against a 41-character non-matching input it
was still running when a 15-second timeout killed it — measured, not inferred. `0.25.0`'s
changelog claimed this was fixed; it was not.

Node has no regex timeout, so the pattern is refused rather than run: a quantifier applied to a
group is rejected at compile time, with the offending pattern named in the message. No pattern
in any shipped model uses one. Both validators carry the identical guard.

## `gitleaks` blocks

The `Secret scan` workflow existed and its job could be red while a PR merged anyway — which is
how #325 landed. `gitleaks` is now a required status check on the default-branch ruleset.

The duplicate trigger goes with it: `push: '**'` plus `pull_request` ran the scan twice for
every PR branch. `pull_request` is the trigger a required check is evaluated on and the only one
that reaches a fork, so it stays; `push` narrows to `main` so a merge is still scanned. A branch
pushed and never opened as a PR is the deliberate gap.

## A patch bump no longer nags

The scaffold-freshness guard tolerates stamp-only differences by design — its docstring says "a
version bump alone must not fail this". The drift notice disagreed, firing on any string
difference, so every patch release told every consumer to re-scaffold into a diff containing
nothing but stamps. Both hosts now compare `(major, minor)`: a patch-only difference is silent,
anything else still fires, and an unparseable version on either side falls back to string
inequality rather than going quiet on garbage.

## The repo-structure tests stop reading the working tree

`tests/test_docs_tree_is_canonical.py` enumerated the live `docs/` directory during a
thirteen-minute suite, so any concurrent write turned it red and pointed at documentation
instead of the race. The two map checks now read `git ls-tree HEAD`. `.tmp/` is gitignored and
still read from disk, which is the only place git cannot answer.
