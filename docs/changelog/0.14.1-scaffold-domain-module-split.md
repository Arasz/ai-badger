# 0.14.1 — scaffold.py domain module split

Refactored `features/common/skills/welcome-ai-badger/scripts/scaffold.py` (1455 lines) into
six focused domain modules using a mixin pattern:

| Module | Domain | Lines |
|--------|--------|-------|
| `scaffold.py` | Entry point, Scaffolder core, CLI | ~600 |
| `mcp_tools.py` | MCP server + external tool management | ~350 |
| `hook_wiring.py` | Hook wiring into .claude/settings.json | ~145 |
| `template_rendering.py` | Doc slot computation + template rendering | ~105 |
| `agent_files.py` | Agent file scaffolding via scaffolding.json | ~130 |
| `extensions.py` | Extension parsing, merge, embed, prune | ~215 |

No behavior change — all 596 tests pass unchanged. The Scaffolder class inherits from all
mixin classes, preserving the public API. The `merge_hooks()` standalone function is now
exported from `hook_wiring.py` (re-exported by `scaffold.py` for backward compatibility).

## Why

scaffold.py was the largest file in the codebase at 1455 lines, containing 5 distinct domains.
Splitting by domain makes code review, maintenance, and testing easier.

## How

- Mixin pattern: each domain module exports a mixin class (e.g. `McpToolsMixin`)
- `Scaffolder` inherits from all mixins: `class Scaffolder(McpToolsMixin, HookWiringMixin, ...)`
- `scaffold.py` adds `_SCRIPT_DIR` to `sys.path` so mixin imports resolve when loaded dynamically
- Both `features/` and `.ai-badger/` copies are kept in sync
