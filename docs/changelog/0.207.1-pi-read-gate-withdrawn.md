# 0.207.1 — the pi read gate is withdrawn: text search is the subject

**Patch** (correction) · **Date:** 2026-10-19

0.206.0 shipped a vendored pi adapter that redirected pi's `read` tool to the
memory-first gate. That was the wrong mapping: `read` is a file view, not a text
search, and a read of a known path is not a query the bank can answer better
than the file itself. The gate's subject is a search.

In pi the text-search tools are `grep` (file contents), `find` (file names) and
greps inside bash. The adapter already maps them to Claude's `Grep`/`Glob`/
`Bash`, which the shipped gate's matcher covers — so those calls were already
redirected to the ai-raccoon bank, with the pattern as the query and the result
in the same JSONL log. No extension change is needed for them; a test now pins
the mapping so it cannot drift silently.

- The vendored pi adapter drops the read gate: no extra bank search per file
  read, and no blocked first read.
- The pi-side test suite pins the contract: pi's `grep`, `find` and `bash` reach
  the shipped memory-first gate, `read` does not, and the search pattern reaches
  the gate as the pattern.
