# 0.167.0 — quick-task skill: the branch+PR fast lane with auto-merge

**Minor** — changes scaffold output shape (default skill rewrite). 2026-09-08.

The `quick-task` skill no longer ships changes as a single commit pushed straight to
`main`. It now cuts a branch from freshly pulled `main`, carries the work as exactly
one commit in the PR, and auto-merges on all-green with rules bypassed — never waiting
for review.

## Changes

- `quick-task` flow rewrite. The shape is unchanged (one sentence, one surface, one
  commit, reversible, no rulings needed — all five, or escalate to `task`), and the
  minimal three-to-six-bullet plan, TDD touched-surface tests, fast gate, and one
  focused review before the push all stay. What changed around them:
  - Never on `main` — `git pull`, then `git checkout -b <short-slug>`. No worktree
    isolation: a quick-task owns one branch in the current checkout.
  - Single commit per PR — code, tests, docs, version bump (when applicable), and
    regenerated artifacts together; post-push fixes amend + force-push with lease,
    never stacked fixups.
  - Version bump only when the repo has no auto-bump chain. When release-please,
    semantic-release, or a CI bump step owns `VERSION`, the bump is skipped (a hand
    bump collides with the chain) and the PR body says so.
  - Docs update in-branch, same PR, same commit — including the ledger/record step.
  - PR opened immediately after pushing; auto-merge enabled at open time. All-green
    merges itself; red stops the line until the branch is fixed. The pre-push review
    was the review — a green quick-task PR never waits for eyes.

## Upgrade notes

- No action required: `scope: default` ships the rewritten skill to every scaffolded
  project on the next `den-refresh`; the Claude Code plugin copy lands under
  `skills/quick-task/`.
- In-flight quick-tasks committed straight to `main` under the old shape keep working;
  new ones follow the branch+PR shape.
