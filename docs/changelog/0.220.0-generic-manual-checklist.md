# 0.220.0 — The manual checklist is generic; each project owns its checks

**Minor** · **Date:** 2026-11-12

The AiRaccoon-only manual checklist is now a project-agnostic skill, `run-manual-checklist`. The
framework ships the rules and the mechanics. Each project keeps its checks in its own checks file
(default `docs/checklist/checks.json`), and a refresh never writes that file. ADR-0050 records why
(`docs/adr/0050-manual-checks-are-project-owned.md`).

## Added

- **`run-manual-checklist`** (common, `scope: optIn`). The general rules for a manual check:
  record evidence, derive facts and never pin them, make every item able to fail, never inherit a
  prior verdict. The skill requires the checks-file path as input. `init` is the procedure the
  agent follows to write a project's first checks file.
- **`scripts/checklist.py`** (stdlib only):
  - `check` validates a checks file.
  - `new-run` writes a dated run file and derives every fact by running its command. It fails
    loudly when a command errors or prints nothing, or prints `0` for a fact marked `nonzero`.
  - `report <run> --checks <checks>` validates a filled run against the checks file and prints
    the counts, every fail, every rejected result and the pending acceptances. Exit 0 done,
    1 incomplete, 2 usage, 3 acceptances pending, 4 some results rejected.

## Removed

- **`ai-raccoon-manual-checklist`** and the **`ai-raccoon` stack**. The 44 AiRaccoon items, the
  fact script and the embedding stub move to the ai-raccoon repository.

## Upgrade notes

- A refresh prunes an unedited copy of `ai-raccoon-manual-checklist`, because its catalog source
  is gone. A project that used it must do two things before it re-scaffolds: create its checks
  file, and add `run-manual-checklist` to `include.skills`. A config that still lists the
  `ai-raccoon` stack must drop it.
