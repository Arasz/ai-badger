# 0.99.0 — a gate nobody enumerates, and a fix that landed on the dead branch

A mutation audit of the suite at 0.97.0. The method was not reading: every finding below was
confirmed by breaking the production code, watching the test stay green, and reverting. Ten
confirmed survivors, all fixed here.

## 0. The isolation floor watched the wrong checkout

The worst of them, and the one that drew blood during the audit itself.

`tracker_lib.collapse_worktree` sends a linked worktree's tracking writes to its **checkout**,
by design. Every isolation fixture in `tests/conftest.py` was anchored on
`Path(__file__).resolve().parents[1]` — the worktree the suite is running from. When the suite
runs from `.ai-badger/worktrees/<name>/`, as it does for every task, those are different
directories, and the one holding live state is the one nothing watched.

A mutation run during this audit dropped the `CLAUDE_PROJECT_DIR` override from
`resolve_project_root`. `test_registering_a_session_lands_outside_the_real_project` then wrote
`current-session.json` into the real checkout for real, and all fifteen tests in
`TestTheSuiteCannotWriteToTheRealTrackingDir` passed. `_real_tracking_state_is_untouched`
passed too: `save_json`'s attribution marker compares the write path against a single
`AI_BADGER_REAL_ROOT`, which was the worktree, so the write was never even marked.

Measured after the fix, against the exact path that leaked:

```
the path the mutation really wrote: <checkout>/.ai-badger/task-tracking/current-session.json
  OLD floor (worktree only)    -> marked=False
  NEW floor (REAL_WRITE_ROOT)  -> marked=True
```

`REAL_CHECKOUTS` now holds this tree and the checkout it collapses to; `real_tracking_files()`
walks both; `AI_BADGER_REAL_ROOT` is set to the outer of the two, and a new test asserts that
containment rather than assuming it. A third asks `collapse_worktree` where a write from here
would land and fails if no fixture watches that directory.

This is #222's own guard failing for the reason #222 was filed.

## 1. A runnable gate that no enumeration finds

`tests/test_every_check_can_fail.py` exists to prove every gate in this repo has a provoked
failure path. It discovered gates by asking for a top-level `main()`, and its own oracle —
`test_discovery_still_finds_every_runnable_gate` — globbed `gates/*_guard.py`. Two different
conventions, and a gate satisfying neither fell through both at once.

Measured: a file `gates/probe_lint.py` with a shebang, an `if __name__ == "__main__":` block
and an entry point named `run()` was added to `gates/`. `test_every_check_has_a_provocation`,
`test_discovery_still_finds_every_runnable_gate`, `test_registry_names_only_checks_that_exist`
and the whole of `tests/test_gates_layout.py` stayed green. Renaming the same file to
`probe_guard.py` turned the oracle red — so the coverage rested entirely on a filename.

`gates/skills_lint.py` already breaks that convention: it is a gate, it is not `*_guard.py`,
and `tests/test_gates_layout.py` carried a hand-maintained `GATE_NAMES` tuple to compensate.
A hand-maintained enumeration of what a mechanical check missed is the defect, not the repair.

Discovery now asks for a top-level `if __name__ == ...` block — what actually makes a file
runnable — and the oracle compares that against an independent signal, the shebang an author
writes on a CLI and omits on a helper module. Both directions fail: a gate with a shebang and
no `__main__` block, and a `__main__` block with no shebang, each produce a named disagreement.
`tests/test_gates_layout.py` iterates the same shebang enumeration, keeping `GATE_NAMES` only
as a floor.

One net did catch the stray gate: `test_docs_match_the_catalog.py::test_every_script_is_named`,
which requires `docs/` to name every script under `gates/`. The gate-enumeration tests did not.

## 2. The dot-directory rule landed on the branch that never runs

`tooling/validate.py:candidate_stack_dirs()` reads `features/` from HEAD wherever git can
answer, and falls back to the working tree only for a root with no index. 0.93.1 added the
rule that a dot directory under `features/` is not a candidate stack — to the fallback branch
only. Every real checkout has an index, so the branch carrying the fix never executes here.

Its test, `test_a_dot_directory_under_features_is_not_a_candidate_stack`, builds a bare
`tmp_path` with no `git init`, so it exercises the same dead branch. Its docstring says so.

Measured, on a git checkout with a committed `features/.ai-badger/config.json`:

```
candidate_stack_dirs: ['.ai-badger', 'python']
catalog_stack_gaps : ['features/.ai-badger: no stack.json and no feature directory, ...']
```

The leading-dot filter now applies to both branches, and a new test builds the checkout with
`_committed_catalog` so the git path is the one under test.

## 3. A guard no fixture could reach

`gates/skills_lint.py:frontmatter_fields()` refuses a `metadata:` key that carries an inline
value alongside an indented block. Deleting `if entry.inline: return None` changed no test's
verdict: every fixture writes the canonical bare `metadata:`, where the block-reader already
refuses on its own, so the guard was doing no work in any test. On the shape it exists for,
the mutant returned a full, "valid" field dict and rule 10 fell silent.

## 4. A check that quietly stops running

`test_docs_only_change_skips_the_expensive_lanes` searched the last 40 commits for a docs-only
one and `pytest.skip`ped when it found none — measured at depth 11 on 2026-08-07, so the check
was some weeks of history away from disabling itself and reporting green. The invariant is now
asserted over a synthetic path list through `verify.sh lanes-for`; the history-mined version
survives as a corroboration that the two entry points agree.

## 5. Containment tested only against payloads that escape outright

Two path-containment predicates, both security-shaped, both tested only with inputs that leave
the parent entirely — which a naive string-prefix comparison rejects just as well. So the
boundary each one exists for was never exercised.

- `_shared._within` (and `drift.py`'s copy of it). Replacing `relative_to` with
  `str(candidate).startswith(str(parent))` left all 14 tests in
  `tests/test_scaffold_hermes_namespace.py` green. The only payload was `../../escaped`; the
  reachable exploit is a sibling like `~/.hermes/skills-evil`, which *does* start with
  `~/.hermes/skills` without being inside it.
- `generated_file_guard._under`. Dropping the `+ "/"` boundary left all 18 tests in
  `tests/test_generated_file_guard.py` green, while `.ai-badger/skills/task-force/x.py` began
  matching the manifest entry for `.ai-badger/skills/task`.

Both predicates were already correct. Both now have the sibling case.

## 6. Two of nine variables asserted, and the load-bearing one not among them

`test_run_git_drops_the_variables_that_pin_git_to_another_repository` named `GIT_DIR` and
`GIT_INDEX_FILE`. Deleting `GIT_WORK_TREE` from `badger_lib.GIT_LOCATION_ENV` — the variable
that most directly overrides the work-tree root, and the closest match to the failure that
module's own docstring describes — left `tests/test_git_invocation.py` green. The test now
exports every name in the tuple and asserts every one is stripped.

## 7. A scanner that saw one spelling of the thing it forbids

`test_no_shipped_script_invokes_git_outside_run_git` walks `engine/`, `tooling/` and `gates/`
for raw git calls. It matched `subprocess.run` with a list literal and nothing else. A real
stray file dropped into `gates/` scanned clean as `subprocess.run(("git", ...))` (tuple argv)
and as `subprocess.Popen(["git", ...])` — both inherit `GIT_DIR` exactly as the forbidden shape
does. The scanner now covers `run`/`call`/`check_call`/`check_output`/`Popen` over lists and
tuples, and four parametrised tests pin each spelling. The real tree is still clean under it.

## 8. A worktree guard with no non-project checkout to guard against

`collapse_worktree` only redirects a worktree whose checkout is itself an ai-badger project —
a vendored project nested in someone else's repo stays put. Deleting that guard changed no
verdict across `test_tracker_state_stays_out_of_the_catalog.py` and
`test_tracker_store_is_shared_with_the_checkout.py`: every worktree fixture's checkout already
carried the marker, so the branch was never taken. A vendored-project fixture now exists.

## 9. A hook argument nothing passed

`ai_badger_hooks._project_cwd` returns `cwd or os.getcwd()`. Every test in
`tests/test_hook_cwd_resolution.py` sets the process directory with `monkeypatch.chdir` and
passes no `cwd` — that is the file's whole point, since Hermes sends none — so swapping the
operands to `os.getcwd() or cwd`, which ignores the argument entirely, changed no verdict. A
Claude host always does send one. One test now passes an explicit `cwd` from a different
working directory and asserts it wins.

## 10. A defence asserted through the wrong mechanism

`scaffold_freshness_guard.rescaffold` points `$HERMES_HOME` at a throwaway directory before
re-running the scaffolder, and `test_the_gate_never_writes_into_the_operators_hermes_home`
watches a seeded `~/.hermes` to prove the user scope is left alone. Deleting the `$HERMES_HOME`
line leaves that test green: the re-scaffold also runs with `--no-install`, which already skips
every Hermes write path, so the outcome is identical either way and only `--no-install` was
ever under test.

No outcome can separate the two while `--no-install` holds, so the belt is now asserted on the
mechanism: the env the re-scaffold actually passes, checked to point outside the operator's
home. A white-box assertion, and labelled as one — the alternative was to keep crediting a line
nothing exercised.

## What the audit cleared

The three failures named in the audit brief were re-checked by mutation and are genuinely
fixed. Removing the `--risk` narrowing from `verify.sh` fails
`test_a_risk_task_drops_the_slow_lanes`; widening `RISK_DROPPED_LANES` to swallow the cheap
lanes fails `test_a_risk_task_keeps_the_cheap_lanes`. Both now measure the flag against the
same tree with risk off, so the file-type narrowing can no longer stand in for it.
