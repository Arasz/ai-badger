# 0.34.1 — a hook never breaks a session, and a gate that says so before you push

## The Hermes sync plugin degrades to silence

`features/common/hooks/learned_skills_sync.py` resolved the framework root **unguarded at module
scope**, so on a machine where no root resolves, importing it raised and the plugin failed to
load. Its sibling `ai_badger_hooks.py` — copied into the same `~/.hermes/plugins/` directory by
the same adjustment — already had the guard, with the contract stated in its own comment: *a hook
degrades to silence; it never breaks a session.* Two files installed side by side disagreed about
whether that rule applied to them.

Hermes catches the failure and logs a warning, so no session ever died. What died quietly was
learned-skills sync, behind one log line nobody watches.

The trigger is narrow but real: the plugin file exists (a scaffold ran), the recorded
`frameworkRoot` no longer resolves, no `$AI_BADGER`, no `~/.ai-badger/framework`. The realistic
path to the second condition is scaffolding from a versioned plugin-cache directory that is later
pruned, or from a temp clone or a removed worktree.

Each entry point now degrades according to its own contract rather than uniformly:

- **`on_skill_manage` returns `None`** — the hook path. `ai_badger_hooks` already treats `None` as
  "nothing happened", so this adds no state and no log noise.
- **`sync_skill` refuses.** Without `unsafe_literals` there is no evidence a skill is safe to
  copy, and refusing is the only safe reading of that.
- **`main()` prints an error and exits 1.** A CLI is not a hook: an operator who typed
  `--reconcile` must not get an empty summary that reads as a clean run.

`scan_for_unsafe_literals` is deliberately left unguarded. Returning `[]` would mean "no unsafe
literals found" when the scanner is merely absent — the exact wrong failure for a security gate.
Every in-tree path reaches it through `sync_skill`, which refuses first.

**The guard against recurrence is a parity test**, not a fix to one file: an AST check requiring
every module-scope `_bootstrap_lib()` call in `features/common/hooks/` to sit inside
`try/except RuntimeError`. A third hook file added later is covered automatically. The defect was
never one missing `try` — it was that two files could disagree at all.

## A pre-push quality gate

`lefthook` runs the full gate before every push: `pytest`, `pylint`, the eight JSON/doc/dependency
guards, the JS suite, `tdd_guard` and `release_guard`. **71s cold, 31–44s warm**, with change
detection so a docs-only push skips the expensive lanes.

**It verifies; it never edits.** A pre-push hook cannot bump `VERSION` — by the time it runs the
commits are fixed, so mutating the tree yields a dirty working copy plus a pushed commit lacking
the bump. `release_guard` is what makes the step unskippable, and it is wired in as a lane. This
release exists because that lane blocked a push on its first live run, having caught a shipped
surface change that had already been merged past a tag.

**Existing hooks were left alone.** `lefthook.yml` configures only `pre-push`, so the Python
pre-commit framework and the code-review-graph hook it chains to still fire; `lefthook install`
would otherwise have renamed the chain to `.old` and silently stopped it. `doctor` asserts this
permanently and fails if a `.old` hook ever appears.

Three escape hatches, printed in the failure block itself — `VERIFY_SKIP=<lane>`, `SKIP_VERIFY=1`,
`git push --no-verify`. A gate that cannot be bypassed in five seconds under pressure gets
uninstalled, and an uninstalled gate is silent coverage loss.

CI is unchanged. The cheap always-on checks stay where they cannot be bypassed.

### Three defects the gate found by being run

Reading the config would not have caught any of them:

- **Lanes inherited `GIT_DIR`/`GIT_INDEX_FILE` from the hook**, so tests that build throwaway
  repositories operated on the real one. It rewrote a checkout's index and left `core.bare=true`
  behind. The hook environment is now dropped after the root is resolved.
- **`pylint` reported a green 0s pass having linted nothing.** An empty file list now fails.
- **A shared log directory** meant the `pytest` lane overwrote the very log the failure block
  cited. Logs are keyed per checkout.

## Upgrading

Nothing required. To adopt the gate locally: `brew install lefthook && lefthook install`. Read
`docs/research/2026-07-27-lefthook-quality-gate.md` §2 first if you have your own hooks installed.
