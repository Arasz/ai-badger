# 0.122.0 — the floor claim was false

`engine/requirements.txt` has declared `jsonschema>=4.26.0` since that pin landed, and that
release requires Python >=3.10. Every doc, docstring and `pyproject.toml` in this repo still
claimed a 3.8 floor. A user on 3.8 or 3.9 following the documented
`pip install -r engine/requirements.txt` got `No matching distribution found for
jsonschema>=4.26.0`, not a package — proven by a CI run on this repo, where pip on the 3.8 and
3.9 legs reported exactly that. CI only looked green because `.github/workflows/pylint.yml`
hand-installed a bare, unpinned `jsonschema` instead of reading `engine/requirements.txt`, so the
matrix never exercised the real install path.

The owner decided: drop 3.8 and 3.9, the floor is now **Python 3.10**. `pyproject.toml`'s
`py-version`, `.ai-badger/config.json`'s `project.summary` (and everything it generates —
`CLAUDE.md`, `HERMES.md`, `.hermes.md`, `copilot-instructions.md` and their `.ai-badger/` and
`.github/` copies), `engine/badger_lib.py`, `CONTRIBUTING.md`, `docs/scripts.md`,
`docs/getting-started.md`, `SECURITY.md` and `gates/deps_guard.py`'s docstring now all say 3.10.
ADR-0007 keeps its original "Python 3.8 floor" text as the historical record and carries an
amendment recording why and when it changed.

`tests/test_python_floor.py` — the local tripwire this claim is enforced by — moves with it:
`METHODS_ADDED_AFTER_3_10` drops `removesuffix`/`removeprefix` (3.9+, now within the floor) and
starts empty rather than guessing at a future stdlib addition; its mechanism test now exercises
the detector with a synthetic banned name instead of depending on a real one staying accurate.
Two docstring-only comments (`gates/release_guard.py`, `gates/deps_guard.py`) that justified a
workaround by citing the old floor were reworded rather than made to claim a new number they
were never really about.

**Not touched:** `.github/workflows/pylint.yml`'s CI matrix (a parallel change owns it) and
`engine/requirements-dev.txt` (owned elsewhere). `docs/changelog/` entries that describe what was
true at an earlier release, and the dated planning notes under `docs/work/`, are left exactly as
written — they are records of the past, not live claims.
