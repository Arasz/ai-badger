## Erratum: 0.172.0's `registryVersion` rationale

The 0.172.0 changelog and commit message said "no member was added or removed".
That was false. One entry — `openrouter/deepseek/deepseek-v4.1-flash` — entered
the `medium` group, and the displaced contributor was appended as its demoted
tail: `medium` went 9 → 10 entries and the registry 18 → 19. What was true:

- no **new model id** entered the registry, because `deepseek-v4.1-flash` already
  ships in `high` — the distinct id set stayed at 17;
- no price moved;
- `registryVersion` stays 1 — the same operation shape as the 0.168.0 high
  rotation (the preferred index rotates, the displaced contributor is re-appended
  as the demoted tail).

The 0.168.0 note carried the same "no member was added or removed" wording, and
it was inaccurate there too — that rotation did add a genuinely new id (`high`
went 3 → 4, distinct ids 16 → 17). This note states the honest invariant once for
both. The rule, plainly: **`registryVersion` tracks the registry's shape/content
generation, and a preferred rotation with no new id and no price movement keeps
it.**
