# 0.210.1 — A nested call's memory result reaches the model again

**Patch** (fix) · **Date:** 2026-10-20

The 0.210.0 fix moved the memory-first gate's result from a user-role follow-up message to
the tool result. It did so for a call the model made itself. For a call the model made
*through* another tool — a nested call, `<parent id>/<n>` — the result never reached the
model at all.

## Fixed

**A nested call's memory result was handed to a tool that never showed it to the model.**

When an extension runs a tool on the model's behalf (pi's `codemode` running `bash` is the
common case), the gate fires for that nested call exactly as it does for a model-issued one,
and the memory result is stashed against the nested id. The ADR behind 0.210.0 assumed pi
never reports a nested call's own result, so the stashed context was left to travel with
the parent. pi *does* report it — as a `tool_result` event, carrying the nested id, and
arriving **before** the parent's result. That event took the context out of the store and
handed it to the nested result, which pi routes to the *calling tool*, not to the
transcript. The parent's result then found an empty store.

Measured live in pi 1.3.0, with the gate's own search log as the witness: the gate
searched, the pattern was recorded as searched, and the model received **no** memory
result. A nested call's memory result was not merely misplaced — it was lost.

A nested id now takes nothing. The nested context waits for the parent's result, which is
the result the model reads, so the result arrives in front of the output it belongs to, on
the same model-side channel as every other result, with no extra model call.

## Evidence

- TDD: a new test — a nested call's own result does not take the context, it waits for the
  parent — was watched fail first, with the failure output showing the nested take.
- Live, before the fix: the parent's tool result carried no memory block; the gate's log
  showed the search and the recording.
- Live, after the fix: the parent's tool result carries the memory block, in front of the
  nested call's output, and no message carries it.
- The pi suite (212 tests) and the type check are green.

## Notes

ADR-0045 records the correction: the decision stands, and one premise underneath it — that
pi never reports a nested call's result — was wrong. The amendment says so, names the
measurement, and points at the one line that changed.
