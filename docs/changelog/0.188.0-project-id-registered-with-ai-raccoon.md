# 0.188.0 — ai-badger reuses or registers its project id with ai-raccoon

**Minor** (scaffold-affecting) · 2026-10-04

## What changed

- `.ai-badger/project-id` is no longer minted blind. When an installing scaffold or any
  den-refresh finds the file missing or blank, it asks the local ai-raccoon
  (`project id get --name <repo>`) and reuses the id the bank already knows — including a
  legacy raw-text id — or mints a uuid4 and registers it (`project id register`). A present
  id file is the identity and is never rewritten; when it is a uuid it costs exactly one
  `register`, which folds aliases, so no `check` call is needed (owner ruling, 2026-10-04).
- The name is the main checkout's basename: `git rev-parse --git-common-dir` collapses a
  linked worktree, so a refresh inside `.ai-badger/worktrees/<task>` never registers a
  project named after the worktree.
- One shared `ensure_project_id` now drives both mint sites; `refresh.py`'s duplicate uuid4
  mint is deleted. den-refresh reports a `projectIdWarning` when the lookup or registration
  needed a human.
- `--no-install` scaffolds never call ai-raccoon. The test suite, the consumer journey and
  the fake all set `AI_BADGER_RACCOON_REGISTER=0`; the switch is checked once and covers both
  verbs. The AI-raccoon client's exit codes live in one constants block (0 ok, 10 usage, 11
  unparseable — a binary older than 1.57.0, or a changed verb — 18 project-unknown, 19
  ambiguous, key band 20-29, server/reach band 30-69, 95 timeout), with a 40 s timeout per
  call.
- The memory-first gate's denial now names the same projectId the memory hook uses: the
  nearest `.ai-badger/project-id`, with `AI_BADGER_PROJECT_ID` first. `AI_RACCOON_PROJECT_ID`
  is retired — the gate and the hook share one override.

## Upgrade notes

- ai-raccoon 1.57.0 is required for lookup and registration. While 1.56.1 is installed, every
  installing scaffold and den-refresh prints the upgrade note (the CLI rejects the verb with
  exit 11 and starts no server); the id is still minted locally, so nothing breaks.
- The first den-refresh on each machine registers the committed uuid with that machine's
  bank. A repo whose uuid the bank does not know yet and whose basename already names a
  legacy project registers a second project under that name, which makes a later
  `get --name` ambiguous; resolve it with ai-raccoon's repair alias map.
