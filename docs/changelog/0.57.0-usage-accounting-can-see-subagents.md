# 0.57.0 — usage accounting can see subagents

Corrects [0.56.0](0.56.0-a-task-records-which-model-did-the-work.md), which
shipped a model split that could not see the work it was meant to measure.

## What was wrong

`parse_transcript_usage` read one file and folded subagent work in by branching
on `isSidechain`. Its docstring said *"sidechains included: they are billed work
too."*

**Across 171 real transcripts, no record carries `isSidechain: true`.** Claude
Code writes each dispatch to `<transcript-dir>/<session-id>/subagents/agent-<id>.jsonl`,
a path that function never opened. So the branch counted nothing, and 0.56.0's
central claim — *"a task whose mix is nearly all high-reasoning model did not
delegate"* — was false as implemented. A task that delegated perfectly still
reported ~100% top tier.

Measured on this repository, per surface:

| scope | output | mid+cheap tier | share |
|---|---|---|---|
| main transcripts (what 0.56.0 saw) | 8.14M | 0.19M | **2.3%** |
| subagent transcripts (invisible) | 7.66M | 2.14M | 28.0% |
| **combined** | 15.80M | 2.33M | **14.7%** |

One session reported 81.6% opus and 0% mid tier. Its real figures are 68.6%
opus, 23.3% sonnet, 0.5% haiku — a delegation ratio of **23.8%**, across 118
dispatches.

## Also wrong: the attribution the skill said was unavailable

`SKILL.md` claimed a per-subagent split "is not" available without chasing
`parentUuid`. Beside every subagent transcript sits `agent-<id>.meta.json`:

```json
{"agentType":"general-purpose","description":"Opus: architecture + graph review",
 "toolUseId":"toolu_01R8pk…","spawnDepth":1,"model":"opus"}
```

No chasing required. `dispatches` now reports the count, the split by
`agentType`, and how many named **no** model — 34 of 118 on that session, each
silently inheriting the session's expensive tier.

## What changed

- `parse_transcript_usage` tallies the main transcript and every
  `subagents/*.jsonl` beside it. `contextTokens` still comes from the main chain
  alone: a subagent has its own window and never occupies this one.
- `dispatches` = `{count, undeclaredModel, byAgentType}`, from the paired
  `meta.json`. An unreadable or reshaped one degrades to `unknown`, never to
  zero — a format change must not read as a delegation collapse that never
  happened.
- **`grandTotal` no longer adds `subagentTokens`.** Those were self-reported
  through `task_tracker.py subagent`; now the transcript sees the same work
  directly, so adding them counted it twice. `subagentTokens` is still recorded,
  which makes it a useful cross-check on what dispatches said about themselves.

## Behaviour changes worth knowing

`grandTotal` drops for any task that reported subagent tokens by hand — it was
inflated before, not deflated now. `cacheEfficiency` and `mainSessionTotal` are
unaffected.

## Rewritten tests worth naming

- `test_compute_usage_computes_deltas_cache_efficiency_and_totals` asserted
  `grandTotal == 1390` (640 + 750 reported by hand). That assertion *encoded the
  double-count*, so it now asserts 640, with a comment saying why it moved.
- `test_parse_transcript_usage_missing_file_returns_zeroed_result` asserts the
  whole dict by equality and gained the `dispatches` key. What it claims is
  unchanged.
