# 0.189.4 — CodeQL, setup-node and pylint toolchain bumps

**Patch** (dependency bumps, no scaffold-shape change) · 2026-10-11

## What changed

Four Dependabot updates, validated and shipped together:

- `github/codeql-action/init` and `github/codeql-action/analyze` 4.38.1 → 4.38.3. These two go
  together. Dependabot opened them as separate PRs (#573, #574), and each one failed `Analyze`
  on its own: `Loaded a configuration file for version '4.38.3', but running version '4.38.1'`.
- `actions/setup-node` 7.0.0 → 7.1.0 in `pylint.yml` (#569).
- `engine/requirements-dev.txt`: `pylint>=4.1.2` and `astroid<4.4` (#571, #572). These two
  also have to land together. pylint 4.1.2 requires `astroid>=4.3.3,<=4.4`, so #571 alone
  could not resolve against the old `astroid<4.1` ceiling. The ceiling comment now states
  pylint 4.1's range.

Every action SHA was checked against its tag: codeql `24c54180` is v4.38.3 and setup-node
`949feb24` is v7.1.0.

## Not taken

Dependabot #570 raised the `pydantic` floor in `engine/requirements.txt` to `>=2.14.0`.
No code needs 2.14. The floor would also stop matching the `pydantic>=2.12,<3` pin in the
PEP 723 headers of `task_graph_server.py` and `task_graph_cli.py`, and the docs that quote
it. CI already resolves pydantic 2.14.0 under the current range.

## Upgrade notes

Contributors: run `uv pip install --python .venv/bin/python3 -r engine/requirements-dev.txt`
to move a local venv to pylint 4.1.x / astroid 4.3.x. Consumers need do nothing.
