# 0.189.2 — task tracker runs on Windows again

**Patch** (content fix, no scaffold-shape change) · 2026-10-07

## What changed

`features/common/skills/task/scripts/tracker_lib.py` imported `fcntl` at module scope,
and `resume_cron.py` did the same. `fcntl` is POSIX-only, so on Windows the tracker died
at import — before any command ran, including `--help`:

```
File "…\tracker_lib.py", line 31, in <module>
    import fcntl
ModuleNotFoundError: No module named 'fcntl'
```

The `/task` flow never reached the point where it creates
`.ai-badger/worktrees/<taskId>`, which is why agents on Windows fell back to hand-made
worktrees in the wrong place.

`tracker_lib` now guards the `fcntl` import and adds a small cross-platform helper:
`lock_file()`/`unlock_file()` use `fcntl.flock` on POSIX and `msvcrt.locking` on Windows,
so two Windows writers serialize instead of racing (a plain no-op lock was the other option,
but it would let concurrent read-modify-write cycles lose updates). `msvcrt` is imported
lazily — a static `import msvcrt` reads to `gates/deps_guard.py` as an undeclared
third-party dependency on the Linux CI that runs this repo, although it is stdlib on
Windows. `locked_store` and `resume_cron`'s `.cron.lock` both go through the helper;
`resume_cron` no longer imports `fcntl` at all.

## Upgrade notes

Nothing required for a consumer. A `den-refresh` replaces the scaffolded copies. The
sibling `badger_store.py` already guarded this import; only the task scripts were missed.

## Provenance

Reported from a Windows consumer running the 0.188.0 scaffold, where the tracker's
import-time crash forced worktrees to be made by hand and placed outside
`.claude/worktrees/`. The fix is upstreamed so a re-scaffold carries it instead of a local
edit being overwritten by the next `den-refresh`. Regression tests load `tracker_lib` with
`fcntl` absent and exercise the `msvcrt` lock path.
