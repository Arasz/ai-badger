# 0.163.0 — pi-native message-bus transport: the message skills use the extension, not the subprocess

**Minor** (additive) · 2026-09-06

## What changed

pi sessions had the transport twice: the `send-message` skill's python script and the
pi-badger-integration `message-bus` extension (native `message-bus` tool, `/messages`
command, turn-boundary delivery hooks — same user-DB bus backend, automatic sender
identity). Both message skills now name the native path first under pi: `send-message`
gains a pi-native transport section (tool-action table with `/messages` equivalents,
extension-install and kill-switch notes, script kept as the fallback), and
`multi-agent-communication`'s How-to-send names the tool send / `ack` with the
extension-enforced inbox-membership and never-ack-an-ack rules.

## Wiring

- `features/common/skills/send-message/SKILL.md`, `features/common/skills/multi-agent-communication/SKILL.md`; plugin copies regenerated via `sync_plugin_skills.py`.
- Doc-coverage tests: pi-native transport pinned in `test_send_message_skill.py`, new `test_multi_agent_communication_skill_doc.py`.

## Residual

The extension is not scaffolded by ai-badger — it ships with pi-badger-integration
(`bun run publish`). A pi session without it sees no `message-bus` tool and falls back
to the script; the skills say so explicitly rather than assuming the install.
