# 0.36.0 — an explicit debug sink, beneath the `$HOME` floor

[0.35.5](0.35.5-the-suite-cannot-reach-the-real-log.md) moved `$HOME` to a scratch directory in
a session-scoped autouse fixture and concluded the suite could no longer reach the real audit
log. **Measured on `main`, it still leaked.** A full run added 76 test-signature records to
`~/.ai-badger/debug/audit.jsonl`:

| Component | Records |
|---|---|
| `commit_reminder_hook` | 37 |
| `ai_badger_hooks/commit_reminder` | 24 |
| `prompt_markers_hook` | 6 |
| `ai_badger_hooks/session_start` | 6 |
| `drift_notice_hook` | 2 |
| `session_start_hook` | 1 |

The reasoning in 0.35.5 was right about the shape of the defect and wrong about when a fixture
runs. A session-scoped autouse fixture runs **after collection**, and a module imported during
collection has already resolved `Path.home()`. Moving `$HOME` afterwards moves nothing for those
copies.

## What changed

`debug_log` resolves its directory through **`$AI_BADGER_DEBUG_DIR`**, and `tests/conftest.py`
sets it with `os.environ.setdefault` **at import time** rather than in a fixture. Unset, the
path is byte-for-byte the old `~/.ai-badger/debug` — asserted by a test, because the default is
the whole contract for real users.

Same suite, after: **0 leaked records.**

**Both isolations are kept.** The `$HOME` move is the wider floor: the suite also writes
`~/.ai-badger/hook-errors.log` and `~/.hermes/plugins/*.py`, which no debug-sink variable
reaches. Those are the same class of defect and are not fixed here.

Why this mattered enough to fix twice: the suite was polluting the very log `call-behaviorist`
reads, which means fabricated components in a health report — the exact problem
[0.35.4](0.35.4-behaviorist-stops-inventing-failures.md) had just removed from the analyzer.

## Rewritten tests

- **`test_an_unredirected_write_lands_in_the_scratch_home` → `..._never_reaches_the_real_home`.**
  It asserted the write landed under the scratch `$HOME`; with the sink override taking
  precedence it lands in the sink instead, and both are safe. It now asserts the contract its
  class is named for — not under the real home — rather than one of two acceptable destinations.
- **`test_the_vendored_copy_matches_the_canonical_one`** is parametrized over all four vendored
  copies rather than asserting against `call-behaviorist` alone. Same byte-equality assertion,
  four times the coverage, and the failure names the offending path.

## Deliberately not done

An "exclude ephemeral paths" filter in `analyze` was considered and rejected. `analyze` already
narrows with `_read_records(project)`, which drops records belonging to another project — so
pytest tmp-dir records were **already** excluded. The records that actually contaminate it carry
**no project at all**, and those are indistinguishable from genuine hook events that legitimately
lack one. The filter would have excluded nothing while adding a heuristic that can silently drop
real records. For logs already polluted in the field, `behaviorist.py clear` is the honest remedy.
