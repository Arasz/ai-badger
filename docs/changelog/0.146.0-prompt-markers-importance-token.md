# 0.146.0 — prompt markers: importance token (`!`) on every marker

Meaning and importance are split. Every marker now accepts an interrupt-grade `!` between
the alias and the colon — `f!:`, `queue!:` — and the important marker gains non-bang base
forms (`i:` / `important:`). The legacy `i!:` / `important!:` is exactly `i` + `!` and is
unchanged. The pi side shipped first (pi-badger-integration `session-signals`, which
aborts the running turn on a `!`-marker); this release teaches the framework the same
grammar.

## What changed

- `user_prompt_hook.py`: `match_marker` builds each catalog prefix's `!`-variant and
  returns `(marker, prefix, bang)`; a bang injects the marker's `injectInterrupt` text
  when the marker defines one, otherwise its `inject` plus a generic preemption suffix
  (`IMPORTANCE_SUFFIX`). The F-21 Windows-drive-letter guard now counts alias letters
  only, so `h!:` is guarded like `h:`. The marker audit record gains `bang`.
- `markers-context.json`: the important marker splits — `inject` is the new high-priority
  non-preempting text for `i:` / `important:`; `injectInterrupt` carries the existing
  emergency STOP text for `i!:` / `important!:`. Behavior name reflects the split
  (`high-priority-attention`).
- Templates (CLAUDE/HERMES) and the agent standing lists: the marker table gains the
  `i:` / `important:` row and the importance-token paragraph; on pi the session-signals
  extension aborts the running turn for a `!`-marker, elsewhere the model preempts.
- `test_prompt_marker_standing_list.py` no longer polices `.ai-badger.bckp/` — those are
  den-refresh's frozen snapshots, not maintained agent files.

## Discovered en route (operational)

`markers-context.json` is a **seed-once** file (#15): the scaffold ships it once and the
project owns the copy afterwards. This repo's own deployed copy had been seeded pre-0.79
and silently frozen at three markers — `q:` and `i!:` never actually fired through this
project's hook; the standing list was the only carrier. The deployed copy is now
re-seeded from the framework catalog. Projects that trimmed their catalog on purpose
should re-apply their trim after upgrading.

## Why

`i!:` could not preempt anything it did not arrive at the start of: mid-turn messages
never reach a turn-start hook, and on pi they waited behind whole delegate runs. The
grammar split lets any correction or scope note escalate to interrupt-grade, and the pi
extension enforces it mechanically.
