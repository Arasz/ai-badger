# 0.195.1: rtk is propose-only for Claude

**Patch** (fix) · **Date:** 2026-10-17

The live check of the 0.194.0 rtk wiring found that Claude Code matches a project's
`permissions.ask` rules against the command rtk's hook rewrote, not the one the model asked to
run. With `Bash(git push:*)` in `ask`, a `git push` ran without the prompt once rtk had turned it
into `rtk git push`. `permissions.deny` and a parallel hook's deny still held. Evidence:
`docs/work/2026-10-17-rtk-live-verification.md`.

- rtk's `meta.json` declares Claude `propose`. The Claude arm wires no handler, removes one that
  0.194.0 wired on the next scaffold, and prints why. Projects that opted Claude in lose the rtk
  hook for Claude only. Codex, Copilot and pi are unchanged.
- The Claude and Codex arms keep rtk's hook group last in `PreToolUse`, behind ai-badger's guards.
  They also no longer rewrite the hooks file on every scaffold. `.codex/*.bak-*` is gitignored.
- The Copilot note now reports what rtk 1.0.1 emits (`updatedInput` for VS Code, `modifiedArgs`
  for Copilot CLI) in place of a version floor that had no source.
- `tests/test_tools_end_to_end.py` scaffolds all five agents with rtk on and off. It checks that
  the output does not depend on PATH, that a rerun is byte-identical, that opting out removes
  everything, that rtk side files never appear, and that a hand-edited block is reported stale.
- ADR 0039 is amended with the verdicts. The docs now list the `tools` feature type,
  `config.tools` and the rtk entry.
