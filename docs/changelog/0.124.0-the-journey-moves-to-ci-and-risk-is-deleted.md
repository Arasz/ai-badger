# 0.124.0 — The Journey Moves To CI And `--risk` Is Deleted

**Type:** MINOR
**Date:** 2026-08-15

Follows [0.123.0](0.123.0-the-push-stops-re-proving-what-ci-proves.md), which moved `pytest` and
`pylint` off the push and named `journey` as the next candidate.

**Breaking:** `task_tracker.py start --risk` no longer exists. A script passing it now fails with
an argparse error instead of being silently accepted.

## What Changed

`journey` joins `CI_ONLY_LANES`, so a push runs 12 lanes rather than 13. `--risk` is removed
outright — the flag, the gate query, the tracker field and the skill section.

## What a local push no longer verifies

The full set, after both releases:

| Lane | What it checks | Who owns it now | Trigger |
|---|---|---|---|
| `pytest` | the full test suite | `.github/workflows/pylint.yml`, `tests` job — `verify.sh pytest` | `on: [push]`, no branch filter |
| `pylint` | 10.00 on non-test Python | `.github/workflows/pylint.yml`, `lint` job — `verify.sh pylint` | `on: [push]`, no branch filter |
| `journey` | scaffold, work in and tear down a throwaway consumer project | `.github/workflows/consumer-journey.yml` — `gates/consumer_journey.py` | `on: [push]`, no branch filter |

All three run on Python 3.10, the floor this project declares. The local interpreter here is
3.14.7, so each was slower on a push *and* a weaker check than the CI job it duplicated.

**A green pre-push is no longer a full verdict.** It is fast feedback; CI is the gate. Branch
protection did not change, so the discipline is to read the checks on the PR.

What a push still runs, and why each stays: `version-sync`, `index`, `plugin-skills`, `deps`,
`docs`, `release`, `paths`, `workflows`, `validate`, `scaffold`, `tdd`, `js` — whole-tree
consistency guards that cost about a second each and catch the cross-file breakage that is
cheapest to hear about before the push, not after.

## Two lists that said the same thing

These are exactly the three lanes the `gates` job in `pylint.yml` skips, because each has a job
of its own:

```
pytest|pylint) continue ;;   # own jobs above
journey) continue ;;         # consumer-journey.yml already runs this on push
```

That skip list and `CI_ONLY_LANES` are one rule written in two files, and nothing compared them.
A lane could leave the local hook, stay in CI's skip list, and be verified by **nothing at all**.
`test_the_gates_job_skips_exactly_the_lanes_the_hook_leaves_to_ci` now fails if they diverge —
and it is what made this release's production change a one-word edit, because it went red first.

Its companion, `test_every_lane_the_gates_job_skips_is_run_by_another_push_job`, checks the
weaker but more important half: each skipped lane is actually run somewhere on a push. A
workflow restricted to `branches: [main]` does not count — `release-tag.yml` is one, and a lane
covered only there is not covered on the feature branch anyone is actually pushing.

## `--risk` is deleted

`RISK_DROPPED_LANES` was `pytest`, and no push ran `pytest` — so the flag dropped nothing, while
the hook still printed *"limited gates: `<task>` is a --risk task, so pytest did not run."*
Machinery announcing a safety trade it is not making is worse than absent, and once the slow
lanes belong to CI there is no trade left to offer.

Removed:

- `.lefthook/pre-push/risk_mode.py`
- `RISK_QUERY`, `_risk_task`, `RISK_DROPPED_LANES`/`VERIFY_RISK_DROPPED`, the notice and the
  `HOOK="risk"` branch in `verify.sh` — `_select_lanes` is now five lines
- the `--risk` flag, its sticky `risk` field and the `risk=on` column in `task_tracker.py`
- the "Limited gates" section of `skills/task/SKILL.md`, replaced by a short note on which
  suites CI owns and a line recording why the switch went

### The tracker field is ignored on read, not migrated

Entries already in `.ai-badger/task-tracking/` carry `"risk": true`. That store is real,
long-lived state nobody rewrites.

**Decision: ignore it.** The entry is a plain JSON dict read by named key, with no schema behind
it — `executed-tasks.json` has no entry in `schemas/`, so there is no `additionalProperties`
check to trip. An unknown key is inert. Migrating would mean rewriting every historical entry to
drop one field nothing reads: a write with no behaviour behind it, against a record whose value
is that it was not edited.

Proven against a hand-built legacy entry rather than only against new ones — which is the whole
point, since no code path produces one any more:

```
LEGACY-1     STARTED      started=2026-08-15T… finished=- tokens=- cacheEff=- mix=- grade=-
PLAIN-1      STARTED      started=2026-08-15T… finished=- tokens=- cacheEff=- mix=- grade=-
```

`status` exits 0, lists the task, no longer prints `risk=`, and leaves the field on disk
untouched. All four assertions are separate tests, because "did not crash" and "did not silently
drop the entry" are different failures.

## Tests

Rewritten or deleted — a rewritten test is where a regression hides:

- `test_a_risk_task_drops_the_lane_it_names`, `test_a_risk_task_keeps_every_other_lane`,
  `test_a_risk_run_that_drops_nothing_announces_nothing`,
  `test_a_risk_run_that_drops_a_local_lane_says_so_and_names_it` (all four from 0.123.0) →
  replaced by `test_no_environment_variable_narrows_the_push_selection` and
  `test_a_push_never_announces_a_limited_gate`, which assert the reduced mode is **gone**
  rather than that it works. The helpers `_risk_stub` and `_a_local_lane` went with them.
- **`tests/test_risk_mode.py` deleted entirely** (9 tests) with `risk_mode.py`:
  `test_it_names_the_task_when_the_branch_is_in_risk_mode`,
  `test_it_is_silent_when_the_task_did_not_ask_for_risk`,
  `test_it_is_silent_for_a_branch_with_no_task`, `test_it_is_silent_once_the_task_is_finished`,
  `test_it_is_silent_when_the_project_tracks_nothing`, `test_a_corrupt_tracker_reads_as_no_risk`,
  `test_an_empty_branch_name_is_never_a_match`, `test_it_looks_where_the_tracker_actually_writes`,
  `test_it_reads_the_checkout_tracker_from_inside_a_worktree`.
- `TestTheRiskSwitchRunsGatesInLimitedMode` (5 tests) → `TestALegacyRiskFieldIsIgnored` (4):
  `test_start_records_the_switch_on_the_task_entry`,
  `test_a_task_that_did_not_ask_for_it_is_not_marked`,
  `test_the_switch_survives_a_resume_and_a_later_start`,
  `test_a_later_start_can_raise_the_switch_on_a_task_that_began_without_it` and
  `test_status_names_the_risky_task_and_leaves_the_others_alone` become
  `test_status_still_lists_a_task_carrying_the_removed_field`,
  `test_the_field_survives_on_disk_untouched`, `test_start_no_longer_accepts_the_flag`,
  `test_a_new_task_gets_no_risk_field_at_all`.

New: `test_the_gates_job_skips_exactly_the_lanes_the_hook_leaves_to_ci`,
`test_every_lane_the_gates_job_skips_is_run_by_another_push_job`,
`test_the_push_trigger_reader_finds_both_spellings`.

Every guard that was green from the start was put in front of its defect and watched fail:

| Defect injected | Caught by |
|---|---|
| `consumer-journey.yml` stops running `gates/consumer_journey.py` | `test_every_lane_the_gates_job_skips_is_run_by_another_push_job` — *"the gates job skips ['journey'] and no other push-triggered job runs them"* |
| the reduced mode restored in `_select_lanes` and its notice | `test_no_environment_variable_narrows_the_push_selection`, `test_a_push_never_announces_a_limited_gate` |
