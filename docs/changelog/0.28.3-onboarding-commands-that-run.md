# 0.28.3 — the onboarding commands actually run

Two bugs in the skill files a brand-new user follows first. Both were found by writing a
getting-started guide and running every documented command verbatim.

## `$AI_BADGER/skills/…` does not exist

`welcome-ai-badger`, `den-refresh`, and `feed-badger` all told the reader to run scripts at
`$AI_BADGER/skills/<skill>/scripts/…`. `$AI_BADGER` is the framework root — the directory
holding `index.json` and `schemas/` — and **a framework checkout has no top-level `skills/`
directory**. The catalog lives at `features/common/skills/`.

Running the very first command of the very first skill produced:

```
python3: can't open file '.../ai-badger/skills/welcome-ai-badger/scripts/detect.py':
[Errno 2] No such file or directory
```

Six paths across three skills, now pointing at `$AI_BADGER/features/common/skills/…`.
`$AI_BADGER/scripts/…` was always correct and is unchanged.

## `pluginScope` is not a config key

`welcome-ai-badger/SKILL.md` step 3 told the reader to set `pluginScope`. The schema defines
`skillScope` and sets `additionalProperties: false`, so a config written from that instruction
fails validation outright:

```
Additional properties are not allowed ('pluginScope' was unexpected)
```

`detect.py` has always emitted the correct `skillScope`; only the prose was wrong.

## Why nothing caught either

`tests/test_skill_docs.py` arrived in 0.27.1 and deliberately **skipped** any path beginning
with `$`, treating shell variables as unresolvable. But `$AI_BADGER` is documented as the
framework root, so it resolves perfectly well against a checkout. That exclusion is exactly why
the bug survived the test written to catch its sibling.

Now checked:

- every `$AI_BADGER/<path>` in any SKILL.md must exist in the checkout, plus a guard asserting
  the check sees a non-trivial number of paths, so it cannot pass vacuously if the regex drifts
- a SKILL.md may not name a `*Scope` config key the schema rejects

## Upgrading

Re-scaffold to pick up the corrected skill files. Any config you hand-wrote containing
`pluginScope` was already being rejected by `validate.py`; rename it to `skillScope`.
