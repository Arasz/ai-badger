# 0.101.0 — the edit guard agrees with the push gate

`generated_file_guard.py` (0.96.0) exists to move `scaffold_freshness_guard`'s verdict from push
time to edit time: if the next scaffold would revert a hand edit, refuse the edit now rather than
reject the push hours later. It decided by feature name, and it exempted `templates` outright:

```python
# `templates` is deliberately absent: a template is seeded once and then belongs to the
# project (`.ai-badger/state.json`, `CLAUDE.md`), so refusing to edit one would refuse the
# intended way to use it.
REGENERATED_FEATURES = frozenset({"skills", "personas", "instructions", "invariants",
                                  "adjustments"})
```

**The premise held for two of this repo's seven `templates` targets.** Probed against the live
guard, all seven were `allow` at edit time. Hand-edited and put to the freshness guard, five came
back flagged:

```
SCAFFOLD FRESHNESS GUARD FAILED: re-scaffolding this repo against itself would change 5 of 1395 path(s):
    .ai-badger/agent-instructions/schema.json  (content differs, hand-edited)
    .ai-badger/delegation.md                   (content differs, hand-edited)
    .github/copilot-instructions.md            (content differs, hand-edited)
    CLAUDE.md                                  (content differs, hand-edited)
    HERMES.md                                  (content differs, hand-edited)
```

Only `.ai-badger/state.json` and `.ai-badger/agent-instructions/model.json` are genuinely
seed-once. So an agent was permitted to edit `CLAUDE.md`, had the edit silently reverted by the
next scaffold, and then had its push rejected as hand-edited — the exact failure the guard was
added to prevent, made *harder* to diagnose by the guard's own permission to make the edit.

## What changed

The scaffolder already knew the answer and was not writing it down. It has three places where it
writes a file and then leaves it alone — `_seed_once_copy()` (two call sites: `state.json`,
`model.json`) and a `seedOnce` entry in `features/<agent>/scaffolding.json` — and nowhere else.

`Scaffolder.record_template()` now takes `seed_once` and stamps `seedOnce` onto the manifest
entry; `_seed_once_copy` passes `True`, and `agent_files.py` forwards the flag `scaffolding.json`
already carried but never recorded. The guard drops `REGENERATED_FEATURES` and tests
`entry.get("seedOnce")`. One flag, one source of truth, no hardcoded path list — and a template
that becomes seed-once later needs no change to the guard.

`schemas/manifest.schema.json` gains `seedOnce` (its `entries` items are
`additionalProperties: false`, so an unlisted key is a validation failure, not a silent extra).

### A manifest older than the flag refuses rather than exempts

The plugin's copy of the guard updates when the plugin updates, not when a project re-scaffolds,
so guard-newer-than-manifest is reachable. Such a manifest carries no `seedOnce` anywhere and
cannot tell the two apart. The guard reads absence as regenerated and refuses:

- A wrong refusal is loud, names `AI_BADGER_ALLOW_GENERATED_EDITS=1` in its own message, and
  disappears after one re-scaffold. It is wrong about 2 of 7 template targets.
- A wrong exemption is silent, costs the push cycle this guard exists to remove, and is wrong
  about 5 of 7.

A gate written to catch a silent failure must not fail silently itself.

## Still open

The disagreement runs the other way inside delivered skills. `skill_delivery` preserves
`project-local.md` and `SEED_ONCE_SKILL_FILES` (today: `prompt-markers/markers-context.json`)
across re-scaffolds, so the freshness guard allows a hand edit to them — but they sit inside a
`skills` manifest *directory* entry, so the edit guard denies it. Verified against the live guard:

```
DENY  .ai-badger/skills/prompt-markers/markers-context.json
DENY  .ai-badger/skills/task/project-local.md
```

These are the files a project is explicitly told to edit. Closing it needs the scaffolder to
record them individually, which `project-local.md` — a file with no framework source — does not
fit today. Tracked separately rather than bundled here.
