# 0.198.0 — the user-scope rtk guard hook no longer depends on the checkout

**Minor** (feature) · **Date:** 2026-10-18

- **`features/common/tools/rtk/scripts/user_hook.py`.** Prints the user-scope Claude
  `PreToolUse` entry for the rtk guard and says whether the settings file already holds it;
  `--apply` writes it into `$CLAUDE_CONFIG_DIR/settings.json` (default `~/.claude/settings.json`).
  The command carries `rtk_guard.py`'s source inline through `tool_hooks.guarded_command`, the
  same command project scope wires. Moving the checkout or checking out an older branch no
  longer silences it.
- `--apply` replaces earlier guard entries, both the marked inline form and a hand-written
  `python3 … rtk_guard.py claude` path. It keeps every other hook, writes through a symlink with
  the file's mode, leaves a timestamped `settings.json.bak-*`, and writes nothing when the
  current entry is already there. A settings file of the wrong shape is refused untouched.
  Re-run it after an upgrade to pick up guard fixes.
- A bare `rtk hook claude` PreToolUse (`rtk init -g`) is left in place and named: it rewrites
  past `permissions.ask` rules, so the guard cannot protect them while it stays.
- ADR-0039 decision 11 records the operator command and narrows ADR-0014 decision 6 to the
  scaffold and the adjusters, which still never write user-global configuration.
