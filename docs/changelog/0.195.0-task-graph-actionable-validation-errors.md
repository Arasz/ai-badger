# 0.195.0 — task-graph: clear argument errors, tolerated runtime fields

**Minor** (additive) · **Date:** 2026-10-17

An agent authoring a plan copied `status` and `evidence` from a stored plan into its
acceptance criteria. pi checked the call against the published input schema and refused it
with `schema is false` and a copy of the whole input, which told the agent nothing it could act on.

- `plan_create` and `plan_replace` now accept `status` and `evidence` on an acceptance
  criterion and ignore them. The criterion still starts `unchecked`, the content hash is the same
  as without them, and the reply carries `warnings[]`: the criterion's path, the ignored fields,
  why they are ignored (`ac_check` and `step_complete` record verdicts) and the expected shape.
  No other new property is accepted; the published schema stays closed.
- `invalid-arguments` from argument validation now has one finding per problem in
  `details.findings[]`: `path`, `problem`, `fix` and the failing object's `expected_shape`.
  Unknown properties on one object are grouped (`properties "foo", "bar" are not accepted at
  steps[0].acceptance_criteria[0]`). `detail` repeats the findings as text. The received value
  is never echoed; unknown property names are cut at 64 characters. Plan-graph failures (unknown
  or self dependency, cycle, duplicate step or criterion id) use the same finding shape, mapped
  back to the authored `steps[i]`, with a fix for each invariant.
- pi checks arguments against the published schema before the server runs, so an unknown
  property still fails there with pi's own message; the new findings reach pi only for checks
  the schema cannot express, and reach the CLI twin and other clients in full.
