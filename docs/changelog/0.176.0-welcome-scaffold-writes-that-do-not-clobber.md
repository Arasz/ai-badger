# 0.176.0 — welcome-ai-badger scaffold writes that do not clobber

**Minor** — `features/common/skills/welcome-ai-badger/scripts/` (P05). 2026-09-24.

## What was wrong

Six defects in the scaffold's own write paths, all previously uncovered by a gate that
had been seen to fail:

- **A missing statusline delegate looked the same as an empty one** (L3-2).
  `_read_delegate` passed `{}` as `kv_get`'s default, so a project with no delegate
  row *and* no legacy delegate file got back `{}` — a value `unwire()` cannot tell
  from "nothing was ever displaced" — and deleted `statusLine` outright, even though
  the documented guard says an unreadable delegate must leave the capture wired.
  `kv_get` now defaults to `None`, and an absent legacy file also returns `None`
  rather than the `{}` `config_guard.read_json_mapping` gives an absent path.
- **A remote's embedded credentials reached the committed config** (L3-3).
  `detect_source_control` copied the git remote URL into `repoUrl` without
  stripping userinfo, so a CI checkout's `https://user:token@host/...` or an
  `ssh://user@host/...` remote landed in `config.json` as-is. Both schemes now have
  their `user[:pass]@` authority stripped before the URL is recorded.
- **A hand-authored primary target was still recorded as generated** (L3-6).
  `agent_files._apply_scaffolding` recorded a template's manifest entry before
  deciding whether `copy_with_header` would actually write it, so a hand-authored
  `CLAUDE.md` the scaffolder correctly declined to overwrite was still claimed in
  the manifest as this run's own generated file — and the edit-time guard then
  refused the project's own future edits to it. `copy_with_header` now reports
  whether it wrote its target, and the entry is recorded only then (seed-once
  targets are still always recorded, once dest is settled either way).
- **A rendered `hashes_source` output could never be pruned** (L3-5). `templates`
  and `adjustments` entries record the framework *source*'s hash (ADR-0006), which
  never matches rendered output, so `superseded_prune._edited_here` always read an
  untouched output as "edited here" and never removed it — the note also blaming
  the project for an edit it never made. Per owner ruling D11, `record()` now also
  stores `outputHash` (version-stamp-normalized, so a version bump alone does not
  read as an edit) for `hashes_source` file entries, and prune compares against it
  when present. An older manifest without one is "unknown", not "edited": the item
  is still never pruned, but the note stops blaming the project.
- **Three writes to the same file in one second clobbered each other's backup**
  (L3-7). `config_guard._backup_path` had one-second resolution, and one scaffold
  can write `.claude/settings.json` up to three times within a second (statusline
  wiring, hook wiring, an agent's own adjustment) — each write copying the
  *current* file over the same `.bak-<ts>` name, so the pre-run original was gone
  by the third write. The first backup of a run keeps the plain `bak-<ts>` stamp;
  each one after it in the same second gets a `-<n>` counter.
- **`config_guard._atomic_write` gave a new file mode 0600** (same class as L1-4,
  0.173.2's `badger_lib.atomic_write_text` fix, which this module cannot import —
  ADR-0009). A brand-new file now gets `0o666 & ~umask` like a plain `open(...,
  "w")` would, instead of inheriting `mkstemp`'s restrictive default; an existing
  file's mode is still preserved exactly as before.

## Wiring

- `features/common/skills/welcome-ai-badger/scripts/statusline_wiring.py`:
  `_read_delegate` passes `None` to `kv_get` and checks the legacy file exists
  before reading it.
- `features/common/skills/welcome-ai-badger/scripts/detect.py`: new
  `_strip_userinfo`, applied to the normalized remote URL.
- `features/common/skills/welcome-ai-badger/scripts/template_rendering.py`:
  `copy_with_header` returns whether it wrote its target.
- `features/common/skills/welcome-ai-badger/scripts/agent_files.py`: the primary
  target's manifest entry is recorded after the write decision, not before.
- `features/common/skills/welcome-ai-badger/scripts/scaffold.py`: `record()`
  delegates its hash fields to the new `record_provenance.provenance_hashes`
  (keeping this module under its 850-line budget, #194); `_seed_once_copy` now
  records only once its target is settled, so `outputHash` cannot depend on which
  run this is.
- `features/common/skills/welcome-ai-badger/scripts/record_provenance.py`
  (new): the hashing rules `record()` used to carry inline, plus `outputHash` for
  `hashes_source` file entries.
- `features/common/skills/welcome-ai-badger/scripts/superseded_prune.py`:
  `_edited_here` returns `Optional[bool]` — `None` for "cannot tell" — and compares
  `outputHash` when a `hashes_source` entry carries one.
- `engine/badger_lib.py`: new `content_hash_ignoring_version_stamp`, normalizing
  away a rendered template's own "Scaffolded by ai-badger `<version>`" line before
  hashing, so `outputHash` does not churn on a version bump alone (the same class
  of noise `gates/scaffold_freshness_guard.py`'s own stamp normalization exists
  for).
- `features/common/skills/welcome-ai-badger/scripts/config_guard.py`:
  `_backup_path` appends a counter once the plain stamp is taken;
  `_atomic_write` gains the same `_default_new_file_mode` fallback as
  `badger_lib.atomic_write_text`.
- `schemas/manifest.schema.json`: new optional `outputHash` entry field.
- `tests/test_config_guard.py` (new), `tests/test_superseded_prune.py` (new),
  plus new coverage in `tests/test_scaffold_statusline_wiring.py`,
  `tests/test_detect.py`, `tests/test_scaffold_agent_files.py` and
  `tests/test_scaffold_manifest.py`.

## Upgrade notes

`outputHash` is optional and additive: an older manifest without it keeps its
previous never-pruned, no-longer-misblaming behavior for `hashes_source` entries.
No config shape change.
