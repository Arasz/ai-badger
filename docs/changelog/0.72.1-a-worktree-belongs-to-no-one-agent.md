# 0.72.1 — A worktree belongs to no one agent

The `/task` skill created its worktree at `.claude/worktrees/<taskId>`. It now creates it at
`.ai-badger/worktrees/<taskId>`.

## The catalog is agent-neutral; the path was not

`task_tracker.py` lives in `features/common/` — the part of the catalog that ships to every
project regardless of which agent it uses. `engine/badger_lib.py` names four of them:
`claude`, `copilot`, `hermes`, `junie`. So a hermes-only project ran `/task`, and got a
`.claude/` directory created for it that nothing else in that project would ever read. The
skill's own closing line says "the base skill above stays platform-, stack- and
model-neutral", and one constant on line 49 made that false.

`.ai-badger/` is the one directory every scaffolded project has, whatever agent it configured,
which is why this needs no config key and no per-agent branch. `tracker_lib.py` already put the
task tracking JSON at `.ai-badger/task-tracking/`; the worktree now sits beside it.

The path-traversal refusal in `worktree_path()` is unchanged. A task id that is empty, `.`,
`..`, or carries a separator is still refused rather than sanitised, for the reason
`SECURITY.md` already gives: a silently rewritten id would stop matching the one in the
tracking JSON.

## The backup is what made this more than a one-line move

`den-refresh` calls `check_breaking_and_backup`, which copies the whole of `.ai-badger/` to
`.ai-badger.bckp/` on every refresh — unconditionally, because a re-scaffold that raises
partway leaves no other recovery path. That was cheap while `.ai-badger/` held config, skills
and JSON. Put task worktrees under it and each one is a full git checkout: on the machine this
was found on, thirteen of them. A `copytree` over a worktree that a live session is writing to
can also fail mid-copy, which would take the refresh down before it reached the re-scaffold.

The backup now passes an `ignore` callable to `copytree` that skips any child directory holding
its own `.git`. The rule is stated as what it protects against — a second checkout is not this
project's state — rather than as the name `worktrees`, so it also covers a clone someone parks
under `.ai-badger/` for reasons nobody has thought of yet. A plain directory sitting beside a
checkout is still backed up, and a test pins that difference.

## Worktrees you already have are not moved

Nothing migrates and nothing is deleted. Git records each worktree by absolute path in
`.git/worktrees/<name>/gitdir`, which holds the location the worktree was created at — so every
existing `.claude/worktrees/<id>` keeps resolving and keeps working exactly as before. Only
worktrees created after this release land in the new place.

`.claude/worktrees/` therefore stays in `.gitignore` alongside the new `.ai-badger/worktrees/`
entry: dropping it would start offering thirteen nested checkouts to `git add`. Anyone who
wants the old ones relocated does it themselves with `git worktree move`; ai-badger will not do
it for them.
