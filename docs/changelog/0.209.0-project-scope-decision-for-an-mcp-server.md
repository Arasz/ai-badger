# 0.209.0 — A project's own scope decision for an MCP server

**Minor** (new capability) · **Date:** 2026-10-20

A project can now say which scope a declared MCP server belongs to, and `ai-raccoon` ships
user-scoped by default.

## New

**`config.mcp.scope`** — a map of server name to `project` or `user`. It is the project's
own decision about a named server, and it overrides the catalog's `scope` in either
direction:

```json
{ "mcp": { "scope": { "ai-raccoon": "user" } } }
```

`user` means the server is in no project file. ai-badger writes it into no `.mcp.json`, no
`.github/mcp.json` and no `.pi/mcp.json`; an entry an earlier run wrote into one of them is
removed, and the removal is reported in a note. The operator registers the server once, in a
user-global config, and every repository uses that one registration. `project` means the
launch config is written into the project's files as usual — which is how a project pulls a
catalog server that ships user-scoped back to project scope.

`config.mcp.decline` still wins over both: a declined server is refused outright, is in
neither scope, and gets no proposal. A name in `config.mcp.scope` that matches no declared
server is reported rather than silently ignored.

**`ai-raccoon` is user-scoped by default.** The catalog declares it `scope: user`, so no
project writes an `ai-raccoon` entry into a project file any more. This ends the ritual of
removing the project-scoped copy after every refresh when the operator had already
registered the server at user scope (`claude mcp add --scope user ai-raccoon -- ai-raccoon`).
A project that wants the old behaviour says so in `config.mcp.scope`.

## Upgrade notes

- **Existing projects lose their `ai-raccoon` entry** on the next scaffold or refresh, and
  the run says so. Register the server at user scope first, or keep it project-scoped with
  `config.mcp.scope`.
- **The server must be registered to be used.** User scope is a proposal, not a write:
  ai-badger never writes user-global configuration (ADR-0014 decision 6). A project whose
  operator has not registered the server has no memory server, and the run's notes say
  what to register.
- **The tool index is unchanged.** A user-scoped server keeps its catalog entry, its prose
  and its tool catalog — the agent still knows the tools exist. Scope decides where the
  launch config lives.

ADR-0044 records the decision: the precedence (decline, then `config.mcp.scope`, then the
catalog), why the knob is a map rather than a one-way list, and why the framework proposes
the user-global registration instead of writing it.
