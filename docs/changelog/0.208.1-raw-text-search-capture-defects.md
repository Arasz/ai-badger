# 0.208.1 — The raw text-search capture stops losing its result

**Classification:** Patch
**Date:** 2026-10-20

## Fixes

Three defects in `skills/get-raw-text-search/scripts/get_raw_text_search.py` made a
captured search invisible or wrong. The retrieval script was fine; the capture was not.

- **The search tool no longer reads the worker's stdin.** The capture worker launched
  `rg`/`grep` with an inherited stdin, so a search without a path argument read the pipe
  or heredoc the worker happened to inherit and reported that instead of the working
  tree — an empty result that looked like a successful capture. The worker now gives the
  search an empty stdin, so it searches the tree it was launched in.
- **A later capture replaces an earlier one.** The worker skipped a capture whose key
  already held a live record, so the first result for a pattern stuck for the whole
  120-second window: a retry after a fix kept returning the first, empty result. A
  capture now always claims the key, and a slow capture never overwrites a newer one.
- **A capture and its retrieval share one scope.** The capture keyed its record by the
  working directory it searched and the retrieval looked it up by the caller's working
  directory, so a capture made in a subdirectory was invisible from the repository root.
  Both sides now key by the repository that owns the working directory; a capture in
  another repository stays invisible, and the pre-0.208 directory scope is still read.

## Changes

- The capture worker keys the record by the repository it searched, so the gate no
  longer computes a scope to pass in the capture key. The legacy
  `"<scope>:<hashes>"` capture key is still accepted.

## Upgrade notes

None: the retrieval CLI (`--pattern`, `--pattern-hash`) and the stored record shape are
unchanged apart from an added `cwd` field.
