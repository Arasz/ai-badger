# 0.196.2 — scaffolded `$schema` paths resolve; `open_pr.py` resumes a failed run

**Patch** (fixes) · **Date:** 2026-10-18

- **`$schema` paths.** A scaffolded `.ai-badger/manifest.json` pointed at `../schemas/`, and
  `.ai-badger/model-groups.json` at `../../schemas/`. Neither exists in a project: the schemas
  are copied to `.ai-badger/schemas/`. Both now point at `./schemas/`. The source
  `features/common/data/model-groups.json` pointed one level short as well (`../../`) and now
  resolves to the root `schemas/`. The registry is delivered with its `$schema` rewritten for
  its new location; the rest of the document is unchanged. A new test checks that every
  relative `$schema` in the framework tree and in a fresh scaffold resolves.
- **`open_pr.py` resume.** A run in a checkout already on `--branch` no longer fails at
  `git checkout -b`. After a failed commit (a hook refused) or a failed push, re-running the
  same command resumes: declared paths a previous run staged are accepted, undeclared ones
  are still refused, and the commit is skipped when nothing is left to commit. The failure
  message says so.

**Upgrade:** run `den-refresh`; it rewrites `manifest.json` and `model-groups.json` with the
corrected references.
