# 0.202.0 — host-only MCP servers get real tags and intents

**Minor** (feature) · **Date:** 2026-10-18

- **Leading-verb tags.** `tool_descriptions.auto_tags` now reads the action from a tool name's
  first `_`/`-` token, matched whole. `get`, `list`, `fetch`, `download`, `export`, `whoami` and
  `describe` give `read`; `query` and `search` give `read, search`; `create`, `update`, `delete`,
  `add`, `upload`, `set` and `patch` give `write`; `cancel`, `pause`, `resume`, `start` and `stop`
  give `run`. A verb inside a word does not count (`budget_report` is not `get`), and no verb
  infers a technology (#171). These verbs led most of the 59 tools the 0.201.0 host-tools smoke left
  `general`.
- **`validate` refuses the placeholder intent.** `TODO: describe what <tool> does` is now one shared
  constant (`tool_descriptions.PLACEHOLDER_INTENT`), and `validate` reports it as `intent is a
  placeholder` instead of passing it for being 10 characters or more. Indexes that already hold
  placeholders now fail `validate`, which is intended.
