# 0.133.0 — QA personas, `design-tests` + `review-tests`, one layered test ruleset

**Minor.** New scaffold output: three personas, two `scope: default` skills, one invariant. Additive —
nothing renamed or moved, `BREAKING_VERSIONS` unchanged.

## What ships

- **One ruleset, used twice** — `review-tests/references/`: 8 principles (`T0-*`, invariant-style, each
  anchored to a proven failure), 40 universal rules (`T1-*`, hard cap 40), 11 kind files (`T2-*`: unit,
  integration, contract, architecture, property, snapshot, performance, time, bdd, end-to-end,
  accessibility), 7 stack files (`T3-*`), `evidence.md`, `archetypes.md` (18 bug archetypes with the
  rule that demands the guard and the mutation that proves it), `conflicts.md` (21 rulings),
  `governance.md`. Every rule carries a `check:` a stranger can run or answer; `weak` evidence caps
  severity at `major` and forces `flag: argued`. Markdown is the truth: `scripts/rules_index.py`
  generates `rules.json`, `walk-review.md` and `walk-design.md`, and `--check` fails on unknown or
  duplicate ids, missing parents, an `absorbs:` id outside the source-lane grammar, an unresolvable
  citation, a weak blocker, a missing or unknown field, a bad filename, a stale artefact, or an L1
  count above 40.
- **`design-tests`** (`scope: default`): with a target, designs a suite from the ruleset; without one,
  an eight-step decision tree ends in a target card or "stop and say so". It runs rather than reasons:
  RED is pasted, `scripts/red_proof.py` applies a named mutation under a journalled restore, and
  `scripts/scan_uncontrolled_resources.py` flags clocks, sleeps, network, filesystem, env, randomness
  and shared state in the tests it wrote. Goes green — a RED-only suite cannot be scored.
- **`review-tests`** (`scope: default`): walks the generated `walk-review.md` in nine
  cheapest-falsifier-first passes (environment capability → vacuity → determinism → …), refuses to run
  without a scope, and emits an improvement plan (`references/plan-format.md`) whose every fix carries an
  acceptance criterion and the gate that proves it, so `task` can consume it.
- **Personas** — `qa` (common), `qa-backend` (`features/dotnet`), `qa-frontend` (`features/react`).
  `test-engineer` is narrowed (writes tests inside feature work; suite design and audit go to `qa`) and
  keeps its name so no consumer's `personaRouting` row is orphaned.
- **Invariant** `tests-are-designed-and-reviewed`; call-site sentences in `task` Phase 1 and Phase 3
  and `code-review-checklist` §3.1; `SKILL_GROUPS["testing"]` installs both skills together.
- **Extensions** `extensions/dotnet` (`stacks=dotnet`) and `extensions/react` (`stacks=react`) on both
  skills, runner facts only.

## Deliberate choices a reader may take for defects

- **`qa`, `qa-backend` and `qa-frontend` carry no `disallowedTools`**, unlike `code-reviewer`. The
  mutation discipline edits production code and reverts it; a read-only persona cannot execute its own
  first principle. That grant *is* the boundary against becoming a second `code-reviewer`.
- **Only `dotnet` and `react` receive extension fragments, and five stack files
  (`stack-azure-functions`, `stack-cosmos`, `stack-node`, `stack-python`, `stack-terraform`) ship
  deliberately near-empty** — a heading, the statement that the stack is unresearched, and how to
  contribute. Shipping seven thin fragments to look complete is the failure mode; `governance.md` says
  how a stack earns rules.
- The react fragments gate on `stacks=react` alone: `react` requires `ts` + `node`, so gating on
  `ts`/`node` would ship frontend fragments to every Node-only API project.
- `design-tests` goes green, not RED-only, because a RED-only suite scores `false_alarm = 1.0` on the
  benchmark that judges it.

## Known unguarded criteria (stated, not hidden)

- The conditionality of the Phase 3 / §3.1 call-site sentences ("if the diff adds or changes test
  files") is enforced by review, not by a gate.
- `SIBLING_REFERENCE_RE` admits no digits in reference filenames; a digit-bearing citation is invisible
  to `tests/test_skill_groups.py`. `rules_index.py --check`'s filename rule closes this for the ruleset.
- `gates/skills_lint.py` measures the catalog file; `tests/test_merged_skill_stays_in_budget.py`
  measures the merged body a project receives. No per-skill lint test exists because the gate already
  globs the catalog and a per-skill test would be the mirror `derive-or-delete-the-list` forbids.
