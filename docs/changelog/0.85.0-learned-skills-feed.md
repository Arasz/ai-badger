# 0.85.0 — Learned skills feed: dotnet/mcp/hermes stacks + optIn workflow skills

First large `feed-badger` harvest from a consumer project (the ai-raccoon MCP server
development). 30 generalized skills + 1 invariant join the catalog, filling two stacks
that previously shipped no in-repo skills and extending the common optIn set.

## What changed

- **New `features/dotnet/skills/`** (12 stack-local skills, shipped to dotnet projects):
  `dotnet-bdd-testing`, `dotnet-cli-parsing`, `dotnet-domain-modeling`,
  `dotnet-flaky-test-diagnosis`, `dotnet-hosted-service-review`,
  `dotnet-hosted-service-testing`, `dotnet-logger-message-design`, `dotnet-mcp-server`,
  `dotnet-nuget-publish`, `dotnet-sqlcipher-encryption`, `dotnet-tool-publishing`,
  `observability-contract-review`.
- **New `features/mcp/skills/`** (1): `mcp-tool-surface-testing` — expectations-first
  black-box testing of every tool an MCP server exports.
- **New `features/hermes/skills/`** (3): `hermes-plugin-development` (merged
  authoring+development copies), `hermes-memory-provider-development`,
  `cron-watchdog-authoring`.
- **14 new optIn common skills** (never ship silently; enable via config):
  `artifact-verification`, `code-review-evidence`, `design-gate-audit`,
  `documentation-drift-audit`, `multi-lane-report-assembly`, `parallel-expert-review`,
  `pre-push-gate-debugging`, `research-record-audit`, `review-gate-diff-verification`,
  `scripts-tooling-refactor`, `spec-driven-refactoring`, `sqlite-bank-space-diagnosis`,
  `sqlite-schema-review`, `worktree-agent-isolation`.
- **New dotnet invariant** `features/dotnet/invariants/static-classes.md`: static
  classes are for extensions, constants, and pure functions only; anything with state
  or I/O is an injectable component.
- `SKILL_SCOPES` gained the 14 optIn entries; `index.json` rebuilt.

## Why

The skills are the proven, project-agnostic core of a year of .NET/MCP/Hermes work —
stripped of repo names, product paths, and machine specifics. The dotnet stack had
instructions and invariants but no skills; the mcp stack had neither. All workflow
skills are optIn so the default scaffold surface is unchanged.
