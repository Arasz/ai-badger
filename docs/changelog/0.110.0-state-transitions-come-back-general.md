# 0.110.0 — the state-transition rule comes back, general this time

0.88.5 purged consumer-facing leakage from the dotnet catalog and removed four lines from
`features/dotnet/instructions/csharp.instructions.md`. Three of them survived the move. One did not:

> If the project models explicit state transitions, route them through the state machine and record
> what triggered them; keep any "needs human attention" signal a flag, not a state of its own.

That line was generically worded and conditionally scoped. It was not leakage. It was cut with the
leakage and relocated nowhere — `grep -rn "state machine" features/` returns only skill references
after 0.88.5, and no instruction or invariant carries the rule.

## How it was found

Not by a test. By running `den-refresh` on a real consumer — the repository the dotnet content had
originally been harvested from — whose own pre-push gate refused the refresh:

```
.github/instructions/csharp.instructions.md missing required topic state-machine
.github/instructions/csharp.instructions.md missing required topic cosmos-userid
```

That project's `model.json` requires the shared C# instructions to mention
`route them through the state machine` / `triggeredBy`, and the rule it was matching had gone. The
project has 35 live `triggeredBy` references, so the requirement was not stale — the content was
missing.

`cosmos-userid` was the opposite case and needed no framework change: the tenant/owner rule **was**
relocated, to `features/cosmos/instructions/cosmos.instructions.md` and
`features/cosmos/invariants/partition-by-userid.md`. A consumer selecting `cosmos` still receives it.

## The audit

Of the four lines 0.88.5 removed:

| Removed line | Where it is now |
|---|---|
| braces, `extension` members, guard-clause library | still in `csharp.instructions.md` |
| RFC problem details, `409`/`202` | still there, updated to RFC 9457 |
| tenant/owner key on every persisted entity | `features/cosmos/` (instruction + invariant) |
| **state transitions through the state machine** | **nowhere — restored here** |

One rule lost, not a pattern. The purge was otherwise correct.

## What changed

`features/common/invariants/state-transitions-through-a-machine.md` — a **common** invariant rather
than a dotnet instruction, because nothing in the rule is language-specific. It renders into every
scaffolded project's `CLAUDE.md`, `HERMES.md` and `copilot-instructions.md`.

It keeps both halves of the original and says why each matters: a status field assigned in one place
and read in five is a state machine nobody can see, and a "needs attention" state gives every real
state a shadow twin.

The condition stays inside the sentence ("Where a domain object has explicit states…"), matching
`screaming-architecture` and `guard-clauses`, which also only bite where the situation arises.

## The budget

Seventeen common invariants now render into every agent file, and this repo's `agentDocs` override
went `228/15400` → `256/17500`. `maxChars` moved with `maxLines` deliberately: at the observed
~65 chars per line, 256 lines needs ~16.6k, so leaving chars at 15400 would have made the stated
line budget unreachable — a limit that does not mean what it says. `HERMES.md` sits at 228 lines and
14924 chars, with headroom in both.

The framework default in `tracker_lib.py` is untouched, so no scaffolded project's budget moves.
