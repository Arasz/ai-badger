# 0.187.5 — task-graph starts from any subdirectory

**Patch** (scaffold-affecting) · 2026-10-03

## What changed

- The task-graph launch that Claude (`.mcp.json`), Copilot (`.github/mcp.json`) and pi
  (`.pi/mcp.json`) receive now changes into the git root before it runs uv:
  `sh -c 'cd "$(git rev-parse --show-toplevel 2>/dev/null || pwd)" && exec uv run --script .ai-badger/skills/task-decomposition/scripts/task_graph_server.py'`.
- 0.187.4 made the launch project-relative, but hosts spawn MCP servers in the session's working
  directory. A session started in a subdirectory still read the root `.mcp.json`, and the
  relative path then resolved under that subdirectory, so the server failed to start.
- In a linked worktree, `--show-toplevel` is the worktree's own root, so the worktree's copy of
  the script runs, not the main checkout's.
- Outside git, the launch stays in the current directory, as before, and git's refusal is kept
  out of the host's server log.
- The task-graph prerequisite now names `git` alongside `uv`.
- `tests/test_task_graph_mcp_catalog.py` runs the generated launch for real, with a stub `uv`
  that records where it was started: once from `repo/src/deep` (it must land in `repo`) and
  once outside git.

## Behaviour changes worth knowing

- **The launch needs a POSIX `sh`.** Native Windows hosts don't have one, so they cannot start
  task-graph from this launch. Hermes keeps the plain `uv run --script` command, because its
  operator anchors the path in `~/.hermes/config.yaml`.
- Consumers pick this up for `.mcp.json` and `.github/mcp.json` on their next den-refresh. An
  existing `.pi/mcp.json` entry is never rewritten (F11), and the den-refresh note says so:
  delete the `task-graph` entry there and refresh again to adopt the new launch.
