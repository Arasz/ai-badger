# 0.50.0 — what the MCP tool index is for

[ADR-0013](../adr/0013-what-the-mcp-tool-index-is-for.md) narrows this feature to three purposes
and records the measurements that put a great deal of tempting work out of scope.

Documentation only. No behavior changed, and [ADR-0012](../adr/0012-bm25-retrieval-with-a-falsifiable-eval.md)
is not reversed — BM25 stays.

## The finding that prompted it

[ADR-0004](../adr/0004-mcp-tool-index.md) justified the index with two problems: prompt bloat and
tool-selection errors. **Only the second was ever addressed.** On a host that loads MCP tool
definitions itself — Claude Code does — ai-badger's hint does not replace them, it is appended
to them. Measured here: ~98 tool schemas already in context, ai-badger's condensed index ~2,300
tokens on disk, the hint ~75 tokens on top. The feature is a net addition to the context it was
justified as reducing.

That is not an implementation defect. It is a premise that was true of a Hermes plugin composing
its own prompt, and false of the deployment the framework now mostly runs in.

## The three purposes

1. **Curation the model cannot derive** — `intent` and `tags` are ours, not the server's.
2. **Answerability** — the index knows what is *not* in it, which is not expressible as a
   similarity score and must therefore be delivered explicitly.
3. **Deployments where the tool list is not all in context** — oversized tool sets,
   budget-limited hosts, and skills whose listings are truncated with descriptions dropped
   least-invoked-first.

Ranking quality is subordinate to all three: it serves selection among tools the model can
already see, and there the model is plausibly better than the matcher advising it.

## Out of scope, each with a measurement

Query expansion and thesauri (29 configurations, paraphrase recall@3 stayed 0.000 — WordNet lacks
`swap → replace`, and an oracle needs two correct expansions where WordNet supplies one);
fine-tuning (recall@1 1.000 in-sample, 0.070–0.256 leave-one-out); a shipped embedding model
(works — 0.731 ungated — but 8.29 MB tracked in three places here and two in every consumer
repository, ~8× clone growth, and not statistically significant at p = 0.125); further weight and
threshold sweeps (structurally incapable of moving false fire).

## What is in scope

The agent-driven enrichment loop, which writes tool semantics — **never the observed query text**,
which scores 1.000 in-sample and 0.000 on a sealed set. Against sealed fixtures enrichment gives
McNemar b=16/c=0 (p=3.1e-05), leaves the authored set completely unmoved, and lowers its false
fire from 0.267 to 0.067, for +18 KB and +0.9 ms per turn. Enriching only the 21 tools that silent
turns pointed at matched enriching all 98.
