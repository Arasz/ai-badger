# 0.156.0 — the user-DB message bus: agents coordinate across harnesses without the human relaying

Sessions on any hooked harness can now exchange messages through one machine-wide
SQLite bus (`~/.ai-badger/ai-badger.db`, store schema version 2): the `send-message`
skill sends with mandatory sender identity, and a shared delivery hook injects each
session's addressed mail at session start, every turn, and cleans up its cursor on
close — exactly once, on every harness ai-badger hooks.

## What changed

- **The bus store (P1).** `messages` and `cursors` tables are born
  through `UPGRADE_HOOKS[1]` on a pre-bus user DB, stamping `SCHEMA_VERSION 2`; a store
  this new refuses older code with the upgrade pointer (fail closed, D27). Delivery is
  one `BEGIN IMMEDIATE` transaction — the read and the cursor advance share it, so two
  hooks racing on one unread message serialize: exactly one injects, both finish at the
  same cursor. The first delivery gates history to the last 30 minutes and caps the
  oldest 16 (overflow lands past the gated window, never revisited); live reads are
  pure cursor-forward and uncapped. Messages and cursors older than 4 days prune on
  open. Every delivery shape is index-bounded (the search-lesson reads).
- **The cwd → projectId resolver (P2).** Sender and receiver identity derive from the
  cwd through the ai-raccoon registry (scope keys + watches UNION, equal-or-ancestor
  containment), with `AI_BADGER_PROJECT_ID` as the explicit override and an injectable
  registry seam (`AI_BADGER_RACCOON_DB`); an unresolved project fails open to 1:1
  delivery only, never cross-project guessing.
- **The `send-message` skill (P3).** One script, three sends: 1:1 (`--session-id`),
  project broadcast (`--project-id`), machine broadcast (no target). Sender identity
  is mandatory — session id overridable, project id resolved from the cwd registry —
  and refusals exit 1 with the reason and write no row.
- **The delivery hook (P4).** One Claude-shaped `message_delivery_hook.py` serves every
  harness: the store's documents render one-per-line, verbatim, chronological, and each
  line validates clean against `schemas/message.schema.json`. Fail-open throughout —
  malformed stdin, corrupt DB, registry explosion and unknown events all emit parseable
  JSON and exit 0. `AI_BADGER_TEST_HOLD` arms deterministic seams for the exactly-once
  race across processes (F5).
- **Wiring on every hooked harness (P5–P8).** Claude rides `SessionStart`,
  `UserPromptSubmit` and `SessionEnd` through hooks.json; Copilot the camelCase
  spellings including `sessionEnd` for cursor cleanup (the close-event verdict: the
  event exists — the hypothesis that it did not was falsified); pi through the
  adapter's `session_start` / `before_agent_start` / `session_shutdown` translations
  onto the Claude spellings; Hermes through the plugin's `on_session_start`,
  `pre_llm_call` and `on_session_end` callbacks. The manifest carries exactly the
  wired set; a hooked harness without the wiring stays safe.
- **Cross-package integration (P9).** The send → deliver → render roundtrip proven
  across two harness shapes with schema-clean output; two hook processes proven to
  deliver exactly once across the process boundary (the F5 env-hold makes the race
  real); harness parity asserted from the real manifest; the 30 non-deferred spec
  scenarios each mapped to an owning test and the mapping executable.

## Consumer impact

- The user DB gains bus tables on first store open (`~/.ai-badger/ai-badger.db`,
  schema version 2); an OLD checkout's store refuses the upgraded DB with the
  upgrade pointer — upgrade the checkout before sharing a machine.
- Mail older than 4 days is deleted on the next store open; a closed session's
  cursor is removed by the close event, a crashed session's by the same 4-day TTL.
- A session's first delivery replays the last 30 minutes (oldest 16); per-turn
  reads only see what arrives after that point — nothing grows without bound.
- `AI_BADGER_USER_ROOT`, `AI_BADGER_RACCOON_DB` and `AI_BADGER_PROJECT_ID` redirect
  the bus for tests and synthetic banks; unset, the real machine-wide store is used.
