# 0.187.6 — AiRaccoon checklist checks the long-query keyword cap

**Patch** (content) · 2026-10-03

## What changed

- The AiRaccoon manual checklist template gains `long-query-keyword-terms-capped` (ADR-0126 in
  AiRaccoon). It checks that a pasted query of ~7,000 characters returns in seconds on a VACUUM
  INTO copy of a real bank, and that the long-query warning names the 64-word keyword cap. On a
  fresh bank, a word after the 64th distinct word must lose its `fts` leg, and the stopword `the`
  must be dropped from a long query but kept in a short one. The release before the cap is the
  negative control, installed into a scratch `--tool-path`. The first run took 47 s → 1.9 s for
  the paste, and a 240 s timeout → 0.6 s for the stopword run.
- Three fixture premises that drifted with AiRaccoon's chunking are corrected:
  - The chunk-boundary note repeats its sentence forty-five times, not ten. Ten now fit in one
    chunk, so the premise of more than one row failed.
  - The opening-chunk regression is now described as the last index of 2, not of 8.
  - The skill's no-overlap semantic query says "inside a stargazing room". "in a" shared `in`
    with the stored text, which gave earlier runs an `fts` leg on the hit.
