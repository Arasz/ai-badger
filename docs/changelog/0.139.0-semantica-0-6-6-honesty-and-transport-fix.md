# 0.139.0 — semantica 0.6.6: transport fix, install pin, and an honesty pass

**Minor release.** Adds an `env` block to the generated `.mcp.json` / `.github/mcp.json`
semantica entry and changes what the `UserPromptSubmit` hook injects, both of which alter
what scaffolding does to a consumer repo (ADR-0001 decision 3).

Every claim below was measured on this machine against a fresh semantica 0.6.6; the
evidence record is `docs/work/2026-08-28-semantica-support-research.md`.

## What was broken

1. **The user-scope install destroys itself on Python 3.14.** `uv tool install semantica`
   with no pin resolves to uv's default interpreter. semantica depends on gensim 4.4.0,
   which publishes macOS arm64 wheels only for cp39–cp313, so uv falls back to a source
   build that fails — `ma_version_tag` was removed from `PyDictObject` in CPython 3.14.
   uv then tears the tool env down but leaves the `~/.local/bin` entrypoint symlinks
   behind, so the failure surfaces later as `ENOENT` on a path that still appears to
   exist. The catalog shipped that exact unpinned command.
2. **The RDF export corrupts the MCP transport.** semantica writes a progress bar to
   **stdout**, which is the JSON-RPC channel. An `export_graph(format="json-ld")` call
   over a live stdio session returns *nothing at all* — the frame is destroyed, not
   merely errored. Measured: 183 stdout bytes without the switch, 0 with it.
3. **Every `export_graph` format errors on 0.6.6**, not just json — `turtle` and
   `json-ld` fail with `'ContextGraph' object has no attribute 'get'`. 0.137.1's claim
   that "the RDF/json-ld branches work fine" was true of 0.6.5 and is false here.
4. **`check.py` reported health it could not deliver.** Its `export_graph_works()`
   consulted `semantica_mcp_wrapper.py` when the native probe failed. Nothing launches
   that wrapper, so the probe passed while the running server's export was broken.
5. **Every session was told to make a call that always fails.** The `UserPromptSubmit`
   nudge instructed `export_graph(format=json)` before finishing.
6. **A failed export was saved as a graph.** `extract_graph_json` guarded three envelope
   shapes and then fell through to `return result`, so a bare
   `{"content":[{"type":"text","text":"{\"error\": …}"}]}` payload was written to
   `.semantica/` as if it were a graph — silently.
7. **A tooling script reverted the catalog on every test run.**
   `tooling/convert_mcp_prerequisites.py` had no argv parsing and performed its rewrite
   on any invocation, including `--help`; `test_engine_tooling_layout.py` runs every
   tooling script with `--help` against the real repo root. Invisible while its
   hardcoded block matched the committed file — and destructive the moment it did not.

## What changed

- `features/common/stack-mcp.json` — the semantica entry declares
  `env: {"SEMANTICA_DISABLE_PROGRESS": "1"}`. The launch command is unchanged.
- `features/common/mcp/semantica/meta.json` — install commands pin `--python 3.13`, and
  the prerequisite commands no longer point at `features/common/mcp/semantica/scripts/…`,
  which does not exist in a consumer project.
- `features/common/mcp/semantica/scripts/install.py` — `ensure_venv` builds with the
  interpreter it selected instead of the running one, and `explain_install_failure()`
  names the gensim/3.14 cause when pip fails with that signature.
- `features/common/mcp/semantica/scripts/check.py` — the wrapper fallback is gone, and
  the two copies of its warning collapse into one constant whose text matches what was
  measured.
- `features/common/retrieval/context_enrichment.py` and the export hook — the nudge keeps
  `record_decision` and drops the export instruction.
- The export hook's fall-through now requires the shape a graph actually has, reports an
  unrecognized payload instead of skipping silently, and recognises the content envelope.
- `tooling/convert_mcp_prerequisites.py` — **deleted.** Its migration shipped in 0.117.0
  and its output is committed, so it was a hand-maintained twin of its own source of
  truth.

## What was NOT fixed, and why

`export_graph` is broken upstream in every format and ai-badger cannot fix it. The
`.semantica/` autosave pipeline stays wired and resumes when a fixed release lands; until
then `.semantica/` staying empty is expected, not a regression.

`semantica_mcp_wrapper.py` is **kept**, though it is on no launch path. It does fix the
json branch (measured), and the review could not establish that no launch route exists —
the plugin ships the whole repo to the plugin cache, where hooks already address files via
`${CLAUDE_PLUGIN_ROOT}`. `check.py` deliberately no longer consults it.

## Limits of the verification

The `env` declaration is locked by a structural test, which cannot prove the transport
stays clean. That proof needs semantica installed plus a live stdio handshake, which CI
does not have. The behavioural evidence is the measurement recorded in
`docs/work/2026-08-28-semantica-support-research.md`, not something CI re-runs.

`features/common/mcp/code-review-graph/meta.json` has the same unreachable-path defect as
item 1's companion fix — its prerequisite commands also point into the framework tree. Not
touched here; it is not a semantica issue.
