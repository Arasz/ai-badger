# 0.72.0 — rules that lived in the prompt

Five working rules were being retyped at the top of every prompt: use plain names, check the
source rather than your own reasoning, only measure when the measurement pays, ask whether a
simpler shape would do, and treat "done" as evidence rather than as code written.

Retyping them is not the cost. The cost is that a rule stated in a prompt reaches exactly one
agent, once. A subagent dispatched three turns later never sees it, and the next session starts
without it unless someone remembers the whole list. Rules that only exist in the prompt are not
rules; they are reminders, and they decay at the speed the operator forgets.

This is package A of the four in
[`docs/work/2026-08-01-work-quality-rules.md`](../work/2026-08-01-work-quality-rules.md), which
sorted sixteen proposed rules by where each belongs. These five are the ones that survived the
test of being about a diff rather than about a session.

## What changed

Five invariants join `features/common/invariants/`, so they scaffold into every project and land
in the `CLAUDE.md` that every agent and every subagent loads on every turn:

| File | Rule |
|---|---|
| `proof-of-done.md` | "Done" means evidence the thing works, not that code was written |
| `plain-names.md` | The simplest accurate word; rare ones only when nothing common fits |
| `check-sources-not-yourself.md` | Re-read the source — that is what goes stale, not your logic |
| `measure-when-it-pays.md` | Benchmark when the decision repays the time; otherwise say so |
| `ask-if-simpler.md` | Before calling it finished, ask what the simpler version looks like |

Each is three lines: a title, a blank, one paragraph. That is the tersest shape the house style
allows, and it is deliberate — see the budget below.

## The house style is now enforced, not just observed

`tests/test_invariant_catalog.py` adds a mechanical guard: every file in
`features/common/invariants/` is at most six lines and carries exactly one `#` heading, on its
first line. Nine files already complied; nothing had ever required them to.

The cap is a token budget rather than a style preference. These files are not documentation
someone opens — they are concatenated into a discovery file that is re-read on every turn, by
every agent and every subagent, for the life of the project. A long invariant is a recurring
charge, and the only moment it is cheap to refuse is at authoring time.

`pr-per-task.md` is the one exemption, named in a single constant in the test. It is seven lines
because it carries a clause about who may waive the PR rule and who may not, and that clause
earns its lines. Exempting it by name keeps the exception visible; loosening the cap for
everybody would have hidden it.

## What this cost

**The agent-doc budget went up.** `agentDocs.maxLines` in `.ai-badger/config.json` is now 180,
raised from 160. This repo's own `HERMES.md` was 152 lines with 8 to spare; five invariants add
20, which put it at 172 and failed `test_agent_doc_budget`. The new cap restores the same 8 lines
of slack the file had before — chosen to preserve the previous headroom, not rounded to a
comfortable number.

That is a real cost and it belongs in the record rather than in a quiet config edit. The budget
gate offers two remedies, shorten the content or raise the cap, and the content was already at
the floor of the house style. `CLAUDE.md` is unaffected at 137 lines; only the Hermes discovery
file, which carries extra sections, was close enough to the old cap to notice.

## Tests

`tests/test_invariant_catalog.py`, red before the invariant files existed — 10 of its 12 failing.
The other 2 passed from the start, which is correct: the house-style checks are a guard on
existing content, not a red test.

- delivery — each of the five is copied to `.ai-badger/invariants/` and appears in the run
  manifest under `feature == "invariants"`
- rendering — each one's heading, demoted by the production `demote_headings`, appears under
  `## Non-negotiable invariants` in the generated `CLAUDE.md`
- house style — the six-line and one-heading guards described above

The rendering test reads each source file's own heading at test time rather than hardcoding the
wording, so it pins the wiring from source through demotion to the rendered document without
freezing the prose.

## A trap left in place

`tests/test_scaffold_agent_files.py::test_multiple_keep_regions_are_all_preserved_in_order`
asserts ordering with `content.index("first") < content.index("second")` against the whole
rendered document. Two drafts of these invariants used the word "second" in ordinary prose, and
the naive substring search found the invariant text ahead of the keep region, failing a test that
has nothing to do with invariants.

The drafts were reworded — both read better for it — so the suite is green. The fragility is not
fixed: any future catalog content containing "first" or "second" will trip the same wire. The fix
is a distinctive sentinel in that test rather than two common English words, and it is left for
its own change rather than bundled into this one.
