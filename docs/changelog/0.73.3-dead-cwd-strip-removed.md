# 0.73.3 — The cwd strip that never ran

0.73.2 added a loop that popped `cwd` from every recorded entry a `pin_cwd=False` destination was
about to write. It could not affect the file: `section.update(entries)` replaces each of those
entries outright on the next line, so the popped key was discarded either way.

The behaviour it looked responsible for is unchanged and now has tests. A rendered entry omits
`cwd` unless the destination pins it, so `update` overwrites a stale one by replacement; a server
ai-badger does not declare keeps whatever `cwd` its author wrote, because the file is merged
rather than owned.
