# 0.172.11 — status-report matches a plan only on the whole task id

**Patch** — two fixes to the `/task` tracking surface: `status-report` plan matching and
task-id validation, plus a `drop` verb for stray rows. 2026-09-24.

## What was wrong

- **Another task's plan could be reported as this task's plan.** `status-report` scored
  plan filenames by substring token overlap and marked the result matched if any single
  token appeared. The repo alias is in every filename, so it always matched. For
  `jsaa-claude-code-review-github-workflow`, another task's
  `…shadow-wiring.plan-review-3-code-reviewer.md` scored 4 of 6 (`jsaa`, `code`,
  `review` inside `reviewer`, `workflow`) and was shown as matched. It is a review
  document with no checkboxes, so the report said "no checkbox items in plan", and the
  newest-file fallback warning never appeared. A numeric key failed the same way: `2` in
  `aib-2` matched every `2026-…` filename.
- **`/task <free-form prose>` created junk rows.** The prompt hook registered the first
  word after `/task` as the task id. In one consumer this produced untitled, branchless,
  IN_PROGRESS rows named `take`, `Job`, `1.`, `Provider`, `I`, `https` and `-`.
  `task_tracker.py start` accepted the same ids, and no verb could remove a row.

## What changed

- A plan matches only when its filename holds the whole task id as a run of
  hyphen-separated tokens. Tokens are compared whole, and a leading date is ignored. The
  contract name `<YYYY-MM-DD>-<taskId>.md` wins over a longer name that contains the id.
- Review documents (a `.review`, `.plan-review-*` or `-impl-review` part outside the
  task id) are never the plan. A task whose own id contains `review` still matches its
  plan.
- When nothing matches, the report still shows the newest plan, but with
  `matched: false` and the existing "newest-file fallback" warning. It uses a review
  document only when no other file exists.
- A task id must match `{repo-alias}-{key}`: two or more runs of ASCII letters and
  digits joined by single hyphens (`is_task_id` in `task_tracker.py`). `start` exits 2
  with a message naming the format. The prompt hook uses the same check, so
  `/task <prose>` registers nothing, and the model derives the id first.
- New: `task_tracker.py drop <taskId>` deletes a row and its token-usage row, but only
  when the row has no title, no branch and no worktree. Anything else exits 2.

## Upgrade notes

- Re-scaffold to pick up the scripts. Existing rows are not changed.
- Task ids made of a single word (`T01`) or containing `_` or `.` are now refused by
  `start`. Use the documented `{repo-alias}-{key}` form.
- To clean up junk rows: `python3 .ai-badger/skills/task/scripts/task_tracker.py drop take`
  (and likewise for each one).
