# 0.208.0 — the model map, and a group that means what it says

**Minor** (new capability) · **Date:** 2026-10-20

The model registry was one file with three groups, each a price-ordered list of OpenRouter
ids, and the first entry won. That worked while the groups were an accident of price, but
it could not answer the question the groups were there for: a persona that asked for a
careful review asked for a cost tier, and the cheapest member of that tier was a small
flash model. The anchors the groups were named for (opus, sonnet, haiku, fable) lived in
the personas as bare lanes and never reached the resolver, so a tier and its anchor could
disagree and nobody would notice.

This release replaces the registry with a model map.

- **The map is one file with four groups.** `low`, `medium`, `high` and `top`, each with
  the family anchors it stands for, one anchor marked primary, and the concrete
  provider-qualified ids that belong to the tier with their price, license and score.
- **A group resolves to its anchor.** The group's preferred member is the model its
  primary anchor names, so `high` is `openrouter/anthropic/claude-opus-5.5` and `top` is
  `openrouter/anthropic/claude-fable-5.1`. The rest of the tier follows in ascending price
  and a zero-priced open-weight member has no price position, so it sits last.
- **The open-weight members are in the map.** The leaderboard prices GLM-5.3 and
  dots3-note at zero, so a member priced 0/0 is legal when its license says it is open
  weight, and a member that is not open weight still has to pay. The old rule that every
  price is above zero is what made a free member unrepresentable.
- **The map says where its numbers came from.** The provenance block names the
  leaderboard file with its checksum and row count, the model store, the generator, the
  OpenRouter catalogue snapshot, the five leaderboard rows it leaves unpriced and the
  thirteen it leaves out with the reason for each.
- **The map is generated, not typed.** `tooling/generate_model_map.py` re-renders it from
  the leaderboard CSV, pi's model store and the catalogue snapshot, and `--check` reports
  drift without writing. The refresh rule is documented in the tool: a row's tier is its
  input price against the rungs 0.1, 2 and 4 dollars per million tokens, a tier keeps the
  newest model of each family, and only a verbatim OpenRouter listing is admissible.
- **`top` is a real group now.** The plan step's level, the task-graph level enum and the
  tier classifier in the decomposition skill all carry the four groups, and the
  classifier's answer set is checked against the leaf's own vocabulary instead of being a
  second copy of it.
- **The rules the old registry had and the map does not are gone with its shape**: the
  demoted tail, the always-latest aliases and the weights-identity evidence. The map is a
  plain list of models with a price, a license and a score.

What this release does not do: it does not yet change a persona. A persona still carries
the `level:` key and the bare Claude lane, and the delivery that maps a group to a family
name for Claude Code and Codex is the next one. Nor does a tier resolve to a free member,
because a zero price has no position in the order, so the billing failure that started
this is still open on the open harness until the extension retries a refused model.
