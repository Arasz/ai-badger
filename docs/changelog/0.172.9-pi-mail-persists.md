# 0.172.9 — pi bus mail consumed mid-run persists and stays on every later call

**Patch** (behavior fix, no shape change) · 2026-09-24

## What changed

The pi adapter's per-turn delivery seam read the bus in pi's `context` event and
appended the mail to the message array that handler returns. That array is a
per-request copy. pi's runner clones it (`let currentMessages =
structuredClone(messages);`), and the agent loop keeps the transformed list local
to one call (`messages = await config.transformContext(messages, signal);`).
The delivery script had already advanced the store cursor, so the mail was
consumed exactly once but reached only one LLM request. It never fired a message
event (the TUI never showed it), never reached the session file, and was gone from
the next request. The timer path was not affected, because it already goes
through `pi.sendMessage`. The context seam usually won the race, though.

The per-turn seam now runs on `turn_end` and hands the mail to
`pi.sendMessage(..., { deliverAs: "steer" })`. pi drains its steering queue right
after `turn_end` and before the next call. It emits the message (`message_start`
/ `message_end`), so the session persists it as a `custom_message` entry, and it
pushes the message onto the run's context. From then on the mail is a session
message on every later call. A turn with no tool results is the run's last. At
that point the seam leaves the mail in the store, where the timer's wake routing
or the next run's `before_agent_start` picks it up. Delivery therefore never adds
an LLM call.

Exactly-once is unchanged: one live read per seam, the store's transaction
advances the cursor once, and the steer is enqueued before pi polls the queue.

Verified against pi 0.84.3 (the pinned harness) and 0.87.1. In 0.87.1, extension
`turn_end` handlers run inside `finishTurn` before the loop emits `turn_end`, and
the loop still polls steering after that.

## Wiring

- `features/pi/adjustments/adapter/index.ts`: the `context` subscription becomes
  `turn_end` → `pi.sendMessage` steer, skipped when the turn has no tool results.
- `features/pi/adjustments/adapter/hook-bridge.ts`: the router's `context` method
  becomes `turnEnd` and shares `beforeAgentStart`'s delivery. The transient
  `ContextInjection` shape is removed.
- `features/pi/tests/adapter-mail-durable.test.ts`: new. It drives pi's real
  `AgentSession`, extension runner and agent loop with pi-ai's faux provider and
  injected bus I/O. Mail consumed mid-run is present on LLM calls 2 and 3, emitted
  once and persisted once. Mail landing during the last call is not consumed. The
  test was red before the fix on both pi versions: `mailPerRequest [0, 1, 0]`,
  `emitted 0`, `persisted 0`.
- `tests/js/pi_message_bus_adapter.test.mjs`, `tests/test_pi_hook_arm_coverage_contract.py`
  and `features/pi/tests/adapter-bus.test.ts` now pin the `turn_end` seam.
