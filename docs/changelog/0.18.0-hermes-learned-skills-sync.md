# 0.18.0 — Hermes learned-skills sync (core module)

**Issue:** #67
**Design:** `docs/design/hermes-learned-skills-sync-impl-plan.md`
**Research:** `docs/research/hermes-learned-skills-sync.md`

First of three PRs. This one ships the logic only — nothing is wired to a hook yet, so no
behavior changes for existing users.

## Added

- `features/common/hooks/learned_skills_sync.py` — one-way sync of a Hermes learned skill
  into `.ai-badger/skills/learned/<category>/<name>/`, event-scoped to a single
  `skill_manage` call. Five gates before any write: the tool must be `skill_manage`, the call
  must have succeeded, `cwd` must be an ai-badger-scaffolded project, the source must resolve
  inside `~/.hermes/skills/` with no symlink on any path segment, and the name must not be
  one the framework manifest already owns.
- Provenance and idempotence record at `.ai-badger/skills-data/hermes/learned.json`,
  deliberately separate from `manifest.json` — a learned skill is not framework-owned.
  Contains only Hermes-root-relative paths.
- `schemas/learned-skills.schema.json`, registered as `--kind learned-skills` in
  `scripts/validate.py`.
- A `--reconcile [--dry-run]` CLI for backfilling skills that predate the sync. Opt-in; never
  runs automatically.
- A refuse-on-secrets guard: a skill containing a high-confidence credential literal is not
  synced. Refuse-and-report only — never redacts, never partially copies.

## Changed

- `feed-badger`'s `detect_additions.py` now emits **one** candidate per learned-skill
  directory instead of one per contained file, named for the skill and tagged
  `origin: "hermes-learned"`. Behavior for all other unmanaged files is unchanged. A
  malformed `learned.json` costs provenance, not the whole detection run.

## Notes

- Deletes in Hermes do not delete in the project; the record is marked `orphaned` and the
  files stay. A background curator must not be able to remove version-controlled files.
- Synced skills are not yet loadable by any agent — nothing distributes `.ai-badger/skills/`
  since #58. That is addressed in the third PR, which reverses #58.
