# 0.213.0 — rtk is out of ai-badger

**Minor** (a shipped integration is withdrawn) · **Date:** 2026-10-21

rtk (`rtk-ai/rtk`) was ai-badger's first member of the `tools` feature type (ADR-0039): a
CLI proxy that rewrites shell commands so their output reaches the model compressed, wired
into each agent harness through a per-harness hook. It is gone from the framework now, and
nothing in ai-badger names it any more — not the catalog, not the shared scripts, not the
live documentation, not the tests.

The `tools` feature type itself stays: it is a generic extension point for an external CLI,
with its own `meta.json` schema, per-agent adjustments and a `config.tools` opt-in. It simply
ships no member, so a project that wants one adds `features/<stack>/tools/<name>/` itself.

## Removed

- **`features/common/tools/rtk/`** — the catalog entry, its `meta.json` and `tool.md`, the
  prerequisite `check.py`/`install.py`, the Claude/Codex `rtk_guard.py`, and the user-scope
  `user_hook.py`. `index.json` no longer carries a tools item.
- **The rtk branches in the shared scripts.** `shell_parser.py` no longer reads `rtk` as a
  wrapper or unwraps its runner subcommands, so `rtk rm x` is a program called `rtk` with
  `rm x` as its arguments. `suite_economy.py` no longer strips an `rtk` prefix before
  classifying a test run, and the memory-first gate no longer takes `rtk rg` for a repo
  search.
- **The rtk suites** — nine test files, replaced by `tests/test_rtk_removed.py`, which
  asserts the absence: no catalog entry, no source that names it, no live document that
  mentions it, and the shared helpers treating an `rtk` command as the ordinary unknown
  program it now is.

## Fixed

- **The away-mode gate judges a command a proxy carries.** Removing `rtk` from the shell
  parser would have left `proxy curl https://x` and `proxy run -c 'rm -rf /tmp/x'` looking
  harmless to the auto-approval gate, where the bare commands are denied. The gate now
  judges the command word an argument starts with, so a wrapped command is never approved
  where the bare one is denied — for every proxy, not for one named tool.

## Upgrade notes

- A project that opted into rtk (`config.tools.rtk`) gets its marked hooks removed by the
  next refresh: the tools adjustment drops every handler carrying the `AI_BADGER_TOOL`
  marker, whether or not the tool is still in the catalog. The config key itself is not
  rewritten — remove it, or the scaffold reports that the named tool is no longer in the
  catalog.
- rtk's own files are not ai-badger's to delete. `.pi/extensions/rtk.ts`, rtk's user-scope
  hook and `~/.rtk/` were written by rtk, not by the scaffold; remove them yourself if you
  want rtk gone from the machine.
- The history stays: ADR-0039 records why the `tools` feature type exists, and the 0.194.0
  through 0.198.0 changelog entries record what rtk did when it shipped. Neither is read as
  current behaviour.
