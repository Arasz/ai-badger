# 0.18.0 — Hermes learned-skills sync (hook wiring)

**Issue:** #67
**Design:** `docs/design/hermes-learned-skills-sync-impl-plan.md` §6

Second of three PRs. This one makes the sync actually run.

## Added

- `ai_badger_hooks.py` now handles `skill_manage` on the `post_tool_call` hook it already
  registered. The branch is fully wrapped — a sync failure logs at debug level and never
  propagates into the user's tool call.
- The sync module is imported lazily and cached, so the plugin still loads on an older
  scaffold where `learned_skills_sync.py` is absent.
- `hermes_skills_root()` resolves `HERMES_HOME` first, then `~/.hermes/skills`, mirroring
  Hermes' own `get_hermes_home()` order.

## Fixed

- `features/hermes/adjustments/adjust_hooks.py` now installs `ai_badger_hooks.py` and
  `learned_skills_sync.py` into `~/.hermes/plugins/`, and is gated on `hermes` being in
  `config.agents`. Previously it copied only into `.ai-badger/hooks/`, which Hermes never
  reads — so the plugin was never installed by the scaffold at all, and any user who had one
  had copied it by hand.

## Notes

Hermes passes **no `cwd`** to plugin hook callbacks — verified at `model_tools.py:1049-1064`
(`post_tool_call`) and `conversation_loop.py:504-509` (`on_session_start`). The sync branch
therefore resolves the project itself with `os.getcwd()` and gates on
`.ai-badger/manifest.json` being present, so a gateway session with an unrelated working
directory writes nothing.

This also means the two pre-existing `cwd`-dependent behaviors in `ai_badger_hooks.py` — the
Hermes drift notice and the MCP-index hit/miss logging — have never fired. That is a separate
defect and is not fixed here; changing untested behavior does not belong in this PR.
