# 0.90.0 — the docs answer to the catalog, not to their own prose

`docs/skills.md` opened with a paragraph that failed its own arithmetic: "twenty-two skills …
twenty-one live under `features/common/skills/` … fourteen are `default` … eight are `optIn`".
Fourteen plus eight is twenty-two, not twenty-one, so the page was wrong before anyone checked
it against reality. Reality was worse: `badger_lib.SKILL_SCOPES` declares **36** skills and
`features/claude/skills/` adds `auto-wm`, so the real total is **37** and the page documented
**23**. Fourteen `optIn` skills — every one of them shipped in #320 — had no row, no section and
no mention anywhere a reader would look.

Nothing in the repo could have caught that. `skills_lint` reads `SKILL.md` frontmatter and
`docs_guard` reads links; a prose undercount is invisible to both. The same shape had already
taken `docs/scripts.md`, which lists the `tooling/` scripts by hand and had lost two of them,
and `docs/work/README.md`, which described two research records in careful detail — both of
which were never committed to any branch in this repository.

## What changed

**`docs/skills.md` documents all 37 skills.** The fourteen missing ones get a row in the
at-a-glance table and a section of their own: `research-record-audit`,
`multi-lane-report-assembly`, `parallel-expert-review`, `code-review-evidence`,
`review-gate-diff-verification`, `design-gate-audit`, `artifact-verification`,
`documentation-drift-audit`, `spec-driven-refactoring`, `scripts-tooling-refactor`,
`worktree-agent-isolation`, `pre-push-gate-debugging`, `sqlite-schema-review` and
`sqlite-bank-space-diagnosis`. The four counts in the opening paragraph are now numerals,
because a numeral can be checked and a spelled-out number invites a guess.

**The table is checked against `SKILL_SCOPES`, not generated from it.** Generating the rows
would mean generating the `Purpose` column too, and the only machine-readable source for it is
each `SKILL.md`'s trigger description — long, second-person and written for a matcher rather
than a reader. `tests/test_docs_match_the_catalog.py` gets the same property for less: the row
set must equal the catalog exactly in both directions, each row's `Ships` cell must equal the
declared scope, and each of the four prose counts is re-derived from `SKILL_SCOPES` at test
time. A skill added to the catalog without a row fails. A row for a skill the catalog dropped
fails. A row that claims `default` for an `optIn` skill fails.

**`docs/work/README.md` lost its two fictional rows.** `2026-08-07-mcp-skills-distribution.md`
and `2026-08-07-mcp-skills-tools-pattern.md` were indexed with full descriptions and exist in no
commit — `git log --all -- <path>` returns nothing for either. The rows arrived through a squash
and described work that never merged.

**The map check now runs both ways.** `tests/test_docs_tree_is_canonical.py` already asserted
that every file beside a README is named in it. It now also asserts that every file a README's
index table names exists, for all eight canonical directories, with a floor on the number of
rows parsed so a drifted row pattern cannot pass the check by matching nothing.

**`docs/plans/` is gone.** PR #111 removed the seven kind-grouped directories; `plans/` came back
with one file and stayed, because the root-README check looked for the substring `plans/` and
found it inside the paragraph explaining that the directory had been deleted. The check is now a
membership test against `CANONICAL_DIRS`, `FROZEN_DIRS` and the two pinned directories, so a
directory off the map is a failure rather than a coincidence. `docs/plans/memory-grade-hook.md`
said `Status: proposed` for a hook that shipped in 0.79.0; it is deleted, not relocated —
`work/` is a desk, not an archive, and a concluded design lives in git history.

**`docs/scripts.md` names every script under `engine/`, `tooling/` and `gates/`.**
`retrieval_eval.py` and `fixture_harvest.py` were missing; the new coverage test is
parametrised over all three directories, so the next one cannot go missing quietly. Both entries
say plainly that `retrieval_eval.py` is wired into no gate — that decision is still open
(D3/W10.f) and the documentation should not imply otherwise.

**ADR-0016's README row said 0.82.0.** Junie support was removed in 0.83.0 — the ADR body says
so and `docs/changelog/0.83.0-junie-support-removed.md` is the entry. The row is corrected; the
ADR itself is untouched.

## Evidence

The tests were written first and run red against the tree as it stood:

```
docs/skills.md has no at-a-glance row for: artifact-verification, code-review-evidence,
  design-gate-audit, documentation-drift-audit, multi-lane-report-assembly,
  parallel-expert-review, pre-push-gate-debugging, research-record-audit,
  review-gate-diff-verification, scripts-tooling-refactor, spec-driven-refactoring,
  sqlite-bank-space-diagnosis, sqlite-schema-review, worktree-agent-isolation
docs/skills.md no longer states the catalog total in a checkable form
docs/skills.md no longer states the features/common total in a checkable form
docs/skills.md no longer states the default count in a checkable form
docs/skills.md no longer states the optIn count in a checkable form
docs/scripts.md omits tooling/: fixture_harvest.py, retrieval_eval.py
docs/work/README.md indexes files that do not exist:
  2026-08-07-mcp-skills-distribution.md, 2026-08-07-mcp-skills-tools-pattern.md
docs/ holds directories the canonical tree does not name: plans
```

Each new check was then re-broken deliberately against the fixed tree and confirmed to go red
again — a row deleted, a row invented, a `Ships` cell falsified, a count edited, a script row
removed, a README row pointed at a file that does not exist, and a stray directory created under
`docs/`.
