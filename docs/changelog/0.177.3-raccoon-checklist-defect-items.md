# 0.177.3 — AiRaccoon checklist items that go red on the defects they cover

**Patch** — `features/ai-raccoon/skills/ai-raccoon-manual-checklist` gains four items, one for
each of four AiRaccoon defects fixed by ADR-0119 to ADR-0122, and an engine stub for one of them. 2026-09-27.

## What was missing

- The checklist had no item for a memory row that can never embed, for an identifier cut in two
  by a chunk boundary, for a watched file changed without an event, or for a source-citing note
  whose opening chunk reported the last chunk index. Each of those shipped broken and passed
  every existing item.
- Checking the first one by hand needs an embedding engine that fails for one input and answers
  for every other. There was none to hand.

## What changed

- `templates/checklist-template.json` adds `poison-memory-row-isolated-and-abandoned`
  (ADR-0119), `keyword-search-across-a-chunk-boundary` (ADR-0120),
  `watch-catch-up-heals-a-missed-change` (ADR-0121) and `note-opening-chunk-reports-index-zero`
  (ADR-0122). Each expected result names its premise or negative control and what a build
  without the fix shows. All four were run against a build before the fix (red) and one with
  it (green).
- `scripts/poison-embedding-stub.py` is a stdlib OpenAI-compatible `/embeddings` endpoint. It
  returns deterministic vectors as floats or as base64 float32, answers 400 for any batch
  holding a marker, and logs `ok N` or `poison N` for each request. `tests/test_poison_embedding_stub.py`
  drives it over HTTP.
- `SKILL.md` adds the four behaviours to Scope, a fourth way an item passes without testing
  anything (a keyword hit that came from the vector leg), and a gotcha: a stopped WAL bank will
  not open read-only.

## Upgrade notes

- Re-scaffold to pick up the new items and the stub. Nothing else changes.
