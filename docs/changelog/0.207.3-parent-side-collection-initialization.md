# 0.207.3 — A collection can be initialized from the parent side

**Minor** (new capability) · **Date:** 2026-10-19

A directory of repositories can become one shared ai-badger scope with two commands. Run in
the directory that holds the projects:

```bash
python3 "$AI_BADGER/features/common/skills/welcome-ai-badger/scripts/shared_scope.py" discover \
  --target /path/to/source --root "$AI_BADGER"
python3 "$AI_BADGER/features/common/skills/welcome-ai-badger/scripts/shared_scope.py" init \
  --target /path/to/source --root "$AI_BADGER"
```

`discover` is read-only: it lists the direct subdirectories that carry a `.git` entry, one
`dir:stacks` line each, plus the union of their stacks. Discovery is one level deep — a
repository inside another one is not a member.

`init` does the work. It discovers the same repositories, decides every identity and every
member's own settings before it writes anything, scaffolds the parent with the union of the
children's stacks, and materializes every member from it. A member with no ai-badger yet is
scaffolded; a member that already has one is converted — its own stacks stay its own, its
own settings become its overrides, and its own project id survives. `--dry-run` reports the
members, the union and every identity decision, and writes nothing.

The `dir:stacks` index is kept in the parent's `.ai-badger/shared-scope.json` as
`memberStacks`, and `collect` writes it too.

The welcome-ai-badger flow now offers this path: when the target holds more than one direct
child repository, it runs the discovery, shows the operator the index, and asks before
initializing.

This amends ADR-0041, which made membership explicit and the collection never
discovering neighbouring repositories on its own. The explicit path (`collect`) is unchanged;
the discovery is one level deep, a directory counts only when it carries a `.git` entry,
every decision is made before the first write, and every repository that was not enrolled is
named in the report. ADR-0042 records the decision.

A member with no identity of its own is resolved through the canonical ai-raccoon lookup on
a machine that has one; on a machine with no ai-raccoon at all, the parent-side path mints
a local id instead of refusing every member, because a collection that cannot be created on
an ordinary machine is not a collection. An answer the bank gave and cannot be trusted on
still refuses the run before anything is written. Nothing is registered with the bank
unless `--register` is passed.
