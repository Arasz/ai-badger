# 0.50.0 — MCP support is configuration, not retrieval

[ADR-0014](../adr/0014-mcp-support-is-configuration-not-retrieval.md) supersedes
[ADR-0013](../adr/0013-what-the-mcp-tool-index-is-for.md) in part, one day after it was accepted.
Its three purposes stand. The premise underneath them does not.

Documentation only. No behavior changed.

## The premise that failed

ADR-0013 reasoned from its own words: *"On a host that loads MCP tool definitions itself — Claude
Code does — ai-badger's hint does not replace them, it is appended to them."*

Claude Code defers tool definitions through ToolSearch once they reach a fraction of the context
window. Confirmed first-hand — the session that wrote ADR-0014 was running deferred, and said so:

> Until fetched, only the name is known — there is no parameter schema, so the tool cannot be
> invoked.

So the model is often working from **tool names with no descriptions at all**. Supplying curated
intent for something the model sees only as `rider:apply_patch` is not redundant with a
description it already has — there is no description. **Curation is the strongest of the three
purposes, not the weakest.**

The measurement that produced ADR-0013 is unaffected: that experiment put the full list in the
prompt, so "a model reading descriptions beats our matcher 0.846 to 0.442" still holds. What no
longer follows is the inference to production, which assumed those descriptions were present.

## What else changed the picture

- **Both hosts can prune, not merely rank.** Hermes takes `mcp_servers.<server>.tools` with
  `include`/`exclude` and fnmatch globs, applied at registration so a filtered tool's name never
  reaches the model — but it is user-global. Claude Code's agent definitions accept
  `disallowedTools` with server-level specs, in `.claude/agents/*.md`, which is project-scoped and
  a file ai-badger legitimately owns. The second is reported from the 2.1.220 schema and not yet
  verified locally.
- **A scaffolder owns two of at least seven arrival routes** by which MCP servers reach Claude
  Code. That is why the index sees tools from servers ai-badger never declared.
- **ai-badger was committing the overreach it warns about**: `.mcp.json` ships in the plugin with
  absolute paths from the maintainer's machine, and Claude Code loads a plugin's `.mcp.json` at
  user scope ([#173](https://github.com/Arasz/ai-badger/issues/173)).

## The decision

MCP becomes a stack-wired catalog feature, the way skills already are: a per-stack `mcp/`
directory and `stack-mcp.json`, resolved by the same stack-aware scaffolding. `external-tools.json`
is removed in favour of a skill carrying an `mcp-tool` field. `mcp-servers.json` is deleted unless
a reader is found. Per-agent server configuration lives in `features/<agent>/adjustments/`.
ai-badger proposes user-global configuration and never writes it.

## A correction to ADR-0014 itself, made the same day

Its Context §5 called `mcp-tags.json` a file documenting "the closed taxonomy ADR-0012 reversed".
**Wrong.** ADR-0012 line 63 exempts it explicitly — *"`mcp-tags.json` is unaffected"* — and the
file is live in `_auto_tags`, `cmd_validate` and `cmd_tag`. Only its own `description` field is
stale, claiming tags drive hook recommendation.

Two neighbouring claims were also wrong and are corrected here rather than in the ADR:

- **`mcp-servers.json` is not dead.** `collect_stack_mcp_servers()`
  (`welcome-ai-badger/scripts/mcp_tools.py:90`) reads it and three test files cover the mechanism.
  What is dead is the *file*: `{"servers": []}` is byte-identical to the file being absent, and no
  stack ships a sibling. Delete the file; keep the mechanism until its replacement ships.
- **It was never "three registries for one concern"** — two that genuinely merge
  (`mcp-servers.json`, `external-tools.json`) plus one vocabulary serving a different concern.

The decisions those claims supported are unaffected. The reasons given for them were not, which is
worth more than the tidiness of an unblemished record.

## Two corrections carried into every document that repeats them

Skill listings are **shortened to fit** their budget, not dropped least-invoked-first. And tool
schemas are not universally resident, which is the claim this entry exists to retire.
