# 0.174.1 — Store fixes: test_economy table, D7 landing, audit doctor, torn legacy files

**Patch**: fixes in `engine/badger_store.py` (and its 37 vendored copies) and the audit sink in
`debug_log.py`. 2026-09-24.

## Fixes

- **The user store now has a `test_economy` table.** The family was registered by its
  caller but had no DDL, so every write failed with `no such table`. It is born in SQLite:
  a `CREATE TABLE IF NOT EXISTS` in the base DDL and a `USER_FAMILIES` entry with no legacy
  path. `SCHEMA_VERSION` stays at 2. The user DB is machine-wide, and a bump would make
  every older copy on the machine refuse to open it.
- **A first bus read with no project id no longer sets up a flood.** Such a read runs the
  1:1 leg only, and its cursor used to land at that leg's max id, usually 0. Once the
  project resolved, the next read replayed the whole 4-day backlog behind the 30-minute
  gate. The cursor now lands at the larger of the 1:1 leg's in-window max and the last id
  older than the window. In-window project rows below an already delivered 1:1 id stay
  skipped, as before.
- **The doctor sees the audit store.** `hook_audit` and `hook_state` moved from
  `USER_FAMILIES` to a public `AUDIT_FAMILIES` with `open_audit()`. Their legacy files
  follow `AI_BADGER_DEBUG_DIR`, as `debug_log.py` already assumed, and `debug_log.py` now
  opens its sink through `open_audit()`. `doctor --status` and `doctor --repair` report
  under `db=user` and `db=audit` (the tracking store stays behind `--project`). Before
  this, a contained `hook_audit` was looked up in `ai-badger.db` and could never be seen
  or repaired.
- **Containment errors name a repair that works.** A task family (tracking store) now
  says to restore the `*.migrated` name or den-refresh the stale surface. It no longer
  suggests `doctor --repair`, which never reaches task families. User and audit families
  still name it.
- **One torn legacy file no longer blocks a whole family.** A `memory-first`,
  `blast-radius-guard` or `dispatch-lanes` file that does not parse is skipped and
  renamed `*.migrated` with the rest, and its valid siblings import. Before, a single
  bad file failed every write to the family.
- **The prune throttle has no check-then-act window.** `prune_expired` re-reads its
  `pruned_at` stamp inside the `BEGIN IMMEDIATE`, so concurrent opens run the DELETE and
  the full-table sweep once. The cheap read before the lock stays, so a throttled call
  still takes no write lock.

## Changes

- `vendored_copies_report()` finds copies by globbing `features/**/badger_store.py` and
  `skills/**/badger_store.py` in the working tree. The hand-kept `VENDORED_PATHS` list,
  which named 18 of 36 copies, is gone. The report works in a non-git root and in the
  plugin cache.
- `Store.delete_cursor` is removed. SessionEnd stopped calling it in 0.173.1, and a
  cursor now dies only by the 4-day prune.
- Docstrings: `_default_badger_root` records where a plugin-cache or Hermes copy lands,
  and two docstrings lost their issue numbers.
