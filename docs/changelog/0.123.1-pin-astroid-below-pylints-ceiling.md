# 0.123.1 — Pin astroid Below pylint's Ceiling

**Type:** PATCH
**Date:** 2026-08-15

## What Changed

`astroid<4.1` added to `engine/requirements-dev.txt`, restating pylint's own constraint so a direct
`pip install -U astroid` cannot cross it.

## The Bug

`pylint` 4.0.7 requires `astroid<=4.1.dev0,>=4.0.2`. pip will install astroid *above* that ceiling
when asked directly, and pylint then dies on **every file**, including files nobody touched:

```
TypeError: NodeNG.infer() got an unexpected keyword argument 'asname'
F0002: Fatal error while checking '<any file>' (astroid-error)
```

This was one of three independent causes of a two-day window in which no push with hooks completed.
Every push ran the full `pylint` lane and then failed on a crash unrelated to any code change. CI
was unaffected because it installs fresh, so the failure looked like a local mystery.

**`pip list --outdated` actively recommends the breakage.** It reports astroid 4.0.4 → 4.3.0 as
available, because it reads a package index rather than the installed consumer's constraints.
Following that advice reinstalls the crash.

## Measured, With a Control

A constraint never seen to bind is not a constraint, so both directions were run in fresh venvs:

| | astroid | pylint on a real file |
|---|---|---|
| `pip install pylint` then `pip install -U astroid` | **4.3.0** | **crashes** |
| `pip install -r engine/requirements.txt -r engine/requirements-dev.txt` | 4.0.4 | works |
| the same upgrade attempted with this file as a constraint | stays 4.0.4 | works |

## Why Restate a Constraint pip Already Knows

pylint's ceiling only binds when pip is resolving pylint. `pip install -U astroid` resolves astroid
alone and will happily break its consumer. Declaring the bound here makes the requirements file
usable as a `-c` constraint file and makes the reason discoverable at the place someone edits.
