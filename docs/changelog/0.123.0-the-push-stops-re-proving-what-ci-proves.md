# 0.123.0 — The Push Stops Re-Proving What CI Proves

**Type:** MINOR
**Date:** 2026-08-15

## What Changed

`.lefthook/pre-push/verify.sh` no longer runs `pytest` or `pylint` on a push, and no longer
routes lanes by changed path. Every push that publishes content now runs the same 13 cheap
lanes; a branch deletion still runs none.

Both lanes stay in `$LANES`. `verify.sh pytest`, `verify.sh pylint` and `verify.sh all` are
unchanged — only the pre-push selection narrowed.

## Why the two slowest lanes leave the local set

`logs/lefthook.log` holds 225 pre-push rows. `pytest` was selected in **209 of them (92%)**.
The 16 runs without it are **p50 4s, max 39s**; the 209 with it are **p50 89s, p90 278s,
max 841s**. Those rows are survivors — a run that hung wrote no row at all until the deadline
landed in 0.122.0 — so the real tail is worse than the measured one.

`.github/workflows/pylint.yml` already runs `verify.sh pytest` and `verify.sh pylint` on every
push to every branch, on the 3.10 this project floors at. Local Python here is 3.14.7, so the
local run was both the slowest thing in the gate and a **weaker** check than the CI job it
duplicated. CI is the gate; the hook is advisory. No branch-protection change.

## `_lanes_for` is gone, and so is the routing table

Once `pytest` and `pylint` left the local set, the routing table's entire remaining effect was
gating the `js` lane. Measured on this machine, `bash .lefthook/pre-push/verify.sh <lane>` run
once per lane:

```
version-sync 0s   index 0s    plugin-skills 1s   deps 0s      docs 0s
release 1s        paths 0s    workflows 0s       validate 0s  scaffold 2s
journey 4s        tdd 0s      js 1s
```

So `_lanes_for` (33 lines), `_is_release_artifact` (7 lines), the `lanes-for` subcommand and the
git-diff half of `_changed_paths` existed to save **one second**, against a whole class of "the
gate quietly stopped verifying" bugs. Deleted.

Two consequences worth naming:

- `_lanes_for` routed any change under `.github/workflows/*` or `.lefthook/*` to the **full**
  suite — so the gate was most expensive exactly when someone was working on the gate. That rule
  is gone with the table.
- `_changed_paths` shrank to `_deletion_only`: the push no longer runs a `git diff` against a
  merge base just to decide which lanes to skip.

`$LANES` is untouched, which matters — the `gates` job in `pylint.yml` reads that line with
`sed` to build the list it walks, and `tests/test_every_check_can_fail.py` reads it to prove
every gate is dispatched. The local set is **derived** from it (`$LANES` minus
`$CI_ONLY_LANES`), so a lane added to `$LANES` joins the push without a second edit.

## `--risk` stops announcing a trade it is not making

`RISK_DROPPED_LANES` is `pytest`, and no push runs `pytest` — so the flag now drops nothing,
while the hook still printed *"limited gates: `<task>` is a --risk task, so pytest did not
run."* Machinery announcing a safety trade it is not making is worse than absent.

The notice now names what the run **actually** gave up — `_without_lanes "$LOCAL_LANES"
"$lanes"` — and stays silent when that set is empty. It is derived, so if a lane in the local
set is ever added to `RISK_DROPPED_LANES` the notice returns by itself.

`--risk` itself is untouched here; its blast radius covers `risk_mode.py`, `skills/task/` and
the task tracker. Deleting it is a follow-up.

## Timing comments that were wrong twice running

Three comments claimed measurements not reproducible from `logs/lefthook.log`:

| Where | Claimed |
|---|---|
| `verify.sh` `RISK_DROPPED_LANES` | `verify.sh all` = 778s, pytest = 664s, "measured 2026-08-07 at 43fbfb49" |
| `verify.sh` `_is_release_artifact` | the same 778s/664s pair |
| `verify.sh` `lane_pylint` | "232s serial against 62s parallel", same date |

There is no `all` row on that date in the log, and the most recent full run in it is 171s. The
previous version of the first comment claimed "pytest is 49s of a 75s gate" — wrong the time
before. All three are deleted along with the machinery they justified, rather than restated.
Any number left in that file names the command that produced it.

## Tests

Rewritten, because a rewritten test is where a regression hides:

- `test_gate_own_files_route_to_every_lane` → **deleted**; every push runs the whole local set
  now, so there is no routing for a gate change to escape.
- `test_docs_only_change_skips_the_expensive_lanes` → replaced by
  `test_a_push_leaves_pytest_and_pylint_to_ci`.
- `test_the_history_mined_docs_commit_agrees_with_the_synthetic_one` → **deleted** (nothing left
  to agree about).
- `test_a_release_only_push_skips_the_full_suite`,
  `test_one_source_file_alongside_a_release_restores_the_full_suite`,
  `test_a_hand_written_json_still_runs_the_full_suite`,
  `test_a_scaffold_stamp_alone_does_not_exempt_a_source_change` → **deleted** with
  `_is_release_artifact`.
- `test_a_risk_task_drops_the_slow_lanes` → `test_a_risk_task_drops_the_lane_it_names`.
- `test_without_a_risk_task_the_slow_lanes_still_run` → folded into the above (it asserted the
  offered-then-selected pair that test now makes in one place).
- `test_a_risk_task_keeps_the_cheap_lanes` → `test_a_risk_task_keeps_every_other_lane`, which
  compares the whole list rather than five named lanes.
- `test_a_risk_run_says_so_and_names_the_task` →
  `test_a_risk_run_that_drops_nothing_announces_nothing` plus
  `test_a_risk_run_that_drops_a_local_lane_says_so_and_names_it`.

New: `test_a_push_runs_every_other_lane` (the local set equals the advertised lanes minus the
CI-owned two, derived from the gate's own usage line), `test_a_ci_owned_lane_is_still_invocable
_by_hand`, `test_all_still_runs_the_ci_owned_lanes`.

`RISK_DROPPED_LANES` became `${VERIFY_RISK_DROPPED:-pytest}` so the notice can be proven to
fire, not only proven silent — the file's existing idiom (`VERIFY_SKIP`, `VERIFY_BASE`,
`VERIFY_DEADLINE`, `VERIFY_LOG_DIR`).

Each guard that was green from the start was put in front of its defect and watched fail:
removing both lanes from `$LANES` fails `test_a_ci_owned_lane_is_still_invocable_by_hand`
(exit 2, `unknown subcommand`) and `test_all_still_runs_the_ci_owned_lanes`; removing the
`_deletion_only` short-circuit fails `test_branch_deletion_runs_nothing`.
