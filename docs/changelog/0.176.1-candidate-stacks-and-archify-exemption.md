# 0.176.1 — candidate stacks are tracked-and-present; archify exemptions need a vendor marker

**Patch** — two `tooling/validate.py` correctness fixes. 2026-09-24.

## What was wrong

- **A deleted-but-uncommitted stack was reported as a catalog gap.** `candidate_stack_dirs`
  read only `git ls-tree HEAD`, so a stack a session had removed from disk but not yet
  committed still counted as a directory the catalog claims to ship — `catalog_stack_gaps`
  then reported it as delivering nothing, for a directory nobody could open.
- **The archify vendored-packet exemptions matched by shape, not by provenance.**
  `FEATURE_JSON_WITHOUT_SCHEMA`'s `skills/*/{schemas,examples,brand-marks}/*.json`,
  `package.json`, `skill-release.json` and `vendor.json` entries exist because Archify's
  vendored packet (ADR-0030) is byte-identical upstream content with its own validators.
  The globs matched any skill's directory of that shape, so a non-archify skill's own
  `schemas/foo.json` was silently exempted from schema coverage too.

## What changed

- `candidate_stack_dirs` now returns directory names that are both tracked in `HEAD` and
  present on disk — the intersection, not the tracked set alone. A stack deleted from disk
  without a commit drops out; an untracked `features/scratch/` still never enters the tracked
  set, so that existing guarantee is unchanged.
- The six archify-vendored `FEATURE_JSON_WITHOUT_SCHEMA` globs now only exempt a match when
  `badger_lib.is_vendored_packet` confirms a sibling `vendor.json` actually marks the packet.
  `is_vendored_packet` moved out of `tests/test_schema_self_description.py`'s local
  `_vendored_packet` and into `engine/badger_lib.py`, so `tooling/validate.py` and the test
  both use the one predicate.

## Verification

- `tests/test_catalog_claims_checkable.py::test_a_tracked_stack_deleted_on_disk_but_not_committed_is_not_reported`
  and `::test_a_non_archify_skills_schema_json_is_flagged` were red against unmodified
  `validate.py` and are green after.
- The existing pin `test_an_untracked_directory_under_features_cannot_fail_validation` was
  proven capable of failing: a working-tree-only mutant (`names &= on_disk` →
  `names |= on_disk`) turned it red, then was reverted.
