# 0.121.2 — pytest-xdist Is Now a Declared Dependency

**Type:** PATCH
**Date:** 2026-08-15

## What Changed

`pytest-xdist` added to `engine/requirements-dev.txt`, pinned `>=3.8.0` to match the version
already in use.

## The Bug

`pytest -n auto` runs today, but `pytest-xdist` was declared in none of `engine/requirements.txt`,
`engine/requirements-dev.txt`, `requirements-mutation.txt`, or `pyproject.toml`. It worked purely
by accident of one developer's venv already having it installed. A fresh clone following
`engine/requirements-dev.txt`'s own install instructions would get a working `pytest`, but
`-n auto` would fail with "unrecognized arguments" the moment anyone tried it.

`gates/deps_guard.py` could not have caught this: it only flags an undeclared *import*, and
`pytest-xdist` is never imported by name — pytest discovers it as a plugin through package
entry points. A dependency that is invoked rather than imported is invisible to an import-scanning
gate by construction. See CONTRIBUTING and `docs/changelog/README.md` conventions for why this
is a per-file entry rather than a hand-maintained root changelog.

## Proven

```
python3 -m venv /tmp/xdist-check
/tmp/xdist-check/bin/pip install -r engine/requirements-dev.txt
/tmp/xdist-check/bin/python -m pytest -n auto --collect-only -q
```

Before this change, `engine/requirements-dev.txt` declared only `pylint` — `pytest` itself was
never a declared dependency anywhere in the repo (`engine/requirements.txt`,
`engine/requirements-dev.txt`, `requirements-mutation.txt`, `pyproject.toml` all omit it; CI's
`pylint.yml` installs it by hand instead of reading a requirements file). A fresh venv following
`engine/requirements-dev.txt`'s own install instructions had no `pytest` at all:
`/tmp/xdist-check-before/bin/python -m pytest ...` failed with `No module named pytest`, before
xdist ever entered the picture.

After adding `pytest-xdist>=3.8.0`, the same fresh-venv install pulls in `pytest>=7.0.0`
transitively (pytest-xdist declares it as a dependency) and `-n auto` now works. This closes the
`pytest-xdist` gap the task set out to fix; it also happens to close the pre-existing, larger
`pytest`-itself gap as a side effect of the transitive dependency, though `pytest` staying
undeclared in its own right is worth flagging even so — see below.

## Known related gaps (not fixed here)

- `pytest` itself has never been declared in any requirements file. It now arrives
  transitively through `pytest-xdist>=7.0.0`'s own dependency, but that is incidental, not a
  declaration — a future change to pytest-xdist's own requirement floor could quietly change
  what pytest version a fresh install gets.
- `.github/workflows/pylint.yml` installs test dependencies by hand
  (`pip install pylint pytest jsonschema pyyaml`) rather than reading
  `engine/requirements-dev.txt` or `engine/requirements.txt`. Declaring `pytest-xdist` here makes a
  local `pip install -r engine/requirements-dev.txt` honest; it does not by itself make `-n auto`
  available in CI, because CI's install step does not consume this file at all.

Both are separate, out-of-scope findings from this change.
