# 0.179.0 — task-decomposition plans on a graph, with the task-graph MCP server

**Minor** · 2026-09-28 · (draft — finalised at release finish)

The planning half of the task pipeline moves from prose packages to a typed, machine-managed
workflow: a `task-plan` whose `workflow` is a directed graph of `step`s, decomposed by the new
`task-decomposition` skill and managed end to end by a local stdio MCP server.

## New features

- `task-decomposition` skill: takes the analyze/research record (and optionally a `create-task-spec`
  `spec.json`) and returns a validated `task-plan` — task context, id, description reference, and a
  `workflow` DAG whose nodes are `step`s (goal, instructions, `effort` → model tier, acceptance
  criteria, file/resource ownership).
- `task-graph` local stdio MCP server (plus an equivalent CLI): plan and step state management —
  build/validate, retrieve, mark complete with evidence, acceptance-criterion checks, transition
  semantics with a derived ready set and parallel waves, and a progress checklist. State persists
  in `.ai-badger/task-tracking/tracking.db` (new `plans` table) behind a revision CAS.
- Checked-in `schemas/task-plan.schema.json` (Draft 2020-12, generated from the pydantic model) with
  a `--check` gate that fails when model and schema drift.
- An opt-in Jev (`typesafe/jev-1.13`) advisory: model-tier upgrade proposals and wave-serialization
  hints at plan time (`AI_BADGER_JEV=1`), never overriding deterministic derivation.

## Changes

- Packages/subpackages are retired as planning units across the `task`, `quick-task` and
  `status-report` skills — `step` is the only unit, and a multi-sink workflow carries a join step
  for cross-step integration checks.
- `status-report` progress comes from the graph (`progress_checklist`) first, with the plan-file
  parser kept as the fallback; `quick-task` explicitly stays decomposition-free and escalates to
  `task` when a change needs one.
- Plan documents are rendered to `.ai-badger/task-tracking/plans/<date>-<taskId>.md` (`**S<N>**`
  headings) for humans; the graph is the single source of truth.

## Upgrade notes

- The tracking store's schema version moves 2 → 3 (new `plans` table). **A v3 `tracking.db` is
  unreadable by pre-0.179 copies** of the task machinery — run `den-refresh` before the next task
  command after upgrading.
- The plan server and CLI are PEP 723 scripts launched via `uv run --script …`; `uv` is the one new
  consumer prerequisite (pydantic is fetched into uv's cache on first launch — no pip install).
