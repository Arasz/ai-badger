# 0.113.1 — "e.g." is not the end of the sentence

0.113.0 compressed each invariant to the sentence that states the rule. On a 12-stack consumer it
shipped this bullet:

```
- **Partition by the tenant/owner key** — Every entity carries the tenant/owner key (e.g.
  → `.ai-badger/invariants/partition-by-userid.md`
```

The rule — the key is *also* the partition key, and every query filters by it — was gone. What
survived is a sentence fragment that binds nobody to anything.

`_rule_sentence` looked for `(?<=[.!?])\s+(?=[A-Z`"*])` and stopped at the first match. The
invariant's opening is `… the tenant/owner key (e.g. `userId` in a …`: a full stop, a space, a
backtick. A perfect match, in the middle of a parenthetical.

The boundary pattern is unchanged; matches now get rejected when the text before them ends in a
known abbreviation (`e.g.`, `i.e.`, `etc.`, `cf.`, `vs.`, `approx.`), and scanning continues to
the next candidate. With no genuine boundary left, the whole opening block is the summary — the
same fallback as before.

Only one shipped invariant was truncated, because only one uses `e.g.` before a code span. The
defect is in the extractor, not that invariant, so the guard sits there.

`test_an_abbreviation_is_not_the_end_of_the_sentence` pins it: red on 0.113.0's extractor with the
exact wording that shipped, green after.
