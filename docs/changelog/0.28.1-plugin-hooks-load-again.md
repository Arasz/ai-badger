# 0.28.1 — plugin hooks load again

## The bug

Installing the plugin produced this, and **every** ai-badger hook failed to load:

```
Failed to load hooks from .../ai-badger/0.27.0/hooks/hooks.json:
Duplicate hooks file detected: ./hooks/hooks.json resolves to already-loaded file
.../hooks/hooks.json. The standard hooks/hooks.json is loaded automatically, so
manifest.hooks should only reference additional hook files.
```

`.claude-plugin/plugin.json` declared:

```json
"hooks": "./hooks/hooks.json"
```

Claude Code already loads `hooks/hooks.json` from a plugin on its own. Naming it again in the
manifest registers it twice, and the duplicate aborts the plugin's entire hook load — not just
the duplicated entry. The `SessionStart` drift notice never ran for anyone using the plugin.

## The fix

The `hooks` key is gone from `plugin.json`. The file stays exactly where it was; it is loaded
automatically, and `${CLAUDE_PLUGIN_ROOT}` is still substituted inside it.

**Why not rename the file instead?** Moving it to a non-standard path and keeping the manifest
entry would also stop the collision, but it opts out of the convention for no benefit: the file
would then load *only* because the manifest points at it, which is one more coupling to keep in
sync, and it contradicts the file's own description. `manifest.hooks` exists for *additional*
hook files beyond the standard one.

## Why it wasn't caught

Nothing asserted anything about the plugin manifest. `tests/test_plugin_manifest.py` now checks
that the manifest does not re-declare the auto-loaded path, that the hooks file still exists
(so removing the declaration is never confused with removing the hooks), and that it parses and
declares at least one hook.

## Upgrading

Update the plugin. No project-side change and no re-scaffold needed — this is entirely in the
plugin manifest.
