# 0.51.0 — MCP rebuild step 3 of 8: one declaration set, three readers

Step 3 of the MCP rebuild [ADR-0014](../adr/0014-mcp-support-is-configuration-not-retrieval.md)
describes, and the last additive one. `features/<stack>/stack-mcp.json`'s `declare: true` now
reaches `.mcp.json` and the Copilot MCP config, alongside the two legacy readers rather than
instead of them.

**`.mcp.json` output is unchanged.** The one server ai-badger declares moved from
`external-tools.json` to `stack-mcp.json` and lands byte for byte where it did before, proven by
a test that renders the file twice — once with the catalog reader silenced, which *is* the old
code path — and asserts the two are equal.

## `McpTools.declared_servers()`

The three readers compose in one place, in ascending precedence:

1. legacy `features/<stack>/mcp-servers.json`
2. legacy `features/<stack>/external-tools.json`, entries with `generate_mcp_json`
3. **`features/<stack>/stack-mcp.json`, entries with `declare: true`** — legacy loses on conflict

`collect_stack_mcp_servers` and `merge_mcp_servers` are unchanged; `declared_servers` composes
above them, so the ~60 tests riding on those two still describe them accurately.

## The project still has the last word — including by its silence

A `config.externalTools` entry naming a server outranks all three readers. It does so **whether or
not it asks for `generate_mcp_json`**: omitting the flag is how a project declines a declaration
and manages `.mcp.json` by hand, which is behaviour `tests/test_external_mcp_tools.py` has pinned
since 0.11.0. A catalog declaration is therefore *skipped* for any server the project names, not
reasserted over it. Reasserting would have been a consumer-visible break in a step whose whole
premise is that it is additive — and the existing test caught the first attempt.

This is the same precedence rule the instruction slots use, deliberately: one rule for both
halves of a server's configuration.

## Behaviour worth knowing

- **`declare` defaults to false.** A `stack-mcp.json` entry that only names a server is a
  *describe* claim — it is relevant to the stack — and writes no launch config. Only two of MCP's
  seven arrival routes accept one, and `rider` or `playwright` arriving user-global or by plugin
  cannot be declared at all.
- The scaffold note now reads `generated .mcp.json with N MCP server(s)` rather than
  `N external tool(s)`: they no longer all come from external tools.
- `external-tools.json`, `mcp-servers.json` and `config.externalTools` are all still read.
  Step 4 removes the first two and the config key.
