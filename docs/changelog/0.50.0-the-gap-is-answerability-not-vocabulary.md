# 0.50.0 — the gap is answerability, not vocabulary

[`docs/retrieval.md`](../retrieval.md) closed §5 by saying the paraphrase failure "points at
vocabulary: synonyms, query expansion, or a second non-lexical signal." All three were measured.
The conclusion was wrong, and the document now says what the measurements show.

Documentation only. No behavior changed.

## What the measurements showed

**Semantic embeddings do close the vocabulary gap.** Ranked without the coverage gate, a 7.6 MB
static embedding table takes recall@3 from 0.481 to **0.731** and the paraphrase class from 0.000
to **0.47**; a BM25-plus-cosine hybrid reaches 0.750. Capacity is not the constraint — the static
table matches a 33 M-parameter contextual encoder, because a document here is a median of nine
tokens.

**The gate takes it all back.** Across ~1,000 operating points per model, the best setting that
does not raise false fire returns the paraphrase class to **0.000–0.059**. Buying paraphrase@3 of
0.47 costs firing on 93% of the easy set's negatives.

**Why, and it is not about words:** every one of the 17 paraphrase positives scores at or below
the best adjacent negative, for a static encoder and a contextual one alike. The area under the
curve for separating "paraphrase we should answer" from "adjacent query we must not" is **0.196**
and **0.520** — chance, or inverted. "Which routines have grown way past a reasonable length" is
answerable here; "profile this code to find performance bottlenecks" is not; they are equally
*similar* to a corpus of developer tools. A similarity function cannot encode which of them the
index can serve, because that is a fact about the index's contents.

**And the shortcut is a trap.** A probe fitted on our own 43 easy positives reaches recall@1 of
**1.000** in-sample and **0.070–0.256** under leave-one-out — worse than the untrained baseline
on the hard set. With ~100 documents and ~900 content tokens, a "perfect matcher" trained on our
own descriptions memorises the vocabulary of whoever wrote them.

## Why this matters beyond the document

It redirects the work. A better similarity signal improves ranking *among things worth
returning*, and does nothing for the decision of whether to return anything at all — which is the
job the coverage gate is doing, on a scalar that provably cannot separate the two classes here.
