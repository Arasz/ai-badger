# 0.178.0 — per-prompt memory context, wired through the ai-raccoon proxy

A hook that fires on every gated user prompt, searches this project's ai-raccoon memory, and
injects a "Memory context" block before the model answers. It is a port of pi's
`mem-based-rag` and `query-pipeline` extensions, and the block is the one pi produces. It runs
on Claude Code, Copilot CLI and Hermes (CLI sessions only), and never on pi. The design and its
reasons are in [ADR-0031](../adr/0031-per-prompt-memory-context-through-the-ai-raccoon-proxy.md).

## The memory-context hook

**Where it runs.** `hooks-manifest.json` gains a `memory-context` entry with three arms and no
pi arm:

- Claude Code: `UserPromptSubmit` runs
  `ai-raccoon-memory/scripts/memory_context_hook.py` with `"timeout": 100`, and the hook prints
  the `hookSpecificOutput` envelope.
- Copilot CLI: `userPromptSubmitted` runs the same entry with `timeoutSec` 100, and the hook
  prints flat `{"additionalContext": ...}`. That is the only shape Copilot CLI 1.0.88 consumed
  when measured (3 of 3 runs; the envelope 0 of 3). Copilot loads repo hooks only for a folder
  listed in `trustedFolders` in `~/.copilot/config.json`. In an untrusted folder the hook never
  runs, and that looks exactly like an empty result.
- Hermes: `pre_llm_call` appends the block last, followed by `(end of memory context)`, in CLI
  sessions only. The gate is Hermes's own normalisation, `(platform or "cli") == "cli"`: Hermes
  passes an empty platform for the CLI, and every named gateway platform stays inert. The
  arm also needs `.ai-badger/skills/ai-raccoon-memory/` in the project, and it memoizes the
  result per session and prompt, so a tool loop searches once. The Hermes plugin now ships
  `memory_context.py`, `openrouter_client.py`, `query_pipeline.py` and `model_groups.py` beside
  `ai_badger_hooks.py`.

**Transport.** Each run spawns the bare `ai-raccoon` executable once (`PATH` first, then
`~/.dotnet/tools/ai-raccoon`) and sends every search over that one proxy session. The hook
never reads or sends the ai-raccoon token; the proxy does the identity proof. When no serve is
running, the proxy may start one, which then lives on under its own idle watchdog. At the
deadline or on any error the proxy is killed by pid (never its process group) and reaped.

**On by default** when `.ai-badger/project-id` resolves and the executable is found. Only the
literal `AI_BADGER_MEMORY_CONTEXT=0` turns it off. An exported `AI_BADGER_PROJECT_ID` routes
every repo to that one project.

**Two modes, one block.** With `OPENROUTER_API_KEY` set and `AI_BADGER_MEMORY_CONTEXT_PIPELINE`
not `"0"`, an OpenRouter planner writes 2 to 6 queries, each is searched once, the Jev
decisions endpoint scores the pool, and pi's document-aware merge keeps five hits. If the
planner fails, the run falls back to one search on the prompt; a Jev failure ranks by the
server's own rank instead, as pi does. The planner model is
`AI_BADGER_MEMORY_CONTEXT_PLANNER_MODEL` when set, else the `medium` tier through the `task`
skill's `model_groups.py`; a project without the `task` skill gets single search unless the
override is set. Every other case is one search on the prompt.

**What leaves the machine.** Only in pipeline mode, and only to OpenRouter: the gated prompt
(the planner's input, and its first 32 000 characters in each Jev request), and for up to 48
pooled hits their file path, kind and a 500-character excerpt of memory and source code. The
key is read from the environment only and never logged. `AI_BADGER_MEMORY_CONTEXT_PIPELINE=0`
keeps everything but the ai-raccoon search local.

**Time caps.** The pipeline is capped at 90 s on Claude and Copilot and at 25 s under Hermes,
which abandons a `pre_llm_call` callback after 30 s by default (Hermes
`hermes_cli/plugins_dispatch.py:153`); Hermes's arm passes `cap=25` to `build()`. Single
search is capped at 5 s everywhere. Every stage draws its share from one run budget, and every
failure is silent with exit 0.

**Search log.** Each enriched prompt, and each planned query, is a real `memory_search` and
writes a row to ai-raccoon's search log.

**Parity with pi, scoped.** The block is byte-identical to pi's for every hit whose path and
string rank hold no line-break or tab characters, whose snippets hold no U+0085, whose rank is
a number, string, boolean or null, and whose text is not cut inside a non-BMP character.
Outside that, this port collapses line breaks in paths and ranks to one space (pi keeps them
raw), prints `?` for a list or object rank, and counts truncation in code
points. ADR-0031 lists the rest.

**POSIX only.** On Windows the hook stays silent and spawns nothing.

## `tooling/validate.py` gains a hooks-manifest resolution check

Every manifest entry's `hooks-json`, `plugin-hooks-json` and `plugin` arm must now resolve to
a real command, callback or event — not merely name an agent (`hooks_manifest_agent_gaps`
already checked that). A `hooks-json`/`plugin-hooks-json` arm resolves when exactly one
command in the relevant `hooks.json` both ends with its `script` and has that script as its
basename (a decoy suffix match, or an ambiguous pair of files sharing one, no longer passes
silently); a `plugin` arm resolves when its `method` is a registered event or callback name
in the Hermes entry file, found by parsing the file's syntax tree rather than scanning its
text, so a `ctx.register_hook(...)` call sitting in a comment or a string never counts. There
is no discovery-fallback exemption: a script findable only by scanning a skill's own
`scripts/` directory is now reported as a gap.

## `prompt-markers` wired explicitly, no longer discovered

`features/common/hooks/hooks.json` now carries an explicit `UserPromptSubmit` command for
`prompt-markers/scripts/user_prompt_hook.py`, alongside `context_enrichment_hook.py` and
`message_delivery_hook.py`. It previously reached both Claude and Copilot only through each
generator's own discovery fallback, which the new resolution check no longer accepts. Copilot's
`timeoutSec` for this hook moves from the discovery path's `5` to the explicit path's default
`10`.

## The Copilot adjuster carries a hook's own `timeout`

`features/copilot/adjustments/adjust_hooks.py` used to hard-code every generated hook's
`timeoutSec` to `10`, discarding whatever `timeout` its source command in `hooks.json` actually
declared. It now carries that value through (`h.get("timeout", 10)`), so a hook that needs
longer than 10 seconds on Claude gets the same headroom on Copilot. Every existing source
command already carries either no `timeout` or exactly `10`, so this release changes no
generated value for the current catalog. The Copilot-to-source event map moves out of the
adjuster and into `engine/badger_lib.py` as `COPILOT_TO_SOURCE_EVENT`, shared with the new
resolution check.

## Tests renamed or rewritten

One test was rewritten: `tests/test_adjust_hooks_copilot.py::test_a1_real_catalog_copilot_timeouts_are_unchanged`
used to assert that every generated Copilot `timeoutSec` is 10. It now asserts 10 for every command
except `memory_context_hook.py`, which carries its source `timeout: 100` on purpose. The old form
would have gone red on the very carry this release adds.

Five existing test files were extended:

- `tests/test_every_check_can_fail.py`, `tests/test_validate.py` and `tests/test_skills_lint.py`:
  the `_hooks_manifest` / `_write_hooks_manifest` fixture helpers gained a resolving
  `hooks.json` and (where a hermes arm is present) a stub plugin entry, so the new check does
  not turn their "clean tree" controls red for a reason unrelated to what each of them tests.
- `tests/test_adjust_hooks_copilot.py`: two new tests for the carried `timeout`.
- `tests/test_hermes_plugin_install.py`: `SHARED_SKILL_FILES` gained the four new module rows,
  and `test_every_lazily_loaded_sibling_is_copied_beside_the_plugin` now also requires
  `memory_context.SIBLINGS` and `memory_context.RESOLVER` in the shipped set.

New test files: `tests/test_hooks_manifest_resolution.py`, `tests/test_memory_context_core.py`,
`tests/test_memory_context_transport.py`, `tests/test_memory_context_openrouter.py`,
`tests/test_memory_context_planner.py`, `tests/test_memory_context_jev.py`,
`tests/test_memory_context_pipeline.py`, `tests/test_memory_context_pipeline_wiring.py`,
