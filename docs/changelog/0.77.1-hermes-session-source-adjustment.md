# 0.77.1 — Task tracking treats every agent equally

The `/task` skill's tracker hardcoded claude as its built-in session source — a transcript
default every other agent inherited. For an open-source framework that is the wrong shape:
no agent is special, so no agent is built in. Every session source is now registered the
same way, by its own adjustment.

- `features/common/skills/task/scripts/tracker_lib.py` is fully generic. The session-source
  registry gains a per-source `resolve()` (each agent owns how it identifies its session)
  and a `transcript` capability (the source that reads JSONL transcripts, which an explicit
  `--session-id` is attributed to). `session_source(name)` returns None for unregistered
  names — callers refuse clearly instead of silently falling back to claude. There is no
  `DEFAULT_SOURCE` anymore.
- New `features/claude/adjustments/claude_session_source.py` + `adjust_task.py`: the claude
  source (CLAUDE_CODE_SESSION_ID env var, pid/cwd fallbacks against current-session.json,
  transcript checkpoint, `claude --resume`) is installed into the scaffolded task skill's
  scripts by the claude adjustment — the same mechanism the hermes adjustment uses.
- `features/hermes/adjustments/hermes_session_source.py` (renamed from session_sources.py):
  registers the hermes source (HERMES_SESSION_ID env var, state.db checkpoint,
  `hermes --resume`, delegation reader) with its own `resolve()`.
- Common tracker_lib.py discovers every `*_session_source.py` sibling — any number of
  agents can coexist, and a project with no agent registered has no session source at all
  (clear error, not a claude assumption).
- The plugin copy of the task skill (Claude Code's distribution) ships the claude session
  source beside the generic scripts, so plugin users keep working without scaffolding.
- `task_tracker.py start`/`finish`/`reattach`/`subagent` guard every source lookup: an
  unregistered source or an unattributable explicit `--session-id` is a clear refusal
  (exit 2), never a silent claude default.
