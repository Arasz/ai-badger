# 0.77.1 — Hermes task tracking ships via the hermes adjustment

0.77.0 put the hermes state.db data path (env constants, sqlite parsing, `--delegation`
reader) directly into the common task skill scripts — every scaffold, claude-only included,
carried hermes code. This project's rule is common = generic, agent-specific via
`features/<agent>/adjustments/`, so the hermes code moves out of the common scripts.

- `features/common/skills/task/scripts/tracker_lib.py` / `task_tracker.py` are generic
  again. The tracker gains a small session-source registry (`register_session_source` /
  `session_source`, claude transcript source built in) and a guarded optional import of a
  sibling `session_sources.py`; start/finish/reattach/subagent dispatch checkpoint, resume
  and delegation reading through it. No hermes identifier remains in the common scripts.
- New `features/hermes/adjustments/session_sources.py` holds the hermes source: state.db
  path, read-only sqlite parsing, delegation usage, and `register(lib)`. The hermes
  adjustment (`adjust_task.py`) copies it into the scaffolded
  `.ai-badger/skills/task/scripts/session_sources.py` when hermes is an agent; a claude-only
  scaffold never sees it.
- `subagent --delegation <id>` stays a generic flag; the session source that recorded the
  task decides how (or whether) delegation tokens are read — the claude source refuses
  cleanly.
- Plugin skills (`skills/task/`) re-synced generic; the hermes `--delegation` note moves
  from the common SKILL.md into the hermes extension.
