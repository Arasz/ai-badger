# 0.164.0 — pi adapter renders bus mail as a card, not raw JSON

**Minor** (additive) · 2026-09-06

## What changed

The python delivery prints each mail as a JSON envelope string
(`{sender: {sessionId, projectId}, content, timestamp}`) and the adapter wake
path forwards it verbatim as the `ai-badger` message content. pi showed
`[ai-badger]` + the raw JSON in every session. New pure `splitMailCard`
(hook-bridge) plus an `ai-badger` message renderer: envelope becomes a
`mail from <short-id> · <timestamp>` head plus the body card; plain strings
pass through; empty renders nothing.

## Wiring

- `features/pi/adjustments/adapter/hook-bridge.ts`, `features/pi/adjustments/adapter/index.ts`
  (vendored from pi-badger-integration, where the canonical suites pin it).
- No behavior change where the renderer API is absent (guarded, warn once).

## Residual

Mail that surfaces outside pi chat rendering (other harnesses' hook output)
is untouched — this covers the pi card only.
