A triage of a redistributed Agent Skills corpus turned up five ideas worth carrying into the
framework's own material. None became a new skill; each landed where a reader already acts on it.

**`code-review-checklist` §3.1 — six hard-fail test triggers.** The phase had items that could not
*fail* anything. Now: no assertion at all; every assertion an always-true literal; a
self-referential assertion; **an un-awaited async assertion**; a swallowed exception; assert-in-catch.
The un-awaited one is the find — `Assert.ThrowsAsync` without `await` passes silently, and nothing
in the framework mentioned it. The A–F rubric that came with the triggers was left behind: a grade
invites arguing about the band instead of the finding. From `dotnet/skills` (MIT).

**`code-review-checklist` §3.3 and the `ts` extension — frontend security.** The security phase was
backend-shaped. Four stack-neutral items joined §3.3, including one genuinely distinct from the
existing no-hardcoded-secrets rule: a build-time environment variable inlined into a bundle is
public even though it appears in no tracked file. Nine browser-runtime items went to the `ts`
extension, which reaches both `ts` and `react` projects. The Preflight Protocol gained the finding
format and one rule worth its line on its own — *a protection you cannot see in the diff is not a
finding; report it as not visible in application code, verify at runtime*. From `openai/skills`
(Apache-2.0).

**`code-review-checklist` §4.3 — observability.** Five diff-checkable questions: a renamed metric,
label or log field is a breaking change for operators; trace context across every async boundary
the change adds; readiness must not depend on optional downstreams; every new metric names its
alert, dashboard or investigation; histogram buckets match the latency objective. Placed in the
checklist rather than as an invariant, so it reaches reviewers of projects that emit telemetry
without landing in the instructions of projects that do not. Origin `Kotlin/kotlin-backend-agent-skills`;
licence not established.

**`test-engineer` persona — two disciplines.** *Tests that pin down behaviour*: property
intersections (bugs live where independent properties meet, not on single axes), behaviour radius
(assert a secondary observable, not only the return value), and fixture realism — never set the
parameter under test to a degenerate value, because a mutant that dies against `capacity=1` died
for the wrong reason. *Mutation findings are run, never reasoned*: apply the mutant, re-run the
covering tests, revert; a finding from static reasoning is labelled unverified. From
`dotnet/skills` (MIT).

**`update-documentation` — reader testing.** A new gate for substantial *new* documents: generate
5–10 questions a reader would realistically ask and give each to a fresh subagent that has only the
document. The existing evidence gate proves every claim resolves to a real file and line; it says
nothing about whether a reader can use the page. Capped at one round, mirroring the skill's
existing per-task verification cap. Origin `anthropics/skills`; licence not established.
