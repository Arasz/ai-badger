# 0.24.0 — The path that publishes now checks what it publishes

**Plan:** `docs/plans/2026-07-27-deferred-work-plan.md` (Wave 10)
**Review:** `docs/reviews/2026-07-26-full-project-review.md` (security I4)

`feed-badger` is the one path that takes content out of a private repo and puts it in a public
PR. It scanned nothing on the way out, and staged everything in the checkout.

## Fixed

- **WP42 — one scanner, two directions.** `scan_for_unsafe_literals` lived inside
  `learned_skills_sync.py`, so only the *inbound* path had it. It is now
  `scripts/unsafe_literals.py`, imported by both, with `scan_tree` (a directory) and
  `scan_paths` (a declared mix of files and directories). `learned_skills_sync` delegates —
  its behaviour and its module-level names are unchanged, so nothing downstream moved.

- **WP43 — the outbound PR is scanned and refuses on a finding.** `open_pr.py` scans every
  declared path before running a single git command. A finding prints the file and the shape
  label and exits 1. The matched text never travels: findings stay `{file, pattern}` with
  `pattern` drawn from a closed vocabulary, the same rule that keeps the inbound path safe to
  log (CodeQL `py/clear-text-logging`).

- **WP43 — `git add -A` is gone.** Contributions are staged with an explicit pathspec built
  from the new **required, repeatable `--path`**. Whatever else is dirty in the checkout —
  local notes, an unrelated experiment, a half-finished edit — is no longer published by
  accident.

## Behaviour changes worth knowing

- **`--path` is required.** `open_pr.py` without it is a usage error, not a full-tree commit.
  `feed-badger/SKILL.md` shows the new invocation: every path you placed, plus `index.json` if
  you regenerated it.
- **A credential-shaped literal blocks the PR.** Replace it with an obviously fake value and
  re-run. The guard checks known literal shapes only — a clean run is not a certificate that
  the contribution carries no secret.
