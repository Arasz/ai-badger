# 0.212.0 — The map pins only the ids the key may route

**Classification:** Minor
**Date:** 2026-10-21

## Changes

- **A map pin is an id the reading key can route.** The refresh that renders the model map
  resolves each leaderboard row against pi's model store, and the `openrouter` section of
  that store is the key's own list: OpenRouter's per-key endpoint already applies the
  workspace's guardrails and provider restrictions. A model that list does not carry has no
  id — the row stays out of the map, and the reason names the list that refused it. The
  public OpenRouter catalogue still records what OpenRouter lists (in the map's source block
  and in every exclusion reason), but it no longer admits a row.
- **A group whose ladder families are all out of reach leads with the best member of a
  declared family**, and that member's family becomes the group's primary anchor, so the
  primary always names a family the group holds. The declared families (anthropic, openai)
  and the ladder itself do not move: a family with no member this key can route keeps its
  ladder slot, which is the family name a host that takes family names resolves on its own.
- **The map re-rendered.** The four tiers now lead with `openrouter/openai/gpt-6-luna`,
  `openrouter/openai/gpt-6.1-sol`, `openrouter/openai/gpt-5.4` and
  `openrouter/openai/gpt-5.5` — the ids this key can route. The anthropic and the newest
  google rows stay out, each with the reason that excluded it.

## Fixes

- A delegation that carried an anthropic id came back `404: 0 endpoints out of 2 requested
  are available matching your guardrail restrictions and data policy — Provider blocked by
  guardrail`, with no fallback to take it from. The map was not wrong about OpenRouter; it
  was wrong about *this key*.

## Upgrade notes

None required. A consumer that re-scaffolds or refreshes the map gets the new ids; a
consumer that keeps the map it already has keeps a map whose ids were routable by the key
that rendered it.

The decision is recorded in
[ADR-0046](https://github.com/Arasz/ai-badger/blob/main/docs/adr/0046-the-map-pins-only-the-ids-the-key-may-route.md).
