# 0.128.0 — Background QoS and a Derived Worker Budget

**Type:** MINOR
**Date:** 2026-08-16

Layers 1 and 2 of the measured design in
[ADR-0020](../adr/0020-background-qos-and-worker-budget.md). Layer 3 (an admission queue) was
designed in the same review and deliberately not built — see the ADR for the memory-pressure
argument it barely addresses.

## Added

- **`worktree-agent-isolation/scripts/run_suite.py`** — wraps a test/build command with two
  independently-disableable layers:
  - **Background QoS** (macOS only): prefixes the command with `taskpolicy -b`, so the
    foreground stays responsive under N concurrent agent processes. Measured 1.0x of idle with
    `-b` vs 4.8x without, under 20 concurrent saturating processes. Disabled by `--no-qos`,
    `AI_BADGER_QOS=off`, or running off macOS.
  - **Parallelism budget**: `budget = max(1, (cores - reserve) // min(agents, slots or
    agents))`, exported as `AI_BADGER_TEST_WORKERS` unless the caller already set it — the seam
    a project's own Vitest/Playwright config reads, since neither tool has a native worker env
    var.
  - Any failure in the script's own machinery (core-count detection, budget math, the
    best-effort diagnostic log) warns on stderr and runs the wrapped command anyway — never a
    false "your tests never ran."
- **`worktree-agent-isolation/references/machine-load.md`** — the three-layer table, the
  measured numbers, the per-tool worker-cap reference, config snippets for Vitest/Playwright/
  xUnit, the timeout risk and its mitigations, a live-PID QoS recovery recipe, and `uptime`/
  `ps`/`vm_stat` diagnosis one-liners.
- **`tests/test_run_suite.py`** — the seven-gate suite: budget never 0, budget is derived (not
  hardcoded), the QoS prefix is absent off-macOS and when disabled, machinery failures never
  block the wrapped command, and the module imports cleanly with `fcntl` blocked.
- **ADR-0020** — records why a queue, a daemon, a `PreToolUse` hook, `flock`, and `nice` were
  each measured or reasoned out and rejected, plus two proxies (sleep-wakeup latency as a
  usability metric, an uncontrolled first late-application measurement) the architect lane got
  wrong before redoing them with a control.

## Behaviour changes worth knowing

- **Do not wrap long-lived infrastructure with `run_suite.py`.** `taskpolicy -b` is inherited by
  child processes; wrapping a command that also starts an AppHost, dev server, or emulator
  throttles that infrastructure for its whole lifetime, not just the one test run. Wrap only the
  test/build runner invocation.
- **Raise fixed timeouts on timing-sensitive suites by >=2.5x when QoS is active.** A `-b`'d
  process is measured 2.11x slower, which tightens every fixed startup timeout by the same
  factor — this is not hypothetical, see the ADR's job-search-ai-assistant `apphost-lock.ts`
  citation.
