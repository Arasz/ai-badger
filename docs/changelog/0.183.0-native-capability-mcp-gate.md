# 0.183.0 - the pi MCP migration gate keys on native pi capability

**Minor** (scaffold-affecting) - 2026-09-30

The MCP half of the pi migration adjustment was gated on the retired `pi-mcp-tools` fork's
capability marker: removal of this project's shape-matched entries from
`~/.pi/agent/settings.json`'s `mcp` key ran only when the installed extension carried
`.ai-badger-capability-project-scope-mcp`. That reader is retired — pi 0.99.1 ships MCP as a
built-in extension (`builtin:mcp`), and the consumer ADR (`pi-badger-integration` →
`docs/work/2026-09-30-retire-pi-mcp-tools-native-mcp-adr.md`, Consequences) names this change
as its follow-up. With the fork gone the marker can never be present, so the gate went inert:
the legacy global `mcp` entries this scaffold once wrote were left behind on every machine
that had already migrated, and every re-scaffold repeated the same warning.

## What changed

The gate now opens on the project's own native config: removal runs iff `<target>/.pi/mcp.json`
exists **and** parses as a JSON object. Three states — present and parseable → removal runs
(shape-matcher and write contract unchanged); absent, malformed, or parsing to a non-object →
`applied=False` with an honest `GATE_WARNING` naming native pi as the reader being restored,
settings untouched, never raising; no `target` in context → treated as absent. No subprocess,
no version probe: the settings `mcp` key's only reader ever was the retired extension, so the
capability that marker declared ("an installed reader can resolve this project's MCP servers
without the global key") is exactly the project's `.pi/mcp.json` under native pi's trust model.

The fork's name is retired from the adjustment machinery: `adjust_mcp.py`, `adjustment.json`,
`pi_settings.py`, `adjust_skills.py`, `support.json`, and the `mcp_tools.py` comments (the
source and the `.ai-badger/` copy). `support.json`'s pi row and the honesty pins in
`tests/test_support_json_honesty.py` now state the native contract — config in
`~/.pi/agent/mcp.json` (global) and `.pi/mcp.json` (project, trust-gated), with the settings
`mcp` key read by nothing but the retired extension.

## Upgrade notes

- **No `.pi/mcp.json`** → the re-scaffold warns and leaves the global entries in place. A
  machine still running the legacy reader may depend on that key; update or remove the reader,
  add the project's native config, and re-run to migrate.
- **`.pi/mcp.json` present** → this project's shape-matched entries are removed from the global
  `mcp` key; a same-named entry that does not match (a user edit or a drifted shape) is
  warn-and-leave, never destroyed.
- A leftover legacy extension directory is cleaned by the retirement's `publish`, not by this
  change.
- Adjustments run before `generate_mcp_json`, so a project whose `.pi/mcp.json` is first
  written by the companion scaffold task (`aib-scaffold-pi-native-mcp-config`, PR #545)
  migrates on the **following** re-scaffold.
