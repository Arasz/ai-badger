# 0.197.0: an rtk guard hook keeps Claude and Codex rules on the original command

**Minor** (feature) · **Date:** 2026-10-18

0.195.1 stopped wiring rtk for Claude and Codex because both hosts match their own rules against
the command a hook rewrote: Claude's `permissions.ask`, and Codex's `prompt` and `forbidden`
prefix rules. ai-badger now ships its own hook in place of `rtk hook claude|codex`. It asks
`rtk rewrite` for the rewrite and hands it over only when no host rule names the original
command. Research: `docs/work/2026-10-18-rtk-ask-preserving-hook.md` (PR #591). Live check:
`docs/work/2026-10-18-rtk-guard-live.md`.

- `features/common/tools/rtk/scripts/rtk_guard.py` is the hook, stdlib only. Claude: on exit 3 it
  calls `rtk rewrite` again with `RTK_REWRITE_HOST=openclaw`, and when that is also 3 an ask rule
  matched, so it prints nothing and Claude judges the original. Otherwise it prints the rewrite,
  with `permissionDecision: "allow"` only on exit 0. Exits 1 and 2 print nothing.
- Codex: it reads `$CODEX_HOME/rules/*.rules` (default `~/.codex`) and each `.codex/rules/*.rules`
  from the cwd up to the git root. No rule files means rewrite, with the `allow` Codex requires
  beside a rewrite. Otherwise it splits the original into plain-chain segments and runs
  `codex execpolicy check` on each. Any matched rule, failed check, missing `codex`, or text that is
  not a plain one-line chain leaves the command unrewritten.
- Review-driven fixes over the research prototype. The first `rtk rewrite` call drops an inherited
  `RTK_REWRITE_HOST`, so a session that exports `openclaw` cannot turn an uncovered command into an
  `allow`. The Codex adapter fails closed on a newline: `shlex` reads one as whitespace, and rtk
  rewrites both lines. It also fails closed when rtk rewrote inside a wrapper (`bash -c`, `env`,
  `time`), where a per-command argv check cannot see, and on text Codex itself does not split: a
  leading `NAME=value`, a glob, or control flow. Codex judges those as one shell invocation, so a
  per-segment check would probe the wrong argv. Claude needs neither: rtk's own ask check
  flags a rule on a second line (checked live).
- `tool_hooks.guarded_command` takes the guard's source and runs it as `python3 -I -c "$1"` inside
  the same marked, fail-open `sh -c` line, so no file has to land in the project and the output
  still depends on config alone. A spec's new `guard` key names the script.
- rtk's `meta.json` sets Claude back to `native`. Codex stays `propose` until a live Codex
  session has run the guard; its spec already names the guard, so switching is one word. The
  propose and native notes for Codex and `tool.md` now say what the guard does.
