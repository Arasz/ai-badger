# 0.189.0 — pi native provider/model IDs

**Minor** (scaffold-affecting) · 2026-10-06

## What changed

The model registry and its schema accept fully qualified `<provider>/<model>` IDs.
Providers are checked by shape, without a catalog or network lookup. Model names
can contain nested segments, colons, `~`, and `@`, so native pins such as
`openai/gpt-6.1-sol`, `local/qwen:7b`, and
`fireworks/accounts/fireworks/models/x` survive pi agent regeneration.
Bare aliases, empty segments, whitespace, and control characters are refused.

The memory query planner still calls OpenRouter. It refuses registry pins for
other providers before HTTP and falls back to the existing local query path.
Its environment override retains the OpenRouter API form `vendor/model`, with
an optional `openrouter/` prefix; nested or native punctuation forms are refused.
Two-segment overrides remain ambiguous and retain their legacy interpretation.

The companion pi-badger-integration change admits the same ID shapes and passes
them unchanged to pi through `--model`. Shared conformance rows verify the
Python, schema, and TypeScript boundaries without live model calls.
Default pins and `registryVersion` stay unchanged.
