# 0.172.13 — open_pr scans what it stages; red_proof checks a journal before restoring

**Patch** — two security fixes to skill scripts that ship to every consumer:
`feed-badger`'s `open_pr.py` and `design-tests`' `red_proof.py`. 2026-09-24.

## What was wrong

- **The outbound credential scan could be bypassed.** `open_pr.py` scanned the declared
  `--path` values, then ran `git add -- <paths>` and `git commit`. Git expands pathspec
  magic: `--path 'features/**'` staged every match, while the scanner saw one missing file
  and skipped it. `git commit` also took anything that was already staged, declared or not.
  Both broke the script's own contract that only declared, scanned paths are published.
- **An oversized file left unscanned.** `engine/unsafe_literals.py` skips any file over
  `LITERAL_SCAN_MAX_BYTES` (1 MB) and reports no finding, so a large file carrying a
  credential passed the outbound scan.
- **A stale `red_proof.py` journal was restored blind.** On start, a leftover journal's
  `original_content` was written to the journal's own `path` with no checks. Nothing
  confirmed the path was inside the repo, and the stored sha256 was never compared. A
  legitimate leftover journal overwrote any edits made since the crash, and a planted one
  chose where to write.

## What changed

- `open_pr.py` refuses when the index already holds staged changes, and names them. It
  stages the declared paths with `GIT_LITERAL_PATHSPECS=1`, so a glob names one literal
  file, and git refuses it when that file does not exist. It then scans exactly
  `git diff --cached --name-only`. A finding, or a staged file over the scan's size cap,
  resets the index to the clean state it started from and refuses. The branch is now created
  after staging, so a refusal leaves you on the branch you started on. `--dry-run` still
  runs no git and scans the declared paths.
- `red_proof.py`'s journal records `mutated_sha256`, computed from the mutated text before
  the target is written. A stale journal is restored only when its path resolves inside the
  repo (and outside `.git`), and the file's current content hashes to the mutated or the
  original sha. Otherwise the tool prints `REFUSED`, writes nothing, and exits 3.
- `SECURITY.md` and the `unsafe_literals` docstring name the scan's size skip. They also
  name the inbound Hermes sync (`learned_skills_sync.py`, `sync_skill`) as the one remaining
  caller that lets an oversized file through.

## Upgrade notes

- Re-scaffold to pick up the scripts.
- `open_pr.py`: commit or unstage anything already staged in the framework checkout
  before running it, and name paths literally. A directory still works.
- `red_proof.py`: a journal left by an older version has no `mutated_sha256` and is
  refused. Compare the file with the journal's `original_content` by hand, restore it if
  needed, then delete `.design-tests/red-proof.journal.json`.

## Verification

- `tests/test_open_pr.py` runs real git in a tmp checkout with a local bare `origin` and a
  stub `gh`. A glob `--path`, a pre-staged file and an oversized declared file each reached
  `origin` before the fix, and each is refused after it.
- `tests/test_design_tests_scripts.py`: a journal pointing outside the repo, a target edited
  after the mutation, and a legacy journal each overwrote the file before the fix. Each now
  exits 3 and writes nothing. A target still holding the mutation is restored.
- Mutation proofs: restoring on the path alone, dropping the containment or sha check,
  turning pathspec magic back on, dropping the clean-index refusal, the size refusal or the
  staged-set scan each turn a gate red.
