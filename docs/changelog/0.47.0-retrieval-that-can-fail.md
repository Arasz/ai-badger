# 0.47.0 — the MCP recommender ranks by BM25, and its accuracy can now fail a test

`_extract_query_tags` in `ai_badger_hooks.py` matched ~70 hand-written keywords with a raw
`keyword in query` substring test, and `_find_relevant_tools` returned `[]` the moment that
produced no tags — before its own intent-word-overlap scoring ever ran. Measured on 15 realistic
queries against this repo's real `.ai-badger/mcp-tools.yaml`: **8 returned nothing at all**, and
the substring test fired `typescript` inside *tests* and `log` inside *login*.

## The fix

`features/common/retrieval/` (new, stdlib-only): a tokenizer that splits on non-alphanumerics
(so `"ts"` is a token that can never match inside `"tests"` again), a generic BM25 corpus
(`k1=1.2`, `b=0.75`), and an MCP-specific matcher that fuses `name`/`tags`/`intent` into one
weighted document per tool. The gate is BM25 **coverage**, not raw score — the worst true
positive and the best out-of-domain false positive overlap in score, so no fixed cutoff works.
The coverage threshold (0.20) was swept and derived against this repo's own 98-tool corpus, not
copied from a smaller one. `ai_badger_hooks.py`'s `_find_relevant_tools` now calls into this
module instead of containing the ranking itself.

`_KEYWORD_TAG_MAP` and its all-or-nothing gate are deleted. Existing tool `tags` are not
discarded — they become a weighted field. `features/common/mcp-tags.json` is unchanged.

## The eval harness

`features/common/retrieval/eval/mcp_queries.jsonl` — 58 fixtures (43 positive, 15 negative) built
from the real index in this repo, `"expect": []` a first-class negative fixture.
`tests/test_mcp_retrieval_quality.py` gates recall@3 (≥0.90, measured 1.000), top-1 (≥0.75,
measured 0.907), false-fire on negatives (≤0.30, measured 0.267), zero-result on positives (== 0,
the old matcher's defining bug, measured 0/43), and determinism across two runs. Fixtures are
author-written, which biases these numbers upward — stated plainly rather than hidden.

This replaces ADR-0004's "100% accuracy on a 16-query spike suite," which cited a script in a
different repo that cannot be run and cannot fail.

## `import yaml` is now guarded

`ai_badger_hooks.py`'s module-level `import yaml` was the only unguarded third-party import in
the tree: if pyyaml were absent, the whole module failed to import, taking the drift notice,
commit reminder, session hints, and MCP recommendations down together, silently (issue #136). It
now degrades `_load_mcp_index` to `None` instead, matching the existing `debug_log` guard
pattern.

## ADR

[ADR-0012](../adr/0012-bm25-retrieval-with-a-falsifiable-eval.md) supersedes ADR-0004's DD-2
(closed tag taxonomy) and DD-3 (YAML for hand-editability — its sole justification, hand-editing,
was withdrawn), and re-affirms DD-1/4/5/6 and the rejection of embeddings (Alternatives B) with
this release's own measured numbers. The JSON migration DD-3's reversal implies is a decided,
not-yet-implemented follow-up: issue #136 stays open, retitled to track it.

## Behaviour changes worth knowing

- The MCP hint in a Hermes turn's injected context can now recommend a tool for queries that
  previously produced nothing (four of the eight measured above are real recoveries; the other
  four are genuinely outside the MCP corpus's domain and stay negative).
- `mcp-tools.yaml` is unchanged in this release; a project need not touch it.
