# 0.162.1 — ai-raccoon-memory: search-quality surface follow-through (sessionId, kind, rank)

**Patch** (content fix, no shape change) · 2026-09-04

## What changed

The `ai-raccoon-memory` skill lagged the server's search-quality contract (ai-raccoon
#602, P1/P3/P4): `memory_search` requires `sessionId`, results carry `kind`
(`both`/`memory`/`code`) with per-section recording semantics, and quality verbs take
`correlationId` plus `servedRank`. The skill now documents all three, including the
`kind=both` rank-ambiguity rule (a bare rank names no section by design) and the
checklist probe. No new paths, no renamed features, no hook contract change.

## Fix

`memory_grade_hook.py` deduplicates follow-through files by path across both row
shapes: the server writes object rows (`{path, rank}`), and the old bare-string
membership check missed dict elements, double-counting the same file. New files still
append as bare strings, which the C# per-element fallback reads. Covered by
`TestMemoryGradeHookRecordSqlInterop` (RED witnessed against the old code: `assert
2 == 1` on the dedupe case).

## Provenance

Feed from the ai-raccoon consumer repo, where these edits were made as the P6
agent-surface sweep of #602 and then overwritten by `den-refresh` 0.161.x → 0.162.0.
