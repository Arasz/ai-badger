# 0.135.1 — Prompt policy rules for short-horizon work

**Patch** — user-facing prompt policy consolidation for ai-badger's agent instruction files and task orchestration flow.

## What changed

- Added the repo-level prompt policy to `.ai-badger/agent-instructions/model.json`, encoding the nine short-horizon rules that survived the research merge.
- Expanded the always-loaded instruction files (`.ai-badger/CLAUDE.md` and `.ai-badger/copilot-instructions.md`) to include one-turn specification, consolidated restart, grounded feedback, tool contracts, placement, reasoning minimization, output-schema separation, positive validation, and few-shot gating.
- Updated the `task` orchestration skill to explicitly require an executable first-turn brief, grounded corrections, and merged restarts instead of drifted follow-ups.
- Updated the `prompt-markers` skill so `f:`/`feedback:` calls must cite the failing evidence, and a repeated failed round triggers a merged restart rather than another commentary pile-on.

## Why

The rule set was distilled from prompt-engineering research and filtered to keep only net-positive behaviors. The strongest signals were that tool schema + success criteria matter more than persona prose, that the first-turn specification should be explicit and short, and that corrections must be evidence-based and validator-backed.

## Upgrade notes

No configuration or command changes are required. This is a documentation and policy update only: the framework now carries the same short-horizon prompt rules in its generated instruction surfaces and task orchestration guidance.
