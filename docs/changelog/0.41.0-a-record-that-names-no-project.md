# 0.41.0 — a record that names no project belongs to no project

[#113](https://github.com/Arasz/ai-badger/issues/113). Found by running `call-behaviorist
analyze` against 32 hours of real usage across two repositories on one machine.

The report came back `degraded` with six high-severity `version_skew` findings. Every one of them
was an artifact. Two real defects were underneath, and they are two halves of the same thing.

## Three hooks never named their project

`debug_log.resolve_project_root` exists for this, and has said why since it was written:

> Shared so every hook attributes its records the same way: an unattributed record pools into
> every project's analysis and skews all of them.

Three hooks never called it:

| Component | Records naming no project |
|---|---|
| `task_user_prompt_hook` | 465 of 465 |
| `drift_notice_hook` | 373 of 413 |
| `stop_hook` | 334 of 334 |

`stop_hook` and `task_user_prompt_hook` passed a project on no path at all. `drift_notice_hook`
passed one only on `fire` — its `no_drift` and `no_framework` skips run with a known root and
still recorded nothing, and those skips are the overwhelming majority of what it emits.

The pattern that fixes it already existed three times in the tree. `session_start_hook`,
`prompt-markers/user_prompt_hook` and `commit_reminder_hook` all keep the payload in a
module-level `_PAYLOAD` and default the project from it. The three hooks above simply never
adopted it; they now do.

`drift_notice_hook`'s `no_root` skip stays unattributed on purpose. It fires precisely when the
hook could not determine a root, and naming one there would be a guess, not attribution.

## `analyze` admitted those records into every project

```python
if project and rec.get(dl.KEY_PROJECT) not in (None, project):
    continue
```

`None` was on the allow-list. Any record naming no project counted as evidence for whichever
project you happened to analyze.

On the machine where this was found, a second repository runs a 0.37.0 scaffold and wires
`task/scripts/user_prompt_hook.py`, `stop_hook.py` and `drift_notice_hook.py`. This repository
wires none of them. Analyzing *this* repository reported:

- **four false `unexpected_component` findings** — another repository's hooks, and one test
  fixture, presented as this project's surprises;
- **0.37.0 in this project's version tables**, from a scaffold that has never run here.

`analyze` now partitions evidence by project instead of pooling it.

### Set aside, counted, never dropped

Records that still name no project are reported as `window.unattributed`, with the components
they came from in `window.unattributed_components`. They are not scored. A `low` finding would
fire on every pre-fix record still sitting in a user's log and pin every report at `warn` for
the next 5000 records — the same crying-wolf failure the `version_progression` rule was added to
prevent in [0.38.0](0.38.0-an-upgrade-is-not-version-skew.md).

### One new failure the fix had to cover

Tightening the filter to exact string equality introduced a hazard of its own: `/var` and
`/private/var` name one directory on macOS, and `$CLAUDE_PROJECT_DIR` and `Path.cwd()` can spell
a project either way. Comparing only the text would silently drop a project's own records — the
same class of defect, inverted. Both sides are now normalized before comparison.

## Why the producers were fixed first

Fixing `analyze` alone would have made roughly 1170 records vanish from every project's report
while the hooks that emitted them still could not be placed. Three live hooks would have gone
invisible to the tool that exists to observe them. In the order shipped, no commit ever loses
sight of a hook.

## What the six `version_skew` findings actually were

All six had observed ranges falling entirely inside a two-hour window, and their records carried
paths like `/private/var/.../pytest-of-arasz/pytest-1088/test_usage_hint_returns_after_0`.

That is the pre-isolation test leak fixed in
[0.35.5](0.35.5-the-suite-cannot-reach-the-real-log.md) and hardened by the import-time
`AI_BADGER_DEBUG_DIR` in `tests/conftest.py`. 3768 of ~4180 records in the file came from those
two hours. No code change was needed; clearing the log removed them. Recorded here so the next
reader does not chase it twice.

## Upgrading

Nothing to do. A re-scaffold delivers the four changed scripts, and until then old records simply
count as unattributed. This is not a `BREAKING_VERSIONS` entry.
