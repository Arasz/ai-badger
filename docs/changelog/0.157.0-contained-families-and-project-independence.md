# 0.157.0 — Contained families and project independence

## What changed

- **Per-family containment on store open (M2).** A resurrected legacy file — a stale
  pre-sqlite surface rewriting a migrated file behind the store — no longer bricks
  `open_user`/`open_tracking` for every family sharing the DB. Open records the
  per-family unavailable state; that family's accessors refuse with the upgrade
  pointer; every other family — the message bus included — opens, reads and writes
  normally. Refuse-on-access is uniform across kinds, including file-set legacy reads.
- **The `doctor` verb.** `badger_store.py doctor --status` lists contained families
  with stamp, file mtime and (for map families) a content diff against the DB rows,
  without creating or migrating anything; `doctor --repair` re-imports the additive
  kinds (jsonl/recent/file-sets) idempotently and prints guidance for map/kvdoc/awm
  families. den-refresh runs `doctor --status` as a pre-flight.
- **Project resolution is ai-badger's own (D2).** The cwd resolver no longer reads the
  ai-raccoon bank: it walks up to the nearest `.ai-badger/` and reads the minted
  `project-id` file (uuid4, written at scaffold time; den-refresh backfills existing
  repos). `AI_BADGER_PROJECT_ID` still wins explicitly. There is no ambiguity to
  refuse — the nearest directory wins — so `ProjectIdAmbiguous` is gone.
- **The first read no longer overshoots (L1).** A gated first delivery in a session
  with no project delivers only 1:1 mail — and now lands the cursor over the legs
  actually delivered, so project/broadcast mail inside the 30-minute window survives
  for a later session instead of being silently consumed.
- **The test hold needs arming (L2).** `AI_BADGER_TEST_HOLD` parks delivery only when
  `AI_BADGER_TEST_HOLD_ARMED` is also set (test preconfiguration); a leaked hold value
  alone is inert. The exactly-once process race still parks and releases through the
  shipped script.
- **pi and Hermes deliver on the first turn (L4/L5).** The start-spawn is deferred:
  pi's `before_agent_start` and Hermes' first `pre_llm_call` read mail and inject it
  in the same transaction — consumption and injection coincide. A session that never
  reaches its first turn consumes nothing; mail survives for a later session instead
  of being consumed and lost.
- **Copilot hook rows carry the existence guard (L9).** Generated
  `.github/hooks/ai-badger-hooks.json` commands wrap in the `if -f` guard with a
  skipped `systemMessage`, matching Claude's adjuster.
- **Docs (L6/L8).** The changelog and the send-message SKILL state the machine-local
  trust boundary (identity asserted, not authenticated) and record Copilot's
  close-event verdict as a residual risk.

## Consumer impact

- Repos scaffolded before this release have no `.ai-badger/project-id`; until
  den-refresh backfills, the bus delivers 1:1/env-only there. Run den-refresh to mint.
- Sessions in a nested `.ai-badger` directory (worktrees) resolve to the nearest
  project — the worktree's own, not the parent repo's.
- A contained family's data refuses on access until repaired: run `doctor --status`,
  then repair (additive kinds re-import; map families print a diff and need an
  explicit decision).
