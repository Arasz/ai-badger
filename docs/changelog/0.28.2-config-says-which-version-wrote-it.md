# 0.28.2 — config.json says which version wrote it

## The bug

`config.frameworkVersion` is schema-required and documented as "ai-badger framework version
this config was generated against". `welcome-ai-badger` never updated it.

`scaffold.py` already writes `.ai-badger/config.json` — it copies the incoming config through
verbatim, stale version and all. Only `den-refresh` ever re-stamped the field. So a project
scaffolded repeatedly through `welcome-ai-badger` kept claiming whatever version first created
its config, indefinitely.

Found by dogfooding `den-refresh` against this repository: `config.json` read `0.18.1` while
the manifest correctly read `0.27.0` — **nine releases apart**, across four scaffold runs on
the same day.

## What it did and did not affect

Drift detection is **not** affected — `drift.py` and `drift_notice.py` both read
`manifest.frameworkVersion`, which `scaffold.py` has always stamped correctly.

What was wrong is `den-refresh`'s own report: it reads `config.frameworkVersion` as the
starting point for "what changed since", so it overstated every upgrade it described.

## The fix

`scaffold.py` stamps the running framework's version into the config it writes. The caller's
dict is left alone — the scaffolder owns its output copy, not the object it was handed.

## Upgrading

Nothing to do. The next `welcome-ai-badger` or `den-refresh` run corrects the value in place.
If your `.ai-badger/config.json` names a version far behind the framework you are running,
that is this bug, and one scaffold run fixes it.
