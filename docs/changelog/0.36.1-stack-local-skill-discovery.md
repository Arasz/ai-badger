# 0.36.1 — stack-local skill discovery

`auto-wm` is a claude-only skill but was declared `default` in `SKILL_SCOPES` — the
universal registry. The scaffold system only scanned `features/common/skills/`, so auto-wm
was registered as default in the index but never actually scaffolded.

## What changed

- **Removed auto-wm from `SKILL_SCOPES`** — `default` means universal; stack-specific
  skills don't belong here (ADR-0010).
- **Added `badger_lib.stack_local_skills()`** — discovers skills in a stack directory not
  in the universal `SKILL_SCOPES`.
- **Added `badger_lib.skills_for_stack(root, stack)`** — single entry point combining
  universal defaults (common) and stack-local (agent-specific). Used by
  `sync_plugin_skills.py`.
- **`Scaffolder.scaffold_skills()` searches all configured stacks** — not just `"common"`.
  Records correct stack provenance in the manifest.
- **`Scaffolder.run()` discovers stack-local skills** from configured stacks before
  scaffolding. Respects `config.exclude`.
- **Catalog routing test** updated: only common-stack skills must be in `SKILL_SCOPES`.
  Stack-local skills are reachable via their stack's directory.

## Files changed

- `scripts/badger_lib.py` — removed auto-wm from SKILL_SCOPES, added `stack_local_skills()`
- `features/.../scaffold.py` — scaffold_skills searches all stacks, run() discovers stack-local
- `scripts/sync_plugin_skills.py` — uses `bl.stack_local_skills()`
- `index.json` — auto-wm no longer has scope field
- `tests/test_scaffold.py` — 3 new tests for stack-local skill discovery
- `tests/test_sync_plugin_skills.py` — catalog routing test updated
- `docs/adr/0010-stack-local-skill-discovery.md` — ADR
