# 0.221.0 — review-flow: a coordinator-driven code review with a typed flow model

**Minor** · **Date:** 2026-11-19

## New features

- New default skill `review-flow` (ADR-0051). One coordinator moves a pull-request review
  through a typed flow: context (issue, ACs), change model, four parallel review lanes
  (business/AC, QA, architecture, code quality), integration, a global-scope check, a result
  file and a publish step. Every judgement is a one-shot worker; the coordinator only runs the
  CLI (`review_flow_cli.py`) and dispatches briefs.
- The flow model is a pydantic model with a declared transition table and named guards. A
  refused move names its guard. Flow state is stored in `tracking.db` (`review_flows`, revision
  checked) with no schema version bump.
- Global-scope check: each finding is re-judged against project facts and gets a disposition —
  keep, downgrade (for example to a nit tagged `DEFENSIVE` when the case cannot happen in
  production) or drop — with the basis it cites.
- GitHub output: each inline comment is four lines or fewer for the human (reason and level),
  with the agent context, repro path and proposed fix in a collapsed `<details>`. One summary
  comment is edited in place and shows the verdict, the reviewed commit and the last update.
  Publish always uses the `COMMENT` event; a round with no inline findings updates only the
  summary.
- Round 2: author replies become proposed review rules in `.ai-badger/review/rules.json`, read
  from the base ref. A rule becomes active only with a maintainer confirmation, a
  script-verified citation, or two independent threads; only OWNER, MEMBER and COLLABORATOR
  replies teach. Active rules are input to every worker brief.
- Publish is idempotent: comment markers and the bot login identify earlier output, a re-run
  after a lost receipt recovers the review and summary ids from GitHub, the receipt is written
  atomically, and a failure after a write keeps the completed results.
- Context is trusted only at the PR's `baseRefOid` (offline: a full commit SHA); lint
  availability is judged from the config at that base.
- `limited-env` extension: the flow runs through the CLI alone when hooks, MCP, `uv` or `gh` are
  missing; offline publish writes `round-N.rendered.md` for the human to post.
- `code-review` routes a PR review that must be published to `review-flow`.
