# 0.17.3 — optional-embeddings-dependency

code-review-graph's semantic search silently degraded to keyword matching when
`sentence-transformers` was missing, with no signal to the user beyond a
buried "0 nodes embedded" line in `list_graph_stats_tool`. Dependency
declarations now support an `optional` shape that detects this instead of
either ignoring it or force-installing a ~2 GB dependency.

## What changed

- **`schemas/dependencies.schema.json`:** new `optional`, `importName`, and
  `note` fields on a dependency entry. `optional: true` means the dependency
  is never auto-installed by `dependency_check.py` — it's detected in the
  host interpreter and surfaced as a hint instead.
- **`dependency_check.py`:** `run_dependency_check()` gains a `"hints"` list
  in its result. For an optional dependency, it resolves the interpreter that
  actually hosts `code-review-graph` (project `.venv` first, PATH `python3`
  fallback — matching how the MCP server is actually launched) and, when the
  optional import is missing, reports a concrete
  `<interpreter> -m pip install "<pkg><extras>"` command plus the
  dependency's `note`. Never installs it.
- **`scaffold.py`:** `_check_dependencies()` forwards hints into
  `Scaffolder.notes`, so they surface in the scaffold report.
- **`features/common/dependencies.json`:** declares
  `code-review-graph[embeddings]` (import name `sentence_transformers`) as
  the first optional dependency, with a note about the ~2 GB torch cost and
  the chance of missing wheels on very new Python versions (e.g. 3.14).
- **`.pre-commit-config.yaml`:** dropped `--rcfile=/dev/null` from the local
  pylint hook — it was discarding `pyproject.toml`'s `[tool.pylint]` config
  entirely, including the test-file message disables, so any commit touching
  a test file with a locally-defined fixture failed the hook even though the
  documented `lint` command was clean.

## Why optional-and-surfaced, not required or silent

`sentence-transformers` pulls in `torch` (~2 GB) and doesn't always have
wheels for bleeding-edge CPython, so it can't be a hard scaffold-time
requirement. But leaving it fully undocumented left users unable to tell
real semantic search from FTS5 keyword matching — nothing errors, nothing
warns, the tool just returns worse results. `optional: true` + detection +
an actionable hint closes that gap without forcing the install.

## Consumer impact

No change for existing scaffolds — the base `code-review-graph` install is
untouched. Projects that scaffold `code-review-graph` now get a note (in
scaffold output, or from a standalone `dependency_check.py` run) when the
embeddings extra isn't installed in the interpreter that runs the MCP
server, naming the exact `pip install` command to fix it.
