# 0.53.0 — the self-scaffold stops being taken on trust

**Date:** 2026-07-30

Closes [#206](https://github.com/Arasz/ai-badger/issues/206).

## What was wrong

This repo is scaffolded by the framework it ships, so `.ai-badger/` is a mirror of
`features/**` and `.ai-badger/manifest.json` is the record of what that mirror last held. A PR
that edits `features/**` and never re-scaffolds leaves the record describing a tree that no
longer exists — and every later PR inherits the discrepancy.

That is exactly what happened. #204 added `features/common/skills/mcp-index/host_listings.py`
and merged without a re-scaffold; the manifest kept `dirMeta.file_count: 6` for a source that
now held seven files, and it shipped in a tagged release.

Detection was never the gap. `drift.py` reported it correctly. **Enforcement was:**
`index_build --check` covers `index.json`, `sync_plugin_skills --check` covers the `skills/`
mirror, `version_sync --check` covers the version literals — nothing covered this repo's own
scaffold state. The assertion "re-scaffolding this repo against itself changes nothing but the
manifest stamp" was made by hand, in a PR report, nine times in one night. Eight were right.
The ninth was not made at all.

## Added

- **`gates/scaffold_freshness_guard.py`** — copies the tracked and untracked-unignored tree to
  a throwaway directory, re-runs the welcome-ai-badger scaffolder there against that copy, and
  fails on every resulting difference. It is a reproduction, not a hash comparison: a manifest
  that agrees with itself is precisely the failure mode #110 already found once, so nothing
  here trusts a recorded hash to answer whether the mirror is current.

  Stamp churn is exempt, because it is not staleness. `frameworkVersion`, `frameworkCommit`,
  `frameworkDirty`, `generatedAt` and `configHash` are dropped from JSON at any depth, and the
  `Scaffolded by ai-badger <version>` line is normalized in the agent-discovery markdown. A
  version bump alone re-stamps the manifest, `.ai-badger/config.json`, `CLAUDE.md`,
  `HERMES.md`, `.hermes.md` and both `copilot-instructions.md` — and must still pass.

  A tree it cannot enumerate is a refusal (exit 2), never a pass: a missing
  `.ai-badger/config.json`, an empty file list, or a `git ls-files` that failed each print why
  and stop. The tree under `--root` is only ever read — the comparison happens in the copy,
  including when it finds staleness.

### The ambiguity drift.py could not resolve

`drift.py` reads a stale mirror and a hand-edited mirror identically, reporting both as
`local` ("this project edited its own copy"), because from the manifest's point of view they
are the same shape. The guard separates them, and says which it found:

- **`stale`** — the source no longer hashes to what the manifest recorded, so the framework
  moved ahead of the mirror. Re-scaffold.
- **`hand-edited`** — the source still matches that record, so a re-scaffold would reproduce
  exactly what the last one wrote and the difference can only be in the target. Re-scaffolding
  will discard the edit; move it into `features/**` first.

The question is asked of the *source*, never of the target's recorded `hash`: the scaffolder
records a skill's `hash` before it has finished writing that directory, so for at least one
skill (`mcp-index`) it does not describe what ends up on disk — and a classifier keyed on it
called a source-side change `hand-edited`. Entries recording their source's hash rather than
the written file's (ADR-0006) are read the same way, and a path no manifest entry owns is
reported without a verdict rather than with a guessed one.

## Changed

- **`.ai-badger/manifest.json`** — re-recorded. A prior PR changed
  `features/common/skills/welcome-ai-badger` and updated the mirror but not the manifest's
  hashes, which is the stale shape this issue is about. Committed separately so the new gate
  starts from a fresh tree.
- **`.lefthook/pre-push/verify.sh`** — new `scaffold` lane, in `$LANES` and in the always-run
  whole-tree set, so any push runs it.
- **`.github/workflows/pylint.yml`** and **`.pre-commit-config.yaml`** — the guard runs in CI
  and on commit. Three surfaces, same as every other gate: a gate registered nowhere is this
  repo's recurring defect, and this one exists because an assertion nobody automated went
  unmade once.

## Tests

- `tests/test_scaffold_freshness_guard.py` (new) — a fresh tree passes; a skill source that
  gains a file fails naming the missing mirror path; a source edit reads as `stale` and a
  mirror edit as `hand-edited`; version-stamp churn alone passes; an unscaffolded root and a
  root git cannot enumerate both refuse loudly; the checked tree is never mutated. Fixtures are
  copies of this repo made fresh by construction, so a stale real tree fails the gate's own
  lane rather than these tests.
- `tests/test_every_check_can_fail.py` — the new gate has a provocation that is run, not
  described: a self-scaffolded copy of this repo, then a file added to a skill source.
- `tests/test_gates_layout.py`, `tests/test_verify_gate.py` — rewritten for the new gate and
  the new lane.
