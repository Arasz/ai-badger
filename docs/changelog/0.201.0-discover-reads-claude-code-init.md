# 0.201.0 — `mcp-index --discover` reads tool names from Claude Code's init event

**Minor** (feature) · **Date:** 2026-10-18

- **Host tools.** `mcp_index.py init|update --discover` now fills what the stdlib client cannot
  reach (servers answering 401/403, `claude.ai <Name>` connectors, servers with no config) from
  Claude Code's own headless init event (`features/common/skills/mcp-index/scripts/host_tools.py`).
  It runs `claude -p --output-format stream-json --verbose --no-session-persistence --settings
  '{"disableAllHooks": true}' /cost` in `--target`. It reads to the `system/init` event and on to
  the `result` event, then kills the process group, under a 60s deadline (`--host-tools-timeout`).
  Measured on Claude Code 2.1.302: ~5.5s, no model turn (0 API requests, `total_cost_usd: 0`), 0
  settings hooks (managed-policy hooks are not covered by `disableAllHooks`), no transcript.
  - It is on by default when `claude` is on PATH and the listing came from `claude`. With
    `--host hermes` it runs only when `--host-tools` asks. `$MCP_INDEX_CLAUDE` overrides the
    path; empty disables. `--no-host-tools` turns it off.
  - The host does the authenticating, and no token store is read.
- **Guards.** The host step runs only for a `--target` that itself accepted Claude Code's trust
  dialog, because `claude -p` skips that dialog and would run the target's settings helpers. A model
  turn (a non-`<synthetic>` assistant message, `total_cost_usd` or `num_turns` above 0) is reported
  loudly and writes `~/.ai-badger/mcp-index/host-tools-billed.json`. While that file exists, every
  run refuses the host step until it is deleted. No `result` within 10s is an `unknown cost`
  warning.
- **What the init event decides.** A connected server's tools are added, never treated as the
  whole list: init's `tools` is filtered by deny rules and managed policy. A connected server with 0
  tools, and any other status, leaves the server as listed. The status is noted, mapped onto the
  listing's own vocabulary (`pending` becomes `pending_approval`). Server names map to
  `mcp__<name>__` prefixes by Claude Code's rule (every character outside `[A-Za-z0-9_-]` becomes
  `_`). A name that parses more than one way is refused rather than guessed. A direct answer wins
  over the host, approval refusals stay refused, and no unnamed source becomes `absent`.
- **`headersHelper`** (`scripts/headers_helper.py`) runs the way Claude Code runs it:
  - a shell command with a 10s timeout and cwd set by the scope that declares the server;
  - `CLAUDE_CODE_MCP_SERVER_NAME` and `_URL` are set, and credential variables are stripped for
    project and plugin helpers;
  - project and local helpers run only in a directory that accepted the trust dialog.

  Its JSON headers override static `headers` and are sent only to that server's URL. A 401/403
  re-runs the helper once and retries. Its run time counts against the server's deadline. A
  failing helper fails only that server.
- **Skip report.** 401 (`needs authorization`) and 403 (`forbidden`) are told apart. The
  `WWW-Authenticate` challenge's `resource_metadata` and `scope` are printed, with the fix:
  authenticate the server in Claude Code via `/mcp`, then rerun with host tools on.
