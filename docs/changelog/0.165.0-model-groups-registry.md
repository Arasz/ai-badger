# 0.165.0 — Model-groups registry: level→model pins with a validated seed (PKG-1)

**Minor** (additive) · 2026-09-05

## What changed

New single source of truth for `level:` (low|medium|high) → model-id resolution:

- `schemas/model-groups.schema.json` (draft 2020-12, manifest-schema conventions).
- Canonical seed `features/common/data/model-groups.json` (`registryVersion` 1): low
  prefers `openrouter/z-ai/glm-5.3-flash`; medium and high prefer
  `openrouter/meta/muse-spark-1.3-contributor`; `claude-sonnet-5` is the evidence-demoted
  medium tail (`status: demoted`, `revisionWatch: true`); `claude-fable-5.1` closes high.
- Shared leaf `features/common/skills/task/scripts/model_groups.py` (stdlib-only):
  `load_groups() / preferred(group) / resolve(level, explicit_model)` with typed errors
  `UnknownLevel` and `RegistryInvalid`. Explicit model wins verbatim; absent level means
  no pin (inherit); the tail never auto-failovers and aliases are never followed.
- `tooling/validate.py` maps the schema to `features/*/data/model-groups.json`, so the
  schema-coverage gate holds the new file.

Seed prices are brief-range pins measured 2026-09-05 (per-entry `measuredAt`); the
`model-tiers-research` memory context was unavailable to this lane, so every fixture cites
the task brief and session verification instead.

## Wiring

- Per-consumer mapping (dispatch gate, delegation map, adjustments) ships in the next
  package; the leaf raises typed errors those consumers will translate.
- No refresh automation: manual edits plus the validate gate. Price-only refreshes must
  preserve preferred-first and lexicographic (input, output) price order or fail loudly;
  a human re-orders and bumps `registryVersion`.

## Delivery (1b)

- `scaffold.py` delivers the seed to `.ai-badger/model-groups.json` on every run
  (rewrite-always managed copy, manifest-recorded as a template entry whose hash covers
  the source, so the freshness guard and drift track it). Consumer projects never edit
  the delivered file; per-consumer level/model mapping only reads it.
- `tooling/validate.py --all` unconditionally enforces the machine invariants over every
  `features/*/data/model-groups.json` instance via the leaf's pure `validate_registry` —
  validate.py is the single enforcer, the rules are duplicated nowhere. Two recorded
  decisions: no git touched/untouched gating (stub trees and tmp checkouts get the same
  answer), and a tree with no instance reports no gap (absence is the L0 suite's and
  the scaffold's concern, not this gate's).
