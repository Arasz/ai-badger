# 0.161.0 — Claude turn-end delivery: mid-work bus mail surfaces without another prompt

**Minor** (additive) · 2026-09-03

## What changed

Claude sessions re-run bus delivery when the assistant finishes a turn
(`Stop`, new `message-delivery-turn-end` manifest row). Mail that arrived
mid-work is injected as `additionalContext`, which continues the turn so
Claude acts on it — no need to mention messages in the next prompt to make
delivery fire. Exactly-once keeps the continuation loop-safe: the follow-up
firing finds nothing new and answers `{}`.

Hermes needs no equivalent arm (`pre_llm_call` already delivers before every
LLM call, including tool-loop continuations); Copilot's `agentStop`
injection semantics are unverified, so its delivery stays on the proven
per-turn seam.

## Residual (host design, not a bug)

A fully idle session fires no hook until its next prompt — Claude Code hooks
cannot wake an idle session. There is no timer surface, and
`FileChanged`/`Notification` discard context output (per the Claude Code
hooks reference, researched 2026-09-03), so mail arriving while idle still
waits for the next turn. True push on Claude would need an external carrier;
the pi adapter's in-adapter poll (0.159.0, ADR-0026) remains the only push
path on any harness.
