# 0.200.1 — `--discover` finds claude.ai-synced plugins; ai-raccoon catalog refreshed

**Patch** (fix) · **Date:** 2026-10-18

- **claude.ai-synced plugins resolve.** `claude mcp list` names a plugin synced from claude.ai
  (`claude mcp get` says "Scope: Dynamic config") as `plugin:<plugin>:<server>`, but
  `server_configs.py` read only `installed_plugins.json`, so `--discover` printed `no config` for
  it — `plugin:browser-use:browser-use` on the reporting machine. It now also reads
  `~/.claude/plugins/synced/<org>_<user>/`: the plugin's files come from the
  `<plugin>~g<generation>` dir that `manifest.json` names, else the highest `<plugin>~gN` dir, else
  the bare `<plugin>/` dir, with `${CLAUDE_PLUGIN_ROOT}` expanded to that dir. An installed plugin
  of the same name wins over a synced one.
- **ai-raccoon catalog matches the live server.** Enumerated live with the 0.200.0 client, the
  server offers 30 tools; `features/common/mcp/ai-raccoon/tools.json` described 19. Added curated
  intents for `memory_get`, `code_get`, `memory_record_followthrough`, `memory_record_grade`,
  `memory_share_extract`, `memory_promotion_list`, `memory_promotion_discard`, `memory_set_ttl`,
  `memory_performance`, `project_id_get` and `project_id_token_get`. No catalog entry had left the
  server, so none was removed.
- **semantica's `get_graph_analytics` stays out.** It is the one live tool the semantica catalog
  lacks, and it still fails on semantica 0.6.6 (`PageRank calculation failed: 'dict' object is not
  callable`), so the catalog keeps excluding it rather than recommending a broken call.
