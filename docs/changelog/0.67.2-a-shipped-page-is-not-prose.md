# 0.67.2 — A shipped page is not prose

Four review findings on #268 were raised by the automated reviewer and the PR merged without
addressing any of them. This closes all four, and shuts the gap that let the first two through.

## The leak

Both generated review forms in `docs/work/` carried
`expectedDir: "/Users/arasz/RiderProjects/ai-badger/.tmp"` — a personal home directory, shipped
in a tracked file, pointing reviewers at a hidden path that `docs/work/` exists to replace. They
now name `docs/work` instead.

## Why the guard let it past

`shipped_paths_guard` exempts `docs/` for a stated and still-correct reason: a changelog entry or
an ADR legitimately quotes a real leaked path as the record of an incident. That reasoning covers
prose.

It does not cover a generated page. `CONFIG.expectedDir` is read by the form's own JavaScript and
shown to a reviewer as the directory to save into — a machine path there is not a record of a
past leak, it is a live instruction. The exemption now stops at `.html`/`.htm`, with the explicit
allowlist still available for a page that genuinely must quote one.

## Dead config

`docs_guard.BUILTIN_EXEMPT` still exempted `docs/archive/`, a directory removed when the
kind-grouped record dirs went. An exemption naming a directory nobody has reads as a live rule,
and would have silently skipped those documents had it ever come back. It is now empty, and a
test asserts every built-in exemption names a directory that exists — the check that already
existed for `RECORD_DIRS`.

Also removed: an unused `LINK_RE` and its `re` import in `test_docs_tree_is_canonical.py`, which
suggested link scanning was part of a guard that never did any.
