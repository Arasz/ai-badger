# 0.162.0 — multi-agent-communication: parallel sessions get a protocol, not just a transport

**Minor** (additive) · 2026-09-04

## What changed

Parallel sessions in one project had a transport (`send-message`) but no protocol: nothing
said when to announce work, what an announcement holds, or how to ack without looping
forever. New default skill `multi-agent-communication` defines it — event table
(`starting`, `pr-opened`, `review-request`, `review-feedback`, `merged`, `blocked`),
project-broadcast command, one-line message shape, and ack-once / never-reply-to-an-ack
discipline (an ack is terminal; answering it restarts the conversation with a full LLM
turn burned per cycle per session).

## Wiring

- `task`, `quick-task`, `worktree-agent-isolation` point at the skill when more than one
  session shares the project (`task` body condensed net-negative to stay under the
  skills-lint token ceiling, which sat at 4999/5000).
- `send-message` backlinks to the protocol; `docs/skills.md` gains the row and counts.
- New invariant `announce-parallel-work` carries the general-instructions mention into
  agent files. This repo's own `agentDocs.maxLines` goes 256 → 260 — `HERMES.md` sat
  exactly at the limit.

## Residual

Delivery is not instant everywhere: an idle Claude session fires no hook until its next
turn, and pi machine-broadcasts do not wake (only addressed mail does unless
`AI_BADGER_PI_BUS_WAKE=all`) — so the protocol says announce-and-continue, never
block-waiting-for-ack.
