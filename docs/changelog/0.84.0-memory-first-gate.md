# 0.84.0 — Memory-first gate: agents must consult memory before text search

Every scaffolded repo now enforces "memory MCP first" on all three agents: Hermes,
Claude Code, and Copilot block repo text-search tools (grep/find/search_files) until
the session has consulted `memory_search`, with a deny reason that names the tool to
call and an explicit re-issue permission. Memory-first, never memory-only.

## Why

The framework tells agents to search memory first (`.hermes.md`/`CLAUDE.md`), but
nothing enforced it — grep-heavy agents never touch the memory bank. This change makes
the instruction mechanically true: one shared module, wired into every agent's existing
hook surface.

## What changed

- **Shared module** `features/common/skills/ai-raccoon-memory/scripts/memory_first_gate.py`:
  tool matchers (`search_files`/`Grep`/`Glob`/`grep`/`rg`, plus `bash`/`terminal` whose
  command's first token is `grep|rg|find|rg.exe` — piped grep in build steps passes),
  per-session consulted markers under `~/.ai-badger/memory-first/`, a 3-strike denial
  guard (pass-through after 3 so an agent cannot stall), `project_id` from the repo
  basename (env override `AI_RACCOON_PROJECT_ID`), and per-host deny builders.
- **Hermes**: the ai-badger plugin registers a new `pre_tool_call` hook
  (`pre_tool_call_memory_gate`); state is in-process keyed by project cwd and reset at
  session start (plugin callbacks carry no session_id — a documented gateway caveat).
  The consulted flag is recorded in `post_tool_observer`, reusing the single
  `memory_grade.is_memory_search` matcher.
- **Claude Code**: `hooks.json` PreToolUse matcher `Grep|Glob|Bash` →
  `memory_first_gate_hook.py` (timeout 10); the Bash arm inspects the command's first
  token itself. Scaffolded projects get the guarded command in `.claude/settings.json`.
- **Copilot**: `.github/hooks/ai-badger-hooks.json` gains a `preToolUse` entry with
  matcher `grep|rg|Glob|bash` (Copilot matches runtime tool names case-sensitively —
  the manifest arm now supports a per-agent `matcher` override, added to
  `schemas/hooks-manifest.schema.json`). The hook exits 0 on every path: Copilot
  command preToolUse is fail-closed, so a crash must never deny a tool call.
- **Recorder folded into `memory_grade_hook.py`**: the consulted marker is touched by
  the existing PostToolUse memory_search entry (unconditional), so Claude/Copilot run
  one process per search instead of two; a separate `--record` entry was rejected
  because the wiring's endswith filter cannot match a command with a trailing flag.
- **hooks-manifest.json** gains `memory-first-gate` naming all three agents; docs and
  the hooks-subsystem reference updated; ADR-0017 records the decision.

## Notes

- The instruction layer stays (`.hermes.md`/`CLAUDE.md` "Search memory FIRST" blocks and
  the pre_llm_call context injection) — it carries agents with no hook surface, e.g.
  Copilot's ephemeral cloud-agent jobs, where the per-session marker has no cross-job
  meaning.
- Existing sessions are unaffected until the plugin/scaffold is refreshed; run
  `den-refresh` to pick the gate up in an already-scaffolded repo.
