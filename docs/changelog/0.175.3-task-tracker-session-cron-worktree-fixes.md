# 0.175.3 — task-tracker: usage, cron marker, session conflict and worktree fixes

**Patch** — five independent fixes to the `/task` tracking surface. 2026-09-24.

## What was wrong

- **`finish` could zero out real usage.** If a task's own `transcriptPath` was empty (e.g.
  a resumed session that never got one recorded), `finish` computed an empty checkpoint
  from it and overwrote the populated `latest` checkpoint that `stop_hook`'s own periodic
  checkpointing had already recorded — reporting the task's usage as 0.
- **The resume cron marker was shared across every project.** `install-cron` and
  `uninstall-cron` used one fixed marker line for all projects on a host. Installing in
  project B silently rewrote project A's resume cron line, and uninstalling anywhere
  removed every project's line.
- **A session-conflict check could miss a real conflict.** `find_other_entry_with_session`
  returned only the first task row found on a session. If that row happened to be
  FINISHED, `start`/`reattach` let a second attachment through even when a later,
  still-active row shared the same session — the database's unique index then threw a
  traceback instead of the documented exit-2 refusal.
- **`dispatch_gate_hook.py` accepted `model: inherit`.** A lane declaring, or a dispatch
  passing, `model: inherit` counted as a declared model because it is a non-empty string —
  exactly the "inherit the session model" outcome the gate exists to deny.
- **A worktree path containing a space broke store lookup.** `_git_worktree_facts` parsed
  `git rev-parse --show-toplevel --git-common-dir`'s two-line output with a whitespace
  `.split()`, which mis-paired the toplevel and common-dir answers the moment either path
  had a space in it.

## What changed

- `is_empty_checkpoint` moved from `stop_hook.py` into `tracker_lib.py`; both `finish` and
  `stop_hook` call the one shared copy. `finish` now keeps a populated `latest` checkpoint
  (and computes usage against it) instead of overwriting it with an empty one.
- The cron marker is now hashed by project root (`# task-skill-resume:<hash>`). Installing
  or uninstalling in one project can no longer touch another project's line. A pre-hash
  legacy marker line is migrated on install, but only when its own log path names this
  project — never another project's legacy line.
- `find_other_entry_with_session` scans every task on the session rather than stopping at
  the first match; an unfinished match always wins over a finished one, so the conflict
  check sees the row that actually matters.
- `dispatch_gate_hook.py` treats `model: inherit` (any case) the same as an empty model:
  denied, whether it comes from an explicit dispatch parameter or a lane file's
  frontmatter.
- `_git_worktree_facts` now runs `git worktree list --porcelain` and parses it line by
  line — each `worktree <path>` line is read whole, so a path containing a space survives.
  The toplevel is the innermost listed entry the project sits under, which also fixes a
  task worktree (nested inside its own checkout) resolving to itself instead of being
  collapsed to the wrong ancestor.

## Upgrade notes

- Re-scaffold to pick up the scripts. Existing rows are not changed.
- A crontab installed by an older version still works; the next `install-cron` migrates
  its legacy marker line in place.
