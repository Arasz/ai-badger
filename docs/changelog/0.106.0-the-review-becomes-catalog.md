# 0.106.0 — the review becomes catalog

A wave of remediation lanes turned up the same two defects over and over. They are now framework
content rather than session memory: two invariants that every scaffolded project inherits, a
dispatch-brief reference beside the `task` skill, and a gate-authoring checklist beside the gates.

## Two invariants, not four

`features/common/invariants/prove-the-check-fails.md` — **a check you have not seen fail is not a
check.** The material behind it is roughly fifteen confirmed instances in this repo alone: a gate
log that was a previous run's artifact (0.88.2), a sync gate with no oracle (0.88.3), a meta-gate
blind to eight mutants (0.88.4) and separately blind to whether any gate is dispatched (0.99.0), a
`--no-install` test that asserted the path the previous fix had patched rather than the invariant
(0.90.1), an acceptance check that hashed only regular files while the bug wrote symlinks
(0.88.6), a test whose verdict depended on which branch you were standing on (`bb8004c2`), and two
that proved only that `assert False` raises (0.99.0).

It deliberately distinguishes itself from `tdd-mandatory`. TDD demands a red step; every one of
those tests had one. What was missing is red *for the reason the check was written*, re-proved
when the code beneath it moves — which is where the `--no-install` case failed, staying green
while the same leak moved one directory over.

`features/common/invariants/derive-or-delete-the-list.md` — **derive the list, or delete it.** Six
instances: three gate-name lists against the gates on disk, `verify.sh`'s `unset` line against
`badger_lib.GIT_LOCATION_ENV`, a hand-written allowlist of `git_env` copies, `REGENERATED_FEATURES`
against what is actually regenerated (deleted at 0.101.0), `SKILL_SCOPES`' 36 entries against 51
skills on disk (deleted at 0.104.0), and `docs/skills.md`'s counts against the catalog (0.90.0).
Both of the best fixes deleted the list, so the invariant leads with deriving and ends with
deleting rather than with adding a check.

Two candidates were rejected. *"I could not make it fail" is not "it cannot fail"* — demonstrated
at 0.103.0, where a lane concluded eight raw git calls were inert and the next lane found the one
environment variable that broke three of them — is the same epistemic move as the first invariant
and now closes its second paragraph. *Shipped and running are different claims* is already carried
by `proof-of-done` ("a run you watched"); its concrete instance, a gate no lane dispatches, is
rule 1 of the new gate checklist. Every invariant is rendered into every scaffolded project's
`CLAUDE.md` forever, so the bar for a fourth was not met.

## The lane dispatch brief

`features/common/skills/task/references/lane-dispatch-brief.md` — the prompt shape that ran this
wave, as a fill-in template plus a short note on why each part is load-bearing: verify the finding
before fixing it, evaluate the recommendation rather than execute it, paste the RED output, break
every gate you add, take the version assigned at dispatch, state the file-ownership boundary
including what is *not* owned, cap sub-agents and name their model, and report each acceptance
criterion with its evidence.

It lives beside the `task` skill, which already owns model delegation, and **not** in
`features/common/templates/` — see below.

## Indexed is not delivered

`docs/authoring-a-feature.md` gains a subsection recording the delivery split, because getting it
wrong produces exactly the defect the invariants above describe.

Skill directories ship on a **denylist**: `SkillDelivery.scaffold_skills` `copytree`s the whole
directory minus test/eval patterns, so `references/lane-dispatch-brief.md` reaches a scaffolded
project with no registration at all — the same way `references/file-schemas.md` already does.
`features/common/templates/` ships on an **allowlist**: `index_build._template_items` indexes every
top-level entry, but nothing iterates that list to copy anything. A templates file is delivered
only when a `features/<agent>/scaffolding.json` entry names it or a call site in `scaffold.py` /
`template_rendering.py` hardcodes it. Dropped in unregistered, it would have appeared in
`index.json` and nowhere else.

## Gate-authoring rules

`gates/README.md` — five rules with the mechanism that enforces each: dispatch it from a lane in
`verify.sh`'s `$LANES`; register a provocation in `tests/test_every_check_can_fail.py`; derive the
lists it compares; fail open on internal error when it gates a tool; prove it can fail before
trusting it. It stays in `gates/` rather than the catalog because three of the five name this
repo's own chassis. The two that generalise are the invariants above, which do ship.
