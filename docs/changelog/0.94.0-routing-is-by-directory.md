# 0.94.0 — one mechanism: a skill declares its own stack and its own scope

Documents only. No production code changes in this release; ADR-0018 records two owner rulings and
recommends an implementation that a separate lane will carry out.

## ADR-0005's revisit condition fired, and the owner ruled twice on what it exposed

ADR-0005 rejected declaring a skill's scope in `SKILL.md` frontmatter on exactly one cost, and
named its own trigger for reopening: *"Worth revisiting if anything else ever needs frontmatter at
build time."*

Seven readers now do. `skills_lint` rule 10 requires eight frontmatter keys on every catalog
`SKILL.md` and refuses a block it cannot parse deterministically; the scaffolder reads persona
`model:` lanes; the dispatch gate reads `model:` to deny an undeclared `Agent` call. The premise is
dead, and so is the specific fear behind it — a parse miss is now a reported violation, never a
silent pass.

Re-examining it found the catalog answering two questions about a skill in two different places:
**which stack owns it** (its directory) and **whether it ships unasked** (a 36-entry hand-kept
dict).

**Ruled: the project routes skills by stack directory.** Proved end to end — a config naming only
`stacks: ["dotnet"]`, with no `--skills` flag and no skill named anywhere, delivered all 11
`features/dotnet/skills/` skills. ADR-0005's rejection of directory-derived routing is superseded;
ADR-0010 is ratified rather than tolerated. `badger_lib.catalog_skills_for_stack`'s own docstring
already argued it — *"Membership here is the directory, not the scope, because that is what 'this
stack owns it' actually means"* — added after filtering by scope delivered an `optIn` skill and
linked it into no discovery directory (#261).

**Ruled: collapse to one mechanism.** A skill's directory says who owns it; a `scope:` key in its
own frontmatter says how it ships. `SKILL_SCOPES` is deleted, and a missing `scope:` becomes a
`skills_lint` failure.

[ADR-0018](../adr/0018-where-the-skill-routing-declaration-lives.md) records both rulings and the
implementation plan.

## The recommendation reversed, and the ADR says why

An earlier draft of ADR-0018 recommended keeping the constant, rejecting frontmatter on the
grounds that it "gives routing I/O, in the one code path whose failure mode is a skill silently
reaching nobody". Every clause of that was wrong, and the facts were available when it was
written:

- **No new I/O.** `skills_lint` already parses all 51 catalog `SKILL.md` files on every gate run
  and enforces five rules on the result — rule 2 already compares the frontmatter `name` against
  the parent directory. Those files are read anyway.
- **The dict never avoided the filesystem.** `default_skills_in` already calls `iterdir()` and
  stats a `SKILL.md` per entry. It filters a directory walk; it does not replace one.
- **Measured, the delta is noise.** 1.17 ms via the dict and a stat walk, **8.16 ms** reading and
  parsing all 36 frontmatter blocks — 20 iterations each, warm cache. A ~7 ms one-time import cost
  in the same release series that removed ~470 ms of `jsonschema` import (0.93.0, D1).
- **Routing is already the filesystem** for 15 of 51 shipped skills, and has been since ADR-0010.

The risk that argument invoked is real; it points the other way. **ADR-0005's guarantee gets
stronger under the collapse.** Today an undeclared skill is *silently not offered* —
`default_skills_in` and `opt_in_skills_in` both `.get()` and drop it — and the hard failure comes
from a test that diffs generated `index.json` and covers only the common stack. `skill_scope()`'s
`UnknownSkillScope`, the raise ADR-0005 credits, is called by nothing in production. A lint rule
fires at the point of authorship, under a glob that covers every stack, on a declaration that
cannot be separated from the thing it declares.

## Three of the review's figures did not survive checking

- `SKILL_SCOPES` holds **36** entries, not 39 — 14 `default`, 22 `optIn`.
- Removing the dict takes `engine/badger_lib.py` from 1032 lines to 991, against pylint's default
  limit of 1000. The `too-many-lines` disable buys **nine lines of headroom**, so it belongs to the
  module's size, not to ADR-0005 — measured with pylint, not estimated.
- `skill_scope()` and `default_skill_names()` have **no production callers**. ADR-0018 recommends
  deleting both rather than porting them: a raise nothing calls is the shape this review exists to
  find.

One framing is retired with them. The fifteen stack-local skills are routed by **presence in a
stack directory**, not by absence from `SKILL_SCOPES`. That clause is a guard against routing a
universal skill twice, and measured at 0.93.1 it excludes nothing.

## Two documents still described the old drift behaviour

0.91.0 changed what Tier 1 drift detection counts as drift. Two documents went on describing the
behaviour it replaced; both are corrected against the code at 0.93.1.

**[ADR-0001](../adr/0001-versioning-and-release-model.md) decision 5** said the check "prints one
line on mismatch and is silent otherwise". A new amendment records what is true now:

- The comparison is `versions_diverge`, which reads `(major, minor)` off each side and ignores the
  patch slot. `0.93.0` against `0.93.1` is silent; `0.93.1` against `0.94.0` still speaks. An
  unparseable version on either side falls back to string inequality.
- The hook can speak with **no version drift at all** — `competing_copies_notice` is emitted on its
  own when the idle `~/.ai-badger/framework` cache disagrees with the tree the session is running
  from.

What has not changed, and the amendment says so: two local reads, no network, silence on every
failure path.

**[hermes-claude-compatibility.md](../hermes-claude-compatibility.md)** carried the same stale
prose plus a working sample that got it wrong. Its `inject_drift_notice` example compared
`scaffold_ver != fw_version`, which is the behaviour 0.91.0 removed — anyone porting it would have
built a hook that nags on every patch release. The sample now carries the `(major, minor)`
comparison, duplicated inline the way the shipped Hermes hook duplicates it and for the reason that
hook's own comment gives, with a pointer to the test that pins the two spellings against each
other. The Option B cron prompt was fixed for the same reason.

## Behaviour changes worth knowing

None yet. Every change in this release is a document. The `SKILL_SCOPES` removal ADR-0018
recommends is a separate lane, and it will be a breaking change for anything reading
`badger_lib.SKILL_SCOPES` directly.
