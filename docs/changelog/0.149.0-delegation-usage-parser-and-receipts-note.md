# 0.149.0 — pi delegation tokens become real: `delegation_usage` parses the subagent log, and the task skill teaches receipts

The tracker's pi session source no longer reports "no token record" for
delegations. `pi_session_source.delegation_usage` parses
`~/.pi/agent/subagent-logs/<runId>.jsonl` — the R4 log format pi-badger-integration's
subagent extension writes — and returns the hermes-shaped record
(`totalTokens` = Σ input+output across assistant `message_end` events, cache
excluded for cross-source parity; `model` from pi's `AssistantMessage`;
`apiCalls` per turn; `at` = exit timestamp, else last turn's, else start).
A run counts as settled when an `exit` line **or** an `agent_settled` line is
present — TUI-aborted runs write no exit line, and their tokens are real
spend, so the exit-line-only policy the draft plan proposed would have
refused exactly the run that motivated it (review M1, witnessed by the
field-for-field d-1 fixture). `task_tracker.py subagent --delegation <id>`
now works under pi instead of refusing to record a fabricated number.

The second ledger item is the orchestrator-side half: the task skill's
Phase 3 now says interactive pi delegations return receipts by default,
the answer arrives as a `delegation-result` followUp carrying
`details.usage` (record input+output), and `background:false` is the
explicit blocking opt-out — with the detail carried in the uncapped
lane-dispatch brief and delegator persona, since SKILL.md sits at its
5,000-token lint cap (review M2). The adjustment's own docstring stops
claiming pi token tracking is unavailable.

## What changed

- **`features/pi/adjustments/pi_session_source.py`:** `SUBAGENT_LOGS_DIR`
  module constant; `_delegation_usage` — bare-filename-component guard
  against path traversal, tolerant line parsing (malformed JSON skipped
  individually, `tee-elided` markers and blank lines ignored), settled
  policy per the M1 ruling, `total == 0` → `None`; wired into
  `register()` replacing the `lambda: None` stub.
- **`features/pi/adjustments/adjust_task.py`:** docstring corrected —
  token tracking is available for pi sessions (S3).
- **Task skill (SKILL.md, lane-dispatch-brief.md, delegator.md):** the
  receipts migration note (ledger item 1) — receipt default,
  `delegation-result` followUps, `details.usage` (input+output; cache
  excluded for cross-source parity), `background:false` semantics, and
  `--delegation <receipt-id>` recording.
- **Tests:** T1–T14 in `tests/test_pi_adjustments.py` — happy path,
  lifecycle (unsettled/spawnError/zero-total), tolerance (malformed,
  elided, blank), guards (traversal sentinel, assistant-only, optional
  model), wiring end-to-end, the d-1 witness, and the `at` fallback chain.
