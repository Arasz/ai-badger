# 0.173.2 — exclusion resolution and engine robustness

**Patch** (behavior fix, no shape change) · 2026-09-24

## What changed

Seven `badger_lib`/`framework_copies` defects, all low severity, none previously
covered by a gate that had been seen to fail:

- **Excluding a skill-group member split the group** (L1-2). `exclusions()` never
  expanded `SKILL_GROUPS`, so naming `design-tests` in `config.exclude.skills` left
  `review-tests` delivered — the exact pairing SYNTHESIS.md ruling A says cannot
  work alone. Per owner ruling D9, `exclusions()` now expands groups the same way
  `include` already does: naming one member declines the whole group. Refusing the
  config was the alternative on the table and was not taken.
- **`inclusion_notes` resolved aliases and groups before checking exclude** (L1-3),
  so a name exclude had already blocked could still be reported as "resolved to
  gateway" or "delivered" instead of "exclude wins; not delivered". The exclude
  check now runs first.
- **A brand-new file written by `atomic_write_text` got mode 0600** (L1-4),
  because `mkstemp`'s restrictive default survived when there was no earlier file
  to preserve the mode of. A new file now gets `0o666 & ~umask`, matching what a
  plain `open(..., "w")` would have produced; an existing file's mode is still
  preserved exactly as before.
- **`recorded_root` crashed on a manifest of the wrong shape** (L1-5). Valid JSON
  that parsed to a list or a scalar raised `AttributeError` out of `.get()`,
  uncaught. It now falls through to the next candidate, like an unreadable or
  malformed manifest already did.
- **`is_breaking_transition` only detected upgrades** (L1-7). den-refresh calls it
  with `(config version, framework version)`, and a downgrade across a
  `BREAKING_VERSIONS` boundary reported `isBreaking: False` — despite `copy_skew`'s
  own rule that a downgrade across a boundary is exactly as dangerous as an
  upgrade. The two versions are now ordered before the boundary check, so the
  function is direction-agnostic. New boundary-case tests pin `0.8.0 → 0.7.0` as
  not breaking (landing on the boundary, not crossing it) against
  `0.9.0 → 0.5.0`, `0.7.0 → 0.6.0` and `0.6.0 → 0.7.0`, all breaking.
- **A non-UTF-8 `VERSION` file crashed the SessionStart drift hook** (L1-8).
  `framework_copies.read_version` caught only `OSError`; a garbled `VERSION`
  anywhere in the plugin cache raised `UnicodeDecodeError` out of `discover()`,
  whose docstring promises it never raises. It now also catches
  `UnicodeDecodeError` and reports `None`, like every other unreadable case.
- **`drift.py` and `skill_delivery.py` called `exclusions()` without gateway
  aliases** (L3-4). `Scaffolder` resolves a stale member name to the gateway it
  was absorbed into; `drift.project_exclusions` and
  `skill_delivery.relink_hermes_skills` did not, so a project that declined a
  gateway by its old member name saw the gateway reported as a new item on every
  refresh, and still linked into its Hermes namespace. Both callers now pass
  `bl.gateway_aliases(root)`.
- **Doc comments in `badger_lib.py` cited issue numbers** (L10-7, the
  `badger_lib.py` half — `badger_store.py`'s copies are out of this package's
  scope). Ten comments carrying a bare `(#nnn)` were reworded to keep their
  substance without the ticket reference, per the minimal-comments invariant.

`_note_exclusions` reports a declined group as one grouped note
(`bl.exclusion_group_notes`), not one "declined skill" line per member.

## Wiring

- `engine/badger_lib.py`: `exclusions()` expands `SKILL_GROUPS` before applying
  aliases; `inclusion_notes()` checks `declined` first; `atomic_write_text()`
  gives a new file the umask-adjusted default mode; `recorded_root()` also
  catches `AttributeError`; `is_breaking_transition()` orders the two versions
  before the boundary check; new `skill_group_for()` and
  `exclusion_group_notes()` helpers.
- `engine/framework_copies.py`: `read_version()` also catches
  `UnicodeDecodeError`.
- `features/common/skills/welcome-ai-badger/scripts/drift.py`:
  `project_exclusions()` takes `root` and passes `bl.gateway_aliases(root)`.
- `features/common/skills/welcome-ai-badger/scripts/skill_delivery.py`:
  `relink_hermes_skills()` takes an optional `root` and passes its aliases
  through.
- `features/common/skills/den-refresh/scripts/refresh.py`: its
  `relink_hermes_skills` wrapper now forwards the `root` it already has.
- `features/common/skills/welcome-ai-badger/scripts/scaffold.py`:
  `_note_exclusions` reports a declined group as one note.
- `tests/test_skill_groups.py`, `tests/test_config_exclude.py`,
  `tests/test_badger_lib.py`, `tests/test_breaking_versions.py`,
  `tests/test_framework_copies.py`: new coverage for each finding above, plus
  the direction-agnostic boundary cases.

## Upgrade notes

None. No config or manifest shape change; `relink_hermes_skills`'s new `root`
parameter is optional and defaults to the old (alias-blind) behavior for callers
that pass none.
