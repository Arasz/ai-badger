# 0.53.0 — entry titles carry their casing and 0.51.0's build order

Issue [#209](https://github.com/Arasz/ai-badger/issues/209). Generating the index from the
entry files ([#207](https://github.com/Arasz/ai-badger/issues/160)) made the index a faithful
view of each entry's `# ` H1 — and that faithfulness exposed two problems in the entries
themselves. Both fixes are data fixes: the generator keeps copying H1s verbatim, and only H1
lines changed — every entry body is a record and stays untouched.

## What was wrong

- **Casing.** ~26 entries used Title Case (`Directory-Content Hash Drift Detection`) or a
  capitalised first word against the repo's majority sentence-case convention, so the
  regenerated table read inconsistently. Six historical H1s were literally slugs
  (`hook-dedup-fix`, `dependency-check`, …), which is a filename, not a title.
- **0.51.0's ordering.** The generator sorts a version's entries filename-ascending — a
  deliberate property, so two branches regenerate the same row whichever lands first. But the
  hand-maintained table had carried the MCP rebuild's *build order*, step 1 (`mcp` becomes a
  catalog feature type) through step 8 (the legacy MCP reader is gone), and alphabetical
  scrambled it.

## What changed

- Title Case and capital-first H1s were rewritten to sentence case, with backticks around code
  identifiers. Slug H1s became prose titles derived from each entry's own body. Filenames are
  unchanged — links and tests that name them keep working.
- The eight ADR-0014 rebuild entries now carry the sequence in their titles
  (`MCP rebuild step N of 8: …`), taken from each entry's own opening line ("Step N of the MCP
  rebuild"). The row stays alphabetical and still communicates the order — one mechanism, no
  new ordering hint, as #209 preferred. The three 0.51.0 entries that are not rebuild steps
  are untouched by the prefix.

## Behaviour changes worth knowing

None in code. The index table was regenerated with `tooling/changelog_index.py`; anyone
linking to an entry by filename is unaffected.
