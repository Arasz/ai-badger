# 0.95.0 — the tooling layer reads the tree it was pointed at

Wave 3, lane L11 of the 2026-08-07 full-project review: items N1, N5, D6 and D4.

## N1 — `sync_plugin_skills --check` failed only under `git commit`

`tooling/sync_plugin_skills.py --check` reported

```
  shape unexpected scripts/__pycache__: task
  shape unexpected scripts/__pycache__/claude_session_source.cpython-314.pyc: task
  shape unexpected scripts/__pycache__/drift_notice_hook.cpython-314.pyc: task
  shape unexpected scripts/__pycache__/tracker_lib.cpython-314.pyc: task

4 of 15 skill(s) out of sync
```

when pre-commit ran it during a `git commit`, and `15 skill(s) in sync` when the identical
command was run by hand moments later in the same worktree.

**The mechanism.** `git commit` **inside a linked worktree** exports `GIT_DIR` (absolute, at
`<main>/.git/worktrees/<name>`) and an absolute `GIT_INDEX_FILE` into every hook's environment.
A plain checkout exports neither — measured, both cases, with an env-dumping `pre-commit` hook.
`_not_ignored_by_git` then ran `git -C skills/task check-ignore …`. With `GIT_DIR` inherited,
git stops discovering the repository by walking up from `skills/task` and instead uses the
exported gitdir with **the process cwd read as the work-tree root**. Git only reads `.gitignore`
files from the work-tree root downward, so the repo-root `.gitignore` — which holds
`__pycache__/` and `*.pyc` — was never consulted. `check-ignore` exited 1 ("nothing ignored"),
and `_not_ignored_by_git`'s `returncode == 1` branch faithfully returned every path as shipped
content.

`_outside_work_tree` could not catch it either: under the same `GIT_DIR`,
`git -C skills/task rev-parse --is-inside-work-tree` answers `true`.

Reproduced against the pre-fix file with `GIT_DIR`/`GIT_INDEX_FILE` set as a worktree commit
sets them, producing the four lines above verbatim; the same file with the variables unset
prints `15 skill(s) in sync`.

**The fix.** `badger_lib.run_git(args, cwd)` is now the one way this repo invokes git. It runs
`git -C <cwd> …` with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`,
`GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_PREFIX`, `GIT_NAMESPACE` and
`GIT_CEILING_DIRECTORIES` stripped, so the directory the caller named is the only thing that
decides which repository answers. All seven call sites in `engine/`, `tooling/` and `gates/`
were converted, and `tests/test_git_invocation.py` fails the build on a new raw
`subprocess.run(["git", …])` outside the helper.

This was not only sync's bug: `gates/scaffold_freshness_guard.py` shells out to git inside a
temporary copy of the tree, where an inherited `GIT_DIR` would have answered for the real
checkout.

## N5 — `catalog_stack_gaps` read the working tree

0.93.1 patched the symptom by skipping dot-directories. The cause was that the check enumerated
`features/` with `iterdir()`, so **any** untracked directory a session left behind failed
validation. `validate.candidate_stack_dirs` now reads
`git ls-tree -d --name-only HEAD features/`.

Measured in this checkout, with an untracked `features/ghoststack/skills.json` present:
`origin/main`'s `catalog_stack_gaps` reported it; this branch's reports nothing. A
*committed* `features/ghoststack` is still reported — `tests/test_catalog_claims_checkable.py`
builds a real git checkout and commits one.

**The dot-directory rule is kept, deliberately, and only on the fallback path.** Where `root` is
a checkout, `ls-tree` subsumes it completely: `features/.ai-badger/` is untracked, so it is not
a candidate, and `git ls-tree -r --name-only HEAD features/` lists no dot-prefixed path segment
at all (checked). Where git cannot answer — a fixture tree, an unpacked tarball — there is no
index to consult and the working tree is the only truth there is, so the leading-dot rule still
carries that case. Deleting it there would have regressed 0.93.1 for no gain.

## D6 — one frontmatter extractor

`engine/frontmatter.py`. `split(text)` returns a `Frontmatter(present, head, raw, body, entries,
well_formed)`; `head + body` is the original text, `raw` is what a caller hands a real YAML
parser, and each `Entry` keeps its key's lines verbatim so a folded block can be re-emitted
byte-for-byte.

Six call sites, previously four-and-a-bit disagreeing readers:

| Call site | Was |
|---|---|
| `engine/badger_lib.skill_description` | its own fence walk + `_folded_lines` |
| `tooling/sync_plugin_skills.render_pointer` | `text.split("---", 2)` |
| `gates/skills_lint.frontmatter_fields` | `validate._frontmatter_fields` + `duplicate_frontmatter_keys` |
| `welcome-ai-badger/scripts/template_rendering` | `frontmatter_fields` + `_frontmatter_end` |
| `features/claude/adjustments/adjust_agents` | `_split_frontmatter` + `_fields` |
| `features/copilot/adjustments/adjust_agents` | `_split_frontmatter` (keeps pyyaml for typed values) |

### The disagreements, and which answer was taken

Each was checked against the real 202-file corpus before choosing.

1. **Where a block opens.** Now: the first line, stripped, equals `---`. This widens
   `template_rendering`/`adjust_agents` (which demanded a literal `---\n`, so CRLF was invisible)
   and narrows `sync_plugin_skills` (whose `split("---", 2)` accepted a `---` anywhere, including
   a thematic break in the body). **Corpus impact: none** — no file uses CRLF, has leading blank
   lines before its fence, or has a body `---` preceding the real closing fence.
2. **Key grammar.** Now `[A-Za-z_][A-Za-z0-9_.-]*`, the widest of the three in use. **Corpus
   impact: none** — no top-level key starts with `_` or carries a `.`.
3. **A blank line inside a folded value.** `badger_lib._folded_lines` stopped there and silently
   truncated; now only the next top-level key ends a value. **Corpus impact: none.**
4. **Duplicate keys.** All four already resolved to the last value, as YAML does; kept, and
   `duplicate_keys()` still reports them for rule 11.
5. **Quotes.** `skill_description` unquotes an inline scalar; the other three keep the value
   verbatim. **Kept as it was** — 52 files carry a quoted `description`/`applyTo`, and the
   copilot adjuster hands `raw` to `yaml.safe_load`, which must see the quotes. Unquoting stays
   at the one call site that renders a value to a human.
6. **`>-` and `|-` block indicators — fixed, not preserved.** `template_rendering`'s
   `.lstrip(">|")` turned `description: >-` into a literal `-`, so
   `features/angular/personas/angular-engineer.md` produced the delegation-map line
   ``- `angular-engineer` — - Angular frontend implementer …`` (reproduced against the old
   function). The shared extractor treats `>-` as the block indicator it is. One persona
   affected; no other stack ships one.
