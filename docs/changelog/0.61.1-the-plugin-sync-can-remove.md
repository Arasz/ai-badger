# 0.61.1 — The plugin sync can remove, so `--check` can see a surplus

`tooling/sync_plugin_skills.py` mirrors the catalog's skills into `skills/`, the one
directory Claude Code reads a plugin's skills from (ADR-0008). Both `sync_all` and
`check_all` walked the shipped list and nothing else.

So a skill dropped from that list kept its directory. It stayed there, still discovered by
Claude Code and still offered to an agent, while `--check` counted the shipped names,
found them all present, and printed `13 skill(s) in sync`. The gate that exists to notice a
divergence was structurally incapable of seeing one, because it never looked at what was
actually on disk.

That is ADR-0005's omission failure turned inside out — a surplus rather than a gap, and
harder to notice for it. A missing skill is reported by the person who wanted it. A stale
one answers.

## What changed

`_orphans()` subtracts the shipped set from the directories actually present under
`skills/`. Sync removes them and says so; `--check` names each one and exits 1; `--dry-run`
reports without deleting.

`MANAGED_EXTERNALLY` now gates deletion as well as writing. Those four directories —
`debug-issue`, `explore-codebase`, `refactor-safely`, `review-changes` — belong to the
code-review-graph MCP server and are never in the shipped list, so a prune that subtracted
only that list would have deleted them on the next sync. There is a test for exactly that,
because the failure would have looked like a successful sync.

The `--check` help string said `.claude/skills/`, stale since ADR-0008 moved plugin skills
to `skills/`.

## Verified

Against the real tree, not only the fixtures: planting `skills/retired-probe` made
`--check` exit 1 naming it, `sync` removed it, and `--check` returned to 0.

Five tests added, no existing assertion changed. Suite 2553 → 2558.
