# 0.33.0 — ai-badger no longer installs a plugin that intercepts every tool call

**`semgrep` is removed from the python stack's default plugins.** Scaffolding a python project
no longer installs it.

## What it was doing

`features/python/skills.json` declared `semgrep` at `scope: default`, so
`welcome-ai-badger --execute` ran `claude plugin install semgrep@claude-plugins-official` for
every python project. That plugin — "Semgrep Guardian" — registers hooks on:

```
PreToolUse   matcher: Write|Edit|Bash
PostToolUse  matcher: Write|Edit|Bash
SessionStart, SessionEnd, PostToolBatch
```

behind a ~16 MB prebuilt Go binary (`hook-darwin-arm64`, `hook-linux-amd64`,
`hook-windows-amd64.exe`, …) and an MCP server named `guardian`. Strings in the binary include
*"Semgrep Guardian secures code Claude writes. You should be redirected to login to Semgrep
momentarily"*, `refreshOAuth`, and `xdg-open`.

The user-visible symptom that surfaced it: **a browser window opening to Semgrep's login on
`git commit`.** A commit is a `Bash` call, so the `PreToolUse` hook fires, finds no
authenticated session, and starts an OAuth flow.

## Why it is removed rather than made configurable

Static analysis is worth having. Interception is a different bargain: this plugin sees every
file write, every edit, and every shell command in the session, and wants an account on an
external platform before it will stop asking. ai-badger installing that **silently, as a
side effect of "scaffold my python project"**, is not a decision the framework gets to make on
a user's behalf — it is the same class as the consent gate added for dependency installation in
[`0.25.0`](0.25.0-hardening.md).

Anyone who wants it can still run `claude plugin install semgrep@claude-plugins-official`. What
changed is that ai-badger no longer does it for you.

## The guard, so this cannot happen again by accident

`tests/test_install_plugins.py::TestThirdPartyPluginsAreNotAddedSilently` pins the complete set
of externally-sourced plugins the catalog installs. Adding one now fails the suite until the
allow-list is updated — which makes it a deliberate act with a reviewer, rather than a line in a
JSON file nobody re-reads.

The remaining defaults were re-checked rather than assumed. `pydantic-ai` and `pyright-lsp` ship
**no hooks, no MCP server and no binaries** — markdown skills and a README. `superpowers` and
`pr-review-toolkit` are unchanged.

## Upgrading

Re-scaffold. If a previous scaffold already installed it:

```bash
claude plugin uninstall semgrep@claude-plugins-official
```

Nothing in ai-badger depends on it, and removing it needs no re-scaffold.
