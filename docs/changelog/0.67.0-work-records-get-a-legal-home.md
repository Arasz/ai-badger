# 0.67.0 — work records get a legal home

Two skills told agents to write their output to `docs/designs/`. That directory is not in the
canonical documentation tree, and it has never existed in this repository. When an agent followed
the instruction and found no such directory, it did what the instruction did not cover: it picked
a scratch path.

Two real owner review gates from 2026-08-01 ended up in `.tmp/` — gitignored, hidden, and
unreachable by ripgrep, which is what the default search of every agent working here is built on.
`scaffold-documentation/references/structure.md` names that exact failure: *"Prose in a hidden
directory — ripgrep skips it; the default search of every agent misses it."* The framework
shipped the rule and broke it.

## What changed

**The canonical tree exists.** `docs/` gains `tutorials/`, `how-to/`, `reference/`,
`explanation/`, `work/`, `assets/` and `meta/`, each with a README that is a complete map of what
sits beside it. `docs/index.md` becomes `docs/README.md` — the name every other directory in the
tree already uses, and the one a browser renders when you open the folder.

**`work/` is where dated records go.** `YYYY-MM-DD-slug`, grouped by nothing. Both review forms
moved out of `.tmp/` into it.

**Two skills stopped naming a directory that does not exist.** `owner-gate-review` and
`differential-feature-refactor` now write to `<docs>/work/`, read the docs root from
`.ai-badger/config.json`'s `docs.root`, and say explicitly that a missing `work/` is created
rather than worked around. Falling back to a scratch path is now named as the defect it is.

**`docs_guard` stopped freezing seven directories that do not exist.** `RECORD_DIRS` named
`design/`, `incidents/`, `plans/`, `research/`, `reviews/`, `specs/` and `archive/` — all deleted
in PR #111, all still listed. It now names `adr/`, `changelog/` and `work/`. A record's dead paths
are the record working; the gate could not grant that to a work record, because it did not know
`work/` was one.

## What did not change, deliberately

**The 38 records under `.tmp/docs/` stay untracked.** Git shows all seven of those directories
were deleted in PR #111, *"docs: trim docs/ to product documentation"* — a deliberate decision.
Restoring them would reverse it. Their fate is filed separately (#267) rather than settled here.

**`brand/` and `screenshots/` stay where they are.** `logo.svg` is the root README's header image
and `owner-gate-review.png` is linked from `docs/skills.md` and named in `.ai-badger/state.json`.
Freeze-list rule 2 makes re-placing a config-pinned path its own PR, never part of a migration.
Both are on the map with the reason stated.

**The seven root `*.md` files are not re-placed into quadrants.** That is a
`migrate-documentation` job, and several of the paths are pinned by `README.md` and
`CONTRIBUTING.md`.

`work/` is also deliberately narrow, and `docs/README.md` says so: a record belongs there while it
is still load-bearing, and leaves once its conclusions have landed in a quadrant page or an ADR.
It is a desk, not an archive. That is the distinction PR #111 did not draw — its assumption, that
a concluded record can live in git history, holds for a finished plan and not for an open review
gate whose verdicts are an input to work still in flight.

## Tests

`tests/test_docs_tree_is_canonical.py` is new: every canonical directory exists, every README is a
complete map of the files beside it, `RECORD_DIRS` names only real directories, and no review form
is left in a hidden directory. Its last class asserts each check can actually go red.

`tests/test_docs_guard.py::test_a_record_document_keeps_link_checking_but_not_path_checking` was
**rewritten** — it exercised `docs/plans/`, one of the seven directories deleted in #111, so it
was proving the freeze worked for a path nothing could reach. It now uses
`docs/work/2026-01-15-plan.md`. A new sibling,
`test_a_deleted_record_dir_is_no_longer_frozen`, asserts the opposite half: a path claim under
`docs/plans/` is now ordinary rot and is flagged.
