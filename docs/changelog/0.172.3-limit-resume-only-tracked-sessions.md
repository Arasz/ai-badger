# 0.172.3 — usage-limit resume only reaches tracked sessions that have stopped

**Patch**: fixes in the `task` skill's usage-limit resume scripts. 2026-09-24.

## Fixes

Three defects in `features/common/skills/task/scripts/` could resume the wrong session with
`claude --resume <id> -p … --permission-mode acceptEdits`:

- **`poll_limit.py` read the wrong store.** Discovery read the legacy `executed-tasks.json`,
  but tasks live in `tracking.db` (ADR-0024). A tracked `IN_PROGRESS` task was invisible, so
  the poller either idled out or fell through to the transcript fallback. It now reads tasks
  through `tracker_lib.load_tasks()`, the same call `task_tracker.py` makes.
- **The `~/.claude/projects` fallback resumed sessions nobody asked for.** It skipped a
  record whose `cwd` did not match and still returned the file's stem, so a transcript from
  another repository became a resume target. So did every past session of this project. The
  fallback is removed: no `SKILL.md`, doc or ADR relied on it. The poller now resumes only
  sessions of unfinished tasks that `/task` tracks.
- **`resume_cron.py` resumed live sessions.** A task counted as stalled once its transcript
  had been quiet for 25 minutes. An idle interactive session writes nothing, so it was
  resumed in parallel with itself. The cron now also checks the pid recorded in the
  `sessions` table.

The poller applies the same pid check. A task whose session is still alive still counts as
unfinished work, so the poller keeps watching it, but never resumes it.

## Changes

- `tracker_lib.live_session_ids()` returns the ids of recorded sessions whose pid answers a
  signal-0 probe (`os.kill(pid, 0)`, which works on Linux and macOS). Both resumers use it.
- `poll_limit.discover_target_sessions()` and `_has_unfinished_task()` take no arguments
  now. The tracking store already knows which project it belongs to.

## Upgrade notes

- No action required. A refresh picks up the new scripts. A poller that is already running
  keeps the old code until it exits (it stops at its 12h cap). Stop it sooner with
  `kill $(cat .ai-badger/task-tracking/poll_limit.pid)`.
