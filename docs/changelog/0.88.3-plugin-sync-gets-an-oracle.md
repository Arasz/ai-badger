# 0.88.3 — the plugin-sync gate gets an oracle

`tooling/sync_plugin_skills.py --check` could not detect a bug in itself. It built its
**expected** value by calling `render_into` — the same function that produced the **actual**
value — so any renderer defect was green by construction. Measured against the shipped tree,
with the declared source of the `task` skill's session reader moved out of the way:

```
after source vanishes, rendered copy has session source: False
check_skill(src, that_copy) = None          <- reports IN SYNC
shape_violations = []
```

`_ship_extra_files` silently no-opped on a missing source (`if src.is_file():`), so renaming
`features/claude/adjustments/claude_session_source.py` would have shipped the `task` skill with
no session source at all — the exact outcome the code's own comment says must not happen — with
every gate still passing.

Three changes close it.

**`_ship_extra_files` raises.** `PLUGIN_EXTRA_FILES` is a repo-internal declaration, not user
input: a source that is not on disk is a bug in the declaration, not a condition to skip past.

**`check_all` asserts the declaration directly.** `extra_file_violations` reads
`PLUGIN_EXTRA_FILES` and checks each target is present in the shipped copy. It never renders, so
a renderer that stops shipping a declared file is caught by something the renderer cannot move.

**The shape check reaches every depth.** `shape_violations` compared `iterdir()` entry names, so
it stopped one directory down. `SKILL_EXCLUDE_PATTERNS` (`tests`, `test_*.py`, `evals`,
`__pycache__`, `*.pyc`, `.DS_Store`) makes those files invisible to the content hash — the blind
spot the shape assertion was added in 0.87.1 to close — and 20 nested directories ship today:

```
top-level  evals/               check: None      shape: ['unexpected evals']   <- caught
scripts/tests/payload.py        check: None      shape: []                     <- INVISIBLE
```

It now compares `rglob("*")` relative-path sets. A file at `skills/task/scripts/tests/x.py` is
reported as `shape unexpected scripts/tests/x.py`.

## The test that proved nothing

`tests/test_shape_violations.py::test_check_all_flags_a_shape_violation` was the only test
connecting the shape loop to `check_all()`, and the whole loop could be deleted from
`check_all()` with the suite green. Its fixture deleted `dest/SKILL.full.md`, which also trips
`check_skill`, and it pointed `TARGET` at the fixture's parent directory, so every sibling
counted as an orphan — the `1` it asserted had two other sources.

It is rewritten as `test_check_all_flags_junk_the_content_hash_cannot_see`: the shipped copy
keeps a nested `__pycache__/*.pyc`, which leaves `check_skill` returning `None`, so only the
shape path can fail the gate. It asserts `check_all() == 0` on the clean copy first, so the
control and the signal are both pinned.

`tests/test_every_check_can_fail.py`'s sync provocation now builds its miniature framework tree
around `prompt-markers` rather than `task`: `task` is the one skill with a `PLUGIN_EXTRA_FILES`
declaration, which a two-file tree cannot satisfy, and the content divergence that provocation
is about has nothing to do with that declaration.

## Verified

Five mutants applied to a scratch copy, run, and reverted — all killed:

| Mutant | Killed by |
|---|---|
| `_ship_extra_files` silently skips a missing source | `test_render_into_refuses_a_declared_source_that_is_absent` |
| `check_all` drops the declaration-derived assertion | `test_check_all_catches_a_renderer_that_stops_shipping_a_declared_file` |
| `shape_violations` compares `iterdir()` names again | `test_a_nested_entry_the_content_hash_ignores_is_reported` |
| `check_all` drops the shape loop | `test_check_all_flags_junk_the_content_hash_cannot_see` |
| `shape_violations` drops the missing-destination return | `test_a_destination_that_was_never_synced_is_check_skills_report_not_ours` |
