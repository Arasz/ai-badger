# 0.145.0 — pi PostToolUse arm: memory_search actually unlocks text search

The pi adapter ran only the PreToolUse arm, so the memory-first gate denied repo text
search on **every** call in pi, forever: the consulted marker that unlocks it is recorded
by a PostToolUse hook, and pi never ran one. Verified live before the fix (three denials
in one session, zero marker files, zero denial counters — the 3-strike pass-through was
dead too, because it counts per session id and pi's payloads carried none). Verified live
after: grep denied → `memory_search` (no hits) → re-issued grep allowed on the marker.

## What changed

- `features/pi/adjustments/adapter/index.ts` registers `pi.on("tool_result", ...)` — the
  pi twin of Claude's PostToolUse marker recording. It runs the project's
  `.ai-badger/hooks/hooks.json` **PostToolUse** entries (marker recorder, memory
  telemetry) after every tool result, advisory only: failures are warnings, the tool
  result is never modified, and there is deliberately no action key to block with.
- `hook-bridge.ts` gained the post-side pure layer: `postToolUseCommands` (collected from
  the same hooks.json, never a second gate list), `toClaudePostPayload` (the five pre keys
  plus the result under `tool_response`/`response`, the spellings the shipped grade hook
  reads), `resolvePost` (notices only) and `resolveSessionId`.
- **Session ids are real now.** Payloads carry pi's own session id via
  `ctx.sessionManager.getSessionId()` (falling back to `PI_SESSION_ID`, then empty). The
  pre arm and the post arm always carry the same id — the marker the post arm records is
  looked up by the pre arm — which also brings the 3-strike pass-through to life in pi.
- **pi's MCP tool-name spelling is understood.** pi delivers `mcp_<server>_<tool>` with
  single underscores (verified live: `mcp_ai-raccoon_memory_search`), where Claude uses
  `mcp__server__tool`. Both `memory_first_gate.is_memory_search` /
  `memory_grade_hook._is_memory_search` and the bridge's post matcher now match the
  memory_search tool as a trailing underscore-joined segment of either spelling — a server
  name may itself contain underscores, so there is no fixed suffix. Anchor semantics are
  unchanged (`memory_search` still does not match `memory_search_extra`).
- `loadGates` returns both arms (`pre`/`post`); the contract test
  (`tests/test_pi_hook_arm_coverage_contract.py`) now pins the stamp↔loader correspondence
  for **both** families and requires the `tool_result` subscription to exist — a vanished
  post arm would put pi back to deny-forever.

## Why

ADR-0017's gate is "memory-first, never memory-only": it must be escapable by consulting
the bank. On pi it was not — the instruction layer was the only working escape, and the
3-strike guard could not rescue a session whose id never reached the hook. The post arm
closes the loop with the same scripts the other hosts already run; no new hook surface was
invented (D1's dynamic reader now serves both arms).
