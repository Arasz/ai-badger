# 0.45.0 — A Project Can Raise the Agent-Doc Size Budget

**Date:** 2026-07-29

## Added

- **`agentDocs` in `config.json`** (`schemas/config.schema.json`): optional `maxChars` / `maxLines`
  override for the agent discovery-file budget the task skill's stop hook enforces. Defaults are
  unchanged (12000 / 110), so a project that omits the key behaves exactly as before.
- **`tracker_lib.doc_budget()`**: resolves the effective budget from config, falling back to
  `CLAUDE_MD_MAX_CHARS` / `CLAUDE_MD_MAX_LINES`. `doc_stats()` now reports the resolved values, so
  `over_budget_docs()` and every caller honour the override.

## Why

The budget is charged to the project, but the files it measures are generated by ai-badger. A
project with an ordinary configuration — 11 invariants across common plus five stacks — renders a
124-line `CLAUDE.md` against the 110-line limit, of which 56 lines are the invariant section alone.
Characters were well inside budget; only lines breached. None of it was project-authored, so the
hook's advice ("drop anything derivable from code/git/docs") had nothing to act on, and the only
project-side levers were editing a generated file (reverted at the next re-scaffold) or declining
invariants to satisfy a line count.

## Changed

- The stop hook's over-budget message now states that these files are generated — edits to them do
  not survive a re-scaffold — and names the three levers in escalating order: shorten the source
  under `.ai-badger/`, decline catalog items via `exclude`, or raise `agentDocs`.

## Notes

A malformed override never widens the budget: non-integer, zero, negative, boolean, wrong container
type and unparseable config each fall back to the default, so a typo cannot silently disable the
gate. A `config.json` whose top level is not an object falls back too — `load_config` returns
whatever parses, so a list would otherwise reach `.get()` and take the stop hook down with it, and
a hook never breaks a session ([0.34.1](0.34.1-a-hook-never-breaks-a-session.md)).

Two of those guards were unpinned when this landed: removing either the `isinstance(value, bool)`
check or the `isinstance(config, dict)` check left the whole suite green. `true` is an `int` in
Python and `true > 0`, so a boolean override would have been honoured as a budget of 1. Both now
have tests verified to fail when their guard is removed — a fail-safe nobody can break by accident
is the only kind worth claiming.
