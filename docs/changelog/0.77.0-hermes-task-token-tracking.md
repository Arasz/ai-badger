# 0.77.0 — Hermes task tracking gathers real token data

The `/task` skill's tracker recorded all-zero checkpoints under Hermes: it resolved sessions
only from `CLAUDE_CODE_SESSION_ID`, parsed only Claude JSONL transcripts, and recorded subagent
tokens only by hand. Hermes stores the same numbers in `~/.hermes/state.db`, so the tracker now
reads them.

The hermes data path is agent-specific, so it ships where this project puts agent-specific
code: `features/hermes/adjustments/hermes_session_source.py`, installed by the hermes
adjustment into the scaffolded `.ai-badger/skills/task/scripts/hermes_session_source.py`. The common
task skill scripts stay generic — they gain a small session-source registry
(`register_session_source` / `session_source` in `tracker_lib.py`); the installed hermes
module registers itself through it, and the claude adjustment installs its own
`claude_session_source.py` the same way. No agent is built in. A claude-only scaffold
never sees the hermes module or the `--delegation` data path.

- `resolve_own_session()` asks every registered source in registration order; the first
  source that resolves wins. The hermes source registers `HERMES_SESSION_ID`, the claude
  source `CLAUDE_CODE_SESSION_ID` — no env var is special.
- The hermes source module maps the Hermes store onto the existing checkpoint shape:
  `sessions` → cumulative tokens (folding one level of delegated child sessions, whose rows
  the parent excludes), `session_model_usage` → per-model breakdown (accumulated across the
  composite-key task rows), `messages` → assistant-message count, `async_delegations` →
  dispatch count. `contextTokens` stays 0 — Hermes stores no per-message tokens
  (`messages.token_count` is NULL on every row) and no context-window snapshot; an honest
  zero beats a fabricated estimate.
- `task_tracker.py start` records `trackingSource` so `finish`/`reattach` (later processes)
  pick the same checkpoint maker; `resumeCommand` comes from the session source
  (`hermes --resume <id>` under Hermes, `claude --resume <id>` by default).
- `subagent --delegation <id>` reads a completed delegation's real tokens from
  `async_delegations.result_json` instead of a hand-typed count — the live `delegate_task`
  return exposes no token count. Mutually exclusive with the manual `<total_tokens>`
  argument; a session source that records no delegation tokens refuses cleanly.
- Reads are read-only (`sqlite3` `mode=ro`): the tracker never writes, locks, or creates the
  Hermes store, and degrades to zeroed checkpoints when Hermes is absent — it never crashes a
  session over missing data.

Fixes the premise behind the `tooling/validate.py` exemptions (which claimed Hermes produces no
session data the tracker could parse). A Hermes plugin hook for automatic per-turn checkpoints
remains an optional future extension; the in-session CLI path is what the `/task` skill drives.
