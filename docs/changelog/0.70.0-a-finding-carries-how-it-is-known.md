# 0.70.0 — a finding carries how it is known

Checked across 177 installed skill descriptions: none owns *findings with provenance*. Zero
descriptions contain the word "research". The five existing report producers emit decisions,
sequences or rubric scores — none says what we found, how we know it, and what stayed open.

`evidence-first-research` fills that gap. `optIn`.

## Why the grading is enforced, not encouraged

A report where *"the gate takes 75 seconds, measured"* and *"the gate takes about five minutes,
roughly"* look identical is a report that gets quoted wrong.

That happened in this repository. A cost claim of "3-5 minutes per push, about an hour across
fifteen pushes" reached a changelog **and** a PR body. Measured, it was 75 seconds and nineteen
minutes — off by four times. It was caught only because someone re-derived it by hand. Nothing in
the format made the unmeasured number look unmeasured.

So `scripts/render_report.py` **refuses** a record rather than rendering a page that looks
finished:

- a finding whose claim carries no grade
- a grade outside the closed set — `[PROBABLY]` fails loudly instead of becoming a fifth grade
- a `MEASURED` or `READ` finding with no `**Evidence:**` line

A clean render is therefore itself a check.

## The four grades

`MEASURED` you ran it · `READ` you read it in an authoritative source · `INFERRED` you reasoned
to it · `UNVERIFIED` you did not check.

The grade records **your relationship to the claim, not the claim's truth**. A number someone else
measured and you copied is `READ`. If you cannot cite where you read it, it is `INFERRED`.

`UNVERIFIED` deliberately requires nothing. Every requirement attached there makes silence cheaper
than admission — and an unverified claim that simply does not appear reads, to the next reader, as
one nobody had a concern about. That is the failure the whole format exists to prevent.

`references/provenance.md` carries the disqualifying conditions for each grade and the
downgrade-never-delete rule.

## The record is the artefact; the HTML is a view

The markdown record goes to `<docs>/work/YYYY-MM-DD-<slug>.md` — the dated-work home 0.67.0
created. `render_report.py` writes the HTML to a temp directory and **refuses any target inside
the repository**: a committed view becomes a second source of truth, and within a month nobody can
say which one is current.

Five chart kinds — `provenance`, `bars`, `line`, `matrix`, `range` — render as inline SVG. No
network, no scripts, no external hosts at all: the `xmlns` attribute is deliberately omitted,
because HTML5 supplies the namespace for inline SVG and dropping it keeps the "no external host"
check a plain substring test rather than one carrying an exception a later reader must trust.

`provenance` is drawn first and always, including grades with zero findings. Ten findings with one
`MEASURED` and nine `INFERRED` is a hypothesis; the same ten mostly `MEASURED` is a finding. Same
conclusion, same word count, entirely different thing to act on.

`range` is preferred over `bars` for timings — a single bar asserts a precision three runs will not
support, and the spread is usually the interesting part.
