# 0.82.0 — ai-raccoon catalog: HTTP serve mode + migrated package id

## What changed

- `features/common/mcp/ai-raccoon/meta.json`: the catalog still taught the retired
  NuGet id `arasz.ai-raccoon` (migrated to `ai-raccoon` in the tool's v1.0.9). The
  package id and the documented install command now match the shipped id, and the
  description teaches the new HTTP serve mode.
- `features/common/mcp/ai-raccoon/server.md`: new HTTP-mode guidance — run
  `ai-raccoon serve` once, then `hermes mcp add ai-raccoon --url
  http://127.0.0.1:7721/mcp` for one long-lived process instead of the ~5-min stdio
  recycle; the 4h idle watchdog and the attach semantics (a second `serve` points at
  the running server). The `.mcp.json` command declaration stays stdio by design:
  `serve` never answers JSON-RPC on stdout.
- New contract test pins the migrated package id so the 1.0.9 drift cannot return.

## Scaffold impact

The seven agent-instruction files (CLAUDE.md / HERMES.md / .hermes.md /
copilot-instructions variants) regenerate with the new server.md section — a
re-scaffold is recommended for consumer repos (den-refresh does it).
