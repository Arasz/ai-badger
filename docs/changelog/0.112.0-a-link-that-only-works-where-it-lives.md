# 0.112.0 — a link that only works where it lives

0.110.0 rewrote the `clean-architecture-layering` invariant's enforcement paragraph, because the
ArchUnitNET rule it recommended can pass without ever being able to fail. That rewrite ended with
a markdown link:

```markdown
[prove the check fails](../../common/invariants/prove-the-check-fails.md)
```

The link is correct where the file lives. `validate.py --all` agreed — its `cross-stack
references` check resolved the path against `features/dotnet/invariants/` and passed.

It is wrong everywhere the text actually gets read. Invariant bodies are **inlined into the
generated agent files**, which sit at the consumer's repo root, and from there
`../../common/invariants/...` points outside the repository. A project that refreshed to 0.110.0
took the broken link into its `CLAUDE.md`, `HERMES.md`, `.hermes.md` and
`copilot-instructions.md` — four copies, all dead.

Replaced with a plain-name reference to the `prove-the-check-fails` invariant. There is no link
left to rot.

## The validator cannot catch this

`cross-stack references` checks paths where a file **lives**. Nothing checks them where the file's
text **ends up**, and for invariants those are different directories by construction. Every
invariant using a relative markdown link has the same defect, and it will pass validation.

That is not fixed here — it needs a check that resolves an invariant's links from the scaffold
target rather than from `features/`, which is a larger change than this entry. It is worth naming
plainly in the meantime: a validator that passes on a broken link is the same shape of problem the
invariant it validates is about.

## Also

The same section is tightened from 48 lines to 38, keeping both ArchUnitNET failure modes and the
reference-allowlist recommendation. This is housekeeping, not a fix — 0.111.0 established that the
default doc budget was unreachable by the generator's own floor, so the overage those extra lines
contributed to was never this invariant's doing.
