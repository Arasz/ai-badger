# 0.35.1 — all hooks instrumented with debug_log

The 5 hooks that were not calling the `debug_log` audit logger now do.

## What changed

Every hook in the framework now emits `debug_log.log_event()` calls at its
decision points — skip paths, fire paths, and checkpoint/block events. The
logger is a no-op unless the `call-behaviorist` skill enables it, so there
is zero cost in normal operation.

### Newly instrumented hooks

| Hook | Component | Events |
|---|---|---|
| prompt-markers/user_prompt_hook | `prompt_markers_hook` | `skip` (no prompt, no match), `fire` (marker matched) |
| task/drift_notice_hook | `drift_notice_hook` | `skip` (no root, no drift), `fire` (drift notice emitted) |
| task/session_start_hook | `session_start_hook` | `start` (session recorded), `skip` (no session id) |
| task/stop_hook | `stop_hook` | `skip` (no session id), `checkpoint` (token updated), `block` (stop blocked) |
| task/user_prompt_hook | `task_user_prompt_hook` | `skip` (no task/session), `register` (task registered) |

A vendored `debug_log.py` was added to `skills/task/scripts/` and
`skills/prompt-markers/scripts/` (same pattern as `commit-reminder`).

## Migration

Nothing required. The debug logger is off by default.
