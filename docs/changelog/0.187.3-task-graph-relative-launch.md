# 0.187.3 — task-graph starts in Claude Code again

**Patch** (scaffold-affecting) · 2026-10-03

## What changed

- `features/common/stack-mcp.json` no longer gives Claude its own task-graph launch. Claude's
  `.mcp.json` entry is now the same project-relative launch Copilot already used:
  `uv run --script .ai-badger/skills/task-decomposition/scripts/task_graph_server.py`.
- The removed override anchored the script path on `${CLAUDE_PROJECT_DIR}`. Claude Code sets
  that variable for hooks only. When it expands `.mcp.json` it reports
  `Missing environment variables: CLAUDE_PROJECT_DIR` and passes the text through literally, so
  uv was handed `<cwd>/${CLAUDE_PROJECT_DIR}/.ai-badger/...` and the server failed with
  `CONNECTION_CLOSED`. That was measured on Claude Code 2.1.288. In the MCP logs of three
  scaffolded projects, no interactive session ever connected with the anchor. The only
  connections came from headless runs whose parent process had already exported the variable.
- The bug arrived with 0.179.0. Between 0.180.0 and 0.184.0 it was hidden in pi-configured
  projects, because `.mcp.json` carried the anchor-free launch for pi's sake. 0.184.0 moved pi
  to `.pi/mcp.json`, and the anchor came back.

## Behaviour changes worth knowing

- **Start Claude Code at the project root.** Claude Code spawns MCP servers in the session's
  working directory, and a session started in a subdirectory still reads the root `.mcp.json`.
  The relative path only resolves from the root, which the task-graph prerequisite note
  already states. A root-finding launch is a separate follow-up.
- Consumers pick up the fix on their next den-refresh. Until then, change the arg in
  `.mcp.json` to the relative path and reconnect.
