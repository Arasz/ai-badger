# 0.210.3 — The memory gate's footer status, counted right

**Classification:** Patch
**Date:** 2026-10-20

## Fixes

- **The footer share is a percentage.** The segment read `[mem 12 9/12%]` — a fraction
  wearing a percent sign. It now reads `[mem 12 75%]`: the number of captured searches and
  the share of them the agent fetched, rounded.
- **The counters follow the session.** The adapter's factory outlives a session — `/new`,
  `/resume`, `/fork` and `/clone` re-fire `session_start` on the same instance — so the
  counters start over with the session. Before, a session that captured nothing republished
  the previous session's numbers on its first tool call.
- **A fetch is counted when the retrieval ran.** A raw-result retrieval that another gate
  denied, or that the user declined at the prompt, fetched nothing and is no longer counted
  as a fetch.
- **A fetch counts once, and only for a ready answer.** The counter watched the command, not
  the answer: a `pending` retrieval (the skill's cue to retry), an expired or failed one, and
  a second read of the same handle all counted as fetches. A fetch now counts once per
  captured handle, and only for a ready answer — and only for a handle the gate captured, so
  the percentage stays a share of what was captured.

## Changes

- The vendored pi adapter carries the corrected counters. Canonical source:
  [Arasz/pi-badger-integration](https://github.com/Arasz/pi-badger-integration) (pull request
  #83), vendored with `bun publish.ts --ai-badger`.

## Upgrade notes

None: the footer segment's shape changed once (`[mem 12 9/12%]` → `[mem 12 75%]`), and
nothing else does.
