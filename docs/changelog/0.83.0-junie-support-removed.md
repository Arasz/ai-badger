# 0.83.0 — Three agents, not four

Junie (JetBrains) support is removed. ai-badger now scaffolds exactly three agents:
`claude`, `copilot`, `hermes`.

## Why

The owner does not use Junie, and there is no capacity to maintain a fourth agent
surface. Removing it is one deliberate catalog change rather than a slow rot of an
unmaintained path (see `docs/adr/0016-junie-support-removed.md`).

## What changed

- `features/junie/` deleted (scaffolding.json, adjustments, templates, plugin
  instructions); `tests/test_adjust_skills_junie.py` deleted.
- `AGENT_NAMES` in `engine/badger_lib.py` is now `["claude", "copilot", "hermes"]`.
- Agent enums in all six schemas (`agents`, `config`, `manifest`, `skills-source`,
  `stack-mcp`, `support`) no longer accept `junie` — a project config naming it now
  fails validation.
- Catalog and support matrix entries removed (`index.json`, `features/common/support.json`).
- `detect.py` no longer detects `.junie/` traces; `scaffold.py` / `agent_files.py`
  no longer write `.junie/AGENTS.md` or symlink `.junie/skills/`.
- `JUNIE_HOOK_EXEMPTION` removed from `tooling/validate.py` and its test deleted.
- Tests and live docs updated to the three-agent scope; a regression test
  (`tests/test_three_agent_scope.py`) pins `AGENT_NAMES`, detection, and schemas.
- Existing `.junie/` directories in already-scaffolded projects are left untouched —
  the framework stops generating and validating junie but does not delete user files.
- Historical changelog entries mentioning Junie (0.7.0, 0.34.0, 0.47.0, 0.50.0, …)
  are kept as release records.
