# 0.196.0 — memory-first gate: each grep pattern is memory-searched first

**Minor** (behaviour change) · **Date:** 2026-10-18

The memory-first gate let `sed -n 50,95p f; echo '---'; grep -n "def merge_hooks\|append" g | head`
through: it read only the first word of a Bash command, and one unrelated `memory_search`
unlocked every later grep for the session. It now keys on the search pattern.

- A text-search call (grep/egrep/fgrep/rg/find in any segment of a shell command, or a
  Grep/Glob/search_files tool) passes only when every pattern it searches for was already
  memory-searched for the project, and a shell command ends with the trailing comment
  `# memory-checked`. Grep/Glob/search_files carry no command and need only the search.
- The first sighting of a pattern is denied and the hook runs one ai-raccoon search for it
  (4 s budget); the hits come back in the deny reason and the pattern is recorded. When no
  search can run (no `ai-raccoon`, no project id, timeout) nothing is recorded and the reason
  asks for a `memory_search` with the pattern. An agent's own `memory_search` records its query:
  a pattern contained in it counts as searched.
- Searched patterns persist per project (`hook_state` row `memory_first.searched.<project_id>`,
  file fallback `~/.ai-badger/memory-first-searched/<project_id>`) and are never reset; Hermes
  uses the same store and session start clears nothing.
- Removed: the session-wide unlock, the 3-denial pass-through (`MAX_DENIALS`) and Hermes's
  per-process gate state.
- New `memory_context.search_block`: one ungated search with a single budget; `build()`
  delegates its single-search path to it.

## Upgrade notes

- A piped grep (`git log | grep fix`) is now gated like any other: search memory for the
  pattern, then add `# memory-checked`.
- See ADR-0017's 0.196.0 amendment for the full rule.
