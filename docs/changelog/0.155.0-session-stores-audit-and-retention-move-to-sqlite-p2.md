# 0.155.0 — session stores, the hook-audit collapse, and retention move to SQLite (P2)

The remaining session-scope runtime state migrates into the store (P2 of the 0.152.0
runtime-store migration; ADR-0024): the memory-first/semantica-nudge/dispatch-lane/dirty-sweep/
blast-radius surfaces, and the debug audit log itself. On top of the migration, the three log
tables gain their promised 60-day retention (D30), and the store grows a read-only CLI verb to
inspect it.

## What changed

- **Session-store schema live.** `memory_first` (denial count as a real column — the gate
  filters on it), `semantica_nudge`, `dispatch_lanes`, `dirty_sweeps` (keyed by the sha1 of the
  main checkout root — all worktrees of a repo share one record, as the warning is repo-wide),
  `blast_radius_denials`, plus `hook_audit` + `hook_state` in the audit sink's own DB file.
  Multi-file families import as one transaction and rename per file, so a crash mid-import
  resumes without duplicates; the legacy directory itself is never renamed or removed (a stale
  surface may keep writing there).
- **The hook-audit collapse.** Six full `debug_log.py` copies become one canonical writer
  (`features/common/hooks/debug_log.py`); the five skill-dir copies are byte-pinned thin shims
  that execute the canonical into their own namespace, so hooks, scaffolds and the plugin-cache
  mirror all run one implementation. The audit sink is its own DB file (`audit.db` beside the
  debug directory); the `$AI_BADGER_DEBUG_DIR` contract moves the whole sink, unchanged.
- **60-day retention (D30).** Every write to a log table is a throttle-armed prune opportunity:
  the timestamp check, the `DELETE`, and the `pruned_at.<table>` stamp share one
  `BEGIN IMMEDIATE` (no check-then-act window), prunes run at most once an hour per table, and
  a broken store fails open as a no-op — maintenance never blocks a hook. `hook_audit` joins the
  `awm_decisions` prune from 0.153.0. Rows whose `ts` never parses (empty, corrupt, an
  ISO-looking month 13) are swept in the same transaction: they could never satisfy any future
  cutoff, so string comparison alone left them immortal.
- **`prune --status` verb.** `python3 badger_store.py prune --status` reports, per log table
  across the user DB and the audit sink: row count, oldest row, last prune stamp. Read-only by
  contract — absent databases are reported as such and never created.
- **Scaffold ships the store to hook consumers.** `badger_store.py` is vendored beside every
  delivered `debug_log.py`, so a scaffolded project's hooks get store-backed audit logging
  without a framework checkout; the vendored-copy manifest keeps every landed copy
  byte-identical to the canonical module.

## Consumer impact

- `~/.ai-badger/memory-first/`, `semantica-nudge/`, `dispatch-lanes/`, `dirty-sweep-*.json`,
  `blast-radius-guard/*.denials` and `~/.ai-badger/debug/audit.jsonl` + `state.json` migrate on
  first write and are retired (renamed `*.migrated` in place) — never deleted.
- Audit records older than 60 days are deleted on the next write after the upgrade — export
  before upgrading if the audit history matters. The same applies to away-mode decisions
  (retention went live in 0.153.0).
- Checkouts that predate this release keep working through the dual-read window; a legacy file
  rewritten after migration trips the fail-closed divergence guard with the upgrade path named.
