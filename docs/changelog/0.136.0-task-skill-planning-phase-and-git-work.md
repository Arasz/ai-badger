# 0.136.0 — task skill: PLANNING phase, research stage, git-work skill

Date: 2026-08-24. Task: task-skill-refactor. PR: #433 (this one).

## What changed

### task skill restructure (features/common/skills/task/)

The orchestration pipeline now reads: Phase 0 Context hygiene → Phase 1 Start
(with a named Research step whose exit gate is a source-cited research record) →
**Phase 2 PLANNING** (architect plan + a dedicated plan-review step before any
implementation dispatch; reviewed sections consolidate into lane briefs) → Phase 3
Execute → Phase 4 Quality gate → Phase 5 Finish → Phase 6 doc audit.

- Per-phase **Entry:/Exit:** lines state the transition conditions; the end-of-file
  Verification Checklist derives from them instead of mirroring them.
- The ten prompting-rule bullets, agent-isolation deep-dive, cache-aware dispatch,
  and slow-suites rationale moved to `references/prompting-rules.md`; the body keeps
  one-line versions with conditioned pointers. Body budget: 18,844 → ~17,700 chars
  (4,711 → ~4,440 proxy) despite the new phase content.
- Language grounded in docs/research/prompt-eng/: positive constraints, machine
  validation preferred over prose conditions, persona prose stays one line.
- Cross-reference sweep in the same change: github/copilot/claude extension headings,
  references/file-schemas.md finish-protocol pointers, config-contract phase mentions.

### New skill: git-work (features/common/skills/git-work/, scope: default)

Push failures a quality gate did not cause (non-fast-forward decision tree with
force-with-lease policy, branch protection, crashed-hook replay, auth), CI failure
triage (`gh run view --log-failed`, reproduce-vs-rerun, env-only failures, flake
attribution), PR lifecycle outside a tracked task (draft → ready → review loop with
quota fallback → batch triage → resolve threads → squash merge), merge/squash
conventions, and join-time conflicts on plain branches. Scope boundaries route
gate failures to pre-push-gate-debugging and worktree mechanics to
worktree-agent-isolation. Two worked cases from this repo's history live in
`references/case-playbooks.md`. The task skill's Quality gate cites git-work for
push/CI/PR trouble.

### Tests

- `test_merged_skill_stays_in_budget.py` now covers `task` (runtime-extension shape:
  extensions stay loaded, body budget still enforced) plus a combined body+extension
  headroom check.

## Why

The task brief asked for research MoE → plan → review MoE → implement → review → qa
as explicit pipeline stages with per-phase transition gates. The plan-review step was
the biggest structural gap — "review every join" existed only as prose in the quality
gate, never forced at planning time where defects are cheapest. The git-work gap was
real: push failures without gate causes, CI triage, and standalone PR lifecycles were
covered nowhere or scattered across other skills' references.
