# 0.87.0 — Skills-lint gate in validate.py

Third PR of the skills-optimization sequence (Part C G4 of the
[opt-skills plan](../work/2026-08-07-opt-skills-plan.md)): a convention lint over every catalog
`SKILL.md`, wired into `tooling/validate.py --all` the same way `hooks_manifest_agent_gaps` is —
one function, no new CLI kind, no `index_build` change. The lint only passes because the
conventions PR-1 (0.85.0) and the individual-improvements PR-2 (0.86.1) landed first, and the
#320 learned-skills harvest was conformed to the same rules in this PR.

## What changed

- **`skills_lint(root)` in `tooling/validate.py`** — ten rules over
  `features/*/skills/*/SKILL.md` (skipping `*-extensions` dirs; missing `features/` yields no
  violations, so fake test roots stay green), reported under `--all` as an `ok/INVALID skills
  lint` line and enforced by the pre-push `validate` lane:
  1. `name` matches `[a-z0-9]+(?:-[a-z0-9]+)*` and is ≤ 64 chars;
  2. frontmatter `name:` equals the parent dir name;
  3. `description:` present and non-empty after folding (reuses `badger_lib.skill_description`);
  4. description ≤ 1024 chars;
  5. description starts with `Use when`;
  6. body ≤ 500 lines;
  7. body ≤ 5,000 chars/4 token proxy (deterministic stdlib — whitespace-token proxies were
     rejected because they undercount 1.53–1.75× and would admit ~8k real tokens);
  8. every `references/…` mention has an explicit when/if/before/after/only-when condition on
     the mention line or in its 3-line context window `{i−1, i, i+1}` — **this rule IS the G2
     checker**, extracted into one shared function (`references_without_conditions`) with the
     numbered-step skip and the `scaffold-documentation:84` exemption, so the G2 acceptance
     script and the lint can never disagree;
  9. the body has a `## Gotchas` heading (numbered variant `## 6. Gotchas` accepted) or the
     one-line "no environment-specific gotchas known" note;
  10. frontmatter completeness: `name, description, version, author, license, platforms,
     metadata.hermes.tags, metadata.hermes.related_skills` all present (arrays may be empty).
- **Stdlib frontmatter extraction** (ADR-0005: no pyyaml for behavioural parsing — pyyaml stays
  optional): the line-oriented extractor extends `badger_lib`'s `_folded_lines` pattern to
  bracket lists and the `metadata:` → `hermes:` → `tags:` nesting; anything it cannot parse
  deterministically is reported as a violation with a hint, never silently passed.
- **#320 corpus conformance** — the 28 learned-harvest skills were never put through the
  G1/G2/G3 conventions. To make the real-corpus test honest rather than skipped: 7 over-budget
  skills had their densest sections moved to `references/` (I-series pattern, G2-compliant
  pointers), 90 `references/` mentions got conditions, 12 skills gained `## Gotchas` sections,
  and 26 gained the canonical frontmatter block. The corpus is 51 `SKILL.md` files, all
  green; the post-split size max is `worktree-agent-isolation` at 4,922 chars/4 (was
  `dotnet-mcp-server` at 13,131 before the split — the measured max is recorded in the
  `MAX_TOKENS` comment).
- **Tests** — `tests/test_skills_lint.py` (test_validate.py style: `tmp_path` + `load_script`):
  one violating-fixture test per rule, a positive fixture passing all rules, the shared-G2
  checker unit tests (window semantics, numbered-step skip, exemption, keyword regex), the
  `validate_all` wiring tests, and `test_the_real_corpus_passes_skills_lint`.

## Migration

None — the lint is a gate over the catalog; consumer projects are unaffected (their
`.ai-badger/` scaffolds already pass `validate.py --kind config`; this rule set only ships as
part of `--all` on the framework tree). No re-scaffold required.
