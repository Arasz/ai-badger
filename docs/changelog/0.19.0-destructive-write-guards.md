# 0.19.0 — no command destroys state it did not create

**Review:** `docs/reviews/2026-07-26-full-project-review.md`
**Plan:** `docs/plans/2026-07-26-remediation-plan.md` (Wave 1)

Wave 1 of the remediation plan derived from a full-project review. Every fix here closes a
path where ai-badger destroyed, leaked, or executed something it did not own. Findings are
referenced by their review IDs (F-01…F-05).

## Fixed

- **F-01 — `sync_plugin_skills.py --dry-run` deleted the trees it claimed to preview.**
  `sync_skill()` called `shutil.rmtree(dest)` *before* the dry-run guard, so `--dry-run`
  removed all eight shipped skill directories from `.claude/skills/` and copied nothing back.
  `main()` also printed a per-skill success line regardless of whether anything happened. The
  guard now precedes the destructive call and the output follows the actual result. This
  script had no test file; it now has one.

- **F-02 — an unparseable config file was treated as empty, then overwritten.** Five sites
  read an existing config, silently substituted `{}` on a parse failure, and rewrote the file —
  destroying `permissions.deny`, `hooks`, and `env`. Two of the five are machine-global and
  shared across every project on the user's machine: `~/.claude/settings.json` and
  `~/.hermes/config.yaml`. A malformed YAML config additionally raised out of
  `Scaffolder.run()` and aborted the scaffold mid-write, and a YAML document parsing to a list
  raised `AttributeError`. New `config_guard.py` centralises the rule: unreadable, unparseable,
  or non-mapping input produces a refusal note instead of an empty mapping, and any write takes
  a timestamped `.bak-*` copy through an atomic replace.

- **F-03 — a user-scope hook executed a project-supplied script.** `mcp_index_hook` shelled out
  to `<cwd>/.ai-badger/skills/mcp-index/scripts/mcp_index_build.py` on session start and after
  every MCP tool call, with no containment check, no hash check, and no consent. Installed as a
  Hermes plugin it is user-scope, so it ran for whatever project the user happened to be in.
  The exec is **removed, not repointed**: the framework never creates a file by that name, so
  every occurrence of that path is foreign code, and correcting the filename to the real
  `mcp_index.py` would have armed the path rather than fixed it. The guard test is parametrized
  over both names so a future rename fails the suite. The two now-unbacked
  `mcp-index-init`/`mcp-index-update` entries are dropped from `hooks-manifest.json`.

- **F-04 — `install_cron` could replace the user's entire crontab.** `crontab -l` exiting
  non-zero was indistinguishable from "no crontab exists", so a permissions error or transient
  failure caused ai-badger to write back a crontab containing only its own line. Only a genuine
  `no crontab for <user>` now counts as empty; every other failure aborts before the write. A
  missing `crontab` binary is reported instead of raising after the success JSON has printed,
  and interpolated paths are `%`-escaped and shell-quoted.

- **F-05 — the learned-skill secret scanner failed open on symlinks.** The scanner skipped
  symlinks while `copytree(symlinks=False)` dereferenced them, so a skill containing a link to
  a file outside the skills root passed the scan and had that file's contents written into the
  project's un-gitignored `.ai-badger/skills/learned/`. `contains_symlink()` now gates both
  `is_syncable` and `sync_skill`, placed *before* the scanner — the scanner's correctness rests
  on everything it skipped being harmless. Refusing rather than reading through the link also
  closes the TOCTOU window. The fixed-vocabulary finding format is unchanged, and a new test
  asserts no scanned or linked bytes reach the refusal string.

## Changed — behaviour

Two changes are observable for existing users:

- **Cron installation is now opt-in.** `task start` no longer installs a resume cron by
  default; pass `--cron`. `--no-cron` is still accepted as a deprecated no-op and prints a
  notice, so existing scripted invocations keep working.
- **A Hermes skill containing any symlink is now refused** rather than synced. The escape hatch
  is to replace the symlink with a real file.

Additionally, a scaffold can now complete with a hook *un-wired* (reported as a note) where it
would previously have overwritten an unparseable settings file or aborted.

## Build

- `.pre-commit-config.yaml`'s pylint hook passes `--rcfile=/dev/null`, which re-enabled the
  `E0401` that `pyproject.toml` disables repo-wide; its isolated venv has no pytest, so every
  new test file reported an unresolvable import and any small one sank the 9.5 threshold. CI
  reads `pyproject.toml` and never saw this, so the two gates disagreed. Aligned.

## Not in this release

Waves 2–5 of the plan remain open, each documented with its ordering constraints. Of note:
wiring `session_start_hook.py` (F-07) is deliberately **blocked** behind the auto-wm tool
denylist (F-12), because that hook is the only launcher of a chain that can enable unattended
auto-approval — it is inert today only because the wiring is missing.
