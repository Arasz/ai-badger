# 0.25.0 — The hardening pass

**Plan:** `docs/plans/2026-07-27-deferred-work-plan.md` (Wave 9)
**Review:** security I1, I2, I5, I7, suggestions 1 & 3

Defence-in-depth, taken as one wave. None of these was exploitable from a hostile repo — every
input is catalog-controlled or written by the user themselves — and each was one bad input away
from mattering.

## Fixed

- **WP37 — install commands no longer go through a shell.** `scaffold.py` ran skill installs
  with `shell=True` on a string assembled from catalog data. Commands are now argv lists:
  `_build_command` tokenises the *template* first and substitutes per token, so a skill name
  containing a space or `;` stays exactly one argument. `install_plugins.printable()` renders
  them for display, and the scaffold prints copy-pasteable lines.

- **WP38 — dependencies are no longer installed without consent.** `run_dependency_check`
  created a venv, ran `pip install`, and ran `npm install -g` into the machine's global prefix
  as a silent side effect of scaffolding. It now defaults to reporting what *would* be
  installed, naming where each package would land; `--execute` (the same flag that gates skill
  installs) opts in.

- **WP39 — the two `.mjs` gates cap what they compile and read.** Model-supplied patterns went
  straight into `new RegExp`, so a catastrophic-backtracking pattern was a hang rather than an
  error. Patterns over 500 chars and files over 1 MB are now refused, and the refusal is
  *reported* through the normal error path rather than thrown as a stack trace.

- **WP40 — user-scope state is owner-only and bounded.** `~/.claude/awm/state.json` and
  `decisions.jsonl` record where you work and what was auto-approved; the prompt-marker state
  stores whole prompts verbatim. All three are now `0600` (the directory `0700`), the decision
  log is capped at 5,000 lines, and `.ai-badger/prompt-markers/` is gitignored here.

- **WP41 — `project.name` cannot escape the Hermes namespace.** It is interpolated into
  `~/.hermes/skills/<name>` while `config.schema.json` constrains it to a non-empty string and
  nothing else, so `../../.ssh` resolved outside the namespace directory. Containment is now
  asserted at the join — not assumed upstream, because `den-refresh` reaches `scaffold.py` with
  a hand-edited `config.json` and no re-validation. The refusal names the project name as the
  cause.

- **WP41b — a manifest `target` cannot steer the hasher out of the project.** `drift.py`
  computed `target / entry["target"]` straight from the manifest, and `pathlib` lets an
  absolute right-hand side win outright (`Path("/a") / "/etc"` is `/etc`). Out-of-project
  targets now fall back to hashing the framework source and are reported in `notes`.

## Behaviour changes worth knowing

- **Scaffolding no longer installs dependencies.** This is why 0.25.0 is in
  `BREAKING_VERSIONS`: a project that relied on the silent install now gets a report instead.
  Re-run with `--execute`, or install the named packages yourself.
- **`install_skills()` returns argv lists, not strings.** Anything consuming
  `result["commands"]` must render them with `install_plugins.printable()`.
- **A pattern over 500 characters in `agent-instructions/model.json` is now an error.**
