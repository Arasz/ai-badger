# 0.32.0 — four defects a real refresh found, and the waves that landed with them

A `0.18.1 → 0.31.1` `den-refresh` of a consuming project surfaced four defects. All four
reproduced on this repository's own dogfooded output, which is why they had survived: the
framework was producing the same broken artefacts it ships, and every gate was green.

## `.mcp.json` and `.claude/settings.json` no longer record the checkout they were written from

Two bugs, one root cause: generated config recorded **absolute paths of whichever checkout ran
the scaffolder**.

**Hooks.** `wire_hooks` wrote an absolute command, and `merge_hooks` deduplicated on the whole
command string — so a second checkout (a git worktree, a second clone, or the
`~/.ai-badger/framework` cache) produced a different string, was never recognised as a
duplicate, and was appended forever. In the reporting project **five real hooks had become
eleven entries** across three generations. The user-visible symptom is the same hook firing N
times: two `drift_notice_hook.py` copies printed two *contradictory* version warnings in one
session, which reads as a versioning bug and sends you hunting in the wrong place.

The aggravating detail: running `den-refresh` from a git worktree — the documented-safe way to
make repo changes — is precisely what minted a new path. The recommended workflow fed the bug.

Commands are now `${CLAUDE_PROJECT_DIR}/.ai-badger/skills/...`. Dedup keys on the script's
repo-relative suffix, so all five spellings of one script collapse to one entry while distinct
scripts stay distinct, and anything with no recognised marker — third-party hooks — falls
through on the literal command and is copied untouched. `merge_hooks` now *removes* superseded
entries rather than only declining to append, which is what repairs an already-broken project
instead of merely halting its growth. **An existing eleven-entry `settings.json` collapses on
the next refresh.**

**`.mcp.json` `cwd`.** Same cause, worse consequence, because `.mcp.json` is *tracked*: a
refresh from a worktree rewrote `cwd` to that worktree and staged it, so merging pointed the
project's MCP server at a directory that later gets deleted. A recorded `cwd` that still names
a scaffolded project is now kept, and a note says so.

`${CLAUDE_PROJECT_DIR}` was deliberately **not** used for `cwd`. Claude Code documents `${VAR}`
expansion in `.mcp.json` for `command`, `args`, `env`, `url` and `headers` — `cwd` is not on
that list, and neither is the default launch directory, so omitting it was equally unfounded.
Same rule as [`0.28.0`](0.28.0-mcp-user-tool-paths.md): an undocumented behaviour is not a
foundation for a framework default.

## Every manifest the scaffolder produced was schema-invalid

`scaffold.py` has always emitted `dirMeta` on directory entries; `manifest.schema.json` set
`additionalProperties: false` and never listed it. Nothing validates the manifest during
scaffold or refresh, so this was silent — 9 of 57 entries in this repo's own manifest, 7 in the
consumer's.

`dirMeta` is load-bearing: `drift.py` uses it as an O(1) structural pre-check before falling
through to the content hash. Removing the emitter would have silently slowed every drift check
to a full re-hash. The schema was widened instead, and a test now scaffolds a project and
validates the manifest it actually wrote, so emitter and schema cannot drift apart again.

## The source of truth was the file that lost content

`.ai-badger/CLAUDE.md` is declared the source of truth for the root `CLAUDE.md`, but a
re-scaffold regenerated it and dropped anything the project had added — while the root
`CLAUDE.md` *was* preserved. The two quietly diverged, and the file you are told to edit was the
one that lost work.

The request was for preserved regions. The cause was narrower: `agent_files.py` wrote the
`.ai-badger/` copy with a bare `write_text(body)`, bypassing `_copy_with_header` entirely — so
the source of truth received **none** of the four preservation mechanisms that already existed.
Both write sites now go through one helper, rather than a fifth mechanism being added beside
them ([ADR-0006](../adr/0006-one-skill-extension-mechanism.md)).

Content between `<!-- ai-badger:keep-start -->` and `<!-- ai-badger:keep-end -->` is now carried
across re-scaffolds verbatim, in order, in every agent file the scaffolder writes. Malformed
markers — unterminated, stray end, nested — leave the file **byte-identical** and emit a note
naming the line: a typo costs a refresh, never content.

## Waves 11, 12, 15 and 18

- **[ADR-0007](../adr/0007-no-python-distribution.md)** — `badger_lib` is not published as a
  Python distribution. Packaging fixes the two deployment shapes that already work and nothing
  for the two that are broken: a `.ai-badger/` scaffold and `~/.hermes/plugins/` are not failing
  to import a library, they are failing to find the catalog they were copied away from, and
  `features/`/`schemas/` are data. Verification corrected three plan claims — seven canonical
  `_bootstrap_lib()` copies rather than nine, **four** disagreeing root predicates rather than
  three, and a fourth deployment shape the three-shape framing omitted.
- **One MCP entry renderer** behind a table of four declared destinations. The duplication
  collapsed; the file got *longer*, because naming the differences costs more lines than the
  branches it removed. The two command splitters were preserved rather than unified —
  unifying them would silently change generated `.mcp.json` content.
- **`test_scaffold.py` and `test_drift.py`** split into twelve modules, verified by AST as
  byte-identical symbol-for-symbol: no renames, no assertion edits, no deletions.
- **gitleaks** scans the commit range on push and PR, and the whole history weekly. A full scan
  of all 307 commits before the gate was added found nothing, so there is **no baseline and no
  `.gitleaksignore`** — it blocks from its first run. A permanently-baselined scanner is theatre.

## A gate for the dependency claim

`scripts/deps_guard.py` fails the build on any third-party import that
`scripts/requirements.txt` does not declare, in pre-commit and on all three CI Python versions.
It resolves each import rather than consulting `sys.stdlib_module_names`, which is 3.10+ and
this project floors at 3.8, and it expands declared *distribution* names to the *module* names
source actually imports — `pyyaml` provides `yaml`.

`SECURITY.md` claimed both dependencies had guarded imports. `jsonschema` is required and
imported unguarded, on purpose: a guarded import would let validation silently pass when it is
absent. 0.29.1 corrected that claim everywhere except there.

## Upgrading

Re-scaffold. The hook-path repair is retroactive — an accumulated `.claude/settings.json`
collapses to one portable entry per script on the next refresh. To keep project-authored
content in a managed agent file, wrap it in `ai-badger:keep-start` / `keep-end` markers; the
first refresh after upgrading is the one that would otherwise drop it.
