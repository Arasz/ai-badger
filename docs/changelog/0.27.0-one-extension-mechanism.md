# 0.27.0 — one way to extend a skill

**Wave 14 of the remediation plan** (`docs/plans/2026-07-27-deferred-work-plan.md`),
addressing architecture findings I5 / R8.

## What changed

The framework had two mechanisms for extending a skill with stack-specific content. One is in
real use — `task` has four extensions, `code-review-checklist` six. The other,
`features/<stack>/skills/<skill>-extensions/<name>/`, had **zero instances anywhere**: dead
code, a schema field, and a documented feature all describing something no content used.

It is gone: `_embed_extensions`, the `index_build.py` scan block, and the `extensions` field in
`schemas/index.schema.json`.

**The supported layout is `<skill>/extensions/<name>/`** — `extension.md`, plus an optional
`extension.json` declaring `requires`. Content merges into `SKILL.md` at `<!-- EXT:name -->`
markers and is pruned when its requirements aren't met.

## Deleting it wasn't enough

`_skill_items` already skips any directory ending in `-extensions`. So with the scan removed,
such a directory would have been *entirely* inert — content that neither ships nor is
mentioned. That is worse than the dead mechanism we started with.

`index_build` now **refuses to build** when it finds one, naming each offender and the path its
contents belong at:

```
UNSUPPORTED EXTENSION LAYOUT — index not built:
  features/dotnet/skills/greet-extensions  ->  move each <ext>/ under features/dotnet/skills/greet/extensions/
```

Reasoning and the alternatives weighed: `docs/adr/0006-one-skill-extension-mechanism.md`.

## Upgrading

No action for anyone using the supported layout — that is every extension in the catalog, so
this release changes no shipped content. If you maintain a downstream catalog that used
`<skill>-extensions/`, move each `<ext>/` directory under `<skill>/extensions/`; the build tells
you exactly where.

## Also fixed

`adjust_task.py` credited `_embed_extensions` for the Hermes task extension. That was wrong
before this change — the extension lives at `task/extensions/hermes/` and has always used the
supported path. The comment now says so.
