# 0.130.1 — Semantica: shim resolves the project dir; export probe runs in the resolved env

**Type:** PATCH
**Date:** 2026-08-20

PATCH because nothing new ships: three findings from the MoE review of the 0.130.0 work
(arrived after that merge) are folded in, all defensive.

## The fixes

1. **The autosave shim wrote `.semantica/` under `os.getcwd()`.** Claude/Copilot
   PostToolUse payloads carry no `cwd`, and the hook's process cwd is the agent's launcher,
   not the project — dumps would scatter across the machine. The shim now resolves
   `$CLAUDE_PROJECT_DIR`, else the payload's own `cwd`, else writes nothing (exit 0),
   mirroring `commit_reminder_hook.resolve_project_root` and `debug_log`.

2. **`check.py` probed export_graph via the ambient python.** For uv-tool / pipx installs
   (the common case, including the machine that found the bug), the ambient python cannot
   import semantica at all, so the probe's exception path silently reported success and
   the WARNING never fired. The probe now shells out to the interpreter beside the
   resolved `semantica` executable (`_interpreter_for_executable`), with a timeout.
   Verified live: against the real 0.6.5 uv-tool install the probe returns False (broken)
   — it returned True (false success) before this fix.

3. **A skipped error result was silent.** The bridge died unseen for weeks before 0.130.0;
   an `export_graph` error that writes nothing now leaves one advisory line on stderr
   (never stdout), so the failure is visible in the hook's log.

## Evidence

- Shim: subprocess tests for the three resolution paths (env wins, payload cwd, neither →
  no write), plus the pre-existing payload spellings.
- check.py: tests prove the probe runs in the resolved interpreter (subprocess invoked
  with the interpreter beside the exe) and stays silent when no interpreter is resolvable.
- stderr diagnostic: error result → one stderr line, stdout empty; valid result → silent.
- Full suite: 4094 passed, 17 skipped, 0 failed.
