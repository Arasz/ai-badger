# 0.31.0 — a health report built from evidence

`call-behaviorist` collected records in 0.30.0. This release makes them answer a question:
**is this project's ai-badger installation actually working?**

```bash
python3 .ai-badger/skills/call-behaviorist/scripts/behaviorist.py analyze --json
```

`analyze` compares what a project **wires** (the hooks in `.ai-badger/hooks/hooks.json`)
against what was **observed** in the audit log, and returns findings — not a verdict. The agent
writes the report; the tool supplies the evidence.

## The findings

| `kind` | Severity | Means |
|---|---|---|
| `never_observed` | high | Wired **and** instrumented, but produced no record. The failure this whole feature exists to catch. |
| `not_instrumented` | low | Wired but calls no debug logger, so it *cannot* produce records. Its silence says nothing. |
| `version_skew` | high | One component ran at more than one framework version — a plugin cache disagreeing with a `.ai-badger/` scaffold. |
| `always_skipped` | medium | Fired every time and exited early every time. Live, but doing nothing. |
| `unexpected_component` | low | Produced records but is not wired here. Often legitimate. |

**`health` can be `unknown`**, and that is not a synonym for `ok`. No records means nobody
looked, and the report says so rather than implying health.

## The distinction that makes it trustworthy

The first dogfood run reported two wired hooks as high-severity failures. Both were simply
**not instrumented yet** — they cannot emit records, so their silence proves nothing. A health
report that cries wolf is worse than none, so `analyze` now reads the wired script and
separates *cannot report* from *should have reported and didn't*.

The same run also exposed a namespace bug: expected names come from hook **script stems**
(`session_start_hook`) while observed names are **phase-qualified**
(`ai_badger_hooks/session_start`). They were being compared directly, so real components looked
unexpected. Matching is now on the whole stem — `hooks/alpha` never satisfies `hooks/never`.

## Records identify their project

Every record now carries `n`: the project's own name from `.ai-badger/config.json`, read once
per process. A path is machine-specific; a name travels.

For a **user-scope install** — a hook running from `~/.claude`, `~/.hermes`, or
`~/.ai-badger` — `n` is the literal `user`. Those components belong to no project, so naming
one would be a guess.

## Filing the report

The skill deliberately prescribes **no command**. It tells the agent to read the project's
`CONTRIBUTING.md` and follow it, because how issues are filed — tracker, template, labels,
whether an issue is even the right channel — is each project's own decision, and this skill
ships into repositories it knows nothing about. If there is no `CONTRIBUTING.md`, it asks.

## Upgrading

Re-scaffold. `analyze` works on whatever records already exist; with none, it reports `unknown`
and tells you how to start collecting.
