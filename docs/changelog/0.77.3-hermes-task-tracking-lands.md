# 0.77.3 — Hermes task tracking actually lands on main

The 0.77.0/0.77.1 changelog entries described the hermes session-source work, but the
implementation never merged: main's VERSION and changelog were brought in line with the
released tags while the code stayed on PR #301's branch. This release closes that gap — the
full implementation now ships on main:

- `features/hermes/adjustments/hermes_session_source.py` registers the hermes session source
  (HERMES_SESSION_ID env var, state.db checkpoint, `hermes --resume`, delegation reader).
- `features/claude/adjustments/claude_session_source.py` + `adjust_task.py` install the claude
  source the same way; the plugin copy of the task skill ships it for plugin users.
- `tracker_lib.py` gains the generic session-source registry: per-source `resolve()`, a
  `transcript` capability, and no `DEFAULT_SOURCE` — every agent registers equally.
- `task_tracker.py` guards every source lookup: unregistered source or unattributable
  `--session-id` is a clear refusal (exit 2), never a silent claude default.
- The docs research record (`docs/work/2026-08-02-hermes-task-tracking.md`) and its changelog
  entries (0.77.0, 0.77.1) land with the code they describe.

VERSION went 0.77.2 → 0.77.3 because the shipped surface changes relative to the 0.77.2 tag
(`features/`, `skills/`, `index.json`); the release_guard requires a bump for that.
