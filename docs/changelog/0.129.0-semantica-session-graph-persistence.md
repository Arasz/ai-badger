# 0.129.0 — Semantica Gets Used, And Its Graph Survives The Session

**Type:** MINOR
**Date:** 2026-08-18

MINOR because the shipped surface grows: a new Hermes hook behaviour (auto-save), a new exported
module shipped beside the hooks, a new `hooks-manifest.json` entry, and two skills reworded to a
directory watch. Nothing a consumer already has stops working.

## The defect

Semantica was integrated as a common MCP server and skill in 0.116.3, but never used. Its graph
lives in a single in-memory stdio process and dies with the session; the only retrieval path is
the agent's own `export_graph` call, and the one export script that existed wrote every export to
`.ai-raccoon/semantica-graph.json` — a single file that each session overwrote. No hook captured
the dump, no session guidance told the agent to use Semantica, and the ai-raccoon watch was manual
and file-scoped. Diagnosis: `docs/work/2026-08-18-semantica-session-export-diagnosis.md`;
plan: `docs/work/2026-08-18-semantica-session-export-plan.md`; MoE review:
`docs/work/2026-08-18-semantica-session-export-moe-synthesis.md`.

## The fix

- **Per-session dump under `.semantica/`.** `export_semantica_graph.py` gains
  `session_export_target`, `is_export_graph`, `extract_graph_json` and `autosave_export`. Each
  export lands in a timestamped `.semantica/<session>-<ts>.json`, so sessions never overwrite each
  other. `extract_graph_json` unwraps Hermes' double-encoded MCP result envelope
  (`{"result": "<graph-json>"}`) and returns `None` on error payloads — the auto-save path skips
  rather than writing a seed. The atomic-write temp file is staged outside `.semantica/` so the
  directory watch never ingests a `.tmp` file.
- **Auto-save hook.** `ai_badger_hooks.py`'s `post_tool_observer` now dispatches
  `_maybe_autosave_semantica`, which lazy-loads the export module (shipped via
  `adjust_hooks.py`'s `SHARED_SKILL_MODULES`) and writes each `export_graph` result to the
  per-session file. Fail-open: a missing or broken module writes nothing and raises nothing.
- **Once-per-session nudge.** `pre_llm_inject_context` injects a Semantica line (record decisions
  via `record_decision`, export via `export_graph(format=json)` before finishing) once per
  session, gated on the MCP index naming a `semantica` source — so a project without Semantica is
  never nagged. The usage hint moved from emptiness- to membership-gating so the two hints are
  independent.
- **Directory watch.** The ai-raccoon-memory and semantica skills now register a one-time watch on
  the `.semantica/` **directory** (not a single file); AiRaccoon's file-watcher ingests each new
  dump. ADR-0019 amended to the per-session design, with the corrected rationale (the timestamped
  filename prevents session/subagent collisions — the watcher re-ingests on change, so
  "creation-triggered only" was wrong).

## Behaviour changes worth knowing

- `.semantica/` is a consumer-local staging directory and must be **gitignored** in every project
  that uses it; the durable record lives in ai-raccoon memory, not the repo. (The framework's own
  `.gitignore` already excludes it.)
- `.semantica/` accumulates one snapshot per export by design — no pruning. Each file is indexed
  separately by ai-raccoon.
- Claude/Copilot auto-save and their manifest entry are deferred to #418; the export module is
  host-agnostic so that port is a thin shim.
- The nudge only fires once the project's `mcp-tools.json` indexes a `semantica` source
  (rebuilt by `mcp-index update`).
