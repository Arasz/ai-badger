# 0.77.2 — freshness guard's `=all` override is host-independent

CI's scaffold-freshness guard failed on `.github/mcp.json`: the committed tree
(scaffolded on a hermes machine) dropped hermes from the Copilot file via the #193
declare-once rule, while CI (no hermes installed) kept it — so a re-scaffold changed
content. `AI_BADGER_MCP_AVAILABILITY=all` forced the availability probe
deterministically, but the `${HOME}` command rewrite still probed the host
filesystem, so the two hosts still disagreed.

- `=all` now short-circuits `_home_relative_command` too: every declared server is
  treated as available, commands stay exactly as declared, and nothing is noted
  "not found". Both hosts produce the same `.github/mcp.json` (hermes present in
  both files, no #193 divergence), the committed tree was re-scaffolded to match,
  and the guard passes with hermes absent.
- The freshness-guard test fixture now scaffolds with `=all` as well, so its clean
  baseline agrees with the guard's comparison re-scaffold on every host (a host
  without hermes previously produced a different baseline than the guard compared
  against).
