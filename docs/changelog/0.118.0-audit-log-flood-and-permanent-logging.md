# 0.118.0 — Audit Log Flood Fix and Permanent Debug Logging

**Type:** MINOR
**Date:** 2026-08-14

## What Changed

### One hook was drowning the audit log (`ai_badger_hooks`)

`_maybe_remind_commit` recorded a `skip` on **every non-edit tool call**:

```python
if commit_reminder is None or not commit_reminder.is_edit_tool(tool_name):
    _debug("ai_badger_hooks/commit_reminder", "skip", tool_name=tool_name)
    return
```

That record is now dropped. Measured on a real 5000-record log
(`~/.ai-badger/debug/audit.jsonl`, window 2026-08-01 → 2026-08-06):

| | Before |
|---|---|
| `ai_badger_hooks/commit_reminder` records | 3404 — **68.1%** of the whole log |
| of which `skip` | 3014 |
| records naming no project | 3014 — **100%** of the log's unattributed total |

Two faults in one line. The volume evicted every other component's evidence from the
5000-record cap, which is why the observable window was only five days. And the call
omitted `project=`, so those 3014 records belonged to no project: `behaviorist analyze`
sets unattributed records aside, so they were pure cost. It was the **only** `_debug` call
in the file missing `project=` — every other one already passes it.

Nothing is lost by dropping it. A missing module is already recorded by
`_load_sibling_module` as `ai_badger_hooks/sibling_load / broken`, and the hook's real work
still logs `checked` and `fire`.

### Debug logging can now stay on indefinitely (`call-behaviorist`)

`behaviorist.py on forever` (also `never` / `always`) enables logging with no expiry.
Bounded durations are unchanged and still capped at 24h.

- `parse_duration` returns `None` for the forever words.
- `cmd_on` writes `expires_at: null`; `cmd_status` prints `never`.
- `debug_log._state()` already skipped the expiry check on a falsy `expires_at`, so no
  change was needed there — but it had never been tested, and now is.

**Why.** A 24h window suits a one-off investigation and cannot answer a question about
drift over weeks: the window closes before the evidence accumulates. The trade is stated
in SKILL.md rather than hidden — always-on is a standing privacy exposure, and the
`MAX_AUDIT_LINES` cap (5000) bounds the disk regardless of duration. That cap is also why
the flood above was a bug and not a preference: a busy component evicts a quiet one.
