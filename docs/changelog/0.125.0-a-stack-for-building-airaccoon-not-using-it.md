# 0.125.0 — A Stack For Building AiRaccoon, Not Using It

**Type:** MINOR
**Date:** 2026-08-16

New stack `ai-raccoon`, detected by `AiRaccoon.slnx` / `AiRaccoon.csproj`, carrying one skill:
`ai-raccoon-manual-checklist`. Detection behaviour changes, hence MINOR — a repo with those
markers now resolves to a stack that did not exist before.

## Why a stack and not `common`

The catalog already carries `ai-raccoon` twice: `features/common/mcp/ai-raccoon/` and
`features/common/skills/ai-raccoon-memory/`. Both stay where they are, and correctly so — any
project may *use* AiRaccoon as its memory server, which is what `common` is for.

This skill is for people *building* AiRaccoon. It force-updates a global tool, starts a server
and writes to a scratch bank; none of that means anything to a project that merely queries one.
Putting it in `common` would ship a checklist full of steps for a product the reader does not
have. A stack is the mechanism this repo already has for content that ships only where it
applies, so the line is: `common` for consuming AiRaccoon, `ai-raccoon` for developing it.

## What the skill is

The hand-run pass over a live build — the things `dotnet test` cannot answer because they need a
real install, a real server and a real bank: build and install, server lifecycle, write and read
paths, noise filtering, the read-path query guard, file watch, promotion queue, the full MCP
surface, and event ids.

## Six defences it exists to carry

It graduated out of one project's `learned/` tier, where it replaced two checklists that had both
rotted the same six ways. The rewrite keeps every defence, and turns four of them from prose into
checks in `tests/test_ai_raccoon_stack.py`:

| Rot | Defence |
|---|---|
| Facts pinned by hand — one asserted `1.9.1` and "25 tools" against a tree at 1.12.0 with 26 | `scripts/derive-facts.sh` reads version and counts from the tree per run |
| Steps for a deleted feature | dead items get deleted from the template, never skipped |
| Results written into `.ai-raccoon/`, a bank directory | results go to `docs/work/checklist/` |
| No evidence field — a filled checklist and an invented one read alike | `command` and `evidence` are required per item |
| `checked`/`accepted` booleans that cannot express "skipped" | tri-state `status`, and `accepted` starts `null` |
| Two drifting copies, one having lost its `templates/` | one copy, template beside the skill |

The derivation script is the substantive change. The original derived its counts with
`grep -rc ... | awk '{s+=$2}'`, which prints a confident `0` when the path moves — a wrong answer
shaped exactly like a right one. The script exits non-zero instead, and the tests drive both
failure branches: a missing tree, and a tree whose directories exist but hold no matches.

## Also

`tooling/validate.py` gains a `FEATURE_JSON_WITHOUT_SCHEMA` entry for
`features/*/skills/*/templates/*.json` — seed bodies a skill tells its reader to copy out and
fill in. Their shape is pinned by the owning skill's tests, which can assert what a schema
cannot: that a field stays unanswerable by default.
